## Short answer

`void` означає «відсутність типу». Три використання:

1. **Функція без повернення**: `void init(void);`
2. **Функція без параметрів**: `int get(void);` – у C `int f()` і `int f(void)` різняться!
3. **Узагальнений вказівник**: `void *ptr` – вказівник на будь-який object type; його не можна напряму розіменувати або робити над ним стандартну pointer arithmetic.

У C `void *` неявно конвертується в object pointer, але перед доступом треба мати конкретний тип: `int *p = ptr;`. У C++ таке перетворення потребує явного cast.[^dou-embedded-interview]

## Detailed explanation

Тип `void` у мові C є унікальним фундаментальним типом. Згідно зі стандартом ISO/IEC 9899 (§6.2.5), `void` визначається як неповний тип (incomplete type), який не може бути завершеним (cannot be completed). Через це неможливо оголосити змінну типу `void` (`void x;` є синтаксичною помилкою) або обчислити його розмір у стандартному C (`sizeof(void)` є неприпустимим).[^iso-c-n1570]

У мові C виділяють три канонічні контексти застосування `void`:[^iso-c-n1570]

### 1. Тип значення, що повертається функцією

Коли функція не повертає значення у точку виклику, типом її результату вказується `void`:[^iso-c-n1570]

```c
void gpio_set_high(uint32_t pin);
```

- Будь-яка спроба використати результат такої функції у виразі (`int a = gpio_set_high(5);`) викликає обов’язкову діагностичну помилку компілятора.
- **Явне приведення до `(void)`:** каст виразу `(void)expr;` використовується для явного повідомлення компілятору та читачу коду, що результат виклику свідомо ігнорується. Це стандартний прийом для усунення попереджень компілятора (compiler warnings) про невикористане значення, що повертається функцією (наприклад, `(void)scanf(...)` або `(void)status;` для невикористаного аргументу).

### 2. Явна вказівка на відсутність параметрів функції

У мові C існує принципова семантична різниця між оголошеннями `int foo()` та `int foo(void)`:[^iso-c-n1570]

- **`int foo(void);`:** це прототип функції (prototype declaration), який явно заявляє, що функція приймає нуль аргументів. Спроба викликати її з будь-яким параметром (`foo(42)`) спричиняє помилку компіляції.
- **`int foo();`:** історична спадщина K&R C (до стандарту C23). Таке оголошення вказує лише на тип повернення, але залишає список параметрів невизначеним (unspecified). Компілятор вимикає перевірку кількості та типів аргументів під час виклику. Якщо викликати таку функцію з аргументом, компілятор C99/C11 не зупинить збірку помилкою, що може призвести до пошкодження стека в runtime при розходженні з визначенням функції.
- *Примітка щодо C23 та C++:* у мові C++ (а також починаючи з C23) запис `foo()` суворо еквівалентний `foo(void)`. Проте в embedded-розробці на C стандарт безпеки MISRA C суворо вимагає завжди писати `(void)` для функцій без параметрів.[^iso-cpp-n4861]

### 3. Узагальнений вказівник на об’єкт (`void *`)

Тип `void *` є універсальним вказівником, що може зберігати адресу будь-якого об’єкта в пам’яті (object pointer):[^iso-c-n1570]

- **Правила неявного приведення типів:** у мові C вказівник на будь-який об’єкт неявно конвертується у `void *` і навпаки без потреби в явному приведенні (наприклад, `int *p = malloc(sizeof(int));`). У мові C++ неявне приведення `void *` до типізованого покажчика заборонено і вимагає явного перетворення `static_cast<int *>(ptr)`.[^iso-cpp-n4861]
- **Заборона розіменування:** оскільки `void` є неповним типом невідомого розміру, вираз `*ptr` заборонений стандартом C – компілятор не знає, скільки байтів зчитувати з пам’яті та як інтерпретувати їхні біти.[^iso-c-n1570]
- **Арифметика вказівників:** за стандартом ISO C арифметика над `void *` (`ptr + 1`, `ptr++`) є нелегальною (§6.5.6). Компілятори GCC та Clang підтримують власне розширення (GNU extension), у якому розмір `void` приймається за 1 байт (`sizeof(void) == 1`). Проте в переносній embedded-розробці для зміщення покажчика на потрібну кількість байтів його слід явно приводити до `uint8_t *` або `char *`.[^iso-c-n1570]

### Роль `void *` у вбудованому ПЗ (Embedded Systems)

Вказівник `void *` є ключовим інструментом побудови поліморфних та абстрактних модулів мовою C:[^iso-c-n1570]

- **Контекст задач RTOS:** функція створення задачі у FreeRTOS `xTaskCreate` приймає параметр `void *pvParameters`. Це дозволяє передавати в нову задачу будь-яку довільну структуру конфігурації без прив’язки до конкретного типу.
- **Універсальні callback-функції:** драйвери переривань та таймерів приймають покажчик на функцію виду `void (*callback)(void *context)`. Користувач передає вказівник на свій об’єкт або структуру драйвера як контекст.
- **Буфери вводу-виводу HAL:** функції на кшталт `memcpy()`, `memset()` або апаратні дескриптори DMA оперують буферами через `void *`, працюючи з пам’яттю як із неперервною послідовністю «сирих» байтів.
