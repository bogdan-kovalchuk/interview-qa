## Short answer

`extern` оголошує ім’я, яке визначене в іншому translation unit: у header пишуть `extern int counter;`, а в одному `.c` файлі має бути визначення `int counter;`. Це дозволяє розділяти declaration і definition без дублювання глобальної змінної.

Також `extern` застосовують для функцій, хоча для звичайних функцій external linkage є типовим. У C++ є окремий випадок `extern "C"` – він вимикає C++ name mangling, щоб C++ код міг лінкуватися з C API або динамічною бібліотекою.[^dou-embedded-interview]

## Detailed explanation

### Оголошення (declaration) проти визначення (definition)

Ключове слово `extern` у мові C слугує специфікатором класу пам’яті, який вказує компілятору, що ідентифікатор має зовнішнє зв’язування (external linkage), а саме визначення об’єкта чи функції розташоване в іншій частині поточної одиниці трансляції або взагалі в іншому вихідному файлі.[^iso-c-n1570]

Фундаментальним є розмежування між оголошенням та визначенням змінної:[^iso-c-n1570]
- **Оголошення (non-defining declaration):** `extern int g_system_state;` повідомляє компілятору тип та ім’я змінної, не виділяючи для неї жодного байта пам’яті в секціях `.bss` чи `.data`. Компілятор генерує нерозв’язаний символ у таблиці символів ELF-файла, делегуючи пошук адреси лінкеру.
- **Визначення (definition):** `int g_system_state = 0;` або `int g_system_state;` (як tentative definition) інструктує компілятор виділити пам’ять під об’єкт. Якщо написати `extern int g_system_state = 5;` з ініціалізатором, стандарт C трактує цей запис саме як визначення об’єкта, незважаючи на наявність слова `extern` (компілятори зазвичай видають застереження про надлишковий специфікатор).

### Організація міжмодульного доступу до глобальних змінних

Канонічний шаблон використання `extern` для спільного доступу до глобальних ресурсів між модулями передбачає таку структуру:

1. У спільному заголовному файлі (наприклад, `system.h`) розміщують оголошення:
   ```c
   #ifndef SYSTEM_H_
   #define SYSTEM_H_
   extern volatile uint32_t g_ticks_counter;
   #endif
   ```
2. Рівно в одному `.c` файлі (наприклад, `system.c`) розміщують визначення:
   ```c
   #include "system.h"
   volatile uint32_t g_ticks_counter = 0;
   ```
3. Будь-який інший модуль, який підключає `system.h`, отримує доступ до `g_ticks_counter`.

Якщо помістити оголошення без `extern` безпосередньо в `.h` файл, кожен `.c` файл, що його підключає, створить власне визначення змінної. За використання сучасних компіляторів (GCC з типовим прапорцем `-fno-common`) це призведе до фатальної помилки лінкера `multiple definition of 'g_ticks_counter'` під час збирання проєкту.

### Оголошення функцій та extern inline

Для функцій специфікатор `extern` є типовим за замовчуванням:[^iso-c-n1570] прототип `void adc_init(void);` є повністю еквівалентним `extern void adc_init(void);`. Проте явне вказування `extern` часто використовується для підкреслення того, що реалізація знаходиться у зовнішній бібліотеці або окремому файлі.

Окремим випадком є використання `extern inline` у стандарті C99:[^iso-c-n1570]
- Якщо функція оголошена як `inline` у заголовному файлі, компілятор намагається підставити її код на місці виклику.
- Якщо оптимізатор вирішить не інлайнити функцію (або взято її адресу через покажчик), лінкер потребуватиме зовнішнього тіла функції. Оголошення з `extern inline` в одному з `.c` файлів змушує компілятор згенерувати глобальну версію функції в об’єктному коді для таких неінлайнених викликів.

### Сумісність C та C++ через extern "C"

У проєктах, які поєднують мови C та C++, конструкція `extern "C"` вимикає механізм модифікації імен (name mangling) у компіляторі C++:[^iso-c-n1570]
- Компілятор C++ додає до імен функцій суфікси з типами аргументів для підтримки перевантаження (overloading).
- Компілятор C залишає імена функцій у символьній таблиці без змін.

Без `extern "C"` виклик C-функції з коду C++ призведе до помилки лінкування `undefined reference`. Для універсальності заголовні файли C оформлюють за допомогою умовної компіляції:
```c
#ifdef __cplusplus
extern "C" {
#endif

void hal_gpio_write(uint32_t pin, uint8_t val);

#ifdef __cplusplus
}
#endif
```

### Доступ до символів лінкер-скрипта в embedded

У низькорівневому коді для мікроконтролерів (зокрема у startup-файлах) `extern` застосовується для доступу до спеціальних міток пам’яті, визначених у linker script (`.ld`):[^gnu-ld-manual]
```c
extern uint32_t _sidata; /* Початок секції .data у Flash */
extern uint32_t _sdata;  /* Початок секції .data у RAM */
extern uint32_t _edata;  /* Кінець секції .data у RAM */
```
Ці символи не займають місця як змінні – вони є чистими адресами в таблиці лінкера. Взяття адреси `&_sdata` дозволяє C-коду дізнатися межі оперативної пам’яті для копіювання даних або обнулення секції `.bss`.
