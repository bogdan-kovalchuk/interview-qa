## Short answer

**Integer promotion** перетворює вузькі integer operands перед операціями, для яких стандарт вимагає promotions: значення стає `int`, якщо той може представити всі значення початкового типу, інакше `unsigned int`.[^iso-c-n1570] Тому `uint8_t` за наявності цього optional typedef зазвичай промотується до `int`, але результат бітового `~` має тип `int`, а не `uint8_t`. Перетворення результату назад до `uint8_t` звужує значення; не покладайся на конкретне подання від’ємного `int` у переносному прикладі.[^iso-c-n1570]

## Detailed explanation

Integer promotions – це стандартні перетворення операндів перед визначеними мовою операціями, а не просто правило «всі числа стають `int` перед будь-якою арифметикою». Для типу з integer conversion rank не більшим за `int`, C спершу визначає, чи вміщує `int` весь діапазон початкового типу. Якщо так, значення перетворюється до `int`; якщо ні – до `unsigned int`. Значення при цьому зберігається.[^iso-c-n1570]

Це важливо для `char` і `short`, бо integer arithmetic зазвичай відбувається вже в промотованому типі. Наприклад, два `uint8_t` не обов’язково додаються в 8-бітній арифметиці: на звичайних реалізаціях, де `int` охоплює 0…255, обидва спершу стають `int`, і сума може бути більшою за 255. Присвоєння вузькому типу виконує окреме перетворення, яке може втратити старші біти або змінити значення відповідно до правил цільового типу.

У виразі `~a` integer promotion відбувається до застосування bitwise NOT. Якщо `a` має тип `uint8_t`, операнд часто стає `int`, отже оператор інвертує біти представлення цього `int`, а не лише вісім бітів `a`. Точний результат для від’ємного signed значення залежить від правил представлення та версії стандарту; тому приклад з `0xFFFFFF37` не можна подавати як універсальний результат для кожної реалізації. Якщо алгоритм має інвертувати рівно вісім бітів, слід явно обмежити результат маскою або працювати з типом потрібної ширини після перевірки правил conversions.

**Приклад:** якщо `uint8_t` існує і `int` представляє весь його діапазон, `uint8_t a = 200;` дає промотоване значення `int` 200. Вираз `~a` має тип `int`; лише подальше перетворення до `uint8_t` задає результат у вузькому беззнаковому типі. Це розділяє дві операції, які часто помилково зливають в одну.

**Типові помилки:**

- Називати integer promotions звичайними arithmetic conversions; це окреме правило, після якого можуть застосовуватися usual arithmetic conversions.
- Вважати, що `uint8_t` гарантує 8-бітні проміжні обчислення.
- Робити висновок про тип виразу лише з типу змінної зліва від присвоєння.

Перевіряй типи операндів до оператора і тип виразу після promotions; коли потрібна точна ширина, формулюй маскування та приведення явно.[^iso-c-n1570]
