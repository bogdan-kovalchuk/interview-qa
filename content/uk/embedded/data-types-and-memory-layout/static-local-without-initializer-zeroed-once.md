## Short answer

**Так.** Локальний `static int x;` має статичну тривалість зберігання і неявно ініціалізується нулем до початку виконання програми; це не відбувається при кожному виклику функції.[^iso-c-n1570]

`static int x = 5;` ініціалізується значенням 5 один раз, а подальші зміни зберігаються між викликами.

<span class="warn">Звичайна</span> локальна `int x;` без ініціалізатора має невизначене значення; не припускайте, що вона дорівнює нулю.[^iso-c-n1570]

## Detailed explanation

Локальна змінна з `static` має статичну тривалість зберігання: її об’єкт існує протягом усього виконання програми, хоча ім’я `x` видиме лише всередині функції. За правилами C об’єкт зі статичною тривалістю зберігання без явного ініціалізатора отримує нульове значення відповідного типу до початку виконання програми.[^iso-c-n1570]

Це відрізняється від звичайної автоматичної локальної змінної. Її час життя обмежений викликом функції, а якщо її не ініціалізувати, її значення є невизначеним. Не можна покладатися на те, що пам’ять стека «чиста» або що змінна випадково міститиме нуль. Читання такого значення до присвоєння не дає переносимого результату; компілятор може оптимізувати код, виходячи з того, що програма не виконує такої помилки.[^iso-c-n1570]

У вбудованому застосунку початкові значення об’єктів зі статичним зберіганням забезпечує стартовий код: він зазвичай копіює ініціалізовані дані у RAM і очищає область нульових даних. Назви секцій на кшталт `.data` і `.bss`, розташування пам’яті та точний алгоритм залежать від linker script і runtime конкретної платформи. Сам стандарт C вимагає початкового значення, а не певного фізичного місця чи способу його встановлення.[^iso-c-n1570]

**Приклад:**
```c
int next_id(void) {
    static int id;
    return ++id; // 1, потім 2, потім 3
}
```
Значення `id` зберігається між викликами. Типова помилка – вважати, що `static` лише обмежує видимість або що воно означає повторне занулення на вході у функцію; перевіряйте тривалість зберігання та правила ініціалізації окремо.[^iso-c-n1570]

Ця відмінність важлива і для тестування: повторний виклик функції бачить значення, залишене попереднім викликом, а не нову копію. Якщо функцію можуть викликати з кількох задач або ISR, спільний `static` об’єкт також потребує синхронізації відповідно до моделі конкурентності платформи. Автоматичне нульове початкове значення не робить подальше читання та запис потокобезпечним.[^iso-c-n1570]
