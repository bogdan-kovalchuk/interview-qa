## Short answer

Якщо результат signed integer arithmetic не представний у типі результату, поведінка C є <span class="warn">undefined behavior</span>; двійкове доповнення не перетворює це на гарантований wraparound. Для визначеного модульного обчислення застосовують unsigned тип, а для перевірки діапазону перед додаванням використовують умову на кшталт `x <= INT_MAX - y` за умови, що `y >= 0`.[^iso-c-n1570]

## Detailed explanation

Signed overflow виникає, коли результат арифметичної операції зі знаковим цілим типом не можна подати в типі результату. C не вимагає, щоб таке додавання оберталося до від’ємного мінімуму: за §6.5 результат поза діапазоном призводить до undefined behavior. Це правило стосується операції, а не лише способу зберігання бітів у конкретному процесорі.[^iso-c-n1570]

Наприклад, на реалізації, де `int` має діапазон від −32768 до 32767, вираз `32767 + 1` не має визначеного стандартом результату типу `int`. Не слід покладатися на те, що конкретний компілятор у конкретному рівні оптимізації видасть −32768. Компілятор може виходити з припущення, що визначена програма не виконує signed overflow, і спростити перевірки або цикли на цій підставі.[^iso-c-n1570]

Умову безпечного додавання невід’ємних значень треба перевірити до самої операції: для `x` і `y` типу `int`, коли `y >= 0`, вираз `x <= INT_MAX - y` дозволяє переконатися, що сума не перевищить верхню межу. Якщо знаки довільні, потрібні перевірки обох меж, причому сама перевірка не повинна переповнитися. Такі перевірки залежать від домену значень і типу операндів.[^iso-c-n1570]

Для wraparound використовують unsigned тип: арифметичний результат там визначений модулем `2^N` для відповідної ширини unsigned типу. Це не означає, що заміна `int` на `uint32_t` завжди безпечна: порівняння, перетворення й алгоритмічний зміст можуть змінитися. У прикладі циклу `i < i + 1` додавання не можна вважати нешкідливим біля `INT_MAX`; межу циклу задають так, щоб до переповнення не доходило.[^iso-c-n1570]

**Типові помилки:**
- Вважати wraparound signed числа гарантованим через поширене двійкове доповнення.
- Перевіряти результат лише після виконання операції, яка вже могла спричинити undefined behavior.
