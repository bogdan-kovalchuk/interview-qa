## Short answer

Динамічна пам'ять може ускладнити передбачення часу виконання, пікового використання RAM і поведінки після фрагментації.[^iso-c-n1570] MISRA C загалом забороняє dynamic allocation, але це правило конкретного coding standard; саме DO-178C не означає універсальної заборони `malloc` для кожного проєкту.[^misra-c-2023-addendum-2]

Алокація під час запуску теж є dynamic allocation і не стає автоматично дозволеною чи безпечною. Її можна розглядати лише коли обрана політика проєкту це дозволяє, а обмеження часу, відмови й пам'яті перевірені для конкретного allocator та конфігурації.[^iso-c-n1570][^misra-c-2023-addendum-2]

## Detailed explanation

Heap – область пам'яті, з якої програма під час виконання запитує блоки змінного часу життя через allocator, наприклад `malloc`, і повертає їх через `free`. У системі з обмеженою RAM така гнучкість має ціну: правильність залежить від того, скільки запитів одночасно живе, їхнього порядку та того, чи повертаються всі блоки.[^iso-c-n1570]

Час алокації не можна назвати недетермінованим для кожного allocator: він залежить від алгоритму, розміру запиту, стану heap і реалізації. Однак динамічні зміни стану ускладнюють доведення верхньої межі часу та RAM. Фрагментація також може залишити достатньо вільних байтів загалом, але не один придатний блок; запит тоді може завершитися невдачею. Це ризики, які аналізують, а не неминучий результат кожної алокації.[^iso-c-n1570]

Статичне виділення резервує об'єкти відомого розміру наперед, а fixed-size pool може надати контрольовану динамічну видачу блоків. Обидва підходи полегшують межовий аналіз, але потребують оцінити максимальну кількість одночасних об'єктів і поведінку при вичерпанні резерву. MISRA C загалом забороняє dynamic memory allocation; це не є підставою поширювати таку саму вимогу на кожен safety-critical стандарт чи проєкт.[^misra-c-2023-addendum-2]

Наприклад, якщо firmware створює до восьми повідомлень однакового розміру, пул з восьми блоків дає явну межу RAM. Дев'ятий запит усе одно має визначену обробку помилки, а час пошуку вільного блока треба перевірити для обраної реалізації. Сам факт використання пулу не доводить часову гарантію.[^iso-c-n1570]

**Типові помилки:** називати `malloc` завжди непередбачуваним або стверджувати, що DO-178C загалом його забороняє. Формулюй обмеження через конкретний coding standard, allocator і вимоги до часу та пам'яті.
