## Short answer

ABI задає, які аргументи й return value ідуть у registers, що кладеться на stack і які registers має зберігати caller/callee. Під час call зберігається return address, створюється stack frame для locals/spills, потім callee повертає результат і відновлює потрібний стан. Для debug HardFault корисно дивитися SP, LR, PC і stack frame.[^dou-embedded-interview]

## Detailed explanation

### Призначення ABI та поділ регістрів на Cortex-M

ABI (Application Binary Interface) – це узгоджений на двійковому рівні контракт між окремими програмними модулями, об’єктними файлами та апаратним забезпеченням процесора. На відміну від API, що визначає інтерфейси на рівні вихідного коду мови C, ABI встановлює чіткі правила представлення типів у пам’яті, вирівнювання даних, взаємодії з системними викликами та реалізації виклику функцій (calling convention).[^arm-aapcs32]

На 32-бітній архітектурі ARM Cortex-M діє стандарт AAPCS32, який ділить регістри процесора на такі функціональні групи:[^arm-aapcs32]
- **`r0–r3` (аргументи та результат / scratch):** використовуються caller-ом для передачі перших чотирьох 32-бітних параметрів і повернення значення. Для callee вони є volatile (caller-saved) – функція може змінювати їх без відновлення.
- **`r4–r11` (збережувані регістри / callee-saved):** зберігають довготривалі локальні змінні. Callee зобов’язаний зберегти старі значення цих регістрів у стек і відновити їх перед поверненням.
- **`r12` (IP – Intra-Procedure-call scratch register):** тимчасовий регістр міжпроцедурного зв’язку (може використовуватися компонувальником для проміжних переходів-трамплінів / veneers).
- **`r13` (SP – Stack Pointer):** покажчик вершини стека. В Cortex-M фізично підтримуються два покажчики: Main Stack Pointer (MSP) та Process Stack Pointer (PSP).
- **`r14` (LR – Link Register):** зберігає адресу повернення з підпрограми.
- **`r15` (PC – Program Counter):** лічильник поточної інструкції процесора.

### Покрокова анатомія виклику: пролог, тіло та епілог

Процес виконання виклику функції компілюється в чітку послідовність етапів:[^arm-aapcs32]

1. **Підготовка caller-а:** Caller обчислює значення аргументів і записує перші чотири слова у регістри `r0–r3`. Решта аргументів заштовхуються у стек із дотриманням 8-байтового вирівнювання покажчика стека. Якщо в `r0–r3` або `r12` зберігалися потрібні caller-у змінні, він попередньо скидає їх у власний stack frame.
2. **Перехід (Branch and Link):** Виконується інструкція `BL target_func`. Процесор записує адресу наступної інструкції (адресу повернення) у регістр `LR` (`r14`) і передає керування за адресою `target_func`.
3. **Пролог функції (Callee Prologue):** Якщо функція не є кінцевою (non-leaf function, тобто викликає інші підпрограми), вона зобов’язана зберегти вміст `LR`, а також ті регістри з діапазону `r4–r11`, які планує перезаписати:
   ```armasm
   PUSH {r4-r7, lr}
   SUB  sp, sp, #16  /* Виділення місця для локальних змінних */
   ```
4. **Тіло функції:** Виконуються обчислення. Доступ до локальних змінних відбувається через зміщення відносно `SP` (або frame pointer у регістрах `r7`/`r11`, якщо компіляція ведеться з прапорцем `-fno-omit-frame-pointer`).
5. **Епілог функції (Callee Epilogue):** Результат обчислень записується у `r0` (або `r0:r1`). Простір локальних змінних звільняється, збережені регістри відновлюються, а керування повертається caller-у:
   ```armasm
   ADD  sp, sp, #16
   POP  {r4-r7, pc}  /* Завантаження збереженого LR безпосередньо в PC */
   ```

### Формування stack frame та збереження контексту

Stack frame – це сукупність даних у пам’яті стека, виділена для конкретного виклику функції. Він містить:[^arm-aapcs32]
- Аргументи, що перевищують перші чотири регістри.
- Збережену адресу повернення (`LR`) та збережені callee-saved регістри.
- Локальні масиви, структури та змінні, адреса яких береться через оператор `&` (що виключає їхнє зберігання суто в регістрах).
- Тимчасові змінні процесора у випадках високого тиску на регістровий файл (spilling).
- Падінг (вирівнювальні байти) для забезпечення кратності покажчика `SP` 8 байтам.

### Апаратний стек під час переривань та HardFault

Особливістю архітектури ARM Cortex-M є автоматичне збереження базового кадру винятків (exception stack frame) на активному стеку під час виникнення переривання або винятку без участі програмного коду:[^armv7m]

Апаратний блок процесора автоматично зберігає 8 слів (32 байти): `r0`, `r1`, `r2`, `r3`, `r12`, `LR`, `PC` та `xPSR`.[^armv7m] Це дозволяє обробникам переривань мовою C працювати як звичайним функціям згідно зі стандартом AAPCS без додаткового збереження caller-saved регістрів.

Під час діагностики збоїв (HardFault) інженер аналізує цей базовий stack frame: значення збереженого `PC` вказує на точну інструкцію, що спричинила помилку (наприклад, звернення за невалідним покажчиком або невірна інструкція), а `LR` показує місце, звідки функцію було викликано.
