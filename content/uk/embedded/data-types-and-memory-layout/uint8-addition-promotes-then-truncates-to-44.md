## Short answer

За наявності `uint8_t` тип представляє значення 0–255, тому обидва операнди спершу промотуються до `int`, який може вмістити цей діапазон. Сума дорівнює 300; при перетворенні до `uint8_t` unsigned-конверсія дає залишок за модулем 256, тобто 44.[^iso-c-n1570]

## Detailed explanation

`uint8_t` існує лише на реалізаціях, де є беззнаковий цілий тип рівно на 8 біт без padding bits. Якщо тип доступний, його діапазон – 0–255, який повністю представляється `int`; тому integer promotions перетворюють обидва операнди на `int` до виконання додавання.[^iso-c-n1570]

Вираз дає `200 + 100 = 300` у типі `int`, отже переповнення під час самого додавання немає. Під час ініціалізації `result` значення 300 перетворюється до беззнакового 8-бітного типу; стандарт визначає результат як значення, конгруентне за модулем 256, тобто 44.[^iso-c-n1570]

Це перетворення відбувається при присвоєнні/ініціалізації, а не тому, що арифметика `uint8_t` автоматично виконується у 8 бітах. Якщо потрібен повний результат, збережіть його в ширшому типі; якщо очікується циклічне значення 8-бітного лічильника, явне звуження робить намір помітним.

Практична перевірка межі проста: якщо результат має залишатися звичайним числом, перевірте суму до звуження або обчислюйте її в типі, достатньому для всіх допустимих входів; беззнакове перетворення визначене, але воно може приховати втрату величини від подальшої логіки.[^iso-c-n1570]

Звуження до беззнакового типу визначене стандартом через повторне додавання або віднімання `UINT8_MAX + 1`, доки значення не потрапить у діапазон типу. У цьому випадку це еквівалентно остачі 300 за модулем 256. Це відрізняється від переповнення signed-типу: тут проміжна сума має тип `int` і значення 300, а перетворення до unsigned має визначений результат.[^iso-c-n1570]

У ширшому виразі не слід припускати, що присвоєння проміжного результату вже сталося. Наприклад, `a + b` залишається `int`, доки його явно не зберегти у вузький тип; додаткові арифметичні операції до цього моменту працюють із промотованими операндами. Перевіряйте тип кожного проміжного виразу, особливо коли значення порівнюється або передається функції, яка очікує 8-бітний результат.

**Приклад:**

```c
uint8_t a = 200, b = 100;
int sum = a + b;          // 300
uint8_t result = a + b;   // 44 після перетворення
```
