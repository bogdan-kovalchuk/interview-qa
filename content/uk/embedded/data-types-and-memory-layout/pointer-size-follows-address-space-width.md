## Short answer

У поширених ABI `sizeof(void*)` дорівнює 4 байтам на 32-бітних системах і 8 байтам на 64-бітних, але стандарт C не виводить розмір вказівника з розрядності архітектури.[^iso-c-n1570] Типова адресна модель платформи впливає на представлення вказівників, проте точне значення визначає реалізація. Перевіряйте `sizeof` у цільовому toolchain і не закладайте конкретний розмір у portable код.[^iso-c-n1570]

## Detailed explanation

`sizeof(void*)` повертає кількість байтів, потрібну реалізації для об’єкта-вказівника на `void`. На поширених ABI це 4 байти для 32-бітної моделі та 8 байтів для 64-бітної, але C визначає `sizeof` через розмір типу в конкретній реалізації, а не через маркетингову назву процесора.[^iso-c-n1570]

Розрядність CPU, ширина адреси, ширина регістра та ширина вказівника не зобов’язані бути одним і тим самим числом. MCU може мати вузький CPU, але ширші зовнішні адреси; процесор також може адресувати байтами простір більшого діапазону, ніж фізично встановлена пам’ять. Тому висновок «32-bit означає рівно 4 байти» – практичне очікування для багатьох ABI, а не переносима гарантія мови.[^iso-c-n1570]

Не плутайте розмір вказівника з розміром об’єкта, на який він вказує. `sizeof(p)` вимірює сам вказівник, тоді як `sizeof *p` вимірює тип об’єкта, якщо тип повний. C гарантує однакові представлення та вимоги вирівнювання для вказівників на сумісні типи; вказівник на `void` має відповідні гарантії сумісності з вказівником на символьний тип, але не слід без перевірки узагальнювати це на будь-які function pointers чи інші архітектурні моделі.[^iso-c-n1570]

Приклад перевірки саме для зібраної цілі:
```c
printf("%zu\n", sizeof(void *));
```

**Типова помилка:** використовувати `sizeof(void*)` як сталу довжину адреси у файлі чи протоколі. Якщо формат вимагає 32-бітне поле, оголосіть його фіксованим типом і серіалізуйте явно; вказівник лишається деталлю ABI процесу.
