## Short answer

<span class="warn">Запис поза межами масиву має undefined behaviour.</span> `p[10]` не є елементом масиву з десяти `int`.[^iso-c-n1570]

`malloc(10 * sizeof(int))` запитує місце для десяти елементів, індекси яких від 0 до 9. Стандарт C не визначає, що фізично міститься після цього об’єкта: запис може пошкодити інші дані або спричинити збій, але пошкодження heap metadata не гарантоване.[^iso-c-n1570]

Для виявлення під час розробки використовуйте доступні засоби на кшталт AddressSanitizer або guard regions; вони залежать від платформи та runtime.[^iso-c-n1570]

## Detailed explanation

Вираз `malloc(10 * sizeof(int))` запитує блок, достатній для десяти об’єктів `int`, якщо виділення успішне. Допустимі індекси такого масиву – від `p[0]` до `p[9]`; `p[10]` означає звернення за його межі. У термінах C арифметика покажчиків дозволяє обчислити покажчик на елемент одразу після масиву, але його не можна розіменовувати або використовувати як місце для запису.[^iso-c-n1570]

Точна поведінка після такого запису не визначена. На конкретній системі адреса може відповідати сусіднім даним, ділянці allocator або захищеній сторінці, тому помилка може проявитися як змінена змінна, збій зараз чи пізніше, або начебто відсутній ефект. Не можна стверджувати, що запис обов’язково перезапише metadata: розташування та формат heap залежать від allocator, і компілятор не зобов’язаний зберігати очікуваний програмою результат після undefined behaviour.[^iso-c-n1570]

**Приклад межі:** якщо успішне виділення дає масив із десяти `int`, останній допустимий запис має індекс 9. Індекс 10 можна утворити як one-past pointer, але присвоєння через нього вже виходить за об’єкт. Кількість елементів має походити з одного джерела істини: передавайте її разом із покажчиком або обчислюйте межу через `sizeof array / sizeof array[0]` лише там, де `array` ще є справжнім масивом, а не параметром-функції покажчиком.[^iso-c-n1570]

Типова помилка – покладатися на те, що тестовий запуск завершився успішно або що `malloc` виділив трохи більше через округлення allocator. Доступ до байтів понад запитаний об’єкт лишається некоректним навіть тоді, коли вони фізично доступні. Перевіряйте розмір перед індексацією; у середовищі, яке це підтримує, санітайзер може допомогти знайти помилку близько до місця запису, але не замінює правильну перевірку меж.[^iso-c-n1570]
