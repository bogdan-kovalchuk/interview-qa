## Short answer

Для `char buf[256]` допустимі індекси `0..255`; `buf[256]` не позначає елемент масиву, і його запис має undefined behavior.[^iso-c-n1570]

Наслідок не визначений стандартом: може статися пошкодження даних або аварія, але конкретну змінну чи адресу передбачити не можна.[^iso-c-n1570]

Якщо треба зберегти 256 символів і завершальний `\\0`, потрібен буфер щонайменше на 257 байтів; для коротшого рядка записуй terminator у межах фактичного розміру.[^iso-c-n1570]

## Detailed explanation

Запис `buf[256]` є помилкою на одиницю: оголошення `char buf[256]` створює рівно 256 елементів з індексами від нуля до 255. Елемент з індексом 256 не існує. C дозволяє сформувати вказівник на позицію одразу після останнього елемента, наприклад для завершення ітерації, але не дозволяє розіменовувати його або використовувати як місце запису.[^iso-c-n1570]

Оскільки запис виходить за межі об’єкта, поведінка програми не визначена. У налагоджувальній збірці це може виглядати як випадкове пошкодження сусідніх даних; оптимізована збірка може поводитися інакше. Не можна стверджувати, що пошкодиться саме локальна змінна, адреса повернення чи `.bss`: розташування об’єктів задає реалізація, а наслідок не має гарантій.[^iso-c-n1570]

**Приклад:**

```c
char buf[256];
buf[255] = '\0';      // допустимий індекс
```

Цей запис правильний лише якщо попередні байти утворюють не більше 255 символів даних. Для рядка з 256 символів плюс terminator потрібні 257 байтів, наприклад `char buf[257]`, а копіювання має бути обмежене місткістю призначення. Для довільного буфера без гарантії нульового terminator зберігай довжину окремо, а не шукай кінець за межами масиву.

**Як помилка проявляється і як її уникнути:** межова перевірка `i <= sizeof buf` часто допускає зайвий індекс; для циклу по елементах використовуй `i < sizeof buf`, а для копіювання враховуй, чи потрібне місце для terminator. Перевіряй граничні довжини 0, 255, 256 та 257 окремо. Місткість треба брати з самого масиву або передавати разом із вказівником: після передачі масиву у функцію параметр-вказівник уже не зберігає його розмір. Це особливо важливо для API, де функція приймає окремо `char *buf` і `size_t capacity`; обидва параметри мають описувати ту саму область пам’яті.[^iso-c-n1570]
