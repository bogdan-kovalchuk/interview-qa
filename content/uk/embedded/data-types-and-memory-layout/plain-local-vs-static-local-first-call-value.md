## Short answer

Ні. `int x;` має automatic storage duration і неініціалізоване значення; читати його до присвоєння не можна. `static int x;` має static storage duration і нульову ініціалізацію, виконану до першого входу у функцію; після присвоєння значення зберігається між викликами. Розміщення у стеку чи `.bss` є типовою деталлю реалізації, а не гарантією мови.[^iso-c-n1570]

## Detailed explanation

`int x;` усередині функції без `static` створює локальний об’єкт з automatic storage duration. Його час життя обмежений поточним виконанням блока: під час наступного виклику функції це інший екземпляр об’єкта, навіть якщо компілятор повторно використав ту саму адресу стеку. Для скалярного `int` без ініціалізатора початкове значення не визначене, тому читання до запису не дає переносимого результату.[^iso-c-n1570]

Додавання `static` змінює саме тривалість зберігання, а не видимість імені: ім’я все ще локальне для функції, але об’єкт існує протягом виконання програми. Нульова ініціалізація відбувається до виконання програми, а не через окреме очищення пам’яті при кожному виклику. Подальші виклики бачать останнє присвоєне значення. Реалізація може розмістити такий об’єкт у `.bss`, але стандарт C гарантує семантику, а не конкретний сегмент пам’яті.[^iso-c-n1570]

Приклад: якщо функція збільшує `static int count`, послідовні виклики дають 1, 2, 3; з автоматичним `int count = 0` кожен виклик починає з нуля. Це корисно для стану між викликами, але приховує залежність від попередніх викликів і потребує окремого захисту, якщо функцію можуть виконувати конкурентно.

У C статична локальна змінна без явного ініціалізатора має статичну ініціалізацію нулем; у C++ локальна змінна зі static storage duration ініціалізується відповідно до правил статичної ініціалізації, а складна динамічна ініціалізація виконується при першому проходженні декларації. Тут `int` має просте нульове початкове значення, тож різниця між мовами цього прикладу не змінює.

**Типова помилка:** пояснювати різницю словами «стек проти `.bss`» як обов’язкове правило. Важливо розрізняти automatic і static storage duration та не читати автоматичну змінну до ініціалізації.[^iso-c-n1570]
