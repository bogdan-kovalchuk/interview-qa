## Short answer

Ширина `int` залежить від реалізації C та ABI, тож передавання його сирих байтів не задає переносний формат повідомлення.[^iso-c-n1570] Використовуй тип фіксованої ширини, наприклад `uint16_t`, лише якщо він доступний і саме така ширина потрібна протоколу; серіалізуй значення у визначений byte order, бо сам тип не задає порядок байтів у мережевому пакеті.

Якщо один бік передає два байти, а інший читає чотири, межі полів зсуваються або частина повідомлення буде прочитана неправильно. Вибирай формат за вимогами протоколу, а не за шириною `int` на поточному пристрої.[^iso-c-n1570]

## Detailed explanation

`sizeof(int)` повертає розмір `int` у байтах для конкретної реалізації. Стандарт C задає мінімальні діапазони типів, але не одну універсальну ширину `int`; ABI компілятора визначає конкретні розміри й вирівнювання для цільової платформи.[^iso-c-n1570]

Протокол має визначати послідовність байтів незалежно від того, як об'єкт представлено в RAM. Якщо передати пам'ять змінної напряму, приймач може очікувати іншу кількість байтів, інший порядок байтів або інше представлення signed values. Навіть коли обидва пристрої мають однаковий `sizeof(int)`, це не є домовленістю про wire format.[^iso-c-n1570]

Для поля 0–65535 протокол може визначити два байти big-endian. Код має явно їх сформувати: `uint16_t` задає ширину числа, але не серіалізує його. Для signed значень і структур теж фіксуй представлення та правила сумісності версій.[^iso-c-n1570]

**Типові помилки:** вважати, що всі Cortex-M мають чотирибайтовий `int`, або що фіксований тип автоматично задає порядок байтів. Обидва висновки залежать від реалізації чи протоколу, тому перевіряй налаштування цільового компілятора і опис формату на межі пристроїв.[^iso-c-n1570]

Завжди перевіряй розмір поля у специфікації wire format окремо від `sizeof` у коді. Це також допомагає виявити зміну ABI після переходу на інший compiler target до того, як несумісний пакет потрапить на дріт.[^iso-c-n1570]

Тестуй серіалізатор відомими байтовими векторами, а не лише двома однаково зібраними пристроями. Такий тест перевіряє сам формат і не приховує спільне припущення про розмір типу або порядок байтів.[^iso-c-n1570]

Наприклад, 500 (`0x01F4`) передається як `01 F4` у big-endian; little-endian приймач прочитає `0xF401`. Порядок байтів протоколу визначає правильне декодування.
