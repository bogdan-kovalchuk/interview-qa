## Short answer

Локальна змінна з `static` має static storage duration: її пам’ять існує протягом усього виконання програми й вона ініціалізується один раз; розміщення саме в `.bss` залежить від toolchain та linker script.[^iso-c-n1570] Такий буфер не є автоматично не reentrant, але паралельні виклики або ISR і main loop, що читають чи змінюють той самий стан, можуть конфліктувати. Розмір 4096 байтів дорівнює 20% лише за бюджету RAM 20 KiB.[^iso-c-n1570]

## Detailed explanation

Локальна змінна, оголошена зі специфікатором `static`, має static storage duration: об’єкт існує від початку до завершення програми, а не лише між входом у функцію та `return`.[^iso-c-n1570] Її ініціалізатор, якщо він є, застосовується один раз; без явного ініціалізатора об’єкт статичної тривалості зберігання нульово ініціалізується. Стандарт C не називає сегмент `.bss` і не задає фізичне розташування: секцію визначають реалізація, linker script і формат прошивки.[^iso-c-n1570]

Це розміщення прибирає потребу створювати масив на stack при кожному виклику, але не зменшує загальний обсяг RAM. Якщо `buffer` має 4096 елементів по одному байту, його ємність становить 4096 байтів незалежно від того, чи викликана функція зараз. Наприклад, це 20% бюджету 20 KiB; треба врахувати також інші глобальні дані, stack усіх задач і heap. Саме фактичний linker map та виміри системи показують, чи є цей обсяг проблемою.

Повторний виклик тієї самої функції сам по собі не робить її небезпечною. Проблема виникає, якщо попередній виклик ще використовує вміст, коли наступний його перезаписує, або якщо два контексти можуть зайти одночасно. Так стається, наприклад, коли ISR перериває main loop під час обробки буфера, або дві задачі ділять один масив. Захист залежить від середовища: окремий буфер на контекст, коротка критична секція, синхронізація для потоків чи передача буфера власнику. Mutex не можна бездумно брати з ISR.

**Приклад оцінки пам’яті:**

```text
4096 bytes / 1024 = 4 KiB
4 KiB / 20 KiB = 0.20 = 20%
```

**Типові помилки:**

- Називати будь-який локальний `static` буфер автоматично «глобальним» або автоматично не reentrant; важливі спільний доступ і час життя даних.
- Вважати `.bss` вимогою мови C; це типове рішення реалізації, а не гарантія стандарту.
- Рахувати лише цей масив і забувати про stack, heap та інші об’єкти RAM.

Для повторно використовуваних буферів варто явно визначити власника, розмір і правила передачі; memory pool допомагає лише за коректної синхронізації та гарантованого часу життя виданого блока.[^iso-c-n1570]
