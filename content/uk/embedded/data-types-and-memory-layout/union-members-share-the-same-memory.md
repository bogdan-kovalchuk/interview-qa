## Short answer

Члени `union` перекривають одне й те саме сховище, а сам `union` має розмір, достатній для найбільшого члена, з можливим padding. На платформі, де `uint32_t` займає 4 байти, цей приклад потребує щонайменше 4 байтів. Читання `bytes` після запису `word` показує представлення платформи: порядок байтів не задає ні `union`, ні мова C, тож послідовність `0x78, 0x56, 0x34, 0x12` для `word = 0x12345678` стосується лише little-endian target.[^iso-c-n1570][^embeddedinterviewlab]

## Detailed explanation

Члени `union` перекривають одну область пам’яті, а його розмір щонайменше достатній для найбільшого члена; точні розмір і вирівнювання визначає реалізація з урахуванням членів та можливого padding.[^iso-c-n1570]

У прикладі масив `bytes` займає чотири байти, а `word` має розмір `sizeof(uint32_t)`, якщо реалізація надає цей точний тип. На поширеній платформі, де `uint32_t` має чотири байти, `sizeof` такого union становить щонайменше чотири байти, але стандарт не гарантує, що загальний розмір дорівнює саме найбільшому `sizeof`: вирівнювання може додати хвостові байти.[^iso-c-n1570]

Запис в один член змінює спільне сховище. Прочитання іншого члена для інтерпретації тих самих бітів має залежні від реалізації аспекти в C; не слід подавати цей прийом як переносну серіалізацію. Крім того, порядок байтів визначається платформою, а не `union`. Наприклад, лише якщо ціль little-endian і `word` справді 32-бітний, запис `0x12345678` матиме байти `78 56 34 12` від молодшої адреси.[^iso-c-n1570]

Для обміну даними між різними MCU безпечніше явно пакувати й розпаковувати байти за протоколом із визначеним порядком байтів. Для перевірки представлення на конкретному target можна виконати діагностичний тест, але це не робить таке представлення універсальним форматом файлу чи мережі.

**Типові помилки:**

- Вважати `sizeof(union)` завжди рівним найбільшому `sizeof` члена без урахування padding.
- Вважати little-endian властивістю мови C або самого `union`.

**Приклад:**

```c
union Value { uint32_t word; uint8_t bytes[4]; };
```

Перед використанням такого union визначте мету: економія спільного сховища, цільова діагностика чи формат даних. Для переносного формату використовуйте явні операції над байтами й перевіряйте ширину типу на цільовій платформі.[^iso-c-n1570]
