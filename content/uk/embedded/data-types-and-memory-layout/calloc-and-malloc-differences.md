## Short answer

`malloc(size)` виділяє блок пам’яті заданого розміру, але <span class="warn">не ініціалізує</span> його: там можуть бути старі байти. `calloc(n, size)` виділяє пам’ять під `n` елементів по `size` байтів і заповнює її нулями.

Ще одна практична різниця: якісна реалізація `calloc` може перевіряти overflow множення `n * size`, тоді як у ручному `malloc(n * size)` цю перевірку легко забути. Обидві функції повертають `NULL` при помилці й пам’ять треба звільняти через `free`.[^dou-embedded-interview]

## Detailed explanation

### Сигнатури та ініціалізація виділеної пам’яті

Обидві функції входять до стандартної бібліотеки C (`<stdlib.h>`) і слугують для динамічного виділення пам’яті у heap, але мають різний інтерфейс та контракти поведінки:[^iso-c-n1570]

```c
void *malloc(size_t size);
void *calloc(size_t nmemb, size_t size);
```

Головна функціональна відмінність полягає в ініціалізації виділеного блоку:
- `malloc` виділяє суміжну ділянку пам’яті розміром `size` байтів, залишаючи її вміст неініціалізованим. Байти містять залишкове сміття (залишкові дані попередніх операцій у цій пам’яті). Читання з неініціалізованого буфера призводить до невизначеної поведінки або витоку конфіденційної інформації (наприклад, фрагментів старих мережевих пакетів чи ключів шифрування).[^iso-c-n1570]
- `calloc` виділяє пам’ять під масив з `nmemb` елементів, кожен розміром `size` байтів, і обов’язково заповнює всі виділені байти нулями.

На сучасних архітектурах мікроконтролерів (ARM Cortex-M, RISC-V) бітова послідовність з усіх нулів гарантовано відповідає числу 0 для всіх цілих типів, покажчику `NULL`, а також числу `+0.0f` згідно зі стандартом IEEE 754.

### Захист від цілочисельного переповнення (integer overflow)

Критична перевага `calloc` перед ручним використанням `malloc(n * sizeof(T))` полягає у вбудованій перевірці цілочисельного переповнення під час множення:[^iso-c-n1570]

Коли програміст викликає `malloc(count * sizeof(item_t))`, множення `count * sizeof(item_t)` обчислюється процесором до виклику самої функції `malloc`. Якщо добуток виходить за межі діапазону типу `size_t` (наприклад, на 32-бітній платформі результат переповнює максимальне значення типу), відбувається арифметичне згортання (wrap-around) до малого числа. У результаті `malloc` виділяє буфер крихітного розміру, але програма вважає операцію успішною і намагається записати туди `count` елементів, що спричиняє катастрофічний heap buffer overflow та пошкодження пам’яті.

Якісна реалізація `calloc` всередині перевіряє факт переповнення:
```c
if (size != 0 && nmemb > SIZE_MAX / size) {
    return NULL; /* Захист від overflow */
}
```
Якщо множення виходить за межі `size_t`, `calloc` безпечно завершується помилкою, повертаючи `NULL` і встановлюючи `errno = ENOMEM`.

### Механіка роботи в embedded-середовищі vs OS

У великих операційних системах (Linux) з підтримкою віртуальної пам’яті `calloc` для великих блоків використовує системний виклик `mmap`, повертаючи анонімні сторінки, які ядро ОС уже оптимізовано зануляє за принципом copy-on-write (COW). Це дозволяє виділяти гігабайтні масиви майже миттєво без витрат процесорного часу на фізичне занулення.

У вбудованих системах на мікроконтролерах (bare-metal або FreeRTOS з `heap_4.c`) віртуальна пам’ять відсутня.[^freertos-heap] Тут `calloc` у бібліотеках на зразок Newlib-nano зазвичай реалізований як прямий виклик `malloc(nmemb * size)` з наступним `memset(ptr, 0, total_size)`. Це означає, що:
- `calloc` завжди витрачає додаткові такти процесора на ініціалізацію кожного байта пам’яті;
- Час виконання `calloc` строго пропорційний розміру буфера;
- Потрібно враховувати затримку процесора під час обробки критичних за часом подій.

### Вплив на детермінізм і безпеку мікроконтролера

Обидві функції мають однакові фундаментальні ризики динамічної пам’яті у microcontrollers:
1. Недетермінований час виконання через пошук вільного блоку у списках (free lists).
2. Ризик фрагментації пам’яті (external fragmentation), коли великий буфер неможливо виділити попри наявність сумарного вільного обсягу.[^freertos-heap]
3. Ризик вичерпання пам’яті та повернення `NULL`, що вимагає ретельної обробки помилок після кожного виклику.

З цієї причини у firmware для медичних, автомобільних та промислових приладів перевагу віддають статичним пулам буферів, а `malloc`/`calloc` допускаються лише на етапі початкової ініціалізації периферії до старту планувальника завдань.
