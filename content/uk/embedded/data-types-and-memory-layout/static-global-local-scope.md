## Short answer

Для **локальної змінної** `static` змінює час життя: змінна створюється один раз, живе до завершення програми й зберігає значення між викликами функції. Область видимості при цьому лишається локальною для блоку.

Для **глобальної змінної** або функції `static` змінює linkage: ім’я видно тільки в поточному `.c`/`.cpp` файлі. Це називається internal linkage і допомагає уникати конфліктів імен між translation units.[^dou-embedded-interview]

## Detailed explanation

### Модифікатор static для локальних змінних (Block Scope)

Коли ключове слово `static` застосовується до змінної, оголошеної всередині функції або блоку коду, воно змінює її тривалість зберігання з автоматичної (automatic storage duration) на статичну (static storage duration):[^iso-c-n1570]
- **Час життя та збереження стану**: замість розміщення на стеку змінна переноситься в оперативну пам’ять до секції `.bss` (якщо не ініціалізована або `= 0`) або `.data` (якщо має ненульовий ініціалізатор). Вона створюється і зануляється/ініціалізується точно один раз під час завантаження прошивки startup-кодом до виклику `main()`. При виході з функції змінна не знищується і зберігає своє значення для наступних викликів.
- **Обмеження видимості (Scope)**: область видимості залишається суворо локальною (block scope). Доступ до цієї змінної за іменем можливий виключно всередині того блоку, де вона оголошена. Вона не має зв’язування (no linkage) і не створює глобального символу для компонувальника.
- **Втрата реентерабельності (Reentrancy Issue)**: у вбудованих системах статична локальна змінна є прихованим спільним станом. Якщо таку функцію викликати одночасно з кількох задач RTOS або перервати її виконання обробником переривання (ISR), виникає стан перегонів (race condition), оскільки всі виклики модифікують один і той самий фізичний екземпляр у RAM. Такі функції є нереентерабельними і небезпечними для потоків.

### Модифікатор static для глобальних змінних та функцій (File Scope)

Коли `static` застосовується на рівні файлу (поза межами будь-яких функцій), змінна вже за замовчуванням має static storage duration. Тому модифікатор змінює іншу характеристику – тип зв’язування (Linkage):[^iso-c-n1570]
- **Зміна Linkage з External на Internal**: за замовчуванням глобальні змінні та функції мають external linkage і експортуються у таблицю символів компонувальника як глобальні сутності (`STB_GLOBAL`). Модифікатор `static` робить зв’язування внутрішнім (`STB_LOCAL`).
- **Інкапсуляція та модульність**: символ стає абсолютно невидимим для інших одиниць трансляції (`.c` файлів). Компонувальник не дозволить звернутися до нього через `extern` з іншого модуля. Це унеможливлює випадкові конфлікти імен (помилка `multiple definition of '...'`) і дозволяє різним драйверам мати однакові за назвою допоміжні функції або буфери.
- **Агресивні оптимізації компілятора**: компілятор знає, що статична функція або змінна ніколи не викликається ззовні даного файлу. Якщо функція коротка, оптимізатор GCC може повністю вбудувати її код (inline) і взагалі не генерувати окремого машинного коду та викликів інструкцій `BL`.

### Розміщення у сегментах пам’яті MCU (.bss, .data, .rodata)

Залежно від наявності ініціалізатора та специфікатора `const`, статичні змінні розміщуються компонувальником у різних областях пам’яті мікроконтролера:[^gnu-ld-manual]
1. `static int uninit_var;` – неініціалізована змінна потрапляє у секцію `.bss`. Вона не споживає місця у Flash, а на старті процесора зануляється циклом у `Reset_Handler`.
2. `static int init_var = 123;` – змінна з ненульовим значенням потрапляє у секцію `.data`. Її початкове значення зберігається у Flash, а під час завантаження копіюється в RAM.
3. `static const uint8_t lookup_table[] = {...};` – константний масив розміщується у секції `.rodata` і залишається виключно у Flash-пам’яті. Він доступний процесору безпосередньо через механізм XIP (Execute-in-Place) або системну шину без витрати жодного байта дорогоцінної оперативної пам’яті MCU.
