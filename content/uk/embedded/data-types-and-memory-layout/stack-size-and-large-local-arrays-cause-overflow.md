## Short answer

Розмір stack на Cortex-M не є фіксованим для архітектури: його задають компонування пам’яті, linker script і вимоги системи.

Великий автоматичний масив, наприклад `uint8_t buf[2048]`, може суттєво збільшити потребу функції у стеку; фактичне розміщення визначає реалізація.

Оцінюйте використання стека для всієї глибини викликів та вкладених ISR і перевіряйте вимоги конкретного linker script.[^iso-c-n1570]

## Detailed explanation

Стек зберігає дані, потрібні під час виконання функцій: адреси повернення, збережені регістри та локальні об’єкти, які реалізація розміщує автоматично. На Cortex-M стандарт мови не задає ані розміру стека, ані універсального «типового» діапазону. Межі визначаються конфігурацією MCU, linker script, RTOS і системою переривань; тому число в кілобайтах без контексту конкретного проєкту не є надійною відповіддю.[^iso-c-n1570]

Великий локальний масив може збільшити використання стека функцією, якщо компілятор розміщує його там. Але оцінювати потрібно не лише один кадр функції: врахуйте максимальний ланцюжок викликів, рекурсію (якщо її дозволено), переривання, вкладені ISR та контекст RTOS. Частина стеку може бути зайнята одночасно різними рівнями виконання. Оптимізація, escape analysis компілятора і атрибути об’єкта також впливають на розміщення.[^iso-c-n1570]

**Приклад оцінки:** масив на 2048 елементів типу `uint8_t` має розмір 2048 байтів, тобто 2 KiB, ще до врахування інших локальних даних. Якщо він справді лежить у стеку розміром 4 KiB, він використовує половину номінальної ємності, але реальний запас залежить від решти кадру та вкладених викликів.

Для оцінки скористайтеся звітом компілятора про стек, картою компонування, аналізом найгіршого ланцюжка викликів та вимірюванням high-water mark на цільовому пристрої. Захист MPU або guard region може допомогти виявити вихід за межу, але не збільшує доступну пам’ять і сам потребує налаштування. Перенесення буфера у `static` чи глобальну область прибирає його зі стеку, проте створює спільний стан, збільшує статичну RAM і може зробити функцію неповторно-вхідною; це не автоматичне виправлення.[^iso-c-n1570]

**Типові помилки:**
- вважати, що кожен локальний масив обов’язково фізично лежить у стеку;
- порівнювати його розмір із повною ємністю стека, не врахувавши виклики та ISR;
- називати розмір стека властивістю Cortex-M замість параметра конкретної системи.
