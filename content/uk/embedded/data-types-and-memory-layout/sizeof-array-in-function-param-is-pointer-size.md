## Short answer

У параметрі функції `int arr[]` коригується до `int *arr`, тому `sizeof(arr)` дає розмір вказівника, а не масиву; точне значення залежить від реалізації.[^iso-c-n1570] Ділення на `sizeof(arr[0])` не відновлює кількість елементів. Передавайте довжину окремим параметром або використовуйте контейнер, що зберігає її, наприклад `std::array` чи `std::span` у C++.[^iso-c-n1570]

## Detailed explanation

У параметрі функції запис `int arr[]` є зручним синтаксисом оголошення, але тип параметра після коригування – `int *`. Це правило діє під час оголошення функції; воно не перетворює кожен масив усюди на вказівник. Саме тому в тілі `f` оператор `sizeof(arr)` вимірює об’єкт-вказівник, а `sizeof(arr[0])` – один елемент типу `int`.[^iso-c-n1570]

Результат помилкового ділення залежить від ABI. Наприклад, якщо `sizeof(int*)` дорівнює 4, а `sizeof(int)` теж 4, результатом буде 1 незалежно від фактичної кількості елементів. На іншій системі співвідношення розмірів може бути іншим. Компілятор часто попереджає про `sizeof` масиву-параметра, і таке попередження варто трактувати як помилку логіки.[^iso-c-n1570]

У самому scope оголошення справжнього масиву його довжину можна обчислити як `sizeof(array)/sizeof(array[0])`, бо там `sizeof(array)` бачить увесь масив. Після передавання у звичайний параметр функції ця інформація типом параметра вже не зберігається. У C передавайте довжину явно; у C++ можна приймати посилання на масив із довжиною як параметром шаблону або використовувати `std::array`/`std::span` відповідно до потрібного часу життя.[^iso-c-n1570]

У декларації параметра також може бути записано розмір у дужках, наприклад `int arr[10]`, але це не означає, що функція автоматично отримує чи перевіряє десять елементів: параметр усе одно коригується до вказівника. Позначення `static` усередині дужок має окрему семантику передумови мінімального доступного розміру для виклику, але не робить масив частиною типу параметра і не дає `sizeof` його довжину.[^iso-c-n1570]

Практично довжина є частиною контракту функції. Передавайте її явно та узгоджуйте одиниці: це може бути кількість елементів, а не кількість байтів. Якщо API приймає буфер і байтову довжину, множення кількості елементів на `sizeof element` слід виконувати до виклику з перевіркою переповнення, коли розмір обчислюється з недовірених даних.

Приклад:
```c
void process(const int *arr, size_t count);
int values[6];
process(values, sizeof values / sizeof values[0]);
```

**Типова помилка:** вважати, що квадратні дужки в оголошенні параметра зберігають довжину. Вони цього не роблять; узгоджуйте вказівник і довжину та не використовуйте формулу `sizeof` усередині функції для параметра-масиву.[^iso-c-n1570]
