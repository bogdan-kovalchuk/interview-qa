## Short answer

Типовий розподіл пам’яті C-програми:[^dou-embedded-interview]

- **.text** – машинний код функцій. Read-only. У MCU часто зберігається у Flash.
- **.rodata** – read-only дані, наприклад рядкові літерали й частина констант.
- **.data** – глобальні та статичні змінні з ненульовою ініціалізацією. Копіюється з Flash у RAM при старті.
- **.bss** – глобальні та статичні змінні без ініціалізації або з `= 0`. Заповнюється нулями startup-кодом;
- **Stack** – локальні змінні, аргументи, адреси повернення;
- **Heap** – динамічна пам’ять (`malloc`); На більшості архітектур stack росте вниз, а heap вгору, але це platform/ABI dependent, не правило стандарту C.

## Detailed explanation

### Статичні секції бінарного образу (Flash та RAM)

Під час компіляції та компонування C-програми об’єктні файли формують структуру секцій у форматі ELF, які компонувальник прив’язує до конкретних адрес пам’яті мікроконтролера:[^gnu-ld-manual]
- **`.text`**: зберігає виконуваний машинний код процесора, вектори переривань (Interrupt Vector Table) та службові таблиці переходів. Розміщується у енергонезалежній Flash-пам’яті (ROM) і має апаратний атрибут доступу Read-Only / Execute.
- **`.rodata`**: область константних даних (Read-Only Data). Тут зберігаються рядкові літерали (`"Hello"`), глобальні змінні зі специфікатором `const`, шрифти для дисплеїв або фіксовані коефіцієнти калібрування. Залишається у Flash-пам’яті, не споживаючи оперативної пам’яті (RAM).
- **`.data`**: містить глобальні та статичні змінні, які мають явну ненульову ініціалізацію (наприклад, `int timeout = 100;`). Оскільки змінні можуть модифікуватися під час роботи програми, під час виконання вони мусять перебувати в RAM. Проте їхні початкові значення зберігаються у Flash. Для секції `.data` розрізняють дві адреси: LMA (Load Memory Address у Flash) та VMA (Virtual/Execution Memory Address у RAM).[^embedded-ld-layout]
- **`.bss` (Block Started by Symbol)**: резервує місце під глобальні та статичні змінні, які не мають ініціалізатора або ініціалізовані нулем (`int counter = 0;`). Для економії простору бінарного файлу нулі не зберігаються у Flash: секція лише описує розмір RAM у заголовку ELF, а фізичне занулення виконує startup-код.[^gnu-ld-manual]

### Динамічні області оперативної пам’яті (Stack та Heap)

Оперативна пам’ять мікроконтролера (SRAM) ділиться між статичними даними та динамічними областями:
- **Stack (Стек)**: область пам’яті швидкого автоматичного виділення, що функціонує за принципом LIFO (Last-In, First-Out). Апаратний регістр процесора (Stack Pointer, SP) керує вершиною стека. Стек містить стекові фрейми функцій: збережені регістри (callee-saved registers), адресу повернення (Link Register на ARM Cortex-M), параметри функцій, які не помістилися у регістри загального призначення, та локальні змінні з автоматичною тривалістю зберігання (automatic storage duration). Зазвичай у Cortex-M стек зростає «зверху вниз» – від старших адрес пам’яті до молодших (Full Descending Stack).
- **Heap (Купа)**: область оперативної пам’яті для динамічного виділення блоків різного розміру у runtime за допомогою функцій `malloc`/`free`. Купа зазвичай починається відразу після закінчення секції `.bss` і росте вгору (у бік збільшення адрес) під керуванням системного виклику `_sbrk()`.
- **Зіткнення стека і купи (Stack-Heap Collision)**: якщо стек і купа розміщені в одному сегменті RAM без захисного розділювача (MPU guard region), їхнє зустрічне зростання призводить до взаємного перезапису даних, що породжує приховані збої та HardFault.

### Роль Linker Script та коду початкового завантаження (Startup Code)

Точне розміщення секцій визначається скриптом компонувальника (GNU ld linker script) за допомогою команд `MEMORY` та `SECTIONS`:[^gnu-ld-manual]
```ld
MEMORY {
  FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 512K
  RAM   (xrw) : ORIGIN = 0x20000000, LENGTH = 128K
}
```
Скрипт компонувальника експортує спеціальні символи, які позначають межі секцій: `_sdata` (початок `.data` в RAM), `_edata` (кінець `.data` в RAM), `_sidata` (початок `.data` у Flash/LMA), `_sbss`, `_ebss` та `_estack` (вершина стека).[^embedded-ld-layout]

Під час подачі живлення або апаратного скидання процесор виконує `Reset_Handler` (startup code). До передачі керування у функцію `main()` початковий завантажувач обов’язково виконує два етапи ініціалізації середовища C:[^embedded-ld-layout]
1. Копіює байти початкових значень секції `.data` з Flash (від `_sidata`) до RAM (у діапазон від `_sdata` до `_edata`).
2. Заповнює область секції `.bss` у RAM нулями (у діапазоні від `_sbss` до `_ebss`).

Тільки після коректного завершення цих двох операцій мовне середовище C гарантує коректність глобальних змінних.
