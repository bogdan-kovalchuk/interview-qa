## Short answer

<span class="warn">Нескінченний цикл!</span> У виразі `i >= 0` значення `uint8_t` проходить integer promotion до `int`, тому порівняння завжди істинне.

Після тіла циклу декремент змінної `i` перетворює результат назад до `uint8_t`; при переході від `0` значення обгортається до `UINT8_MAX` (255 для 8-бітного типу).

Щоб завершити обхід, перевіряйте `i == 0` до декременту або використайте знаковий тип, що вміщує весь діапазон.[^iso-c-n1570]

## Detailed explanation

Умова `i >= 0` порівнює `int` зі значенням, отриманим з `i` через integer promotion. Для `uint8_t` значення завжди можна подати типом `int`, тож результат порівняння не може бути від'ємним. Після ітерації, де `i == 0`, постфіксний декремент спершу обчислює результат у promoted type, а потім записує його назад у `uint8_t`; перетворення до беззнакового типу дає значення за модулем `UINT8_MAX + 1`.[^iso-c-n1570]

Для точного 8-бітного `uint8_t` максимальне значення – 255. Тому перевірка `i >= 0` не виявляє перехід від нуля до найбільшого значення, і цикл повторюється. Така сама помилка можлива при зворотному обході масиву з `size_t`.[^iso-c-n1570]

Для `uint8_t` з `<stdint.h>` реалізація, яка надає цей тип, гарантує рівно 8 біт без padding; його значення лежать у межах від 0 до 255. Цей діапазон вміщується в `int`, який за стандартом має щонайменше 16 біт, тому integer promotion тут саме до `int`, а не до `unsigned int`.[^iso-c-n1570]

Це розрізнення пояснює, чому проблема не зникає після promotion: арифметика `--i` тимчасово дає `-1` у типі `int`, але присвоєння результату беззнаковому `i` перетворює його за модулем 256. Отже, наступне значення знову невід'ємне, і перевірка `i >= 0` залишається істинною.[^iso-c-n1570]

**Як уникнути помилки:** якщо нуль має бути останнім індексом, можна використовувати знаковий тип, що вміщує весь діапазон. Для беззнакового лічильника завершуйте цикл до декременту нуля.

Приклад беззнакового обходу, який завершується після обробки індексу 0:

```c
for (uint8_t i = 10; ; --i) {
    use(i);
    if (i == 0) break;
}
```

Тут декремент нуля не виконується. Обгортання беззнакового значення визначене стандартом C, але логіка програми має не покладатися на нього для завершення циклу.[^iso-c-n1570]
