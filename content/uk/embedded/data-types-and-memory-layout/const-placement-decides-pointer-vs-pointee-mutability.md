## Short answer

`const uint32_t *p` – вказівник на `uint32_t`, який не можна змінювати через `*p`, але сам `p` можна перенаправити.

`uint32_t * const p` – вказівник із фіксованою адресою, але значення `*p` можна змінити.

`const uint32_t * const p` не дозволяє змінювати ані адресу, ані дані через цей вираз.[^iso-c-n1570]

Правило читання декларації допомагає побачити, до якого рівня належить `const`. Для register pointer `volatile uint32_t * const REG` фіксує адресу, а `volatile` кваліфікує доступ до регістру.[^iso-c-n1570]

## Detailed explanation

`const` кваліфікує конкретний тип у декларації, а не «весь» вказівник чи об’єкт одразу. У `const uint32_t *p` кваліфіковано тип елемента: через вираз `*p` не можна присвоїти нове значення, проте сам `p` може згодом містити іншу адресу. У `uint32_t * const p` кваліфіковано сам об’єкт-вказівник: його адресу не можна змінити після ініціалізації, але доступний через нього `uint32_t` можна записувати.[^iso-c-n1570]

Якщо кваліфіковано обидва рівні, як у `const uint32_t * const p`, не можна змінити ані адресу вказівника, ані значення через цей шлях. Це обмеження доступу через конкретний вираз, а не доказ того, що об’єкт у пам’яті фізично незмінний: інший дозволений вказівник може мати право запису, якщо сам об’єкт не був визначений як const.[^iso-c-n1570]

`const` на вказівнику верхнього рівня має сенс, наприклад, у локальній змінній, яку не треба перенаправляти. На параметрі-функції верхньорівневий `const` не є частиною типу функції для сумісності декларацій. Натомість `const` на даних у параметрі-вказівнику документує й забезпечує відсутність записів через цей параметр.[^iso-c-n1570]

У драйвері регістрів кваліфікатори вирішують різні задачі: `volatile` вимагає відповідного спостережуваного доступу до регістру, а `const` після `*` забороняє змінювати базову адресу вказівника. Саме `volatile` не забезпечує атомарність чи синхронізацію між контекстами; ці властивості визначаються платформою та механізмами синхронізації.[^iso-c-n1570]

**Типові помилки:**
- Читати `const uint32_t *p` як незмінний вказівник: змінювати не можна `*p`, але можна `p`.
- Вважати `uint32_t * const p` вказівником на незмінне значення: тут фіксується адреса, а не дані.
- Приписувати `const` властивість фізичної незмінності об’єкта або використовувати `volatile` як заміну синхронізації.[^iso-c-n1570]
