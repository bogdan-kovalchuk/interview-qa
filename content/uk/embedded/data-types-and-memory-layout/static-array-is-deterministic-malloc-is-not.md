## Short answer

Статичний масив має заздалегідь визначений розмір і тривалість зберігання; його розміщення у `.bss` чи `.data` залежить від ініціалізації та linker script. `malloc(256)` запитує блок під час виконання, може не знайти потрібного блока й повернути null pointer, тому результат треба перевірити. Вартість і придатність allocator-а для ISR залежать від реалізації та вимог часу; safety-проєкти часто обмежують динамічну пам’ять, але це не універсальна вимога MISRA чи IEC 61508.[^iso-c-n1570]

## Detailed explanation

Статичний масив і `malloc` відрізняються передусім часом ухвалення рішення про розмір і тривалістю життя пам’яті. Для `static uint8_t buf[256]` компілятор і компонувальник знають розмір об’єкта до запуску; конкретний linker script вирішує, до якої секції та ділянки пам’яті він потрапить. Об’єкт зі статичною тривалістю зберігання має гарантовану нульову ініціалізацію, якщо явного початкового значення немає, але назви `.bss` і `.data` є домовленістю toolchain, а не вимогою мови C.[^iso-c-n1570]

`malloc` дає змогу обрати розмір під час роботи та звільняти блоки раніше завершення програми. Натомість кожен запит може завершитися невдачею: виклик повертає null pointer, якщо простору не виділено. Алгоритм allocator-а, фрагментація, затримка та блокування залежать від його реалізації; сам стандарт C не задає для `malloc` граничного часу виконання. Через це динамічне виділення часто обмежують або забороняють у ділянках із жорстким real-time дедлайном, але твердження «malloc завжди недетермінований» без назви allocator-а й конфігурації надто широке.[^iso-c-n1570]

У ISR не варто викликати довільну heap-функцію, якщо документація конкретного allocator-а не гарантує безпечність для переривань і прийнятну затримку. Виклик може захоплювати внутрішній lock, змінювати спільний стан або виконувати пошук змінної тривалості; це властивості реалізації, а не універсальна заборона стандарту. Статичний буфер або заздалегідь виділений пул зазвичай простіше перевірити на обмеження часу та пам’яті.

**Приклад вибору:** для UART RX буфера фіксованого розміру статичне сховище робить споживання SRAM видимим під час компонування. Якщо ж розмір залежить від конфігурації, виділіть ресурс до запуску real-time задач і перевірте результат, або використайте пул фіксованих блоків. Розмір буфера все одно треба обґрунтувати максимальною чергою даних; спосіб виділення сам по собі не запобігає переповненню буфера чи гонці між ISR і кодом задачі.
