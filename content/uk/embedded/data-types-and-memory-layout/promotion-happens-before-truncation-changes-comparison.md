## Short answer

Вираз `a + b` проходить integer promotion до `int`, тому його результат – `300` типу `int`, і порівняння `300 > 250` істинне. Якщо суму спершу присвоїти `uint8_t result`, перетворення дає `44`, тож `result > 250` хибне. Integer promotion відбувається до операції, а перетворення до вужчого типу – під час присвоєння.[^iso-c-n1570][^embeddedinterviewlab]

## Detailed explanation

Під час додавання `uint8_t` операнди спершу зазнають integer promotion, тому на звичайних реалізаціях із `int`, здатним подати значення від 0 до 255, обчислення `a + b` відбувається як `int`; сам тип `uint8_t` не змушує додавання переповнюватися у восьми бітах.[^iso-c-n1570]

У цьому прикладі `a` дорівнює 200, `b` дорівнює 100, а проміжна сума дорівнює 300. Умова без присвоєння порівнює цю суму з `250`, отже вона істинна. Проте присвоєння до `uint8_t result` перетворює 300 до діапазону восьми бітів: для точного 8-бітового беззнакового типу результатом буде остача 44. Наступна умова порівнює 44 з 250 і є хибною.[^iso-c-n1570]

Це не суперечність: вирішальним є місце, де значення звужується. Вбудована система не змінює правила мови, хоча розмір `int` та властивості реалізації треба перевіряти для конкретного toolchain. Для прикладу передбачається, що `uint8_t` існує і має рівно вісім бітів, як визначено в `<stdint.h>`. C гарантує integer promotion для типів, ранг яких не перевищує ранг `int`, але вибір між `int` та `unsigned int` залежить від того, чи може `int` подати всі значення початкового типу. Для беззнакового 8-бітового типу звичайний 16- або 32-бітовий `int` уміщує всі його значення; тому умовний випадок у запитанні має саме результат `int`.[^iso-c-n1570]

**Типові помилки:**

- Вважати, що тип змінних-операндів автоматично задає тип проміжного результату.
- Приписувати саме додаванню втрату старших бітів, хоча вона стається під час перетворення результату до `uint8_t`.

**Приклад:**

```c
uint8_t a = 200, b = 100;
bool direct = a + b > 250;  // true: sum is int 300
uint8_t result = a + b;     // 44
bool stored = result > 250; // false
```

Щоб уникнути пастки, визначайте тип кожного проміжного значення й перевіряйте межі до звужувального перетворення. Якщо сума має лишатися повною, зберігайте її в достатньо широкому типі; якщо потрібне модульне обчислення, явно документуйте це як частину алгоритму. Не покладайтеся на удаваний восьмибітовий overflow у виразі: integer promotion виконується до арифметичної операції.[^iso-c-n1570]
