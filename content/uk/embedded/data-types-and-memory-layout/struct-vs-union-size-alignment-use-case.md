## Short answer

`struct` містить усі поля як окремі members із padding, визначеним реалізацією; `union` надає members спільне сховище. Тому `sizeof(struct)` не обов’язково дорівнює простій сумі полів, а `sizeof(union)` не обов’язково дорівнює точному розміру найбільшого поля через padding. Обидва типи мають alignment, визначений реалізацією.[^iso-c-n1570]

## Detailed explanation

У `struct` кожен non-bit-field member має окреме місце у послідовності об’єкта, а адреси полів зростають у порядку оголошення. Реалізація може вставити padding між полями або наприкінці, щоб кожен member мав коректний alignment і щоб масив структур був вирівняний для наступного елемента. Через це арифметична сума `sizeof` полів не є переносимим способом передбачити розмір структури.[^iso-c-n1570]

У `union` members накладаються на спільне сховище й починаються з однієї адреси; у певний момент зберігається значення активного варіанта. Розміру має вистачити для найбільшого member, а alignment union повинен задовольнити вимоги його членів. Реалізація може додати padding, тому формулювання «розмір дорівнює рівно найбільшому member» надто категоричне.[^iso-c-n1570]

Практичний вибір залежить від моделі даних. `struct` підходить, коли всі поля мають існувати одночасно: стан драйвера, параметри конфігурації або група полів у внутрішньому API. `union` доречний, коли значення є одним із взаємовиключних варіантів, зазвичай разом із окремим tag-полем, яке вказує активний тип. Без tag легко прочитати не той варіант і втратити сенс даних.

**Приклад:** якщо `struct` містить `uint8_t` і `uint32_t`, компілятор може додати проміжні байти перед 32-бітним полем. Якщо аналогічні типи помістити в `union`, вони займають ті самі початкові байти, а об’єкт матиме місце для ширшого member. Точні `sizeof` і `_Alignof` варто вимірювати на цільовому compiler ABI, коли це має значення.

Не слід ототожнювати внутрішній layout із wire format або hardware register map. Протокол фіксує offsets, ширини й byte order незалежно від ABI; memory-mapped register layout також має умови виробника й компілятора. Для таких меж використовуйте явні маски/зсуви чи перевірені platform-specific визначення, а не припущення про відсутність padding.[^iso-c-n1570]

**Типові помилки:**
- Підсумовувати розміри полів `struct` і вважати результат гарантованим.
- Вважати, що всі members `union` одночасно зберігають окремі значення.
- Використовувати layout структури як серіалізацію без перевірки ABI та протоколу.[^iso-c-n1570]
