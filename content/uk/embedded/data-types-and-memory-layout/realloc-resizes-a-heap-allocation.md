## Short answer

`realloc(ptr, new_size)` змінює розмір раніше виділеного heap-блоку[^dou-embedded-interview]: якщо поруч є місце, блок розширюється на місці; інакше виділяється новий блок, старі дані копіюються, а старий звільняється.

Типове використання – динамічні масиви, буфери вводу, рядки змінної довжини. Важливий патерн: `tmp = realloc(ptr, n); if (tmp) ptr = tmp;`, бо при помилці `realloc` повертає `NULL`, але старий `ptr` лишається валідним. `realloc(NULL, size)` працює як `malloc`, а на `realloc(ptr, 0)` portable code не повинен покладатися: на багатьох реалізаціях це поводиться як `free(ptr)`, але деталі залежать від стандарту/реалізації.

## Detailed explanation

### Семантика роботи та алгоритм realloc

Функція `realloc(void *ptr, size_t size)` призначена для динамічної зміни розміру раніше виділеного блоку пам’яті з купи (heap). Вона реалізує оптимізовану логіку, яка мінімізує переміщення пам’яті:[^iso-c-n1570]
1. **Зміна розміру на місці (in-place resizing)**: якщо після поточного блоку в купі є вільний суміжний чанк достатнього розміру (при розширенні) або якщо блок зменшується (при звуженні), аллокатор просто коригує заголовки метаданих чанка. Фізична адреса буфера залишається незмінною, повертається початковий вказівник `ptr`, а дані не копіюються.
2. **Переміщення зі створенням нового блоку (relocation)**: якщо безпосередньо за блоком немає вільного місця, аллокатор виділяє абсолютно новий блок розміром `size` в іншій частині купи (за логікою `malloc`). Після цього він копіює менший із двох розмірів (старий або новий) байтів зі старого блоку в новий (`memcpy`), автоматично звільняє старий блок пам’яті (еквівалентно `free(ptr)`) і повертає вказівник на нову адресу.

### Критична помилка втрати вказівника при відмові (Memory Leak Trap)

Найнебезпечніший і найпоширеніший антипатерн використання `realloc` виглядає так:
```c
/* НЕБЕЗПЕЧНО: пряме переприсвоєння вказівника */
ptr = realloc(ptr, new_size);
```
Якщо в купі недостатньо неперервної пам’яті для нового розміру, `realloc` завершується помилкою і повертає `NULL`. При цьому старий блок пам’яті залишається недоторканим і НЕ звільняється аллокатором.[^iso-c-n1570] Пряме присвоєння перезаписує змінну `ptr` значенням `NULL`, безповоротно втрачаючи єдине посилання на старий блок. Це створює гарантований витік пам’яті (memory leak).

Правильний ідіоматичний підхід завжди вимагає проміжної змінної:
```c
void *tmp = realloc(ptr, new_size);
if (tmp == NULL) {
    /* Обробка помилки: ptr все ще валідний, старі дані цілі */
    handle_error();
    free(ptr);
    ptr = NULL;
    return -1;
}
ptr = tmp;
```

### Граничні випадки стандарту та ризики для Embedded

Стандарт мови C визначає особливу поведінку для граничних аргументів:[^iso-c-n1570]
- **`realloc(NULL, size)`**: повністю еквівалентний виклику `malloc(size)`. Це дозволяє писати компактні цикли накопичення даних без окремої ініціалізації першого виділення.
- **`realloc(ptr, 0)`**: історично в C89/C99/C11 цей виклик поводився як `free(ptr)` і повертав або `NULL`, або унікальний ненульовий вказівник. Проте у стандарті C23 така поведінка визнана застарілою або призводить до невизначеної поведінки; безпечний переносний код повинен завжди явно викликати `free(ptr)` замість передачі нульового розміру.

У вбудованих мікроконтролерах використання `realloc` пов’язане з підвищеними ризиками:
- **Інвалідація сторонніх посилань (Pointer Invalidation)**: якщо інші модулі чи структури зберегли вказівники на елементи всередині старого буфера, переміщення блоку через `realloc` робить усі ці посилання висячими вказівниками (`dangling pointers`). Звернення за ними є невизначеною поведінкою і призводить до пошкодження пам’яті.
- **Підвищена фрагментація**: регулярні зміни розміру буферів (наприклад, під час прийому пакетів невідомої довжини) залишають у невеликій купі мікроконтролера численні «дірки», прискорюючи вичерпання RAM.
- **Важкі накладні витрати на копіювання**: копіювання даних ядрами без DMA блокує процесор і погіршує часові характеристики реакції на переривання.
