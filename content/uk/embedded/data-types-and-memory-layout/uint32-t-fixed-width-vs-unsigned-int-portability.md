## Short answer

`unsigned int` має щонайменше 16 біт, а його ширина залежить від реалізації; стандарт не прив’язує її до назви MCU.[^iso-c-n1570] `uint32_t` доступний лише якщо реалізація має беззнаковий цілий тип рівно 32 біти без padding bits, і тоді саме стільки він має.[^iso-c-n1570] Для протоколів і регістрів використовуйте точний тип, якщо він доступний та відповідає специфікації; для розмірів об’єктів – `size_t`.

## Detailed explanation

`unsigned int` – стандартний беззнаковий цілий тип, але стандарт C задає мінімальну ширину його діапазону, а не одну фіксовану кількість бітів для всіх реалізацій. Тому код не повинен виводити його розмір лише з того, що цільовий процесор називають 16-bit або 32-bit: ABI компілятора визначає фактичні розміри типів.[^iso-c-n1570]

Тип `uint32_t` оголошується заголовком `<stdint.h>` за наявності відповідного точного типу. Умова «точний» означає рівно 32 біти і відсутність padding bits; це не обіцянка, що такий тип існує на кожній архітектурі. Якщо заголовок його надає, тип зручний для полів протоколу та регістрів, де формат задає рівно 32 біти. Однак сам по собі він не визначає порядок байтів у пам’яті й не гарантує переносимий бінарний layout структури: ці властивості треба задавати окремо.[^iso-c-n1570]

Для лічильника, який просто має бути беззнаковим, `unsigned int` може бути цілком доречним. Для індексів масивів і розмірів об’єктів зазвичай використовують `size_t`, оскільки саме цей тип призначений представляти результат `sizeof`. Перед передаванням значення між типами перевіряйте діапазон і формат інтерфейсу.

Наприклад, якщо повідомлення визначає поле як 32 біти, серіалізація має явно видати чотири байти у визначеному протоколом порядку. Просте копіювання `uint32_t` зі структури в буфер не задає порядок байтів і може залежати від endian-ness та padding структури.[^iso-c-n1570]

**Типова помилка:** вважати, що `uint32_t` гарантовано існує всюди або що його використання саме собою робить структуру wire-format. Перевіряйте доступність типу й кодуйте поля відповідно до специфікації протоколу.
