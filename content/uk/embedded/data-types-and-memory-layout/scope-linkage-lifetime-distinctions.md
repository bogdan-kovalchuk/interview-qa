## Short answer

**Scope** – де ім’я видиме в source code. **Linkage** – чи одне й те саме ім’я може посилатися на той самий object/function між scopes або translation units. **Lifetime/storage duration** – коли існує сам об’єкт у пам’яті; наприклад, block-scope `static` має локальну видимість, але живе весь runtime.[^dou-embedded-interview]

## Detailed explanation

### Три ортогональні концепції мови C

У мові C кожен ідентифікатор (ім’я) та об’єкт (ділянка пам’яті) характеризуються трьома фундаментальними, але абсолютно незалежними властивостями:[^iso-c-n1570]

1. **Scope (Область видимості)**:
   - Властивість *ідентифікатора* (імені), що визначає ділянку тексту вихідного коду, де це ім’я є відомим компілятору і може бути використане для доступу до сутності.
   - Стандарт C визначає чотири види scope:
     - **Block scope**: від місця оголошення до кінця поточного блоку `{ ... }` (локальні змінні, параметри функцій).
     - **File scope**: від місця оголошення до кінця одиниці трансляції (translation unit, `.c` файл з усіма включеними заголовками).
     - **Function scope**: поширюється на всю функцію; застосовується виключно для міток переходів оператора `goto`.
     - **Function prototype scope**: діє лише всередині списку параметрів прототипу функції.

2. **Linkage (Тип зв’язування)**:
   - Властивість *ідентифікатора*, що визначає, чи посилаються однакові імена, оголошені в різних областях видимості або різних одиницях трансляції, на один і той самий об’єкт або функцію під час компонування.
   - Три типи зв’язування:
     - **External linkage**: ідентифікатор посилається на одну глобальну сутність у межах усієї скомпільованої програми (типово для глобальних функцій і змінних без `static`). Символ потрапляє до таблиці символів ELF як `STB_GLOBAL`.
     - **Internal linkage**: ідентифікатор доступний для зв’язування лише в межах поточної одиниці трансляції (`static` на рівні file scope). Символ позначається як `STB_LOCAL`.
     - **No linkage**: ідентифікатор представляє унікальну сутність, яка не зв’язується з жодним іншим оголошенням (локальні змінні, поля структур `struct`, переліки `enum`).

3. **Storage Duration / Lifetime (Тривалість зберігання та час життя)**:
   - Властивість *об’єкта* (фізичної пам’яті), яка визначає період виконання програми, протягом якого об’єкт гарантовано існує в RAM/ROM, зберігає значення та має дійсну адресу.
   - Чотири класи тривалості:
     - **Static storage duration**: об’єкт живе протягом усього часу роботи програми (у секціях `.data`, `.bss` або `.rodata`).
     - **Automatic storage duration**: об’єкт створюється при вході у блок і знищується при виході з нього (на стеку або в регістрах).
     - **Allocated storage duration**: пам’ять виділяється вручну через `malloc`/`calloc` і звільняється через `free`.
     - **Thread storage duration**: у багатопотокових середовищах C11 (`_Thread_local`).

### Чому ці поняття плутають і як працює ключове слово static

Плутанина найчастіше виникає через те, що одне й те саме ключове слово `static` у мові C перевантажене і виконує кардинально різні завдання залежно від місця застосування:[^iso-c-n1570]
- **`static` всередині функції (block scope)**: не впливає на видимість і зв’язування (scope залишається block scope, linkage – no linkage). Проте воно кардинально змінює *lifetime*: замість automatic змінна отримує static storage duration, розміщується в оперативній пам’яті (`.data` або `.bss`) і зберігає свій стан між викликами функції.
- **`static` на рівні файлу (file scope)**: не змінює час життя (змінна й так мала static storage duration). Воно змінює *linkage*: замість external зв’язування стає internal, інкапсулюючи символ усередині поточного файлу.

Аналогічно, ключове слово `extern` змінює не час життя (він залишається static), а лише декларує external linkage, повідомляючи компілятору, що сам об’єкт визначений у іншому translation unit.

### Матриця типових комбінацій у прошивці

| Оголошення | Scope | Linkage | Lifetime | Секція пам’яті |
|---|---|---|---|---|
| `int a;` (поза функціями) | File | External | Static | `.bss` (або tentative) |
| `static int b;` (поза функціями) | File | Internal | Static | `.bss` (локальний у TU) |
| `int c;` (всередині функції) | Block | None | Automatic | Stack / CPU Register |
| `static int d;` (всередині функції) | Block | None | Static | `.bss` |

Розуміння цієї різниці є критичним для проектування модульних драйверів в embedded: використання `static` на рівні файлу приховує приватні регістрові структури драйвера, запобігаючи колізіям імен у глобальній таблиці символів компонувальника.
