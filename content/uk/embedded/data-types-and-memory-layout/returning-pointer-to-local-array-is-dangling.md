## Short answer

Після завершення блоку локальний масив з automatic storage duration завершує lifetime; C робить значення вказівника на такий об’єкт indeterminate.[^iso-c-n1570] Тому функція не може безпечно повернути caller’у вказівник для подальшого доступу до `buf`; слово «stack» описує поширену реалізацію, а не вимогу стандарту.[^iso-c-n1570] Передай буфер від caller’а, поверни статичне сховище з явною моделлю спільного доступу або виділи пам’ять із документованим ownership.

## Detailed explanation

Масив `buf` у прикладі є локальним об’єктом із automatic storage duration. Його lifetime охоплює виконання блоку функції й завершується, коли виконання виходить із цього блоку. `return buf` перетворює ім’я масиву на pointer до першого елемента, але не продовжує lifetime масиву.[^iso-c-n1570]

Після завершення lifetime стандарт C каже, що значення pointer на об’єкт стає indeterminate; звернення до об’єкта поза його lifetime має undefined behavior.[^iso-c-n1570] Тож основна помилка – не те, що адреса обов’язково фізично зникає або що об’єкт неодмінно лежав на stack. Пам’ять може ще містити байти `test`, але інша функція вже може використати ті самі байти для власних локальних даних. Результат залежить від реалізації й контексту, тому читання повернутого pointer не має визначеної поведінки.

Обери модель володіння, яка переживає повернення з функції. Найпростіший варіант – caller передає масив і його місткість параметрами; функція записує лише в межах місткості, а caller контролює lifetime. Інший варіант – повернути результат, скопійований у виділену пам’ять, і чітко домовитися, хто викликає `free`. Локальний `static` масив живе довше, але всі виклики ділять один буфер, тож паралельне використання або вкладений повторний виклик може перезаписати дані.

**Приклад передачі буфера:**

```c
void get_name(char *buf, size_t len);
```

Контракт такої функції має визначити поведінку для `len == 0`, чи додається `\0`, і що відбувається, якщо результат не вміщується. Саме ці межі роблять API безпечним для виклику; одного правильного типу pointer недостатньо.

**Типові помилки:**

- Пояснювати дефект лише тим, що масив «на stack»; вирішальною є тривалість життя об’єкта.
- Вважати, що pointer залишається придатним, бо числова адреса не змінилася.
- Замінити локальний масив на `static`, не врахувавши спільний стан і повторний вхід.

Компілятор може попередити про повернення адреси локальної змінної, але відсутність warning не робить lifetime коректним.[^iso-c-n1570]
