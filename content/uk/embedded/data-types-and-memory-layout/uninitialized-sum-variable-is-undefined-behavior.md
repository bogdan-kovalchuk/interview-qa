## Short answer

Локальна `int sum;` має невизначене значення. Для звичайного автоматичного об’єкта C читання такого неініціалізованого значення є undefined behavior; це не обов’язково «сміття зі стека».[^iso-c-n1570]

Ініціалізуйте суму явно, наприклад `int sum = 0;`, перш ніж додавати елементи.[^iso-c-n1570]

## Detailed explanation

`sum` має автоматичну тривалість зберігання, бо це локальний об’єкт без `static`. Оголошення `int sum;` резервує об’єкт, але не задає його початкового значення. За C такий об’єкт має невизначене значення; у випадку звичайного неініціалізованого `int`, який можна було б оголосити з `register`, використання його значення перед записом спричиняє undefined behavior.[^iso-c-n1570]

У виразі `sum += arr[i]` оператор читає поточне значення `sum`, додає елемент і записує результат. Отже, помилка стається вже при першій ітерації, ще до того, як накопичувач отримав коректне початкове значення. Це не правило про конкретний фізичний стек: компілятор може тримати змінну в регістрі, оптимізувати її чи не створювати окремого сховища. Так само не слід описувати поведінку як гарантоване отримання випадкового числа. Після undefined behavior стандарт не обіцяє конкретного результату.[^iso-c-n1570]

Правильне виправлення для суми – встановити початкове значення до циклу. Водночас перевірте, чи тип і діапазон суми достатні для всіх елементів: правильна ініціалізація не усуває переповнення signed типу. Якщо `n` може бути нульовим, початкове значення все одно має бути осмисленим результатом порожньої суми.

**Приклад:**
```c
int sum = 0;
for (int i = 0; i < n; ++i) {
    sum += arr[i];
}
```

Для виявлення подібної помилки корисні попередження компілятора, зокрема `-Wall` у GCC, однак попередження не є доказом відсутності помилки, а його поява залежить від того, чи може компілятор простежити всі шляхи виконання. Типова пастка – сприймати збіг результату в налагоджувальному запуску як гарантію: оптимізація або інша збірка може змінити прояв дефекту.[^iso-c-n1570]

Присвоєння після циклу не допоможе: перше читання в `+=` уже відбувається до цього присвоєння. Якщо суму потрібно зберігати між викликами, це має бути свідомо задана семантика, а не побічний ефект неініціалізованого автоматичного об’єкта. Для звичайного накопичення локальний `int sum = 0;` гарантує, що кожен виклик починає обчислення з визначеного стану.[^iso-c-n1570]
