## Short answer

**Звичайна локальна** має automatic storage duration: існує під час виконання блока й без ініціалізатора має невизначене значення; C не вимагає розміщувати її на стеку.[^iso-c-n1570]

**Static локальна** має static storage duration: існує протягом виконання програми, а без явного ініціалізатора ініціалізується нулем. Вона зберігає значення між входами в блок; `.bss` і `.data` – типові секції реалізації, а не вимога мови.[^iso-c-n1570]

Спільний змінний `static` стан може порушити reentrancy чи створити data race, але ключове слово саме по собі не робить функцію небезпечною для потоків.[^iso-c-n1570]

## Detailed explanation

Для локальної змінної без `static` мова C задає automatic storage duration. Її storage існує, поки виконується відповідний блок; при повторному або рекурсивному вході виникає окремий екземпляр. Компілятор зазвичай розміщує такі об’єкти у stack frame, але може тримати значення в регістрі або оптимізувати його, якщо це зберігає спостережувану поведінку програми.[^iso-c-n1570]

Локальна змінна зі `static` має static storage duration і той самий scope імені, що й раніше. Об’єкт існує весь час виконання програми, а ініціалізується один раз до початку виконання `main`; об’єкт без явного ініціалізатора отримує нульове значення. Розміщення у `.bss` чи `.data` – поширене рішення linker/toolchain, не правило стандарту C.[^iso-c-n1570]

Наприклад, лічильник викликів зберігає попереднє значення між викликами функції. Це може бути корисним для стану, але робить його спільним між усіма викликами цієї функції. У recursive або concurrent коді такий прихований стан треба враховувати; одночасні несинхронізовані записи можуть утворити data race. `static` сам по собі не означає, що будь-яке використання функції є небезпечним – висновок залежить від доступу до об’єкта.

Для interrupt-driven коду це означає, що ISR і звичайний код можуть побачити те саме значення. Якщо обидва контексти його змінюють, потрібен механізм синхронізації, який відповідає платформі; `volatile` сам по собі не забезпечує атомарність чи захист від race condition. Статичний об’єкт також займає пам’ять увесь час роботи системи, що важливо для обмеженої RAM.

**Типова помилка:** ототожнювати scope і lifetime. Ім’я локальної `static` змінної видно лише всередині блока, хоча сам об’єкт існує протягом усього виконання програми.
