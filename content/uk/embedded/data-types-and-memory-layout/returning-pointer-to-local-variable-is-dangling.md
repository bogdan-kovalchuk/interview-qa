## Short answer

Локальна змінна живе на **стеку** і знищується при виході з функції (SP змінюється).[^dou-embedded-interview] Повернений вказівник стає <span class="warn">dangling pointer</span> – вказує на вже недійсну пам’ять. Читання або запис через нього – <span class="warn">undefined behavior</span>: може повернути сміття, перезаписати інші змінні або спричинити crash.

```c
int* f(void) { int x = 42; return &x; }
```

Пам’ять може бути перезаписана наступним викликом функції, а GCC попереджає: `warning: function returns address of local variable [-Wreturn-local-addr]`.[^embeddedinterviewlab]

Правильні альтернативи: повертати значення (не вказівник); виділяти пам’ять через `malloc` (heap); використовувати `static` змінну (але не потокобезпечно); передавати буфер через параметр.

## Detailed explanation

### Механізм виникнення висячого вказівника (Dangling Pointer)

Змінні, оголошені всередині тіла функції без модифікатора `static`, мають автоматичну тривалість зберігання (automatic storage duration). Вони розміщуються у стековому фреймі (stack frame) поточної функції під час її виклику.

Коли функція завершує виконання і повертає керування, процесор відновлює попереднє значення покажчика стека (Stack Pointer, SP), наприклад за допомогою інструкції `ADD sp, sp, #imm` або `POP {..., pc}` на архітектурі ARM Cortex-M. З цього моменту життєвий цикл локальної змінної офіційно завершується: пам’ять, яку вона займала, вважається вільною і відкритою для перезапису.[^iso-c-n1570]

Якщо функція повертає адресу такої змінної (`return &x;`), отриманий викликачем вказівник стає висячим вказівником (dangling pointer). Згідно зі стандартом C (ISO/IEC 9899:2011, розділ 6.2.4), звернення за вказівником на об’єкт після закінчення його часу життя є невизначеною поведінкою (undefined behavior).[^iso-c-n1570]

### Чому дефект часто маскується і як він руйнує пам’ять

Небезпека повернення адреси локальної змінної полягає в оманливому успіху під час простого тестування:
1. **Ілюзія коректної роботи**: вихід із функції змінює лише значення регістру SP, але фізичні біти в комірках SRAM не затираються нулями миттєво. Якщо викликаючий код негайно прочитає значення `*ptr`, він може отримати очікуване число 42, створюючи хибне враження, що код працює стабільно.
2. **Перезапис іншими функціями**: будь-який наступний виклик будь-якої іншої підпрограми (наприклад, функції форматування рядка чи логування `printf`) виділить новий стековий фрейм на тому ж самому місці. Старі дані негайно затираються новими локальними змінними або адресами повернення.
3. **Руйнування стека через запис (Stack Corruption)**: якщо програма спробує записати дані через висячий вказівник (`*ptr = new_val;`), вона буквально спотворить стековий фрейм активної функції або перезапише збережене значення регістра зв’язку (Link Register, LR). При спробі виходу з активної функції процесор виконає перехід за сфальсифікованою адресою повернення, що призведе до миттєвого зависання або виклику виключення `HardFault`.
4. **Непередбачуваність переривань (ISR)**: у мікроконтролерах апаратне переривання може виникнути в будь-який момент часу між виходом із функції та розіменуванням вказівника. Обробник переривання використає стек і повністю знищить залишки локальної змінної.

Компілятор GCC зазвичай здатний виявити найпростіші випадки цієї помилки та видає попередження `warning: function returns address of local variable [-Wreturn-local-addr]`.[^embeddedinterviewlab] Проте у разі непрямого повернення (наприклад, через запис адреси локальної змінної в глобальну структуру або через проміжний вказівник) статичний аналізатор компілятора може пропустити дефект.

### Безпечні інженерні патерни передачі результату

Вбудована розробка використовує чіткі архітектурні патерни замість повернення адреси стекового об’єкта:
- **Повернення за значенням (Return by value)**: для примітивних типів (`int`, `uint32_t`, вказівники) та невеликих структур (до 16 байтів). За стандартом викликів ARM AAPCS такі значення повертаються безпосередньо через регістри `r0`-`r3`, не вимагаючи розміщення в пам’яті.
- **Буфер викликача (Caller-allocated buffer / Out-parameter)**: викликаюча функція сама виділяє буфер (на власному стеку або статично) і передає вказівник та граничний розмір у підпрограму:
  ```c
  int read_sensor_data(sensor_data_t *out_data, size_t max_len);
  ```
- **Статичний буфер (`static` storage duration)**: змінна всередині функції оголошується як `static`. Вона розміщується в `.bss` або `.data` і живе протягом усього часу роботи програми. Проте цей підхід має критичний недолік: функція стає нереентерабельною (non-reentrant) і небезпечною для використання у багатозадачному середовищі RTOS або всередині ISR.
