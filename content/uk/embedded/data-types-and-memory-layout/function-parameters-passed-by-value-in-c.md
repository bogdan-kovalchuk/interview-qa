## Short answer

У C параметри передаються **за значенням**: функція отримує копію аргументу.[^dou-embedded-interview] Якщо передати `int x`, зміна параметра всередині функції не змінить змінну caller-а.

Щоб функція могла змінити об’єкт або не копіювати великий об’єкт, передають адресу: `void f(int *p)` або `void g(struct Big *s)`. Масиви в параметрах фактично перетворюються на вказівник на перший елемент, тому розмір масиву окремо треба передавати явно. У C++ додатково є references: `T&` і `const T&`.

## Detailed explanation

### Принцип передачі за значенням (pass-by-value) у мові C

Фундаментальне правило стандарту ISO/IEC 9899 (пункт 6.5.2.2) стверджує: у мові програмування C абсолютно всі аргументи передаються у функцію **виключно за значенням (pass-by-value)**.[^iso-c-n1570]

Це означає, що під час виклику функції:
1. Вираз кожного аргументу повністю обчислюється caller-ом.
2. Значення виразу копіюється у виділену для параметра пам’ять (у регістр процесора або у стек функції-callee).
3. Формальний параметр всередині функції є цілком незалежною локальною копією.
4. Будь-які зміни, присвоєння чи модифікації цього параметра всередині тіла функції діють лише на цю локальну копію і жодним чином не впливають на оригінальну змінну викликаючої сторони:[^iso-c-n1570]

```c
void modify_val(int x) {
    x = 100; /* Змінюється лише локальна змінна x на стеку або в регістрі r0 */
}

int main(void) {
    int a = 10;
    modify_val(a);
    /* a все ще дорівнює 10 */
}
```

### Емуляція передачі за посиланням через вказівники

Оскільки мова C не підтримує концепцію посилань (references), яка згодом з’явилася у C++, для зміни стану зовнішніх змінних використовують покажчики (pointers). Проте важливо усвідомлювати: навіть у цьому випадку діє той самий механізм передачі за значенням.[^iso-c-n1570]

Коли викликається функція `modify_ptr(&a)`:
- Оператор `&` обчислює адресу змінної `a` в пам’яті (числове значення адреси).
- Це числове значення адреси копіюється у параметр функції (покажчик `int *p`). Сам покажчик передається за значенням.
- Всередині функції розіменування `*p = 100;` звертається за переданою адресою, змінюючи оригінальний об’єкт у пам’яті caller-а.
- Якщо змінити сам покажчик (`p = NULL;`), це оновить лише локальну копію покажчика, не зачепивши вихідну адресу.

Для захисту даних від ненавмисної зміни під час передачі адрес великих структур застосовують кваліфікатор `const`: `void process(const sensor_data_t *data)`. Це повідомляє компілятору про режим «тільки для читання» і дозволяє безпечно передавати покажчики на об’єкти, розташовані у Flash-пам’яті (`.rodata`).

### Особливість масивів: decay до вказівника на перший елемент

Спроба передати масив у функцію мовою C підпорядковується правилу array-to-pointer decay (пункт 6.3.2.1 стандарту ISO C):[^iso-c-n1570] вираз типу масив (окрім випадків застосування операторів `sizeof` та `&`) неявно перетворюється на покажчик на його перший елемент (`&arr[0]`).

Це має прямі наслідки для сигнатур функцій:
```c
void process_buffer(uint8_t buf[64]);
void process_buffer(uint8_t buf[]);
void process_buffer(uint8_t *buf);
```
Для компілятора всі три наведені оголошення є абсолютно тотожними – функція отримує простий покажчик `uint8_t *buf`. Вказівка розміру `[64]` компілятором ігнорується.

Через це виклик `sizeof(buf)` всередині функції `process_buffer` поверне розмір покажчика (4 байти на 32-бітному ARM або 8 байтів на 64-бітних CPU), а не реальний розмір масиву в 64 байти. Тому у C розмір буфера завжди передається як явний додатковий числовий аргумент: `void process_buffer(uint8_t *buf, size_t len)`.

### Вплив на продуктивність і стек у embedded-системах

У вбудованих системах спосіб передачі параметрів безпосередньо впливає на надійність та швидкодію:[^arm-aapcs32]
- **Скалярні типи:** Передача базових типів (`int`, `uint32_t`, `float`, покажчики) за значенням є максимально ефективною. Згідно з AAPCS, перші чотири слова передаються через швидкі регістри процесора `r0–r3`, взагалі не торкаючись оперативної пам’яті стека.[^arm-aapcs32]
- **Структури за значенням:** Якщо передати велику структуру за значенням (`void send_packet(packet_t pkt)`), компілятор зобов’язаний повністю скопіювати всі її поля. Це викликає масивні інструкції копіювання пам’яті та стрімко вичерпує критично обмежений стек задачі (типовий стек RTOS-задачі становить лише 512–2048 байтів).
- **Інженерне правило:** Примітивні скалярні типи завжди передають за значенням, а будь-які структури, об’єкти конфігурації та масиви передають через покажчик (бажано `const *`, якщо функція не змінює об’єкт).
