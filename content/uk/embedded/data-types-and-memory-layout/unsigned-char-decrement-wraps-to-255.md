## Short answer

Після `x--` значення `x` буде **255**, якщо `unsigned char` має 8 бітів; стандарт C не вимагає саме 8 бітів. Цілочисельне підвищення означає, що віднімання виконується після promotion, а присвоєння приводить результат до типу `unsigned char` за модулем `UCHAR_MAX + 1`.[^iso-c-n1570]

Це визначене перетворення, не signed overflow. Умова `i >= 0` для unsigned завжди істинна, тож цикл такого вигляду не завершується звичайним спаданням.[^iso-c-n1570]

## Detailed explanation

У виразі `x--` спочатку застосовуються integer promotions: `unsigned char` зазвичай підвищується до `int`, якщо той може представити всі значення цього типу, або до `unsigned int` в іншому разі. Віднімання відбувається у типі після promotion, а результат зберігається назад у `x` з перетворенням до `unsigned char`.[^iso-c-n1570]

Для беззнакового цілого перетворення дає значення, конгруентне вихідному за модулем `UCHAR_MAX + 1`. Коли `x` дорівнює нулю, результат після збереження дорівнює `UCHAR_MAX`. Якщо `CHAR_BIT` дорівнює 8 і `unsigned char` має діапазон 0–255, це буде 255; переносимий код не повинен без перевірки припускати саме цей діапазон.[^iso-c-n1570]

Важлива пастка – відрізняти тип операнда під час обчислення від типу об’єкта, куди записується результат. Також беззнакова арифметика не має undefined behavior через переповнення, але wraparound може бути логічною помилкою. Наприклад, перевірка `i >= 0` завжди істинна для беззнакового `i`, тому цикл не зупиниться при досягненні нуля: після декременту значення обернеться до максимального значення типу.[^iso-c-n1570]

**Приклад:**
```c
#include <limits.h>
unsigned char x = 0;
x--;
/* x == UCHAR_MAX; це 255 лише коли UCHAR_MAX == 255 */
```

Щоб ітерувати вниз без такого дефекту, обирайте тип і умову, які явно представляють стан «до нуля», або перевіряйте нуль перед декрементом. Не виправляйте код лише припущенням, що `unsigned char` завжди має конкретну ширину: діапазон задає реалізація, а межі потрібно брати з `<limits.h>`.[^iso-c-n1570]

У виразі з postfix-декрементом результат самого виразу дорівнює попередньому значенню, хоча об’єкт уже зменшується. Не плутайте його з новим значенням `x`, якщо оператор використовується всередині більшого виразу. Окремий рядок `x--;` змінює об’єкт, а результат виразу тут відкидається.[^iso-c-n1570]
