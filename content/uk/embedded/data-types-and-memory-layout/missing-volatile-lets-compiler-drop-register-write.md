## Short answer

Компілятор може оптимізувати запис як звичайний доступ до пам’яті, бо зовнішній пристрій не є частиною абстрактної машини C.[^iso-c-n1570]

Без `volatile` немає гарантії, що потрібний запис буде збережений як апаратний доступ.

Для memory-mapped регістра використовують pointer на `volatile` тип, наприклад `volatile uint32_t *reg`; це вимагає відповідних доступів за правилами C, але саме по собі не гарантує правильну адресу, атомарність чи потрібний порядок операцій.[^iso-c-n1570]

## Detailed explanation

`volatile` повідомляє компілятору, що доступ до об’єкта має спостережуваний ефект і його не можна оптимізувати як звичайний невикористаний запис; саме тому його застосовують до memory-mapped register.[^iso-c-n1570] Без цього кваліфікатора компілятор аналізує вираз за правилами звичайної абстрактної машини C і може прибрати запис, якщо програма надалі не читає значення.

Адреса `0x40020000` у прикладі лише ілюстративна. Для реального периферійного регістра потрібні адреса й ширина доступу з документації конкретного MCU, а також правильний тип і правила доступу. Просте приведення цілого числа до вказівника саме по собі не робить цей доступ допустимим для всіх реалізацій C або всіх платформ.

`volatile` гарантує вимогу щодо виконання відповідних доступів у межах правил мови, але не робить операцію атомарною, не синхронізує потоки, не очищає кеш і не замінює memory barrier чи периферійний протокол. Воно також не забезпечує правильного порядку між звичайною пам’яттю та пристроєм на кожній архітектурі. Для таких вимог користуються примітивами платформи й інструкціями, визначеними архітектурою.[^iso-c-n1570]

При роботі з регістром важливо знати, чи це read/write, write-one-to-clear або регістр із побічними ефектами читання. Наприклад, read-modify-write для регістру статусу може випадково очистити прапорці; правильний доступ визначає reference manual, а не сам `volatile`. Так само qualifier має бути на типі, на який вказує pointer: `volatile uint32_t *reg` означає volatile-доступ через `reg`.

**Типова помилка:** сприймати `volatile` як універсальне виправлення concurrency або апаратної синхронізації. Використовуй його для спеціальних доступів, перевіряй семантику регістру та окремо застосовуй atomic/barrier/API платформи, коли потрібні атомарність чи порядок.
