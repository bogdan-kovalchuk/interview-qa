## Short answer

**У C переповнення signed integer** під час обчислення має undefined behaviour: стандарт не гарантує ні перехід до `INT_MIN`, ні будь-який інший результат. Перевіряти межу потрібно до збільшення; порівняння вже переповненого значення не виправляє операцію. Для unsigned типу результат обчислюється за модулем `MAX + 1`, тож `uint32_t` дає wraparound, якщо цей тип доступний.[^iso-c-n1570]

## Detailed explanation

У C вираз `x++` для `int x = INT_MAX` намагається отримати значення, яке не представляється типом `int`, тому програма має undefined behaviour. Це правило стандарту, а не обіцянка конкретного апаратного результату: навіть якщо процесорна інструкція природно переходить через нуль, компілятор оптимізує програму відповідно до припущення, що коректна програма не виконує signed overflow.[^iso-c-n1570]

Типова помилка – трактувати побітове представлення як семантику C і очікувати, що `INT_MAX + 1` стане `INT_MIN`. Двійкове доповнення визначає поширений спосіб кодування значень, але не створює гарантії wraparound для signed арифметики. Так само перевірка на кшталт `if (x++ < x)` вже містить проблемну операцію; умову межі треба перевірити перед нею. Для циклів і лічильників обирайте ширину та знаковість типу відповідно до можливого діапазону.[^iso-c-n1570]

Безпечний варіант залежить від наміру. Якщо потрібна циклічна арифметика, застосовуйте unsigned тип відповідної ширини; стандарт визначає її за модулем `UINT_MAX + 1`. Якщо потрібна насичувальна арифметика, явно перевірте `x == INT_MAX` перед додаванням і визначте, чи залишати значення на межі, чи повертати помилку. `uint32_t` існує лише на реалізаціях, що мають рівно 32-бітний тип беззнакового числа без padding bits, тож на іншій реалізації треба вибрати доступний тип і його відповідну межу.[^iso-c-n1570]

Значення `INT_MAX` береться з `<limits.h>` і залежить від реалізації; не припускайте, що `int` завжди має 32 біти лише тому, що MCU має 32-бітні регістри. Операція `x++` спершу обчислює значення типу `int`, і саме неможливість представити результат створює проблему. Перевірка `x < INT_MAX` перед інкрементом безпечна, якщо між перевіркою та зміною ніхто не змінює `x`; для спільного стану окремо потрібна синхронізація.[^iso-c-n1570]

**Типова помилка:** перевіряти `x + 1 > x` як спосіб виявлення переповнення. Сам вираз `x + 1` може вже мати undefined behaviour; порівняйте `x` з `INT_MAX` до операції або використайте перевірену функцію арифметики конкретної платформи.
