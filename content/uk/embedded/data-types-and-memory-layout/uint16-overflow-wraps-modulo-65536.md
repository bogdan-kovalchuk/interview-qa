## Short answer

Після виразу `x += 10000` значення `x` дорівнює `4464`: діапазон `uint16_t` – `0..65535`, а 70000 при перетворенні назад до цього типу зводиться за модулем 65536.[^iso-c-n1570]

Unsigned арифметика має модульну семантику, але точний шлях обчислення залежить від integer promotions: на типовій платформі з 32-бітним `int` додавання дає 70000, а обрізання відбувається при присвоєнні; на реалізації з 16-бітним `int` операнди можуть просуватися до `unsigned int` і обертання стається в додаванні. В обох випадках для цього прикладу результат – 4464, не undefined behavior.[^iso-c-n1570]

Але якщо очікувалось `70000` - баг від неправильного вибору типу; використовуй `uint32_t`.[^embeddedinterviewlab]

## Detailed explanation

`uint16_t` – необов'язковий тип з точно 16 бітами беззнакового значення, який доступний лише якщо реалізація може його надати. Його діапазон тоді `0..65535`. У виразі `x += 10000` значення `x` бере участь у додаванні після integer promotions, а отриманий результат перетворюється назад до типу `x`.[^iso-c-n1570]

Це розрізнення важливе на поширеній платформі з 32-бітним `int`: він може представити всі значення `uint16_t`, тому `x` просувається до `int`; додавання 60000 і 10000 дає 70000 без переповнення проміжного типу. При присвоєнні до `uint16_t` результат зводиться до значення, конгруентного за модулем 2^16: 70000 мінус 65536 дорівнює 4464.[^iso-c-n1570]

Якщо `int` не представляє весь діапазон `uint16_t`, promotions можуть дати `unsigned int`, і модульність виникає вже під час додавання. Тому твердження, що воно завжди обертається саме у 16 бітах, не переносне; кінцеве значення прикладу лишається тим самим.[^iso-c-n1570]

**Приклад обчислення:**
```text
60000 + 10000 = 70000
70000 mod 65536 = 4464
```
Після операції `x` дорівнює `4464`. Це визначена поведінка для беззнакового результату та перетворення, а не signed overflow; якщо програма має зберегти 70000, змінна результату має бути ширшого типу, наприклад `uint32_t`.[^iso-c-n1570]

**Типова помилка:** називати це «переповненням 16-бітного додавання» без згадки promotions. Перевір тип виразу й призначення окремо; для суми понад 65535 використовуй ширший тип.

Такий аналіз особливо важливий, коли арифметика формує розмір буфера, індекс або лічильник протоколу: правильне модульне значення може бути небезпечним для логіки навіть без undefined behavior. Перевіряй допустимий діапазон до самого додавання, якщо wraparound не є бажаною поведінкою.[^iso-c-n1570]

У виразі `x += 10000` компілятор застосовує правила compound assignment, еквівалентні обчисленню зліва й подальшому перетворенню до типу лівого операнда. Саме тому оголошений тип `x` сам по собі не повідомляє тип проміжної суми.[^iso-c-n1570]
