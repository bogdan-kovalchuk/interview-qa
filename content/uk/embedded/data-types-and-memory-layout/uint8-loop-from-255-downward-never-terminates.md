## Short answer

<span class="warn">Цикл не завершується.</span> Після integer promotion порівняння відбувається як `int`, але після декременту нуля значення зберігається назад у `uint8_t` як 255.[^iso-c-n1570]

Коли `i == 0`, `i--` обчислює `-1` як `int`; присвоєння назад до `uint8_t` дає 255, тож наступна перевірка істинна.[^iso-c-n1570]

Для включного спуску від 255 до 0 використайте знаковий тип, здатний вмістити обидві межі, наприклад `int`; або зупиняйте беззнаковий лічильник до декременту нуля.[^iso-c-n1570]

## Detailed explanation

У цьому циклі `i` має тип `uint8_t`, який представляє значення від 0 до 255, тому сам лічильник не може зберегти від’ємне число. Водночас треба розрізняти тип об’єкта і тип арифметичного виразу: integer promotion перетворює `i` на `int` перед порівнянням і декрементом, оскільки `int` може представити всі значення `uint8_t`.[^iso-c-n1570]

Тому пояснення «`i >= 0` завжди істинне, бо `i` unsigned» неточне для цієї декларації. Порівнюються два значення типу `int`. Цикл усе одно нескінченний з іншої причини: коли тіло виконується при `i == 0`, `i--` обчислює `-1` у типі `int`, а присвоєння результату назад до `uint8_t` перетворює його на 255. У наступній перевірці 255 більше за нуль, і цей перехід повторюється.[^iso-c-n1570]

**Приклад проходу:** початкове значення 255 веде через усі значення до нуля; після тіла для нуля наступне значення знову 255. Отже, тіло циклу не має кінцевої останньої ітерації. Значення після збереження визначається правилами перетворення до беззнакового типу, а не поведінкою конкретного MCU.[^iso-c-n1570]

Виправлення залежить від того, чи потрібен включний нуль. Для діапазону 255…0 зручний `int`, який також може тимчасово містити `-1` після останнього декременту. Для беззнакового лічильника треба перевірити нуль до декременту або побудувати умову так, щоб не декрементувати його після нуля. Типова помилка – вважати, що integer promotion усуває проблему: вираз справді обчислюється як `int`, але результат потім перетворюється назад до діапазону `uint8_t`. У граничних циклах завжди перевіряйте момент оновлення лічильника.[^iso-c-n1570]

Для такого циклу перевіряйте також початкове значення лічильника.[^iso-c-n1570]
