## Short answer

**DMA** переносить дані між peripheral і memory без копіювання кожного байта CPU. Проблема в тому, що CPU cache може містити старі або ще не записані дані, а DMA бачить RAM напряму. Перед TX потрібен clean/flush cache, після RX – invalidate, плюс правильне alignment, memory barriers і buffers у DMA-accessible memory.[^dou-embedded-interview]

## Detailed explanation

### Суть проблеми узгодженості кешу (Cache Incoherency)
У високопродуктивних мікроконтролерах і мікропроцесорах (наприклад, ARM Cortex-M7, Cortex-A) процесорне ядро працює значно швидше за системну оперативну пам’ять (SRAM або зовнішню SDRAM). Щоб уникнути затримок доступу (wait states), використовується апаратний кеш даних (L1 D-Cache) [^armv7m-arm].
Контролер DMA (Direct Memory Access) є окремим майстром системної шини (Bus Master), який зазвичай підключається безпосередньо до внутрішньої матриці шин (AHB/AXI) або зовнішньої пам’яті, минаючи L1-кеш процесора.

Через це виникає проблема відсутності когерентності (Cache Incoherency):
- **Сценарій передачі (TX: CPU -> Memory -> DMA -> Peripheral)**:
  Процесор готує буфер даних у пам’яті. Якщо ділянка пам’яті налаштована як `Write-Back`, оновлені дані тимчасово зберігаються лише в рядках L1 D-Cache процесора (вони є «брудними» – dirty lines). У фізичній оперативній пам’яті (RAM) залишаються застарілі байти. Коли активується DMA, він зчитує з RAM старі дані, і периферія відправляє сміття.
- **Сценарій прийому (RX: Peripheral -> DMA -> Memory -> CPU)**:
  Периферія передає дані, і DMA записує нові байти безпосередньо у фізичну RAM. Однак процесор раніше міг спекулятивно або з циклу зчитати цей буфер, тому в L1 D-Cache лежить стара копія. Коли процесор намагається прочитати дані буфера, кеш-контролер бачить попадання (cache hit) і повертає застарілі значення з кешу замість оновлених із фізичної RAM.

### Операції обслуговування кешу (Cache Maintenance Operations)
Для вирішення проблеми неузгодженості розробник повинен вручну викликати інструкції обслуговування кешу (через CMSIS або апаратні регістри SCB) [^armv7m-arm]:
1. **Clean (або Flush)**:
   Примусовий запис усіх модифікованих (брудних) рядків із L1 D-Cache у фізичну пам’ять RAM.
   - *Коли застосовувати*: обов’язково перед стартом операції передачі через DMA (`TX`).
   - Функція CMSIS: `SCB_CleanDCache_by_Addr((uint32_t*)tx_buf, size);`
2. **Invalidate**:
   Позначення рядків у кеші як недійсних. Наступне звернення процесора до цих адрес спричинить промах кешу (cache miss), змушуючи ядро вичитати свіжі байти безпосередньо з фізичної RAM.
   - *Коли застосовувати*: обов’язково після завершення прийому даних контролером DMA (`RX`) перед тим, як процесор почне читати буфер.
   - Функція CMSIS: `SCB_InvalidateDCache_by_Addr((uint32_t*)rx_buf, size);`
3. **Clean and Invalidate**:
   Записує модифіковані дані у фізичну пам’ять і одночасно інвалідує рядок кешу. Використовується для двонаправлених спільних буферів.

### Критична вимога: вирівнювання за розміром рядка кешу (Cache Line Alignment)
Рядок кешу (Cache Line) у ядрі ARM Cortex-M7 має розмір 32 байти: функції CMSIS для обслуговування D-Cache за адресою очікують адресу, вирівняну на межу 32 байтів [^cmsis-core-dcache]. В інших ядрах розмір рядка може бути іншим, тому його беруть з документації конкретного ядра або з регістрів опису кешу, а не закладають 32 «назавжди». Операції `Invalidate` та `Clean` здійснюються не окремими байтами, а цілими рядками!

Якщо буфер DMA не вирівняний на межу 32 байтів або його розмір не кратний 32 байтам:
- Буфер DMA може ділити один рядок кешу з іншими сусідніми змінними програми.
- Коли викликається `Invalidate` для буфера RX, рядок кешу інвалідується цілком. Якщо у цьому ж рядку зберігалася сусідня локальна або глобальна змінна, яку процесор змінив у кеші, її оновлене значення безповоротно стирається, що призводить до катастрофічного пошкодження даних (data corruption).

**Правило безпеки**: Усі буфери для роботи з DMA повинні мати вирівнювання:
```c
// Вирівнювання на розмір рядка кешу (32 байти для Cortex-M7)
__attribute__((aligned(32))) uint8_t dma_rx_buffer[BUFFER_SIZE_ALIGNED_32];
```
Крім того, розмір виділеного буфера повинен бути кратним розміру рядка кешу (наприклад, округленим угору до найближчого кратного 32).

### Альтернативні апаратні підходи
1. **Виділення Non-Cacheable ділянки пам’яті через MPU**:
   За допомогою модуля захисту пам’яті (MPU – Memory Protection Unit) можна виділити спеціальний регіон RAM (наприклад, секцію для DMA-буферів або дескрипторів) і налаштувати його атрибути як `Device` або `Normal, Non-cacheable` [^armv7m-arm]. Доступ до такої пам’яті відбувається повільніше для CPU, проте повністю усуває необхідність операцій Clean/Invalidate.
2. **Використання TCM (Tightly Coupled Memory)**:
   Пам’ять DTCM (Data TCM) підключена безпосередньо до процесорного ядра з нульовими затримками доступу без проходження через кеш. Проте слід пам’ятати, що не всі контролери DMA мають прямий доступ до TCM-пам’яті (залежить від конфігурації шини мікроконтролера).
3. **Бар’єри пам’яті (Memory Barriers)**:
   Для гарантії завершення всіх операцій запису перед передачею керування контролеру DMA слід використовувати інструкцію бар’єра даних: `__DSB()` (Data Synchronization Barrier) [^armv7m-arm].
