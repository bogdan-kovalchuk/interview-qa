## Short answer

**Atomic operation** – операція, яка виконується неподільно: інші потоки або CPU не бачать проміжного стану.[^dou-embedded-interview] Наприклад, atomic increment не розкладається для інших учасників на окремі read/modify/write.

Типові приклади: atomic load/store, increment/decrement, compare-and-swap (`CAS`). У C++ використовують `std::atomic<T>`.

Atomics потрібні для counters, flags і lock-free synchronization; Але треба розуміти memory ordering: атомарність самої змінної ще не завжди означає правильний порядок доступу до всіх пов’язаних даних.

## Detailed explanation

### Сутність атомарності та проблема Read-Modify-Write

**Атомарною** (від грецького *atomos* – неподільний) називається операція, яка з точки зору всієї решти системи виконується як єдиний неподільний крок. Проміжний стан змінної або структури даних є принципово неспостережуваним: жоден інший потік виконання (потік RTOS, обробник переривання чи сусіднє процесорне ядро) не може побачити частково оновлені дані чи вклинитися всередину операції.[^armv7m-arm]

Класична проблема у вбудованих системах виникає при звичайному інкременті спільної змінної `counter++`. На Cortex-M цей рядок C зазвичай компілюється у три окремі процесорні інструкції (Read-Modify-Write, RMW):
```assembly
LDR  R0, [R1]      ; Read: зчитування поточного значення змінної з ОЗП у регістр
ADD  R0, R0, #1    ; Modify: обчислення нового значення в АЛП
STR  R0, [R1]      ; Write: запис оновленого значення назад у пам’ять
```

Якщо в момент між `LDR` та `STR` процесор переривається обробником ISR або планувальник RTOS перемикає контекст на іншу задачу, яка також модифікує `counter`, виникає стан гонитви (race condition). Запис від першого потоку перезапише результат другого, що призведе до втрати даних.

### Апаратна підтримка атомарності в ARM Cortex-M

Залежно від архітектури та складності ядра, атомарність реалізується різними апаратними механізмами:[^armv7m-arm]
1. **Природна атомарність одиночних інструкцій**:
   - В архітектурі ARM Cortex-M вирівняні (word-aligned) 32-бітні інструкції завантаження (`LDR`) та збереження (`STR`) виконуються за один транзакційний цикл шини й є атомарними відносно переривань.
   - Водночас 64-бітний доступ (`LDRD`/`STRD`) або робота з неалінійованими даними може бути розбита шинною матрицею на дві окремі транзакції, між якими може вклинитися переривання.
2. **Інструкції ексклюзивного доступу (Exclusive Access: LDREX / STREX)**:
   - Починаючи з ARMv7-M (Cortex-M3/M4/M7/M33), введено пари інструкцій з апаратним локальним монітором ексклюзивності (Local Exclusive Monitor); на Cortex-M0/M0+ (ARMv6-M) їх немає.[^cmsis-core-intrinsics]
   - Інструкція `LDREX` зчитує значення за адресою і переводить монітор у стан *Exclusive*.
   - Інструкція `STREX` записує нове значення лише за умови, що монітор все ще перебуває у стані *Exclusive*. Якщо інше ядро, операція запису чи контекстне перемикання (виконання винятку або інструкції `CLREX`) скинули монітор, `STREX` повертає помилку (значення `1` у цільовий регістр) і не записує дані в пам’ять.
   - Це дозволяє реалізувати безблокуючі примітиви (Lock-Free), зокрема Compare-And-Swap (CAS) та атомарний інкремент:
     ```assembly
     retry:
         LDREX R0, [R1]       ; Зчитуємо значення та зводимо монітор
         ADD   R0, R0, #1     ; Збільшуємо значення
         STREX R2, R0, [R1]   ; Спробуємо зберегти: R2 = 0 при успіху, 1 при колізії
         CMP   R2, #0         ; Перевіряємо успішність
         BNE   retry          ; При колізії повторюємо цикл спочатку
     ```
3. **Біт-бендинг (Bit-banding)**:
   - В архітектурі Cortex-M3/M4 опціонально реалізовано механізм відображення пам’яті Bit-Band, де кожен окремий біт у межах 1 МБ простору пам’яті (SRAM або периферії) має власне окреме 32-бітне слово в просторі аліасів (Bit-Band Alias).
   - Запис одиниці або нуля у слово-аліас апаратно перетворюється шинною логікою в атомарну операцію RMW безпосередньо в комірці пам’яті без можливості вклинювання переривань.

### Захист критичних секцій: вимикання переривань проти Atomics

В одноядерних мікроконтролерах без підтримки `LDREX`/`STREX` (наприклад, Cortex-M0/M0+) класичним способом забезпечення атомарності є блокування переривань:[^freertos-kernel-book]
- Глобальне вимикання переривань (`__disable_irq()` через інструкцію `CPSID i`, тобто встановлення `PRIMASK`). Вибіркове маскування за пріоритетом через регістр `BASEPRI` на Cortex-M0/M0+ недоступне, воно є лише на старших ядрах (Cortex-M3/M4/M7 тощо).[^cmsis-core-registers]
- **Недоліки блокування переривань**: збільшення джиттеру системи, порушення детермінізму реакції на жорсткі часові дедлайни та ризик блокування системних таймерів RTOS.
- Використання апаратних атоміків (`LDREX`/`STREX`) усуває потребу в критичних секціях із вимкненими перериваннями для простих лічильників, прапорців і вказівників; складніші структури (черги з кількома полями) все одно потребують продуманого lock-free алгоритму або критичної секції.

### Багатоядерні системи, порядок пам’яті та бар’єри (Memory Ordering)

У багатоядерних SoC (наприклад, ESP32, RP2040, STM32MP1) вимикання локальних переривань на Core 0 не захищає від одночасного доступу з Core 1:[^armv7m-arm]
- Атомарність між ядрами забезпечують засоби конкретної платформи: глобальний монітор ексклюзивності (Global Exclusive Monitor) для ARM-ядер з `LDREX`/`STREX`, апаратні спінлоки (Hardware Spinlocks / Semaphores), як у RP2040 з ядрами Cortex-M0+, або власні атомарні інструкції архітектури (ESP32 використовує ядра Xtensa або RISC-V, а не ARM).
- **Порядок доступу до пам’яті (Memory Consistency)**: процесорні конвеєри та буфери запису шини AHB/AXI можуть змінювати порядок виконання операцій читання й запису. Атомарне оновлення прапорця готовності не гарантує, що дані в сусідньому буфері вже дійшли до фізичної пам’яті.
- Для гарантування послідовності використовуються апаратні бар’єри пам’яті:
  - `DMB` (Data Memory Barrier) – гарантує видимий порядок явних звернень до пам’яті до і після бар’єра, але не їх завершення;
  - `DSB` (Data Synchronization Barrier) – завершується лише тоді, коли завершено всі явні звернення до пам’яті перед ним;
  - `ISB` (Instruction Synchronization Barrier) – очищує конвеєр команд процесора, тож наступні інструкції вибираються заново.[^cmsis-core-intrinsics]
- У сучасних мовах стандарту C11 (`stdatomic.h`) та C++ (`<atomic>`) використовують моделі впорядкування: `memory_order_relaxed`, `memory_order_acquire`, `memory_order_release` та `memory_order_seq_cst`.
