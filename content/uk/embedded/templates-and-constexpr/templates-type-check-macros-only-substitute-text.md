## Short answer

**Templates: повний type checking, аргументи раз, дебаг, constexpr-обчислення. Макроси: текст, double evaluation, лише preprocessor output.**

Ціна: templates ризикують code bloat (копія на інстанціацію) і повільнішим білдом; макроси – швидкі й портативні на C89, але небезпечні.

Правило: у C++ обирай templates для типобезпеки; макроси лишай для того, що шаблон не вміє (`#`/`##`, conditional compilation).[^embeddedinterviewlab]

## Detailed explanation

### Текстова підстановка проти семантичного аналізу компілятора

Макроси препроцесора (`#define`) обробляються на ранній фазі трансляції (Phase 4 за [lex.phases] та [cpp] у [^iso-cpp-n4861]). Препроцесор працює виключно як текстовий замісник токенів: він не має уявлення про типи даних, області видимості (scopes), простори імен (`namespaces`) та синтаксичне дерево компілятора (AST).

Шаблони C++ ([temp] у [^iso-cpp-n4861]) є повноправними сутностями мови, які компілятор аналізує на етапі семантичного аналізу. Вони підкоряються правилам строгої статичної типізації, дозволяють проводити аргумент-залежний пошук імен (ADL), коректно перевантажуються і відкривають доступ до обчислень під час компіляції (`constexpr` та `consteval`).

### Пастки макросів у низькорівневому та embedded-коді

1. **Подвійне обчислення аргументів (Multiple Evaluation Trap)**:
   Класичний макрос вибору максимуму:
   ```c
   #define MAX(a, b) ((a) > (b) ? (a) : (b))
   ```
   Якщо викликати його як `MAX(read_sensor(), threshold)` або `MAX(*fifo_reg, limit)`, вираз з побічним ефектом виконається двічі. У випадку апаратного регістра читання змістить вказівник FIFO, що призведе до мовчазної втрати байтів. Шаблонна функція позбавлена цієї вади, оскільки аргументи обчислюються рівно один раз при передачі:
   ```cpp
   template <typename T>
   constexpr const T& max(const T& a, const T& b) {
       return (a < b) ? b : a;
   }
   ```

2. **Забруднення простору імен (Macro Pollution)**:
   Макроси ігнорують простори імен і назви класів. Макрос `#define STATUS 0x01` підмінить будь-який член переліку чи поле `Device::STATUS` у підключених сторонніх бібліотеках, викликаючи заплутані помилки складання. Шаблони завжди ізольовані у власних просторах імен.

3. **Складність відлагодження (Debugging)**:
   Препроцесорний макрос не залишає по собі інформації в налагоджувальних таблицях DWARF. У GDB неможливо покроково зайти всередину макроса, перевірити типи локальних проміжних значень або встановити точку зупину (`breakpoint`). Шаблонний код розгортається у реальні функції зі своїми фреймами та символами.

### Баланс ціни: розмір коду та час збирання

- **Code Bloat**: Шаблони параметризуються типами та числовими значеннями. Необережне створення окремої інстанціації для кожного периферійного каналу створює дубльовані копії коду у Flash. Макроси підставляють код безпосередньо за місцем використання без генерування слабких символів (`weak symbols`) та COMDAT-секцій.
- **Час компіляції**: Розбір великої кількості складних шаблонів значно сповільнює збирання проєкту вбудованого ПЗ.

### Де макроси залишаються незамінними

Попри переваги шаблонів, у сучасній вбудованій розробці макроси мають чітко окреслену сферу застосування:
- **Умовне збирання (`#ifdef`, `#if`)**: увімкнення апаратно-залежних блоків або вилучення налагоджувального виводу з релізного бінарного образу ще до аналізу синтаксису.
- **Стрінгіфікація (`#`) та конкатенація токенів (`##`)**: автогенерація таблиць векторів переривань, структур опису RTOS-задач або лінкерних секцій.
- **Діагностичні метадані**: збір контексту компіляції через системні макроси `__FILE__`, `__LINE__`, `__func__` у механізмах assert та логерах[^embeddedinterviewlab].
