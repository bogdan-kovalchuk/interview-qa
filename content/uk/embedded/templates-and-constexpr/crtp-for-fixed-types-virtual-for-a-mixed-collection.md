## Short answer

**CRTP – фіксовані типи, performance-critical (ISR, tight loops), без virtual dispatch і vtable на об’єкт.**

Virtual – потрібен runtime-поліморфізм: гетерогенні колекції, плагіни, динамічне завантаження драйверів. CRTP не дозволяє тримати різні типи в одному масиві без додаткової type-erasure обгортки.

Правило: відомі типи + швидкість -> CRTP; різні типи в runtime -> virtual.[^embeddedinterviewlab]

## Detailed explanation

### Порівняння механізмів: статичний проти динамічного поліморфізму

- **CRTP (Curiously Recurring Template Pattern):** патерн статичного (compile-time) поліморфізму, у якому похідний клас передає сам себе як аргумент шаблону базового класу:[^iso-cpp-n4861]
  ```cpp
  template <typename Derived>
  class GpioBase {
  public:
      void set() { static_cast<Derived*>(this)->set_impl(); }
  };
  class StatusLed : public GpioBase<StatusLed> {
  public:
      void set_impl() { /* прямий запис у BSRR регістр */ }
  };
  ```
  Усі виклики методів резолвляться під час компіляції. Компілятор бачить конкретний тип і може повністю заінлайнити метод у точку виклику без додаткових інструкцій переходу.

- **Virtual (динамічний поліморфізм):** класичний механізм C++, де базовий клас містить віртуальні методи (`virtual void set() = 0;`). Резолв виклику відбувається під час виконання програми через таблицю віртуальних методів (`vtable`) та прихований вказівник на неї (`vptr`), що зберігається в кожному екземплярі об’єкта.

### Порівняння для вбудованих систем

| Властивість | CRTP (Static) | `virtual` (Dynamic) |
|---|---|---|
| **Швидкодія виклику** | Максимальна: нуль тактів оверхеду, повний `inline` | 2–3 звернення до пам’яті (`LDR`, `LDR`, `BLX`), зрив конвеєра CPU |
| **Накладні витрати RAM** | **0 байтів** | **4 байти** на кожен об’єкт для збереження `vptr` (на 32-бітному MCU) |
| **Накладні витрати Flash** | Дублювання коду базового класу для кожного похідного типу | Одна таблиця `vtable` у `.rodata` на клас |
| **Гетерогенні колекції** | Не підтримуються напряму (різні непов’язані типи) | Природна підтримка: масив вказівників `IBase* devices[N]` |
| **Використання в ISR** | Ідеально підходить для переривань і критичних циклів | Не рекомендується через недетермінований час виклику |

### Коли слід обирати CRTP

1. **Драйвери фіксованої апаратної периферії:**
   Коли типи відомі під час складання проєкту (наприклад, драйвери `Uart<Uart1>`, `Spi<Spi2>`, пін `Pin<PortA, 5>`). Немає потреби динамічно підміняти апаратний порт у runtime.
2. **Критичні за часом ділянки (ISR, DSP, tight loops):**
   Усередині обробника переривання кожна мікросекунда на рахунку. CRTP дозволяє оптимізатору розгорнути виклик методу безпосередньо в одну інструкцію запису в регістр (`STR`), минаючи накладні витрати на виклик підпрограми.
3. **Економія RAM на дрібних об’єктах:**
   Якщо система має 32 екземпляри пінів введення-виведення, віртуальні методи додадуть `32 * 4 = 128` байтів у RAM лише для вказівників `vptr`, тоді як у CRTP екземпляри мають нульовий розмір (Empty Base Optimization, EBO).

### Коли слід обирати virtual

1. **Гетерогенні колекції та поліморфні списки:**
   Коли потрібно зберігати різнорідні об’єкти в єдиному масиві чи черзі та обробляти їх в одному циклі:
   ```cpp
   ISensor* sensors[] = { &temp_sensor, &pressure_sensor, &imu_sensor };
   for (auto* s : sensors) s->update();
   ```
   У CRTP різні нащадки породжують несумісні типи, тому створити спільний масив без складного обгортання (type erasure) неможливо.
2. **Динамічна конфігурація в runtime:**
   Коли склад драйверів визначається під час завантаження (наприклад, читанням конфігурації з EEPROM чи виявленням підключеного модуля по I2C/USB).

### Типові помилки та пастки

- **Використання `virtual` у драйверах GPIO:** додає 4 байти в RAM на пін і робить перемикання піна в десятки разів повільнішим через непрямий перехід.
- **Спроба поліморфного виклику CRTP через вказівник на невідомий тип:** базовий клас `GpioBase<Derived>` є шаблоном, тому `GpioBase<PinA>` і `GpioBase<PinB>` – це два абсолютно різні типи без спільного предка.
- **Object slicing:** передача об’єкта за значенням замість посилання або вказівника призводить до зрізання віртуальної таблиці та копіювання лише базової частини.
