## Question code

```c
struct Node {
    int value;
    struct Node next;
};
```

## Short answer

<span class="warn">Структура містить саму себе by value, тому її розмір був би нескінченним.</span>

Compiler не може завершити layout: щоб знати розмір `Node`, треба знати розмір `next`, який знову є `Node`. Дозволений варіант – pointer: `struct Node *next;`.

Захист: для recursive data structures використовуйте pointer або index у pool, а не вкладений object того самого типу.[^iso-c-n1570]

## Detailed explanation

У визначенні `struct Node` член `struct Node next;` намагається зберігати цілий об’єкт `Node` безпосередньо всередині іншого `Node`. Це неможливо, бо розмір структури мав би включати розмір такого самого об’єкта, який знову містив би ще один `Node`.[^iso-c-n1570]

Компілятор має визначити скінченний layout структури, зокрема розмір кожного члена й padding. Для рекурсивного члена за значенням обчислення не завершується: розмір зовнішнього `Node` залежить від розміру `next`, а `next` має той самий невизначений розмір. Тому це порушує обмеження мови C для повного типу члена структури й потребує діагностики під час трансляції.[^iso-c-n1570]

Щоб зробити рекурсивну структуру скінченною, зберігайте покажчик: `struct Node *next;`. Розмір цього члена відомий реалізації незалежно від розміру `Node`. Приклад: вузол linked list містить `value` та адресу наступного вузла; об’єкти вузлів розміщуються окремо, а зв’язок задається адресами.[^iso-c-n1570]

У середовищі з фіксованою пам’яттю можна обрати іншу модель: масив вузлів і цілочисельний індекс наступного елемента. Індекс має спеціальне значення для кінця списку, а межі масиву треба перевіряти. Така модель уникає pointer traversal через довільні адреси, проте не змінює правила: вкладений об’єкт того самого типу за значенням усе одно не має скінченного розміру.[^iso-c-n1570]

Помилка зазвичай проявляється як compiler diagnostic на декларації `next`; якщо toolchain пропускає її як extension, код не є переносимим C. Замініть член на покажчик або індекс і перевірте, що створення, видалення та обходи вузлів підтримують цілісність зв’язків.[^iso-c-n1570]

**Типова помилка:** думати, що оголошення всередині структури просто створить «наступний вузол». Воно описує член самого об’єкта, а не відкладене посилання; для зв’язку потрібен покажчик або індекс.[^iso-c-n1570]
