## Short answer

Розмір `union` дорівнює розміру найбільшого його поля плюс можливий padding для виконання найсуворішої вимоги вирівнювання серед полів.[^dou-embedded-interview] Тобто union має бути достатньо великим і правильно вирівняним для будь-якого свого member-а.

Наприклад, `union U { char c[5]; float f; };` може мати розмір 8: найбільше поле займає 5 байтів, але `float` потребує alignment 4, тому додається padding. Точне значення завжди перевіряють через `sizeof(union U)`.

## Detailed explanation

### Правило стандарту для розміру та вирівнювання union

Згідно зі стандартом ISO C ([^iso-c-n1570], 6.7.2.1), розмір об’єднання (`union`) повинен бути достатнім для розміщення найбільшого з його членів. Усі поля об’єднання починаються з одного й того самого зміщення (offset 0 від початку об’єкта в пам’яті).

Крім розміру найбільшого поля, стандарт вимагає дотримання вимоги вирівнювання (`alignment`):
- Вирівнювання самого `union` визначається найбільш суворою вимогою вирівнювання серед усіх його членів.
- Загальний розмір `union` повинен бути строго кратним цьому максимальному вирівнюванню.
- Якщо розмір найбільшого члена не ділиться націло на максимальне вирівнювання, компілятор зобов’язаний додати байти заповнення наприкінці об’єднання (trailing padding)[^iso-c-n1570].

### Практичний розрахунок розміру на прикладі ARM Cortex-M

Розглянемо типове оголошення в 32-бітній системі:

```c
union Packet {
    uint8_t  payload[5];  // Розмір: 5 байтів, вирівнювання: 1 байт
    uint32_t header;      // Розмір: 4 байти, вирівнювання: 4 байти
};
```

1. **Найбільший член**: масив `payload` вимагає 5 байтів пам’яті.
2. **Найсуворіше вирівнювання**: поле `header` типу `uint32_t` вимагає адреси, кратної 4 байтам. Відповідно, вирівнювання `union Packet` становить 4 байти.
3. **Обчислення розміру з padding**: щоб задовольнити вимогу вирівнювання під час створення масивів `union Packet array[2]`, кожен наступний елемент повинен починатися за адресою, кратною 4. Тому розмір об’єднання округлюється вгору до найближчого кратного 4 числа: `5 + 3 = 8` байтів. Виклик `sizeof(union Packet)` поверне значення 8.

### Робота з пам’яттю та Type Punning

Вбудовані системи часто використовують об’єднання для перетворення представлення даних (type punning), наприклад, для розбиття 32-бітного слова на окремі байти:

```c
union RegConverter {
    uint32_t word;
    uint8_t  bytes[4];
};
```

- У мові C (починаючи з C99) запис в одне поле `union` і подальше зчитування з іншого є офіційно стандартизованим і дозволеним способом перетворення типів[^iso-c-n1570].
- У мові C++ зчитування неактивного члена `union` формально є `undefined behavior`[^iso-cpp-n4861]. Для побітового перетворення в C++20 стандартом рекомендовано використовувати `std::bit_cast`, а в раніших версіях – функцію `std::memcpy`.

### Пастки та інженерні рекомендації у прошивках

- **Мережеві пакети та бінарні протоколи**: Якщо розробник надсилає `union` через інтерфейси зв’язку (UART, SPI, Ethernet), відправка повного розміру `sizeof(union)` призведе до передачі байтів trailing padding, які містять невизначені значення (сміття з пам’яті), створюючи ризики витоку даних або помилок протоколу.
- **Упакування структур**: Використання атрибутів упаковки `__attribute__((packed))` усуває padding, але створює ризик невирівняного доступу (unaligned access). На архітектурі ARMv6-M (Cortex-M0/M0+) такий доступ до 32-бітних слів апаратно не підтримується і викликає виключення `HardFault`, а на ARMv7-M (Cortex-M3/M4/M7) при активному прапорці `UNALIGN_TRP` у регістрі `CCR` або під час операцій `LDM`/`STM`/`LDRD` призводить до `UsageFault`.
