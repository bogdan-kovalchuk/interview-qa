## Short answer

`union` – тип, у якому всі поля ділять одну й ту саму область пам’яті. У кожен момент логічно активним є одне поле, а запис в одне поле перезаписує байти, які могли використовуватись іншими полями.

Приклад: `union U { uint32_t word; uint8_t bytes[4]; };`. Використовується для економії пам’яті, варіантних даних, низькорівневого доступу до представлення байтів. Треба бути обережним із type punning, endianness, alignment і правилами активного member-а, особливо в C++.[^dou-embedded-interview]

## Detailed explanation

### Принцип роботи та модель пам’яті

Об’єднання (`union`) – це складений тип даних у мовах C та C++, у якому всі оголошені члени розміщуються за однією й тією самою базовою адресою в пам’яті (мають зміщення `offset = 0` від початку об’єкта)[^iso-c-n1570].

Ключові властивості моделі пам’яті `union`:
- **Розмір об’єкта**: розмір `union` дорівнює розміру його найбільшого елемента плюс можливий хвостовий заповнювач (padding) для задоволення вимог вирівнювання: `sizeof(union) >= max(sizeof(member_i))`[^iso-c-n1570].
- **Вимоги до вирівнювання**: вирівнювання (`alignment`) всього об’єднання встановлюється рівним найсуворішому вирівнюванню серед усіх його членів.
- **Спільне сховище**: зміна значення одного члена призводить до негайного перезапису бітів у спільній пам’яті, що впливає на байти всіх інших членів.

### Типові сценарії застосування у вбудованих системах

1. **Економія дефіцитної оперативної пам’яті (RAM)**:
   Якщо пристрій підтримує кілька взаємовиключних режимів або обробляє різні типи пакетів протоколу в різні моменти часу, пам’ять під ці структури виділяється спільно. Наприклад, буфер прийому повідомлень CAN-шини може інтерпретуватися або як кадр телеметрії сенсорів, або як кадр конфігурації приводів:
   ```c
   struct CanPacket {
       uint32_t id;
       uint8_t dlc;
       union {
           struct { float temperature; float pressure; } telemetry;
           struct { uint16_t target_rpm; uint8_t flags; } motor_cmd;
           uint8_t raw_payload[8];
       } data;
   };
   ```
2. **Розмічені варіанти (Tagged Union / Variant)**:
   Оскільки чистий `union` не зберігає інформацію про те, яке саме поле було записано останнім, у надійних прошивках створюють структуру з явним дискримінатором (типом або тегом):
   ```c
   typedef enum { TYPE_INT, TYPE_FLOAT } ValueType;
   typedef struct {
       ValueType type;
       union {
           int32_t as_int;
           float   as_float;
       } val;
   } Variant;
   ```

### Type Punning: кардинальна різниця між C та C++

Використання `union` для низькорівневого доступу до бітового представлення іншого типу (наприклад, читання окремих байтів із `float` чи `uint32_t`) називається **type punning**.

- **У мові C (C99/C11)**:
  Стандарт C (виноска 95 до §6.5.2.3 стандарту ISO/IEC 9899:201x)[^iso-c-n1570] явно дозволяє читання неактивного члена `union`, якщо об’єкт був записаний через інший член. Це вважається легальним способом отримати доступ до об’єктного представлення (object representation).
- **У мові C++**:
  Відповідно до стандарту C++[^iso-cpp-n4861], лише один член `union` вважається активним (in its lifetime) у кожен момент часу. Спроба прочитати значення з іншого члена є невизначеною поведінкою (`undefined behavior`) та порушує правило суворого псевдонімування (`strict aliasing rule`). Компілятор під час оптимізації `-O2` або `-O3` має право припустити, що значення не змінювалося, і викинути потрібне читання з пам’яті.
  У C++ для безпечного перетворення представлень слід використовувати `std::bit_cast` (починаючи з C++20) або стандартну функцію `std::memcpy`, яку оптимізатор перетворює на звичайне переміщення між регістрами процесора без накладних витрат.

### Апаратні пастки: Endianness та HardFault на ARM Cortex-M

- **Порядок байтів (Endianness)**:
  Розбиття слова через об’єднання на кшталт `union { uint32_t word; uint8_t bytes[4]; }` є апаратно-залежним. На little-endian мікроконтролерах (переважна більшість ядер ARM Cortex-M) `bytes[0]` є наймолодшим байтом слова (LSB). Якщо ту саму прошивку портувати на big-endian процесор, `bytes[0]` виявиться найстаршим байтом (MSB), що зламає обробку протоколів зв’язку.
- **Вимоги до нерівного вирівнювання (Unaligned Access)**:
  Якщо `union` розміщений у довільному буфері зв’язку без вирівнювання (наприклад, після застосування директиви `__attribute__((packed))`), читання 32-бітного члена `word` на процесорах архітектури ARMv6-M (Cortex-M0, Cortex-M0+) призведе до апаратного виключення `HardFault`, оскільки ці ядра не підтримують неконформні (unaligned) звернення до пам’яті.
