## Short answer

Ширина задається після двокрапки: `unsigned field : 5;`. Layout залежить від compiler ABI: порядок розміщення, alignment allocation unit, padding і packing rules не є універсальними. Тому bit-fields годяться для локального компактного state, але не як переносимий binary layout.[^dou-embedded-interview]

## Detailed explanation

### Синтаксис завдання ширини та допустимі типи

Ширина бітового поля в мові C задається за допомогою двокрапки після імені члена структури з наступним константним виразом, що обчислюється на етапі компіляції:

```c
struct PeripheralConfig {
    unsigned int mode      : 3;  // діапазон значень: 0..7
    unsigned int priority  : 2;  // діапазон значень: 0..3
    unsigned int           : 3;  // безіменне поле: пропуск 3 бітів
    unsigned int           : 0;  // вирівнювання за межею наступної одиниці
    unsigned int interrupt : 1;  // починається з нового слова
};
```

Згідно зі стандартом ISO/IEC 9899 §6.7.2.1[^iso-c-n1570]:
- Ширина бітового поля є невід’ємним цілим числом і не може перевищувати ширину базового типу, вказаного при оголошенні.
- Спеціальний випадок – **поле нульової ширини** (`unsigned int : 0;`). Воно не може мати власного імені та слугує спеціальною директивою для компілятора: примусово завершити заповнення поточної одиниці пам’яті (allocation unit) і розмістити наступне бітове поле з початку нової одиниці пам’яті.

### Фактори, що визначають layout бітових полів у пам’яті

Фізичне розташування бітових полів у пам’яті не є універсальним і регулюється стандартом ABI (Application Binary Interface) конкретної платформи та реалізацією компілятора[^iso-c-n1570]:

1. **Порядок розміщення бітів у межах одиниці (Allocation Order)**:
   Компілятор вирішує, з якого краю машинного слова починати пакування: від молодшого біта до старшого (LSB-to-MSB) чи від старшого до молодшого (MSB-to-LSB). Наприклад, для процесорів x86 та little-endian ARM компілятори GCC і Clang за замовчуванням пакують поля від LSB до MSB, проте стандарт C дозволяє будь-який варіант.
2. **Розмір одиниці розміщення пам’яті (Storage Allocation Unit)**:
   Розмір контейнера залежить від базового типу полів (`uint8_t`, `uint16_t`, `uint32_t`). Якщо сусідні поля мають різний базовий тип, компілятор може або об’єднати їх у ширшу одиницю, або почати нову одиницю вирівнювання, вставивши невикористані байти padding.
3. **Правила перетину межі одиниці розміщення**:
   Якщо черговому полю не вистачає бітів до кінця поточної одиниці зберігання (наприклад, залишилося 2 біти в 16-бітному слові, а поле має ширину 4 біти), реалізація визначає, чи розбивається поле на дві частини, чи залишається порожній проміжок (padding), а поле цілком переноситься в наступне машинне слово. Більшість компіляторів створюють padding.
4. **Атрибути пакування (`packed`)**:
   Директива `__attribute__((packed))` або директиви `#pragma pack` видаляють байтові вирівнювальні проміжки між структурами, однак внутрішній порядок розміщення бітів у межах байта все одно залишається implementation-defined.

### Пастка знаковості однобітних полів

Якщо базовий тип поля вказано без явного модифікатора `signed` або `unsigned` (наприклад, `int flag : 1;`), стандарт C дозволяє компілятору трактувати його як знакове або беззнакове число[^iso-c-n1570].

Якщо компілятор обере знаковий тип, то для однобітного поля єдиний наявний біт виступає знаковим (sign bit у системі two's complement):
- Значення `0b0` інтерпретується як `0`.
- Значення `0b1` інтерпретується як `-1`.

Якщо у коді виконати присвоєння `s.flag = 1;` та згодом перевірити `if (s.flag == 1)`, умова ніколи не виконається, оскільки читання `s.flag` поверне `-1`. Для усунення цієї помилки у вбудованому C обов’язково використовують виключно `unsigned int` або явний `uint32_t`.

### Практичне значення для embedded

Через залежність від ABI бітові поля не можуть використовуватися як переносимий двійковий формат для збереження даних у Flash-пам’ять, передачі по радіоканалах чи зв’язку з зовнішніми мікросхемами. Вони придатні виключно для компактного зберігання внутрішніх прапорців у RAM у межах одного бінарного модуля.
