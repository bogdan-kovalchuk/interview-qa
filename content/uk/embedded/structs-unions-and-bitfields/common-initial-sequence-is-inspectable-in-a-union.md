## Short answer

**У C дозволено читати спільну початкову послідовність members структур у `union` за умов стандарту**, коли його поточний member є однією з цих структур.[^iso-c-n1570]

Це правило стосується саме C; переносити його на C++ без окремої перевірки стандарту не можна. Спільність визначається сумісністю відповідних початкових members, а для bit-fields – також шириною.[^iso-c-n1570]

Винесений tag часто простіше підтримувати: він доступний незалежно від активного варіанта й не вимагає покладатися на це вузьке правило.[^iso-c-n1570]

## Detailed explanation

Common initial sequence – це найдовша початкова послідовність членів двох структур у `union`, для якої відповідні members сумісні за правилами C.[^iso-c-n1570]

Стандарт робить спеціальний виняток для читання: якщо об’єкт `union` зараз містить одну з таких структур, програмі дозволено перевірити спільну початкову частину іншої структури, коли в цій точці видиме повне оголошення типу `union`. Це корисно для варіантів із загальним префіксом, наприклад для спільного поля `kind`, за яким ідуть різні payload-и.[^iso-c-n1570]

Члени мають збігатися послідовно від початку: їхні типи мають бути сумісними з урахуванням кваліфікаторів, а відповідні bit-fields мають однакову ширину. Правило не дозволяє читати довільні bytes іншого варіанта й не гарантує, що будь-яке поле після першої відмінності має осмислене значення. Для застосування правила потрібні саме оголошення структур як членів того самого `union`, а не просто однаковий префікс у двох незалежних об’єктах.[^iso-c-n1570]

**Приклад:**

```c
struct Text { unsigned kind; unsigned char length; };
struct Number { unsigned kind; double value; };
union Value { struct Text text; struct Number number; };
```

Якщо `Value` містить `number`, дозволено інспектувати `text.kind`, оскільки перший member обох структур має сумісний тип. Читати `text.length` у такому стані не можна вважати безпечним лише через те, що поле стоїть поруч: воно не входить до спільної початкової послідовності.[^iso-c-n1570]

Типова помилка – думати, що `union` дозволяє безумовно читати будь-який інший member, або застосовувати правило до C++ так само, як до C. Якщо варіант має tag, практична альтернатива – зберігати його окремо й перемикатися за tag перед читанням відповідного payload. Так намір зрозумілий, а коректність не залежить від помилково розширеного трактування винятку.[^iso-c-n1570]
