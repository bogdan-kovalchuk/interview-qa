## Short answer

Вирівнювання потрібне для швидкого й коректного доступу CPU до даних.[^dou-embedded-interview] Багато архітектур читають 2/4/8-байтові значення ефективніше, коли адреса кратна розміру типу; деякі MCU на misaligned access можуть згенерувати fault.

Контролювати можна через порядок полів у struct, стандартні засоби `alignas` у C++ або `_Alignas`/`alignas` у сучасному C, а також compiler-specific атрибути типу `__attribute__((aligned))`, `__attribute__((packed))`, `#pragma pack`. `packed` треба використовувати обережно: він економить байти, але може сповільнити доступ або зламати вимоги hardware.

## Detailed explanation

### Фізична та архітектурна суть вирівнювання (Alignment)

Вирівнювання даних – це вимога апаратної архітектури процесора, згідно з якою змінні певного розміру повинні розташовуватися в оперативній пам’яті за адресами, кратними їхньому розміру (наприклад, 2-байтові `uint16_t` – за парними адресами, 4-байтові `uint32_t` – за адресами, кратними 4, а 8-байтові `uint64_t` чи `double` – за адресами, кратними 8) [^iso-c-n1570].

Системні шини мікроконтролерів (наприклад, шини AHB/AXI в архітектурі ARM Cortex-M) [^armv7m-arm] зчитують пам’ять 32-розрядними або 64-розрядними словами. Якщо 32-бітне число вирівняне, процесор зчитує його за одну машинну транзакцію шини інструкцією `LDR`. Якщо ж число розміщене за невирівняною адресою і перетинає межу 4-байтного слова:
- На ядрах ARM Cortex-M0/M0+ апаратний невирівняний доступ не підтримується взагалі: будь-яка спроба виконати `LDR` за некратною адресою миттєво генерує апаратний виняток `HardFault`.
- На ядрах ARM Cortex-M3/M4/M7/M33 базові інструкції `LDR`/`STR` підтримують невирівняний доступ, але ядро змушене виконувати дві послідовні транзакції шини замість однієї, що призводить до падіння швидкодії. Крім того, інструкції завантаження двох слів (`LDRD`/`STRD`) та множинного завантаження (`LDM`/`STM`) вимагають строгого вирівнювання – спроба передати невирівняну адресу викликає `UsageFault` (біт `UNALIGN_TRP` у регістрі `CCR`).

### Стандартизовані механізми контролю: alignas та _Alignas

У сучасному стандарті C11 (§6.2.8, §6.7.5 ISO C) [^iso-c-n1570] з’явилося ключове слово `_Alignas` та заголовок `<stdalign.h>` (який надає макрос `alignas`):
```c
#include <stdalign.h>

// Вирівнювання буфера по межі 16 байтів для DMA або криптоприскорювача
alignas(16) uint8_t dma_tx_buffer[128];

// Отримання вимоги вирівнювання для типу
size_t req = alignof(uint32_t); // 4 байти на 32-бітних MCU
```
У мові C++11 для цього слугують стандартні оператори `alignas` та `alignof`. Примусове збільшення вирівнювання зазвичай застосовують для буферів контролерів DMA, Ethernet MAC дескрипторів та рядків кеш-пам’яті (на Cortex-M7), де апаратура вимагає вирівнювання на 16 або 32 байти.

### Атрибути компілятора: __attribute__((packed)) та пастки в embedded

Для пакування даних компілятори GCC/Clang надають атрибут `__attribute__((packed))` або директиву `#pragma pack(n)`:
```c
struct __attribute__((packed)) PacketHeader {
    uint8_t  cmd;
    uint32_t length;
    uint16_t checksum;
};
```
Атрибут `packed` змушує компілятор прибрати всі проміжні байти заповнення (`padding`), зменшуючи розмір структури до чистої суми її полів. Проте у вбудованих системах це несе серйозні ризики:
1. **Збій при взятті вказівника на поле**: якщо написати `uint32_t *p = &header.length;`, тип покажчика повідомляє компілятору, що адреса вирівняна за 4 байти. Спроба виконати `*p = 100;` згенерує звичайну інструкцію `STR`, яка на ARM Cortex-M0 спричинить `HardFault`.
2. **Роздування коду**: якщо компілятор знає про спакованість структури, для доступу до поля `header.length` він змушений генерувати чотири інструкції побайтового читання `LDRB` зі зсувами та `ORR`, що збільшує розмір Flash-коду та сповільнює виконання.

### Оптимізація порядку полів без використання packed

Найбезпечніший спосіб контролю розміру структури – ручне сортування полів за спаданням їхнього вирівнювання: спочатку розміщують 64-розрядні типи (`uint64_t`), потім 32-розрядні (`uint32_t`, вказівники), далі 16-розрядні (`uint16_t`) і наприкінці 8-розрядні (`uint8_t`, `bool`). Це повністю усуває внутрішнє заповнення без шкоди для продуктивності та без ризиків аварійних збоїв шини процесора.
