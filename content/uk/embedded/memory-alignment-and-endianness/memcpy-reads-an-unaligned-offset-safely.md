## Question code

```c
uint32_t value;
memcpy(&value, &buf[3], sizeof value);
```

## Short answer

**Через `memcpy`, а не cast `(uint32_t*)&buf[3]`.**

`&buf[3]` не можна безпечно розіменовувати як `uint32_t*`: адреса може не задовольняти вимогу вирівнювання, а підтримка невирівняних доступів залежить від ядра та інструкції. `memcpy` копіює байти в окремий вирівняний об’єкт; воно не визначає порядок байтів у буфері.

Захист: перевірити довжину буфера, скопіювати байти в локальну змінну, а для мережевого формату окремо декодувати endian.[^iso-c-n1570]

## Detailed explanation

`memcpy` читає байти з буфера без вимоги, щоб початкова адреса була вирівняна для `uint32_t`, і копіює їх у локальну змінну належного типу.[^iso-c-n1570]

Cast змінює лише тип вказівника. Він не пересуває адресу й не змінює її вирівнювання. Якщо адреса не задовольняє вимогу `uint32_t`, розіменування такого вказівника має undefined behavior у C; конкретний процесор може виконати доступ, сповільнити його або згенерувати виняток.[^iso-c-n1570]

Перед копіюванням перевірте, що від позиції 3 у буфері залишилося щонайменше `sizeof value` байтів. Після копіювання значення числового типу відповідає порядку байтів платформи, на якій виконується код. Якщо байти надійшли з протоколу, треба окремо декодувати визначений протоколом порядок байтів, а не вважати, що `memcpy` це зробив.[^iso-c-n1570]

Важливо також перевірити, що сам вказівник `buf` справді вказує на доступну область пам’яті протягом усієї операції. `memcpy` усуває проблему вирівнювання джерела для такого способу читання, але не може виправити неправильний розмір буфера чи невалідну адресу.[^iso-c-n1570]

Приклад:

```c
if (length >= 3 + sizeof value) {
    memcpy(&value, &buf[3], sizeof value);
}
```

**Типові помилки:**

- Вважати, що cast виправляє вирівнювання.
- Вважати, що `memcpy` перевіряє довжину або перетворює endian.

У цьому прикладі перевірка довжини запобігає читанню за межами буфера; для формату з фіксованим порядком байтів потрібне окреме декодування.
