## Short answer

**Linker script** описує Flash/RAM regions, entry point, sections, vector table і symbols для startup. Типові помилки: неправильна адреса vector table, overlap `.data/.bss/heap/stack`, неекспортовані `_sidata/_sdata/_edata/_sbss/_ebss`, невірний RAM origin/length. <span class="warn">Такі помилки часто виглядають як reset loop або HardFault до main</span>.[^dou-embedded-interview]

## Detailed explanation

### Призначення та ключові директиви Linker Script

**Linker script** (скрипт компонувальника GNU `ld`) є конфігураційним файлом, який керує процесом об’єднання вхідних об’єктних модулів (`.o`), розподілом секцій за фізичними адресами та експортом спеціальних символів адресації[^gnu-ld-manual].

У типовому скрипті для мікроконтролера визначено такі основні секції:
1. **Директива `ENTRY(Reset_Handler)`**: повідомляє компонувальнику назву точки входу, яка записується в заголовок ELF-файлу для налагоджувача.
2. **Блок `MEMORY`**: визначає фізичні регіони пам’яті мікроконтролера, їхні початкові адреси (`ORIGIN`), довжини (`LENGTH`) та атрибути доступу (`rx` для Flash, `rwx` для SRAM):

```ld
MEMORY
{
  FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 512K
  RAM   (xrw) : ORIGIN = 0x20000000, LENGTH = 128K
}
```

3. **Блок `SECTIONS`**: описує правила відображення вхідних секцій (`*(.text*)`, `*(.rodata*)`, `*(.data*)`) у вихідні регіони. Тут також задається співвідношення між VMA (Virtual Memory Address – адреса виконання в RAM) та LMA (Load Memory Address – адреса зберігання у Flash) за допомогою синтаксису `> RAM AT > FLASH`.

### Помилки у скрипті, що руйнують старт прошивки (Startup Failures)

Помилка у визначенні адреси чи порядку секцій призводить до аварійного завершення ще до входу у функцію `main()`:

1. **Невірне розміщення таблиці векторів переривань (`.isr_vector`)**:
   За стандартом архітектури ARM Cortex-M ([^armv7m-arm]), під час апаратного скидання процесор автоматично зчитує 32-бітне значення вершини стека за адресою `0x00000000` (або `0x08000000` при завантаженні з Flash) та адресу `Reset_Handler` за адресою `0x00000004`.
   Якщо секцію `.isr_vector` розмістити не на самому початку Flash або перед нею випадково потрапить інший код через помилку у скрипті, процесор завантажить сміттєві адреси у лічильник команд (PC) та вказівник стека (SP). Це миттєво генерує `HardFault` або вводить мікроконтролер у нескінченний reset loop.
2. **Пропущена або некоректна директива `AT>` для секції `.data`**:
   Секція `.data` містить ініціалізовані змінні. Її початкові значення мають зберігатися у Flash (LMA), а під час роботи змінюватися в RAM (VMA).
   Якщо у linker script не вказати `AT > FLASH`, компонувальник призначить LMA такою самою, як і VMA (у діапазоні RAM). При прошиванні у Flash початкові значення взагалі не потраплять на чіп, а startup-код скопіює випадкове сміття з неініціалізованої пам’яті.
3. **Порушення вирівнювання (Alignment) експортованих символів**:
   У коді ініціалізації (`Reset_Handler`) копіювання `.data` та занулення `.bss` зазвичай оптимізовано для роботи зі словами по 4 байти (`uint32_t`):

```ld
.bss :
{
  . = ALIGN(4);
  _sbss = .;
  *(.bss*)
  . = ALIGN(4);
  _ebss = .;
} > RAM
```

   Якщо пропустити вирівнювання `. = ALIGN(4);`, символ `_sbss` або `_ebss` може отримати непарну адресу. Спроба startup-коду виконати 32-бітний запис `STR` за невирівняною адресою викличе `UsageFault` (UNALIGNED) або пошкодить сусідні байти інших секцій пам’яті.
4. **Некоректний розрахунок меж Stack і Heap**:
   Символ вершини стека `_estack` часто розраховують як `ORIGIN(RAM) + LENGTH(RAM)`. Якщо розмір RAM вказано неправильно (наприклад, 128K замість 64K для молодшого чіпа лінійки), вказівник стека вказуватиме на неіснуючу фізичну пам’ять. Перший же виклик функції або збереження контексту викличе `BusFault` (PRECISERR)[^dou-embedded-interview].

### Симптоми збоїв та методика налагодження

Коли прошивка "зависає на старті", алгоритм локалізації включає:
- **Підключення апаратного відладчика через GDB/OpenOCD**:
  Команда `break Reset_Handler` із подальшим `stepi` дозволяє побачити, чи процесор успішно стартує з першої інструкції та чи відповідають адреси регістрів `PC` та `SP` карті пам’яті мікроконтролера.
- **Інспекція регістра VTOR (Vector Table Offset Register)**:
  Якщо використовується перенесення векторів (наприклад, у прошивках із завантажувачем), слід переконатися, що регістр `SCB->VTOR` налаштовано на фактичну адресу початку таблиці векторів, вирівняну щонайменше на 128 або 256 байт згідно з вимогами архітектури ARM.
- **Аналіз карти компонування (`.map`)**:
  У файлі карти пам’яті перевіряють значення експортованих символів `_sidata`, `_sdata`, `_edata`, `_sbss`, `_ebss` та переконуються у відсутності перекриття (overlap) між діапазонами статичних даних, купи та стека.
