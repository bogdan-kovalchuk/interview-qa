## Short answer

`const int *p` (або `int const *p`) – **вказівник на константний int**:
- `*p = 5` – заборонено (дані захищені);
- `p = &y` – дозволено (адресу можна змінити).

`int * const p` – **константний вказівник на int**:
- `*p = 5` – дозволено;
- `p = &y` – заборонено (адреса фіксована).

`const int * const p` – і дані, і адреса незмінні. Правило: читай справа наліво.[^embeddedinterviewlab]

## Detailed explanation

### Правило читання справа наліво та синтаксис стандарту

У мові C семантика покажчиків із кваліфікатором `const` залежить від його розташування відносно зірочки `*` (оператора оголошення покажчика). Найбільш надійний спосіб розбору складних типів – це правило читання справа наліво (clockwise/spiral rule):

- `const int *p` (або еквівалентний запис `int const *p`): читаємо справа наліво – `p` є покажчиком (`*`) на ціле число (`int`), яке є константним (`const`). Тут `const` кваліфікує тип об’єкта, на який посилається покажчик (pointer to const).
- `int * const p`: читаємо справа наліво – `p` є константним (`const`) покажчиком (`*`) на змінюване ціле число (`int`). Тут `const` стоїть праворуч від зірочки, тому кваліфікує сам покажчик (const pointer).
- `const int * const p`: константний покажчик на константне ціле число. Як адреса, що зберігається в покажчику, так і дані за цією адресою є незмінними.

Згідно зі стандартом ISO/IEC 9899 (§6.7.3), якщо спробувати модифікувати значення через кваліфікований `const`-вираз, транслятор зобов’язаний згенерувати діагностичне повідомлення про помилку під час компіляції.[^iso-c-n1570]

### Порівняння операцій модифікації та захисту даних

Різниця чітко проявляється на операціях перепризначення адреси та зміни значення даних:

```c
int a = 10;
int b = 20;

/* 1. Покажчик на константу (pointer to const) */
const int *p1 = &a;
*p1 = 15;        /* ПОМИЛКА: дані захищені від запису */
p1 = &b;         /* ДОЗВОЛЕНО: сам покажчик можна перенаправити */

/* 2. Константний покажчик (const pointer) */
int * const p2 = &a;
*p2 = 15;        /* ДОЗВОЛЕНО: значення за адресою можна змінювати */
p2 = &b;         /* ПОМИЛКА: адресу покажчика змінити не можна */

/* 3. Константний покажчик на константу */
const int * const p3 = &a;
*p3 = 15;        /* ПОМИЛКА: дані змінити не можна */
p3 = &b;         /* ПОМИЛКА: адресу змінити не можна */
```

### Застосування у вбудованих системах: апаратні регістри та API драйверів

У низькорівневому та системному програмуванні кожен із цих варіантів має чітке практичне призначення:

1. **Безпечні контракти функцій (`const T *`):** під час передачі буферів у драйвери передавання даних (UART, SPI, I2C) покажчик джерела оголошується як `const uint8_t *tx_buf`. Це гарантує стороні виклику (caller), що драйвер не спотворить дані, дозволяє передавати рядки й константи безпосередньо з Flash-пам’яті (`.rodata`) та забезпечує відповідність правилу MISRA C Rule 8.13.
2. **Апаратні регістри керування (`volatile T * const`):** базові адреси периферійних модулів у карті пам’яті MCU фіксовані на апаратному рівні. Покажчик на такий регістр не повинен випадково зміститися в коді, проте біти самого регістра змінюються апаратно або записуються програмою:
   ```c
   /* Адреса регістра незмінна, але значення вмісту змінюване та volatile */
   volatile uint32_t * const GPIOA_ODR = (volatile uint32_t *)0x40020014;
   ```
3. **Регістри тільки для читання (`const volatile T * const`):** регістри стану чи вхідних ліній (наприклад, `GPIOA_IDR` або прапорці статусу таймера), куди процесор не повинен нічого записувати, але чий стан змінюється апаратно зовнішніми сигналами, комбінують обидва рівні константності:
   ```c
   const volatile uint32_t * const GPIOA_IDR = (const volatile uint32_t *)0x40020010;
   ```
