## Question code

```c
int arr[4]={0};
int *p=arr;
p+=5;
*p=1;
```

## Short answer

<span class="warn">Так, undefined behavior (UB)</span> (навіть без розіменування).

Формування вказівника `p += 5` виходить за межі масиву більш ніж на 1: `arr` має 4 елементи, тому валідні вказівники: `arr` до `arr+4` (включно "one-past-the-end"). Вираз `arr+5` – це UB вже при формуванні адреси.

One-past-the-end (`arr+4`) – дозволено формувати, але <span class="warn">не розіменовувати</span>.[^embeddedinterviewlab]

## Detailed explanation

Цей приклад демонструє одне з найсуворіших правил адресної моделі мови C: вихід покажчика за межі допустимого діапазону масиву призводить до `undefined behavior` ще на етапі обчислення значення адреси, до будь-якої спроби читання чи запису.[^iso-c-n1570]

### Модель пам’яті ISO C та семантика GEP Inbounds

Згідно з ISO/IEC 9899 (§6.5.6 Additive operators, пункт 8), масив у мові C розглядається як ізольований об’єкт у пам’яті.[^iso-c-n1570] Якщо тип масиву `T arr[N]`, то стандарт дозволяє зміщення покажчика від початкового елемента виключно в межах від `0` до `N`:
- Адреси від `arr + 0` до `arr + (N - 1)` вказують на дійсні елементи об’єкта;
- Адреса `arr + N` є єдиним легітимним граничним значенням (one-past-the-end pointer), призначеним для порівняння в циклах;
- Будь-яке зміщення `arr + k`, де `k > N` (як у цьому випадку `p += 5` для масиву з 4 елементів) або `k < 0`, є прямим порушенням стандарту C і породжує `undefined behavior`.[^iso-c-n1570]

У сучасній інфраструктурі компіляторів (зокрема LLVM Clang та GCC) зміщення покажчиків транслюються в інструкції проміжного представлення з предикатом меж, наприклад `getelementptr inbounds` у LLVM IR. Предикат `inbounds` вимагає, щоб обчислювана адреса належала тому самому виділеному об’єкту пам’яті або була на одну позицію за його кінцем. Якщо ця інваріанта порушується, компілятор розглядає такий шлях виконання як аномальний і генерує `poison value` або повністю оптимізує відповідні гілки коду як недосяжні (`unreachable`).[^embeddedinterviewlab]

### Стек-фрейм ARM Cortex-M та наслідки розіменування

Операція розіменування `*p = 1;` за невалідною адресою спричиняє фізичне руйнування пам’яті (Memory Corruption):[^iso-c-n1570]

- Масив `arr[4]` оголошений як локальна автоматична змінна, тому він розташований у стеку поточної функції (SRAM мікроконтролера).
- На 32-бітній архітектурі ARM Cortex-M зміщення на 5 елементів становить `5 * 4 = 20` байтів від початку масиву. Сам масив займає 16 байтів (`4 * 4`).
- Запис 4 байтів за зміщенням `+20` потрапляє у службову область стек-фрейму. Там зазвичай розташовані:
  1. Інші локальні змінні функції;
  2. Збережений покажчик кадру (`R7` у Thumb-режимі або `R11`);
  3. Збережене значення регістра повернення `LR` (Link Register / `R14`).
- Якщо запис `*p = 1` змінює значення в комірці стека, де збережено `LR`, при виконанні інструкції виходу з функції `POP {..., PC}` процесор завантажить у лічильник команд `PC` значення `0x00000001` (або інше спотворене число). Оскільки в ARM Cortex-M молодший біт 0 адреси визначає виконання інструкцій Thumb (біт T у регістрі EPSR), перехід за парною адресою (біт 0 = 0) викликає спробу переходу в непідтримуваний режим ARM з викликом `UsageFault` (INVSTATE), а перехід за адресою `0x00000001` веде до вибірки інструкцій із нульової адреси Flash (де зберігається початковий покажчик стека MSP замість коду), провокуючи `HardFault` або збій шини `BusFault`.[^embeddedinterviewlab]

### Правила безпечного проектування циклів та буферів

1. **Суворий контроль меж ітерації:**
   Використовувати покажчик one-past-the-end виключно як умову зупинки:
   ```c
   int arr[4] = {0};
   int * const end = arr + 4; // Валідно: one-past-the-end для arr[4]
   for (int *it = arr; it != end; ++it) {
       *it = 1; // Безпечно: розіменовуються лише індекси 0..3
   }
   ```
2. **Ніколи не розіменовувати past-the-end:** Спроба `*end = 1;` є такою ж фатальною помилкою, як і зміщення на 5 елементів.
3. **Статичний аналіз коду:** Використання статичних аналізаторів (Cppcheck, PC-lint, MISRA C:2012 Rule 18.1), які забороняють обчислення вказівників за межами допустимих об’єктів масиву.[^embeddedinterviewlab]
