## Short answer

Якщо `arr` за адресою `0x2000` -> `p = 0x2000 + 2 * sizeof(uint16_t) = 0x2000 + 4 = 0x2004`.

Крок pointer arithmetic для `uint16_t*` = 2 байти. `p += 2` -> зсув на 2 елементи × 2 байти = 4 байти.

Тепер `p` вказує на `arr[2]`. Зважай: кроки завжди у "елементах типу", не у байтах.[^embeddedinterviewlab]

## Detailed explanation

Арифметика покажчиків у мові C є типобезпечною та автоматично масштабується відповідно до розміру типу даних, на який посилається покажчик. Стандарт ISO/IEC 9899 (§6.5.6 Additive operators) визначає, що додавання цілого числа `n` до покажчика `P`, який вказує на елемент масиву, формує покажчик на елемент того ж масиву зі зміщенням на `n` позицій. Нова фізична адреса обчислюється за формулою: адреса = базова адреса + `n * sizeof(*P)`.

Для типу `uint16_t` (беззнакове 16-бітне ціле число) розмір строго зафіксований стандартом і становить 2 байти (`sizeof(uint16_t) == 2`). Тому додавання значення `2` (`p += 2`) збільшує числове значення адреси не на 2, а на 2 * 2 = 4 байти. Якщо масив розташований за базовою адресою `0x2000`, покажчик `p` переміщується на адресу `0x2004`.[^iso-c-n1570]

### Карта пам’яті та адресація елементів

Масиви у C гарантовано розміщуються у пам’яті у вигляді неперервного послідовного блоку байтів без проміжків між елементами (§6.2.5). Для масиву `uint16_t arr[4]` комірки пам’яті розподіляються таким чином:[^iso-c-n1570]

| Елемент | Зсув у байтах | Діапазон адрес | Покажчик після операції |
|---|---|---|---|
| `arr[0]` | `+0` | `0x2000`–`0x2001` | Початковий `p` (`p = arr`) |
| `arr[1]` | `+2` | `0x2002`–`0x2003` | `p + 1` |
| `arr[2]` | `+4` | `0x2004`–`0x2005` | Результат `p += 2` |
| `arr[3]` | `+6` | `0x2006`–`0x2007` | `p + 3` |
| *past-the-end* | `+8` | `0x2008` | `p + 4` (дозволена границя) |

Оператор `uint16_t *p = arr;` виконує неявний array-to-pointer decay: ім’я масиву `arr` у виразі перетворюється на покажчик на свій перший елемент (`&arr[0]`), тобто `p` отримує адресу `0x2000`. Після виконання `p += 2;` покажчик вказує на третій елемент масиву `arr[2]`, а розіменування `*p` поверне значення цього елемента.

### Генерація машинного коду на ARM Cortex-M

На рівні асемблера ARM Thumb-2 арифметика покажчиків відображається безпосередньо в команди додавання зі зміщенням або спеціальні режими адресації інструкцій завантаження `LDRH` (Load Register Halfword):[^iso-c-n1570]

```assembly
; Припустимо, r1 містить базову адресу масиву 0x2000
ADDS    r1, r1, #4          ; Безпосередній зсув на 4 байти для переходу до arr[2]
LDRH    r0, [r1]            ; Читання 16-бітного значення arr[2] у регістр r0
```

Якщо доступ до елемента виконується через індексний регістр у циклі, процесор ARM підтримує апаратне масштабування зміщення в один такт:

```assembly
; r1 = базова адреса arr, r2 = індекс елемента (2)
LDRH    r0, [r1, r2, LSL #1] ; Зсув r2 вліво на 1 біт (множення на 2) і завантаження
```

Це демонструє, чому масштабування на розмір типу інтегроване в мову C на найнижчому рівні: воно точно відповідає апаратним режимам адресації мікропроцесорів.

### Пастки та типові помилки в embedded-прошивках

- **Плутанина між байтовими зсувами та елементами:** При роботі з апаратними регістрами (MMIO) та DMA документація на мікроконтролер наводить зміщення у байтах. Якщо розробник оголосить покажчик `uint16_t *reg = BASE_ADDR;` і виконає `reg += OFFSET_BYTES;`, адреса зміститься на подвоєну кількість байтів, що спричинить запис у хибний регістр периферії.
- **Невідповідне вирівнювання (alignment):** Приведення довільного покажчика `uint8_t *` до `uint16_t *` з подальшою арифметикою може створити непарну адресу. На ядрах ARM Cortex-M0/M0+ доступ до 16-бітного слова за непарною адресою заборонений апаратно і негайно генерує виняток `HardFault`.
- **Вихід за межі масиву (out-of-bounds):** Стандарт дозволяє обчислювати покажчик на один елемент за межами масиву (`p = arr + 4`), але його розіменування є undefined behavior.[^iso-c-n1570]
