## Short answer

**Strict aliasing rule** (C99/C11 §6.5): компілятор припускає, що вказівники несумісних типів не адресують одну й ту саму пам’ять.

Це дозволяє агресивну оптимізацію: запис через `float*` не змушує компілятор перечитувати значення через `int*`.

Виняток: символьні типи (`char*`, `unsigned char*`, `uint8_t*`) можуть адресувати будь-який об’єкт.

Порушення: `int x; float *fp = (float*)&x; *fp = 1.0f;` спричиняє UB. Безпечний type punning: `memcpy` або `union` (у C).[^embeddedinterviewlab]

## Detailed explanation

### Суть правила strict aliasing та стандарт ISO C

Термін *aliasing* (накладання імен) описує ситуацію, коли одна й та сама область пам’яті може адресуватися через дві різні назви чи вказівники.

Згідно зі стандартом ISO/IEC 9899:201x (C11), пункт 6.5 (пункт 7), об’єкт може мати доступ до свого збереженого значення лише через lvalue-вираз сумісного типу [^iso-c-n1570]. Це фундаментальне правило має назву **strict aliasing rule**. Воно встановлює, що вказівники на несумісні типи (наприклад, `int*` та `float*`) ніколи не можуть вказувати на одну й ту саму фізичну комірку пам’яті.

Стандарт передбачає чітко визначені винятки, коли накладання дозволено:
* Символьні типи: покажчики типів `char*`, `signed char*` та `unsigned char*` (а також `uint8_t*`, який є псевдонімом `unsigned char`) мають право посилатися на пам’ять будь-якого об’єкта [^iso-c-n1570].
* Кваліфіковані версії сумісних типів (наприклад, `const int*` та `int*`).
* Знакові та беззнакові варіанти одного базового типу (`int*` та `unsigned int*`).
* Типи структур або об’єднань (`union`), що містять відповідний тип серед своїх членів.

### Вплив на оптимізацію компілятора та асемблерний код

Правило strict aliasing дозволяє оптимізатору компілятора (GCC / Clang при `-O2` або `-O3`) генерувати набагато ефективніший машинний код для процесорів ARM Cortex-M.

Розглянемо приклад:
```c
void update_values(uint32_t *a, float *b) {
    *a = 100;
    *b = 3.14f;
    send_data(*a);
}
```
Оскільки типи `uint32_t*` та `float*` несумісні, компілятор спирається на strict aliasing і припускає, що запис у `*b` жодним чином не змінює значення за адресою `*a`. Тому компілятору не потрібно повторно зчитувати значення `*a` з пам’яті (RAM) через повільну інструкцію `LDR`. Він просто зберігає константу `100` у регістрі `r0` і передає її у функцію `send_data`.

Якщо програміст порушує правило шляхом прямого приведення вказівників:
```c
/* ПОМИЛКА: Невизначена поведінка (Strict Aliasing Violation) */
uint32_t raw_val = 0x3F800000;
float f = *(float*)&raw_val;
```
Компілятор може виконати агресивне перевпорядкування інструкцій або зберегти старе значення у регістрі, через що програма отримає непередбачувані дані.

### Пастки у вбудованих системах (Embedded)

Найчастіше порушення strict aliasing трапляється при розбиранні пакетів комунікаційних протоколів (UART, CAN, SPI, Ethernet):
```c
/* Небезпечний патерн розбору пакета */
uint8_t rx_buffer[64];
// ... прийом байтів у буфер ...
struct SensorPacket *pkt = (struct SensorPacket*)rx_buffer; /* UB! */
```
Цей код містить одразу дві критичні небезпеки:
1. **Порушення strict aliasing**: спроба читати масив `uint8_t` через вказівник на структуру.
2. **Порушення вирівнювання (Alignment Fault)**: на процесорах ARM Cortex-M0/M0+ непідтримуваний неідеально вирівняний доступ (*unaligned access*) при читанні 32-бітних полів структури негайно спричиняє апаратний виняток `HardFault`.

### Безпечні та переносні способи (Type Punning)

Для коректного реінтерпретування пам’яті без порушення стандарту слід використовувати один із підходів:

* **Стандартний виклик `memcpy`**:
  ```c
  uint32_t raw = 0x3F800000;
  float val;
  memcpy(&val, &raw, sizeof(val));
  ```
  Сучасні оптимізатори розпізнають виклик `memcpy` відомого розміру і замінюють його на пряме переміщення між регістрами (наприклад, інструкцію `VMOV` між регістрами загального призначення та блоком FPU).
* **Використання `union` (у мові C)**: стандарт C99/C11 (Annex J.5.7) явно дозволяє запис в одне поле об’єднання та зчитування з іншого як поширене розширення мови (*type punning*):
  ```c
  union Converter {
      uint32_t u;
      float f;
  };
  union Converter conv;
  conv.u = 0x3F800000;
  float val = conv.f; /* Легітимно у C99/C11 */
  ```
* **Прапорець компілятора `-fno-strict-aliasing`**: вимикає припущення компілятора щодо strict aliasing (активно застосовується в ядрі Linux), проте позбавляє частину коду корисних оптимізацій.
