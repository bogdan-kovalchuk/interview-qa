## Short answer

За стандартом C (§6.5.2.1): **`arr[i]` визначається як `*(arr+i)`**. Це не синтаксичний цукор – це точне визначення subscript operator.

Наслідки:
- `arr[2] == *(arr+2) == *(2+arr) == 2[arr]` – всі еквівалентні;
- Індексування – просто pointer arithmetic + dereference;
- Від’ємні індекси (`arr[-1]`) формально дозволені якщо вказівник вже зсунутий і результат вказує у межах масиву.[^embeddedinterviewlab]

## Detailed explanation

### Визначення стандарту та комутативність додавання

У мові C оператор індексування масиву `[]` не є самостійною апаратною операцією. Згідно зі стандартом ISO/IEC 9899 (пункт §6.5.2.1), постфіксний вираз `E1[E2]` за суворим визначенням є абсолютно тотожним виразу `(*((E1)+(E2)))`.[^iso-c-n1570] Один із виразів обов’язково має бути вказівником на об’єкт, а інший – цілочисельним індексом.

Оскільки математична операція бінарного додавання `+` є комутативною, вирази `(arr + i)` та `(i + arr)` мають однаковий результат. Прямим наслідком цього є те, що запис `i[arr]` цілком валідний для компілятора C і транслятор згенерує ідентичний машинний код, що й для `arr[i]` або `*(arr + i)`.[^iso-c-n1570] Проте форма `i[arr]` погіршує читабельність і заборонена промисловими стандартами безпечного коду, такими як MISRA C.

### Масштабування адреси в pointer arithmetic

Ключова відмінність арифметики вказівників (pointer arithmetic) від звичайної арифметики цілих чисел полягає в масштабуванні зміщення. Додавання одиниці до вказівника типу `T*` насправді збільшує фізичну адресу на `sizeof(T)` байтів:

`address = base + (i * sizeof(T))`

На архітектурі ARM Cortex-M (набір інструкцій Thumb-2) компілятор оптимізує такі вирази в одну інструкцію завантаження з апаратним зсувом (barrel shifter), наприклад `LDR R0, [R1, R2, LSL #2]` для масиву 32-розрядних слів `uint32_t`.[^armv7m-arm] Базова адреса масиву передається в `R1`, індекс у `R2`, а зсув `LSL #2` множить індекс на 4 на льоту без додаткових тактів процесора.

### Від’ємні індекси та межі об’єктів

Стандарт C формально дозволяє використання від’ємних індексів за умови, що вказівник попередньо вказує не на початок, а на елемент усередині масиву:

```c
int buffer[10];
int *ptr = &buffer[5];
int val = ptr[-2]; /* Еквівалентно *(ptr - 2) -> buffer[3] */
```

Вираз `ptr[-2]` повністю коректний, оскільки результуюча адреса залишається в межах масиву `buffer`.[^iso-c-n1570] Проте вихід за межі масиву як у від’ємний бік (`buffer[-1]`), так і за його край (`buffer[10]` і далі) є невизначеною поведінкою (undefined behavior). C не виконує рантайм-перевірок меж (bounds checking), тому вбудована система ризикує прочитати випадкові значення з пам’яті або пошкодити сусідні структури даних.
