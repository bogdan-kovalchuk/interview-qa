## Short answer

**void*** – type-erased pointer: може зберігати адресу об’єкта будь-якого типу без explicit cast.

Обмеження:
- <span class="warn">Не можна розіменувати</span> без cast: `*p` – помилка компіляції;
- <span class="warn">Не можна виконати arithmetic</span> без cast (стандарт C). GCC дозволяє як extension (розмір елемента = 1 байт).

Використання: `malloc`/`free`, `memcpy`/`memset`, generic callbacks, `qsort`. У embedded: generic ISR handler tables.[^embeddedinterviewlab]

## Detailed explanation

### Сутність та правила void* за стандартом C

За стандартом ISO/IEC 9899 (§6.2.5 Types, пункт 19), тип `void` позначає порожню множину значень і є неповним типом (incomplete type), який не може бути завершений[^iso-c-n1570].
Вказівник на `void` (`void*`) є універсальним вказівником на об’єкт (generic pointer).

Згідно з ISO/IEC 9899 (§6.3.2.3 Pointers, пункт 1):
- Вказівник на будь-який тип об’єкта може бути неявно перетворений на `void*` і назад без втрати точності.
- Приведення вказівника до `void*` і подальше повернення до вихідного типу гарантовано повертає початкову адресу: `(T*)(void*)p == p`.
- У мові C таке перетворення відбувається автоматично без явного приведення типів (type cast), на відміну від C++, де потрібен явний `static_cast<T*>` або C-style cast.

### Фундаментальні обмеження void*

Оскільки компілятор не знає тип і структуру даних за адресою `void*`, стандарт встановлює два ключові обмеження:
1. **Заборона розіменування (`*p`)**:
   Компілятор не може згенерувати інструкцію доступу до пам’яті, оскільки розмір цільового об’єкта невідомий. Компілятор не знає, яку інструкцію ARM викликати – `LDRB` (1 байт), `LDRH` (2 байти), `LDR` (4 байти) чи `LDRD` (8 байтів)[^armv7m-arm], а також як інтерпретувати байти (як знакове ціле, число з плаваючою комою чи покажчик). Спроба розіменування викликає помилку компіляції: `invalid use of void expression`.
2. **Заборона адресної арифметики (`p + 1`, `p++`, `p2 - p1`)**:
   Адресна арифметика спирається на множення зміщення на `sizeof(*p)`[^iso-c-n1570]. Оскільки `sizeof(void)` не визначено (неповний тип), крок адреси обчислити неможливо.
   *Розширення GCC (GNU extension):* компілятор GCC дозволяє арифметику над `void*`, умовно вважаючи `sizeof(void) == 1`. Це дозволяє писати `p + offset`, проте такий код є нестандартним, не переноситься на інші компілятори (наприклад, IAR, Keil або стандартні режими Clang) і порушує правила MISRA C.

### Застосування у вбудованому C та RTOS

1. **Абстрактні системні функції роботи з пам’яттю**:
   Функції на зразок `memcpy(void *dest, const void *src, size_t n)` або `memset(void *s, int c, size_t n)` оперують чистими байтами пам’яті незалежно від типів структур.
2. **Потоки та завдання в операційних системах реального часу (RTOS)**:
   У FreeRTOS або Zephyr функція створення завдання приймає аргумент `void *pvParameters`:
   ```c
   void vTaskFunction(void *pvParameters) {
       SensorConfig_t *config = (SensorConfig_t*)pvParameters;
       // робота з типізованою конфігурацією
   }
   ```
   Це дає змогу передавати в задачу вказівник на будь-яку довільну структуру даних.
3. **Диспетчеризація зворотних викликів (Callbacks) та переривань**:
   Драйвери периферії (UART, CAN, DMA) реєструють функції зворотного виклику з користувацьким контекстом:
   ```c
   typedef void (*DriverCallback_t)(void *context, uint32_t event);
   ```
   При виникненні події драйвер повертає переданий вказівник `context`, що дозволяє обробнику розпізнати екземпляр пристрою.

### Небезпеки та правила безпеки (Type Safety)

- **Втрата типобезпеки**: використання `void*` повністю вимикає перевірку типів компілятором. Випадкова передача покажчика на `uint32_t` замість очікуваної структури призведе до фатальних помилок під час виконання.
- **Ризик порушення вирівнювання (Alignment fault)**: якщо вказівник `void*` вказує на адресу, не вирівняну по межі 4 байтів, і розробник приводить його до `uint32_t*` для розіменування, на мікроконтролерах ARM Cortex-M0/M0+ це викличе апаратне виключення `HardFault`[^armv7m-arm].
- **Вказівники на функції**: тип `void*` призначений виключно для вказівників на об’єкти (дані). Перетворення між вказівником на функцію та `void*` заборонене стандартом ISO C і є undefined behavior[^iso-c-n1570].
