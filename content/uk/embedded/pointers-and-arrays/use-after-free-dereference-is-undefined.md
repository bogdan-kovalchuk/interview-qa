## Question code

```c
free(ptr);
if(*ptr == 0)
```

## Short answer

<span class="warn">Use-after-free – undefined behavior.</span> Після `free(ptr)` блок пам’яті повертається heap manager-у і може бути одразу перевикористаний.

Читання `*ptr` – це UB: може повернути 0, старе значення або нове значення від іншого malloc. У реальному коді – джерело security vulnerabilities (type confusion, heap exploitation).

Правило: після `free` завжди: `ptr = NULL;`; тоді перевірка `if(ptr != NULL && *ptr == 0)` безпечна.[^embeddedinterviewlab]

## Detailed explanation

Наведений фрагмент демонструє класичну пастку керування динамічною пам’яттю: розіменування покажчика після звільнення асоційованого з ним блоку. Цей дефект має назву **Use-After-Free (UAF)** і є критичною вразливістю програмного забезпечення.[^iso-c-n1570]

### Життєвий цикл пам’яті за стандартом ISO C

Відповідно до стандарту ISO/IEC 9899 (§7.22.3.3 The free function):[^iso-c-n1570]

> «Функція `free` звільняє простір, на який вказує `ptr`, роблячи його доступним для подальшого виділення. Якщо `ptr` є нульовим покажчиком, жодні дії не виконуються.»

Після завершення виклику `free(ptr)` життєвий цикл (lifetime) виділеного об’єкта повністю припиняється. Згідно з §6.2.4 p2 стандарту, значення вказівника на об’єкт, чий життєвий цикл завершився, стає **невизначеним (indeterminate)**. Спроба розіменування такого вказівника (`*ptr`) або навіть простого звернення до його значення є чистим `undefined behavior` (UB).[^iso-c-n1570]

### Механіка купового менеджера (Heap Allocator) у мікроконтролерах

У вбудованих системах керування динамічною пам’яттю (наприклад, у FreeRTOS `heap_4.c`/`heap_5.c` або Newlib nano-malloc) реалізується через зв’язні списки вільних блоків (free blocks list):[^embeddedinterviewlab]

1. **Перезапис метаданими алокатора:** Коли викликається `free(ptr)`, алокатор повертає блок у пул вільної пам’яті. Для організації двозв’язного чи однозв’язного списку алокатор зазвичай використовує корисне навантаження щойно звільненого блоку для збереження власних службових структур: розміру блоку та вказівників на сусідні вільні фрагменти пам’яті (`next` / `prev`).
2. **Фантомне читання (Dirty Read):** Читання `*ptr` вже не повертає значення, яке там було до `free`. Найчастіше воно повертає бітові маски метаданих менеджера купи або нуль, створюючи ілюзію стабільної роботи на стенді, яка руйнується при масштабуванні навантаження.
3. **Негайне перевиділення пам’яті:** В умовах багатозадачності RTOS інше завдання або обробник переривання може викликати `malloc()` одразу після звільнення. Цей самий блок пам’яті передається новому об’єкту. Будь-яке наступне читання або запис через старий `ptr` спотворює чужі дані іншої підсистеми.
4. **Heap Corruption при модифікації:** Якщо після `free` виконати запис `*ptr = value;`, це пошкодить вказівники зв’язного списку купи. Наступний виклик `malloc()` або `free()` призведе до аварійного завершення роботи або нескінченного циклу обходу пошкодженого списку.[^embeddedinterviewlab]

### Ризики кібербезпеки: UAF у підключених IoT-пристроях

У класифікаторі Common Weakness Enumeration дефект Use-After-Free зареєстровано як **CWE-416**. У мікроконтролерах із мережевими інтерфейсами (Wi-Fi, Ethernet, BLE) вразливість UAF активно використовується зловмисниками для атак:

- **Type Confusion:** Звільнений буфер пакета даних негайно перерозподіляється під структуру з вказівниками на функції (callback handlers). Читання та запис через застарілий `ptr` дозволяє підробити адресу виклику колбеку.
- **Control Flow Hijacking:** На пристроях без захисту пам’яті підміна покажчика на функцію дозволяє передати виконання на довільний шеллкод або шкідливу функцію прошивки.

### Правила безпечного кодування

1. **Негайне занулення покажчика:**
   Після виклику `free(ptr)` слід негайно присвоїти покажчику значення `NULL`:
   ```c
   free(ptr);
   ptr = NULL;
   ```
   Якщо після цього відбудеться помилкова спроба розіменування `*ptr`, вона гарантовано викличе контрольований апаратний збій (Null Pointer Dereference), який усувається на етапі тестування і не призводить до прихованого пошкодження пам’яті.
2. **Використання безпечної обгортки:**
   ```c
   #define SAFE_FREE(p) do { free(p); (p) = NULL; } while (0)
   ```
3. **Статичний аналіз та AddressSanitizer:**
   Інструменти статичного аналізу (Clang Static Analyzer) та запуск тестів прошивки на QEMU/хості з опцією `-fsanitize=address` надійно перехоплюють дефекти Use-After-Free.[^embeddedinterviewlab]
