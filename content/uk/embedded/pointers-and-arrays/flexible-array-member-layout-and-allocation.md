## Short answer

**Flexible Array Member** (FAM) – останнє поле структури з невказаним розміром: `struct Packet { uint8_t len; uint8_t data[]; };`

`sizeof(struct Packet)` не включає `data`. FAM виділяється разом зі структурою: `malloc(sizeof(Packet) + n)` – тоді `data` займає `n` байт одразу після полів структури.

Зберігається у тому ж блоці пам’яті, що й структура (heap або static). Не може бути єдиним членом struct, і структура з FAM не може бути елементом масиву.[^embeddedinterviewlab]

## Detailed explanation

**Flexible Array Member (FAM)** – це стандартизований мовний механізм, введений у C99 (ISO/IEC 9899:1999 та ISO/IEC 9899:201x, §6.7.2.1 Structure and union specifiers, пункт 18), що дозволяє створювати структури змінної довжини без використання окремих покажчиків і подвійного виділення динамічної пам’яті.[^iso-c-n1570]

### Синтаксис та правила стандарту C99

Гнучкий масив оголошується як масив без зазначення розміру (порожні квадратні дужки `[]`) в ролі **останнього поля структури**:[^iso-c-n1570]

```c
struct Message {
    uint16_t msg_id;
    uint16_t length;
    uint8_t payload[]; // Flexible Array Member (FAM)
};
```

Стандарт визначає суворі нормативні обмеження:
1. FAM зобов’язаний бути останнім іменованим полем структури;
2. Структура повинна мати принаймні одне інше іменоване поле (FAM не може бути єдиним членом структури);
3. Структура, що містить FAM, не може бути базовим типом для масиву (`struct Message arr[10]` заборонено);
4. Структура з FAM не може входити до складу іншої структури (якщо тільки вона сама не є її останнім членом).[^iso-c-n1570]

### Розмір структури, вирівнювання (Alignment) та пам’ять

Оператор `sizeof(struct Message)` **не враховує розмір елементів гнучкого масиву** (§6.7.2.1 p18).[^iso-c-n1570] Проте він враховує необхідне внутрішнє вирівнювання та заповнення в кінці структури (tail padding), щоб зміщення елементів FAM задовольняло апаратним вимогам вирівнювання типу елемента масиву:

- Для наведеної структури `sizeof(struct Message)` поверне 4 байти (два поля `uint16_t`).
- Поле `payload` починається безпосередньо зі зміщення `+4` байти від початку структури без жодних проміжків.

Пам’ять для структури та її корисного навантаження завжди виділяється як **єдиний суцільний (contiguous) блок пам’яті**:[^embeddedinterviewlab]

```c
size_t n_bytes = 64;
struct Message *msg = malloc(sizeof(struct Message) + n_bytes * sizeof(uint8_t));
if (msg != NULL) {
    msg->msg_id = 0x01;
    msg->length = (uint16_t)n_bytes;
    msg->payload[0] = 0xAA; // прямий доступ до елементів буфера
}
```

Де зберігається FAM: він завжди розташований у тому ж блоці пам’яті, що й сама структура:
- Зазвичай у динамічній пам’яті (Heap) через `malloc()`;
- У статичній пам’яті (Flash або `.data`), якщо константний об’єкт конструюється через розширення компілятора або макроси;
- На стеку чи у статичному масиві байтів через явне приведення типів буфера (placement idiom).

### Переваги FAM в embedded-системах проти використання вказівників

У вбудованому ПЗ на мікроконтролерах FAM надає суттєві переваги над структурою з покажчиком (`uint8_t *payload`):[^embeddedinterviewlab]

1. **Єдина алокація та захист від фрагментації купи:** Замість двох викликів `malloc()` (спочатку для структури, потім для буфера) і подвійного `free()`, потрібен лише один виклик. Це критично для RTOS (FreeRTOS, Zephyr), де часті алокації спричиняють фрагментацію пам’яті.
2. **Локальність даних (Data Locality) та DMA:** Усі байти заголовка та даних лежать у пам’яті строго підряд. Такий буфер можна безпосередньо передати апаратному контролеру прямого доступу до пам’яті (DMA) для передачі через SPI/UART/Ethernet одним дескриптором транзакції.
3. **Економія пам’яті SRAM:** Відсутній оверхед на збереження 4-байтного або 8-байтного покажчика адреси та службових метаданих другого блоку пам’яті в heap allocator.
4. **Продуктивність асемблерного коду:** Звернення до поля-покажчика вимагає двох інструкцій читання пам’яті (спочатку завантажити покажчик, потім значення). Для FAM адреса елемента `msg->payload[i]` обчислюється компілятором як пряме зміщення від бази структури за одну інструкцію `LDRB` ядра ARM Cortex-M.[^embeddedinterviewlab]

### Відмінність від застарілого struct hack

До введення стандарту C99 розробники використовували так званий `struct hack`: оголошували масив розміром в один елемент `uint8_t payload[1];` або нульовий масив `payload[0];` (розширення GCC). Такий підхід порушував стандартний аналіз меж компілятором, викликав діагностичні попередження `-Warray-bounds` та ризики порушення правил strict aliasing. FAM є офіційним та переносним стандартом мови C.[^iso-c-n1570]
