## Short answer

`void(*isr_table[16])(void)` – масив із 16 function pointers: кожен вказує на функцію без аргументів, що повертає void.

Ініціалізація: `isr_table[0] = nmi_handler; isr_table[1] = hardfault_handler;`

Виклик: `isr_table[irq_num]();` або `(*isr_table[irq_num])();`

Це патерн software interrupt controller або event dispatcher. Cortex-M Vector Table у Flash – апаратний аналог: масив адрес обробників переривань.[^embeddedinterviewlab]

## Detailed explanation

### Розбір синтаксису за правилом праворуч-ліворуч

Оголошення `void (*isr_table[16])(void)` читається за стандартним правилом спіралі (правилом пріоритетів мови C, ISO/IEC 9899 §6.7.6):[^iso-c-n1570]
1. `isr_table[16]` – `isr_table` є масивом із 16 елементів (квадратні дужки мають вищий пріоритет, ніж зірочка розіменування);
2. `*` – кожен елемент масиву є вказівником;
3. `(void)` – кожен вказівник вказує на функцію, яка не приймає аргументів;
4. `void` – кожна така функція повертає `void`.

Для покращення читабельності коду у вбудованому ПЗ цей тип зазвичай оголошують через `typedef`:
```c
typedef void (*isr_handler_t)(void);
isr_handler_t isr_table[16];
```

### Синтаксис виклику функції за індексом

Згідно зі стандартом C (ISO/IEC 9899 §6.5.2.2), виклик функції через вказівник можна здійснювати двома еквівалентними способами:[^iso-c-n1570]
- **Спрощений синтаксис:** `isr_table[irq_num]();` – ім’я вказівника на функцію розіменовується неявно.
- **Явний синтаксис:** `(*isr_table[irq_num])();` – явне розіменування елемента масиву перед викликом.

Обидва варіанти транслюються у повністю ідентичний машинний код для архітектури ARM Cortex-M: завантаження адреси обробника з таблиці в регістр (наприклад, `r3`) та непрямий перехід за адресою через інструкцію `BLX r3`.[^armv7m-arm]

### Апаратна таблиця векторів переривань проти програмного диспетчера

У мікроконтролерах концепція масиву покажчиків реалізована на двох рівнях:
1. **Апаратна таблиця векторів (Vector Table):** В архітектурі ARM Cortex-M таблиця векторів у Flash-пам’яті (або в SRAM після ремапінгу через системний регістр `SCB->VTOR`) є масивом 32-бітних адрес функцій-обробників.[^armv7m-arm] Контролер переривань (NVIC) апаратно читає відповідний елемент під час спрацьовування сигналу переривання, зберігає контекст у стек і передає керування на адресу обробника.
2. **Програмна таблиця диспетчеризації (Jump / Dispatch Table):** Масив `isr_table` застосовується на рівні драйверів для демультиплексування спільних ліній переривань (наприклад, коли одна лінія переривання `EXTI15_10_IRQHandler` обслуговує кілька зовнішніх пінів GPIO 10..15, або для обробки черги команд чи пакетів протоколів зв’язку).

### Критичні інженерні пастки та захист у прошивках

При реалізації програмних таблиць обробників необхідно враховувати специфіку низькорівневого середовища:[^embeddedinterviewlab]
- **Перевірка меж індексу (Index Bounds Checking):** Якщо `irq_num >= 16`, звернення до пам’яті вийде за межі масиву. Зчитування довільних даних з пам’яті та спроба виконати перехід за ними призведе до виконання сміттєвого коду або фатального `HardFault`.[^armv7m-arm] Перевірка `if (irq_num < 16)` є строго обов’язковою.
- **Захист від NULL:** Якщо елемент масиву не ініціалізовано (`NULL`), виклик `isr_table[irq]()` спричинить стрибок на адресу 0. Надійною інженерною практикою є ініціалізація всієї таблиці вказівником на функцію-заглушку за замовчуванням (`default_handler()`) з нескінченним циклом або логуванням діагностики.
- **Вимога Thumb-state в ARM:** Для процесорів архітектури ARM Cortex-M молодший біт (біт 0) адреси функції завжди повинен дорівнювати 1, позначаючи виконання в режимі Thumb.[^armv7m-arm] Компілятор C встановлює цей біт автоматично під час взяття адреси функції, проте при ручному формуванні адрес відсутність встановленого LSB призведе до винятку `UsageFault` (помилка `INVSTATE`).[^armv7m-arm]
