## Short answer

`arr` -> `0x1000` (decay до `int*`, вказує на arr[0]). `&arr` -> `0x1000` (вказує на весь масив, тип `int(*)[4]`). Та сама адреса, різний тип!

`arr+1` -> `0x1004` (крок = `sizeof(int) = 4`), `&arr+1` -> `0x1010` (крок = `sizeof(int[4]) = 16`).

Ось де різниця типів проявляється: однакова початкова адреса, різний крок.[^embeddedinterviewlab]

## Detailed explanation

Це класична числова задача з інтерв’ю для перевірки розуміння системи типів та адресної арифметики стандарту C (ISO/IEC 9899, §6.3.2.1 та §6.5.6). Для 32-бітної архітектури мікроконтролера (наприклад, ARM Cortex-M), розмір типу `int` дорівнює 4 байтам (`sizeof(int) == 4`). Масив `int arr[4]` займає в пам’яті `4 * 4 = 16` байтів (`0x10` у шістнадцятковій системі).[^iso-c-n1570]

### Покроковий розбір значень та типів виразів

Розглянемо кожен вираз окремо, виходячи з базової адреси `0x1000`:[^iso-c-n1570]

1. **`arr` (адреса `0x1000`, тип `int *`):**
   - У виразі ім’я масиву зазнає `array-to-pointer decay` і перетворюється на вказівник на свій перший елемент `&arr[0]`.
   - Числове значення дорівнює початковій адресі першого елемента: `0x1000`.
2. **`&arr` (адреса `0x1000`, тип `int (*)[4]`):**
   - Оператор `&` бере адресу всього масиву як єдиного неподільного об’єкта.
   - Масив починається з першого байта свого нульового елемента, тому чисельне значення адреси є тим самим: `0x1000`.
   - Проте тип виразу кардинально інший: це вказівник на масив із 4 цілих чисел.
3. **`arr + 1` (адреса `0x1004`, тип `int *`):**
   - Операція додавання одиниці до покажчика типу `int *`.
   - Згідно зі стандартом C (§6.5.6), зміщення масштабується розміром базового типу: `1 * sizeof(int) = 4` байти.
   - Підсумкова адреса: `0x1000 + 4 = 0x1004`. Це адреса другого елемента масиву `&arr[1]`.
4. **`&arr + 1` (адреса `0x1010`, тип `int (*)[4]`):**
   - Операція додавання одиниці до покажчика на масив типу `int (*)[4]`.
   - Зсув масштабується розміром усього типу, на який вказує покажчик: `1 * sizeof(int[4]) = 4 * 4 = 16` байтів.
   - У шістнадцятковій системі числення 16 байтів записуються як `0x10`.
   - Підсумкова адреса: `0x1000 + 0x10 = 0x1010`.

### Карта розміщення масиву в пам’яті

Розподіл пам’яті для масиву `arr` та обчислених покажчиків має такий вигляд:[^iso-c-n1570]

| Діапазон адрес | Елемент / Сутність | Розмір | Вираз, що вказує сюди |
|---|---|---|---|
| `0x1000`–`0x1003` | `arr[0]` | 4 байти | `arr`, `&arr` |
| `0x1004`–`0x1007` | `arr[1]` | 4 байти | `arr + 1` |
| `0x1008`–`0x100B` | `arr[2]` | 4 байти | `arr + 2` |
| `0x100C`–`0x100F` | `arr[3]` | 4 байти | `arr + 3` |
| `0x1010` | *past-the-end адреса* | – | `&arr + 1` |

### Стандарт C та покажчик «one past the last element»

Згідно з ISO/IEC 9899 (§6.5.6 p8), стандарт явно дозволяє обчислювати покажчик, який вказує на одну позицію за межі об’єкта (past-the-end pointer):[^iso-c-n1570]

- Вираз `&arr + 1` легітимно формує покажчик на комірку, що розташована одразу після завершення всього масиву.
- Порівняння таких покажчиків є визначеною поведінкою (наприклад, для визначення межі блоку пам’яті).
- Проте будь-яка спроба **розіменувати** такий покажчик (`*(&arr + 1)`) є невизначеною поведінкою (undefined behavior), оскільки за адресою `0x1010` цільового об’єкта не існує.

### Типові помилки на співбесідах

- **Помилка шістнадцяткового переведення:** додавання 16 байтів до `0x1000` часто помилково записують як `0x1016` замість правильного `0x1010` через неуважність до шістнадцяткової системи числення.
- **Приведення типів:** якщо привести масив до байтового покажчика `((char *)arr) + 1`, результат дорівнюватиме `0x1001`, оскільки розмір `char` строго дорівнює 1 байту.
