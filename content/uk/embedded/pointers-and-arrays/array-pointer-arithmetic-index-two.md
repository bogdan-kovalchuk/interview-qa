## Question code

```c
int arr[5] = {10,20,30,40,50};
int *p = arr;
printf("%d", *(p+2));
```

## Short answer

`30`.

`arr` затухає (decays) до вказівника на перший елемент. `p = arr` -> `p` вказує на `arr[0]`.

`p+2` -> вказівник на `arr[2]` (кроком `2 * sizeof(int) = 8` байт на 32-bit). `*(p+2)` -> розіменування -> `arr[2] = 30`.

За стандартом: `arr[i] ≡ *(arr+i) ≡ *(i+arr) ≡ i[arr]` – всі чотири форми еквівалентні.[^embeddedinterviewlab]

## Detailed explanation

### Поетапне виконання: decay, арифметика вказівників та розіменування

У наведеному фрагменті виконується класичний ланцюжок операцій роботи з пам’яттю мови C:

1. **Ініціалізація та decay масиву:** масив `int arr[5] = {10,20,30,40,50};` виділяє суміжну область пам’яті під 5 елементів типу `int`. Під час виконання присвоєння `int *p = arr;` ім’я масиву затухає (decay) до вказівника на його нульовий елемент `&arr[0]` (ISO/IEC 9899, пункт 6.3.2.1).[^iso-c-n1570] Змінна `p` тепер зберігає початкову адресу буфера.
2. **Арифметика вказівників (pointer arithmetic):** вираз `p + 2` виконує додавання цілого числа до вказівника. За правилами стандарту C (пункт 6.5.6), зсув автоматично множиться на розмір базового типу `sizeof(int)`.[^iso-c-n1570] Вказівник переміщується на `2 * sizeof(int)` байтів уперед, вказуючи точно на комірку `arr[2]`.
3. **Розіменування:** унарний оператор `*` зчитує 32-розрядне ціле значення за отриманою адресою, повертаючи число `30`.[^embeddedinterviewlab]

### Автоматичне масштабування за типом елемента

Компілятор C автоматично враховує розмір цільового типу при будь-яких арифметичних діях над вказівниками. Якщо базова адреса `p` дорівнює умовному значенню `0x20000000` (типовий початок оперативної пам’яті SRAM у контролерах STM32/Cortex-M):
- Для `int *p`: вираз `p + 2` дає фізичну адресу `0x20000000 + 2 * 4 = 0x20000008`;
- Для `uint8_t *p`: вираз `p + 2` дав би адресу `0x20000000 + 2 * 1 = 0x20000002`;
- Для вказівника на структуру `struct Packet *p` розміром 32 байти: вираз `p + 2` дав би зсув на 64 байти (`0x20000040`).

Це позбавляє розробника необхідності вручну розраховувати байтові зміщення, захищаючи код від апаратних помилок вирівнювання (alignment faults).

### Відмінність між змінною-вказівником та ідентифікатором масиву

Хоча вирази `*(p + 2)` та `*(arr + 2)` дають однаковий результат, між `p` та `arr` існує фундаментальна системна різниця:
- `p` є повноцінною змінною-вказівником (lvalue), яка має власну комірку пам’яті (на стеку або в регістрі процесора) і може змінювати своє значення в процесі роботи програми (`p++`, `p += 2`).
- `arr` є ідентифікатором масиву (non-modifiable lvalue). Він жорстко позначає виділений блок пам’яті і не може бути змінений або перепризначений: операції на зразок `arr++` або `arr = p` є грубою помилкою компіляції.

За стандартом C усі наступні форми доступу є повністю семантично еквівалентними:[^iso-c-n1570]
`arr[2] == *(arr + 2) == *(p + 2) == p[2] == 2[p] == 2[arr]`.

### Апаратно-орієнтована оптимізація в архітектурі ARM

Сучасні вбудовані архітектури мають пряму апаратну підтримку масштабованої адресації. Наприклад, в інструкціях Thumb-2 ядра ARM Cortex-M доступ за виразом `*(p + 2)` або `p[2]` транслюється в одну машинну інструкцію:

```assembly
LDR R0, [R1, #8]    ; R1 = базова адреса p, зсув #8 закодовано в коді інструкції
```

Якщо зміщення обчислюється динамічно через змінну `i`, ядро задіює barrel shifter:

```assembly
LDR R0, [R1, R2, LSL #2]  ; R1 = p, R2 = i; апаратний зсув вліво на 2 біти (множення на 4)
```

Така адресація виконується за один машинний такт без потреби у попередніх обчисленнях проміжних адрес в окремих регістрах.
