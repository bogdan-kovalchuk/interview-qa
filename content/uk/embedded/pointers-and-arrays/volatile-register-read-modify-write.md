## Question code

```c
uint32_t reg=*((volatile uint32_t*)0x40020010);
reg|=(1<<5);
*((volatile uint32_t*)0x40020010)=reg;
```

## Short answer

Read-Modify-Write (RMW) операція над hardware register: **Read** читає поточне значення регістру з адреси `0x40020010`, **Modify** встановлює біт 5 (`|= (1<<5)`) не змінюючи інші біти, **Write** записує назад у регістр.

<span class="warn">Ризик</span>: між read і write інший потік або ISR може змінити регістр – виникає race condition, тож для атомарного RMW використовуй STM32 BSRR (GPIO) або disable IRQ навколо RMW.[^embeddedinterviewlab]

## Detailed explanation

### Суть операції та роль кваліфікатора volatile

Наведений код реалізує трифазну операцію **Read-Modify-Write (RMW)** над апаратним 32-бітним регістром периферійного модуля (наприклад, `GPIOA_ODR` у мікроконтролерах сімейства STM32 за адресою `0x40020010`):
1. **Read (Читання)**: `uint32_t reg = *((volatile uint32_t*)0x40020010);` зчитує поточний стан регістру з апаратної шини у локальну змінну `reg`.
2. **Modify (Модифікація)**: `reg |= (1 << 5);` виконує побітову операцію «АБО» з бітовою маскою, виставляючи 5-й біт у логічну одиницю та залишаючи всі інші 31 біт без змін.
3. **Write (Запис)**: `*((volatile uint32_t*)0x40020010) = reg;` записує оновлене значення назад у фізичний регістр периферії.

Використання кваліфікатора `volatile` є критично обов’язковим згідно зі стандартом ISO C (ISO/IEC 9899:2011, §6.7.3)[^iso-c-n1570]. Воно вказує оптимізатору компілятора, що пам’ять за цією адресою відображає апаратний стан (`Memory-Mapped I/O`), який може змінюватися зовнішніми факторами. Кваліфікатор забороняє компілятору викидати запис (`dead store elimination`), кешувати значення в регістрі процесора або змінювати послідовність звернень до пам’яті.

### Робота на рівні пам’яті та асемблера ARM Cortex-M

В архітектурі ARM Cortex-M (набір інструкцій Thumb-2) цей фрагмент компілюється в окремі інструкції завантаження, логічної модифікації та збереження[^armv7m-arm]:

```assembly
LDR     R0, =0x40020010     ; R0 = базова адреса периферійного регістра
LDR     R1, [R0]            ; READ: зчитування поточного значення в R1
ORR.W   R1, R1, #32         ; MODIFY: побітове АБО з маскою (1 << 5 = 0x20)
STR     R1, [R0]            ; WRITE: запис оновленого слова назад у периферію
```

Ключова проблема полягає в тому, що послідовність завантаження, модифікації та збереження **не є атомарною**:
- Якщо між інструкціями `LDR` та `STR` виникає переривання (ISR) або диспетчер операційної системи реального часу (RTOS) перемикає контекст на іншу задачу;
- І якщо цей ISR або інший потік змінює інші біти того ж регістра `0x40020010` (наприклад, скидає пін 2 або виставляє пін 7);
- То після повернення в перерваний код інструкція `STR R1, [R0]` запише старе значення `R1` з модифікованим лише 5-м бітом, тим самим повністю затерши всі апаратні зміни, зроблені перериванням! Це класичний стан гонитви (`race condition`), який надзвичайно складно відтворити та відлагодити.

### Апаратні та програмні способи захисту

Для усунення race condition в embedded-системах застосовують такі підходи:

1. **Використання апаратних Set/Reset регістрів (BSRR / BRR):**
   У мікроконтролерах STM32 для кожного GPIO є спеціальний регістр `BSRR` (Bit Set/Reset Register). Запис одиниці в молодші 16 бітів атомарно виставляє відповідний пін, а в старші 16 бітів – атомарно скидає його за одну транзакцію запису `STR` без попереднього читання:
   ```c
   // Атомарне встановлення піна 5 без RMW:
   GPIOA->BSRR = (1U << 5);
   ```

2. **Апаратний механізм Bit-Banding (ARM Cortex-M3 / Cortex-M4):**
   Архітектура ARMv7-M надає область bit-band alias, де кожному окремому біту периферійного регістра відповідає окрема 32-бітна адреса пам’яті[^armv7m-arm]. Запис одиниці за цією alias-адресою транслюється внутрішньою шиною мікроконтролера в атомарну апаратну операцію.

3. **Критичні секції (відключення переривань):**
   Якщо апаратних регістрів прямого бітового доступу немає (наприклад, у регістрах конфігурації таймерів або системного тактування), RMW огортають у критичну секцію:
   ```c
   uint32_t primask = __get_PRIMASK();
   __disable_irq();
   *((volatile uint32_t*)0x40020010) |= (1U << 5);
   __set_PRIMASK(primask);
   ```

### Пастка статусних регістрів з бітами W1C (Write-1-to-Clear)

Ніколи не застосовуйте RMW (`|=`) до статусних регістрів периферії (наприклад, регістрів прапорців UART, SPI, DMA), у яких біти очищаються записом одиниці (`write-1-to-clear` або `rc_w1`).
Якщо виконати `SR |= FLAG_RXNE;`, операція `LDR` зчитає всі інші активні прапорці (наприклад, помилки кадру `FE` або переповнення `ORE`), а наступна операція `STR` запише одиниці у всі ці біти, випадково очистивши важливі апаратні події до того, як їх обробить відповідний драйвер.
