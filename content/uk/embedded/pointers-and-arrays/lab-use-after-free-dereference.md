## Question code

```c
int *p = malloc(sizeof(int)*10);
free(p);
printf("%d", p[0]);
```

## Short answer

<span class="warn">Use-after-free – undefined behavior.</span> Після `free(p)` пам’ять повернута heap manager-у і може бути негайно перевикористана (наприклад, наступним `malloc`).

`p[0]` після `free`: може повернути 0 (heap manager записав туди metadata), старе значення, або crash. У security контексті: джерело use-after-free exploits.

Захист: `free(p); p = NULL;`, потім `if(p != NULL)` перед доступом.[^embeddedinterviewlab]

## Detailed explanation

### Стандарт C та семантика use-after-free

Згідно зі стандартом ISO/IEC 9899 (§7.22.3.3), виклик функції `free(p)` деалокує блок пам’яті, на який вказує покажчик `p`, повертаючи ресурс системі для подальшого виділення.[^iso-c-n1570] Після повернення керування з `free` значення покажчика стає невизначеним (indeterminate). Будь-яке наступне читання або запис через цей вказівник (`p[0]`, `*p`) є канонічним випадком **use-after-free** і класифікується стандартом як `undefined behavior` (невизначена поведінка).[^iso-c-n1570]

Сам виклик `free(p)` звільняє виділену динамічну пам’ять, проте не змінює значення локальної змінної `p` у поточному стековому кадрі – вона залишається вказівником, що завис (dangling pointer), і зберігає попередню віртуальну чи фізичну адресу блоку.

### Що відбувається на рівні менеджера динамічної пам’яті (Heap Manager)

У середовищі вбудованих систем (наприклад, у реалізаціях FreeRTOS `heap_4.c`, newlib або dlmalloc) деалокований блок негайно інтегрується у внутрішні структури даних купи:[^embeddedinterviewlab]
- **Перезапис заголовка службовими метаданими:** Менеджер пам’яті розміщує метадані вільного списку (free list) безпосередньо на початку вивільненого блоку. За адресою `p[0]` замість оригінальних даних користувача опиняється покажчик на наступний вільний блок (`next`), розмір фрагмента або магічні маркери цілісності (canary bytes).
- **Коалесценція (злиття блоків):** Якщо сусідні блоки у купі також вільні, менеджер об’єднує їх в один більший безперервний фрагмент, повністю перезаписуючи структуру заголовків.
- **Негайне перевикористання іншим потоком або задачею:** В умовах багатозадачності RTOS інша задача може викликати `malloc()` одразу після `free(p)` і отримати той самий блок пам’яті. Читання `p[0]` поверне дані, щойно записані іншим модулем, а запис у `p[0]` призведе до прихованого пошкодження пам’яті чужої задачі (silent memory corruption).

### Наслідки у вбудованих системах та вразливості безпеки

Вбудовані системи часто працюють без повноцінного апаратного захисту віртуальної пам’яті (MMU), тому наслідки use-after-free проявляються особливо небезпечно:[^iso-c-n1570]
1. **Збої часу виконання (Crash / HardFault):** Якщо купа контролюється модулем захисту пам’яті (MPU), або якщо розіменування пошкоджених метаданих призводить до стрибка за неіснуючою адресою, процесор негайно переходить у стан `HardFault`.
2. **Вразливості безпеки (CWE-416):** В автономних мережевих IoT-пристроях use-after-free є одним із критичних векторів атак. Зловмисник, маніпулюючи чергою виділення пакетів пам’яті (heap spraying), може перезаписати метадані купи або покажчики на функції зворотного виклику (callbacks), досягнувши виконання довільного коду (arbitrary code execution).

### Стратегії запобігання та захисту у прошивках

Для гарантування стабільності прошивки застосовують такі інженерні практики:[^iso-c-n1570]
- **Очищення вказівника (Nullifying pointer):** Одразу після виклику `free` покажчик слід зануляти:
  ```c
  free(p);
  p = NULL;
  ```
  Подальша спроба розіменування `p[0]` на системах з ОС або мікроконтролерах із налаштованим MPU згенерує детермінований апаратний збій (MemManage / HardFault), що значно спрощує локалізацію помилки під час налагодження. (На bare-metal Cortex-M без активного MPU адреса `0x00000000` відображає початок Flash-пам’яті з вектором MSP, тому читання за адресою `NULL` не викликає апаратного винятку автоматично, але спроба запису або захист нульової сторінки через MPU надійно фіксують збій).
- **Макроси безпечного звільнення:** Оголошення макросу, що гарантує обнулення покажчика:
  ```c
  #define SAFE_FREE(ptr) do { free(ptr); (ptr) = NULL; } while (0)
  ```
- **Відмова від динамічної купи:** У критичних embedded-системах (згідно зі стандартами MISRA C) динамічне виділення пам’яті після етапу ініціалізації забороняється, замінюючись пулами статичних буферів фіксованого розміру (static pool allocators).
