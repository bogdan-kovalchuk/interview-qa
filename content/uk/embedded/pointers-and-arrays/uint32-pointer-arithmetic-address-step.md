## Short answer

`p+1 = 0x2004`.

Pointer arithmetic для `uint32_t*`: крок = `sizeof(uint32_t) = 4` байти. `0x2000 + 1*4 = 0x2004`.

Загальна формула: `p + n` -> адреса = `(uintptr_t)p + n * sizeof(*p)`.

Регістровий bank: якщо `volatile uint32_t *reg = (volatile uint32_t*)0x40020000;` -> `reg+1` -> регістр за адресою `0x40020004`.[^embeddedinterviewlab]

## Detailed explanation

Адресна арифметика покажчиків у мові C є масштабованою (scaled arithmetic), що фундаментально відрізняє її від звичайної цілочисельної арифметики. Стандарт ISO/IEC 9899 (§6.5.6 Additive operators) визначає правила збільшення адреси покажчика при додаванні цілого числа.[^iso-c-n1570]

### Математика адресної арифметики та стандарт ISO C

Згідно з пунктом 8 параграфа 6.5.6 стандарту ISO/IEC 9899, коли до покажчика `p`, який вказує на об’єкт типу `T`, додається ціле число `n`, результуючий покажчик вказує на об’єкт, зміщений на `n` позицій у масиві:[^iso-c-n1570]
- На рівні фізичних байтових адрес це означає, що числове значення адреси збільшується не на `n`, а на `n * sizeof(T)` байтів:
```text
нова_адреса = (uintptr_t)p + n * sizeof(*p)
```
- Для типу `uint32_t` розмір `sizeof(uint32_t)` дорівнює точно 4 байти.
- Якщо вихідна адреса `p` дорівнює `0x2000`, вираз `p + 1` обчислює адресу:
```text
0x2000 + 1 * 4 = 0x2004
```
- Якщо додати `n = 5` (`p + 5`), адреса стане `0x2000 + 5 * 4 = 0x2014` (тобто плюс 20 байтів у шістнадцятковій системі числення).

### Апаратна підтримка в архітектурі ARM (Barrel Shifter)

В архітектурі процесорів ARM (включаючи ядра ARM Cortex-M) масштабована адресна арифметика реалізована безпосередньо на апаратному рівні завдяки вбудованому бочковому зсувачу (barrel shifter):
- Інструкція завантаження `LDR` вміє виконувати зсув індексного регістра «на льоту» в межах одного такту:
```assembly
LDR     r0, [r1, r2, LSL #2]   ; r0 = *(r1 + (r2 << 2))
```
- Тут `r1` містить базову адресу (`0x2000`), а `r2` – логічний індекс елемента. Зсув `LSL #2` множить індекс на 4 (розмір 32-бітного слова), не вимагаючи окремих інструкцій множення.

### Робота з регістрами периферії (MMIO)

У низькорівневому системному коді мікроконтролерів (драйвери периферійних модулів, CMSIS) ця властивість використовується для навігації регістрами керування:[^iso-c-n1570]
- Майже всі конфігураційні регістри периферії STM32 чи NXP (GPIO, UART, SPI, таймери) мають розрядність 32 біти і розташовані в адресному просторі з кроком у 4 байти (`0x00`, `0x04`, `0x08`, `0x0C`, `0x10` тощо).
- Якщо базовий регістр порту GPIO оголошено як:
```c
volatile uint32_t * const gpio_base = (volatile uint32_t *)0x40020000;
```
- Тоді `gpio_base + 0` адресує `MODER` (`0x40020000`), `gpio_base + 1` адресує `OTYPER` (`0x40020004`), `gpio_base + 2` адресує `OSPEEDR` (`0x40020008`), а `gpio_base + 5` адресує `ODR` (`0x40020014`).

### Класична пастка: байтове зміщення проти кроку покажчика

Найпоширеніша помилка інженерів-початківців під час роботи з документацією (Reference Manual):
- У документації на мікроконтролер зміщення регістрів завжди наводяться **в байтах** (наприклад: *Offset: 0x08*).
- Якщо розробник спробує звернутися до регістра за кодом `base + 0x08`, маючи покажчик `uint32_t *base`, адреса буде зміщена на `0x08 * 4 = 0x20` (32 байти), що призведе до запису в абсолютно інший регістр або апаратного збою!
- **Правильне правило розробки:**
  1. Або індексувати за кількістю 32-бітних слів: `base + (0x08 / sizeof(uint32_t))` -> `base + 2`.
  2. Або виконувати арифметику над байтовим покажчиком `uint8_t *` чи `uintptr_t` з наступним приведенням:
     ```c
     *(volatile uint32_t *)((uintptr_t)base + 0x08) = value;
     ```
  3. Або використовувати стандартні структури CMSIS (наприклад, `GPIO_TypeDef`), де взаємне зміщення полів автоматично контролюється компілятором відповідно до типів членів структури.
