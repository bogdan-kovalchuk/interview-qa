## Question code

```c
int arr[]={1,2,3,4,5};
int *p=arr+4;
int *q=arr+1;
printf("%td", p-q);
```

## Short answer

`3`.

Відняття вказівників (`p - q`) повертає тип `ptrdiff_t` – кількість **елементів між ними**, не байт: `(arr+4) - (arr+1) = 3` елементи.

`%td` – формат для `ptrdiff_t`. Результат може бути від’ємним якщо `q > p`.

Фізично: байтова різниця = `3 * sizeof(int) = 12` байт, але pointer subtraction ділить на `sizeof(int)`.[^embeddedinterviewlab]

## Detailed explanation

Операція віднімання покажчиків у мові C призначена для знаходження відстані між двома елементами одного і того ж масиву. Стандарт ISO/IEC 9899 (§6.5.6 Additive operators, paragraph 9) строго формулює правила та семантику цієї операції:[^iso-c-n1570]

> «Коли два покажчики віднімаються, обидва повинні вказувати на елементи одного і того ж масиву або на один елемент за межами масиву (one past the last element). Результатом є різниця індексів цих двох елементів масиву».

### Покроковий розбір обчислення

Розглянемо вираз `p - q` для заданого масиву `int arr[] = {1, 2, 3, 4, 5};`:

1. `arr` – масив із 5 цілих чисел.
2. `p = arr + 4;` – покажчик вказує на п’ятий елемент масиву, тобто `&arr[4]` (значення елемента `5`).
3. `q = arr + 1;` – покажчик вказує на другий елемент масиву, тобто `&arr[1]` (значення елемента `2`).
4. При відніманні `p - q` обчислюється різниця їхніх індексів: `4 - 1 = 3`.
5. Результатом є числове значення `3`, що виводиться у консоль.[^iso-c-n1570]

### Фізична різниця адрес проти логічної відстані

У фізичній пам’яті мікроконтролера адреси покажчиків відрізняються на байтову величину, пропорційну розміру типу:

- Якщо базова адреса `arr` дорівнює `0x2000`, а `sizeof(int) == 4`, то:
  - Адреса `q` (`arr + 1`): `0x2000 + 1 * 4 = 0x2004`.
  - Адреса `p` (`arr + 4`): `0x2000 + 4 * 4 = 0x2010`.
- Фізична різниця адрес у байтах: `0x2010 - 0x2004 = 0x0C` (12 байтів у десятковій системі).
- Мова C автоматично ділить байтову різницю на розмір типу об’єкта: `12 / sizeof(int) = 12 / 4 = 3` елементи.

Якщо поміняти операнди місцями (`q - p`), результат дорівнюватиме `-3`. Операція є спрямованою, саме тому тип результату є знаковим.

### Тип ptrdiff_t та форматний специфікатор %td

Стандарт визначає, що результат віднімання двох покажчиків має спеціальний тип **`ptrdiff_t`**, оголошений у заголовному файлі `<stddef.h>`. Це знаковий цілочисельний тип, розрядність якого відповідає розрядності адресної шини цільової архітектури:
- На 32-бітних процесорах ARM Cortex-M тип `ptrdiff_t` зазвичай є синонімом `int32_t` (4 байти).
- На 64-бітних платформах – `int64_t` (8 байтів).

Специфікатор формату `%td` введений у стандарті C99 спеціально для коректного та переносного виведення змінних типу `ptrdiff_t`. Використання специфікаторів `%d` або `%ld` є потенційно небезпечним, оскільки на 64-бітних системах або деяких архітектурах DSP розмір `ptrdiff_t` не збігається з `int`.

### Машинна реалізація на ARM Cortex-M

На асемблері ARM Thumb-2 компілятор реалізує віднімання покажчиків через інструкцію віднімання та арифметичний зсув вправо:[^iso-c-n1570]

```assembly
; r0 = p (0x2010), r1 = q (0x2004)
SUBS    r0, r0, r1          ; r0 = 0x2010 - 0x2004 = 12 (різниця в байтах)
ASRS    r0, r0, #2          ; Арифметичний зсув вправо на 2 біти (ділення на 4) -> r0 = 3
```

Інструкція `ASRS` (Arithmetic Shift Right) зберігає знак числа, що забезпечує коректність результату навіть для від’ємних значень.

### Невизначена поведінка (Undefined Behavior)

Віднімання покажчиків, які вказують на різні незалежні об’єкти або різні масиви (наприклад, два окремих буфери в RAM), є **undefined behavior** згідно зі стандартом C (§6.5.6 p9). Компілятор оптимізує код, виходячи з припущення, що обидва покажчики належать одному лінійному масиву; порушення цього правила може спричинити некоректну оптимізацію або переповнення діапазону `ptrdiff_t`.[^iso-c-n1570]
