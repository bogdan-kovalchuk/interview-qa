## Short answer

```c
int find_max(const int *arr, size_t n) {
    if (arr == NULL || n == 0) return INT_MIN;
    const int *p = arr;
    const int *end = arr + n;
    int max = *p++;
    while (p != end) {
        if (*p > max) max = *p;
        p++;
    }
    return max;
}
```

Ключові моменти: `const int*` – читання без зміни, `size_t n` – розмір явно, `arr + n` – one-past-the-end як sentinel. `INT_MIN` потребує `<limits.h>`; у real API краще повертати status окремо від значення.[^embeddedinterviewlab]

## Detailed explanation

### Алгоритм обходу масиву за допомогою вказівників

Обхід масиву за допомогою вказівників (*pointer traversal*) базується на прямій адресній арифметиці замість індексації зі зміщенням. Вказівник ініціалізується початком масиву, послідовно інкрементується та порівнюється з вартовим значенням (*sentinel pointer*), яке вказує на адресу відразу за останнім елементом.

Згідно зі стандартом ISO/IEC 9899:201x (C11), пункт 6.5.6 (пункт 8), створення вказівника на один елемент за межами масиву (`arr + n`) є повністю легітимним [^iso-c-n1570]. Такий вказівник заборонено розіменовувати, але його дозволено використовувати в операціях порівняння (`p != end` або `p < end`).

### Ефективність на рівні асемблера ARM Cortex-M

Історично обхід через покажчики вважався ефективнішим за індексацію `arr[i]`, оскільки на простих процесорних архітектурах обчислення `arr[i]` вимагало розрахунку `base + i * sizeof(type)` на кожній ітерації циклу.

Архітектура ARM Thumb-2 підтримує спеціальний режим адресації з поставтоінкрементом (*post-indexed addressing*). Код обходу масиву 32-бітних чисел транслюється компілятором у компактний асемблерний цикл:
```assembly
loop:
    LDR     r3, [r0], #4      @ r3 = *p, після чого r0 (вказівник p) автоматично збільшується на 4
    CMP     r3, r2            @ порівняння поточного значення з поточним максимумом
    IT      GT
    MOVGT   r2, r3            @ оновлення максимуму за потреби
    CMP     r0, r1            @ перевірка досягнення кінця (p == end)
    BNE     loop
```
Завантаження значення елемента та оновлення адреси вказівника виконуються однією апаратною машинною інструкцією `LDR r3, [r0], #4`, що мінімізує кількість тактів у внутрішньому циклі.

### Архітектура надійного API для вбудованих систем

У коді для інтерв’ю часто використовують спрощений варіант, де у разі порожнього масиву повертається `INT_MIN`. Однак у реальних промислових прошивках повернення `INT_MIN` як ознаки помилки є небезпечним антипатерном: якщо масив містить від’ємні числа або складається з єдиного значення `INT_MIN`, викликаючий код не зможе відрізнити валідний максимум від помилки валідації.

Професійний інтерфейс функції повинен чітко розділяти статус виконання та результат обчислень:
```c
#include <stddef.h>
#include <stdbool.h>

bool find_max_secure(const int *arr, size_t n, int *out_max) {
    if (arr == NULL || n == 0 || out_max == NULL) {
        return false; /* Захист від некоректних аргументів */
    }

    const int *p = arr;
    const int *end = arr + n;
    int max = *p++;

    while (p != end) {
        if (*p > max) {
            max = *p;
        }
        p++;
    }

    *out_max = max;
    return true;
}
```

### Практичні правила та рекомендації

* **Константна коректність (`const correctness`)**: масив повинен прийматися як `const int *arr`. Це гарантує, що функція пошуку не зможе випадково пошкодити вміст буфера, а також дозволяє передавати масиви констант, розташовані у Flash-пам’яті (`.rodata`).
* **Типізація розміру**: використання беззнакового типу `size_t` для параметра `n` унеможливлює передачу від’ємних значень розміру та гарантує сумісність із максимально можливим об’ємом об’єкта в пам’яті.
* **Вимоги MISRA C**: правило MISRA C:2012 Rule 18.4 обмежує використання вказівникової арифметики там, де індексація є наочнішою. Проте патерн обходу від `arr` до `arr + n` є стандартним для ітераторів (зокрема при взаємодії з алгоритмами C++ `std::max_element`).
