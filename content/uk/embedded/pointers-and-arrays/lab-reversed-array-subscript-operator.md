## Question code

```c
int arr[]={5,10,15};
printf("%d", 2[arr]);
```

## Short answer

`15`.

Вираз `2[arr]` за стандартом еквівалентний `*(2 + arr)` – що ідентично `arr[2]`. Оператор індексації `[]` симетричний через комутативність додавання: `arr[2] == *(arr + 2) == *(2 + arr) == 2[arr]`.

Усі чотири форми генерують тотожний машинний код. Запис `2[arr]` є валідним у C, але погіршує читабельність коду; на співбесідах перевіряє розуміння адресної арифметики.[^embeddedinterviewlab]

## Detailed explanation

### Стандартне визначення оператора індексації у мові C

Вираз `2[arr]` виводить число **15** (значення третього елемента масиву). Хоча такий синтаксис виглядає як друкарська одруківка чи помилка, він є повністю валідним у стандарті C завдяки математичному визначенню оператора індексації.

Згідно зі стандартом ISO/IEC 9899:201x (C11), пункт 6.5.2.1 (Array subscripting, p2), постфіксний вираз, за яким слідує вираз у квадратних дужках `[]`, визначається через еквівалентність розіменування та додавання [^iso-c-n1570]:
```c
E1[E2] == (*((E1) + (E2)))
```

Один із виразів обов’язково повинен бути вказівником на повний тип об’єкта, а інший – цілочисельним виразом. Оскільки операція математичного додавання адреси та цілого зміщення є **комутативною** (`E1 + E2 == E2 + E1`), стандарт мови не вимагає, щоб саме ім’я масиву передувало квадратним дужкам [^iso-c-n1570]:
```c
arr[2]  ==  *(arr + 2)  ==  *(2 + arr)  ==  2[arr]
```

У виразі `2[arr]` число `2` виступає першим доданком, а ім’я масиву `arr` неявно приводиться (відбувається *array decay*) до покажчика на свій перший елемент `&arr[0]`.

### Генерація коду на рівні асемблера ARM Cortex-M

Компілятор (GCC або Clang) ще на етапі побудови абстрактного синтаксичного дерева (AST) транслює як `arr[2]`, так і `2[arr]` у спільну проміжну форму розіменування адреси зі зміщенням.

Для 32-бітної архітектури ARM Cortex-M локальний масив `int arr[] = {5, 10, 15};` розташовується у стеку. Елемент із індексом 2 зберігається за адресою `SP + 2 * sizeof(int) = SP + 8`.
Асемблерний код для обох варіантів є абсолютно тотожним:
```assembly
LDR     r1, [sp, #8]      @ завантажує значення arr[2] (15) у регістр r1
```
Жодної різниці у швидкодії, розмірі двійкового коду або споживанні пам’яті між `arr[2]` та `2[arr]` не існує.

### Принципова відмінність у C++

Незважаючи на повну сумісність для вбудованих масивів у C та C++, у мові C++ виникає суттєва відмінність, якщо замість звичайного масиву застосовано клас-контейнер (наприклад, `std::vector<int>` або `std::array<int, 3>`):
```cpp
std::vector<int> v = {5, 10, 15};
int a = v[2];  // Коректно: викликається перевантажений метод v.operator[](2)
int b = 2[v];  // ПОМИЛКА КОМПІЛЯЦІЇ: оператор [] у C++ не може бути зовнішньою функцією
```
У C++ перевантажений `operator[]` може бути оголошений виключно як нестатичний метод класу. Тому синтаксис `2[v]` для об’єктів класів призведе до помилки компіляції.

### Практичне значення у розробці вбудованих систем

* **Чому це неприпустимо у реальних проєктах**: синтаксис `2[arr]` серйозно погіршує читабельність коду, ускладнює супровід прошивки та відхиляється під час код-рев’ю.
* **Вимоги стандартів якості**: подібні конструкції суперечать духу правил MISRA C та загальним рекомендаціям безпечного програмування CERT C.
* **Призначення запитання на співбесідах**: це класичне питання технічних інтерв’ю. Його мета – перевірити, чи розуміє інженер зв’язок між масивами та покажчиковою арифметикою у C, а також той факт, що квадратні дужки є лише синтаксичним цукром для операцій розіменування та додавання.
