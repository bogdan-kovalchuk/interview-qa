## Short answer

Для статично розмірного масиву потрібно вказати **розмір внутрішнього виміру**: `void f(int arr[][4], int rows) { arr[2][3] = 99; }` або еквівалентно: `void f(int (*arr)[4], int rows) { ... }`

Без розміру компілятор не знає крок рядка (stride). `arr[i][j]` -> `*(*(arr+i)+j)` -> в пам’яті: `arr + i*4*sizeof(int) + j*sizeof(int)`.

Для динамічного: передавай як `int *` і обчислюй offset вручну.[^embeddedinterviewlab]

## Detailed explanation

Передача багатовимірних масивів у функції мови C базується на правилі занепаду типів (array-to-pointer decay) та математиці адресної індексації. Стандарт ISO/IEC 9899 (§6.3.2.1 Lvalues, arrays, and function designators, §6.7.6.3 Function declarators) визначає, що вираз типу «масив типів T» перетворюється на покажчик на T.[^iso-c-n1570]

### Чому внутрішній вимір (Inner Dimension) є обов’язковим

Для двовимірного масиву `int matrix[ROWS][COLS]` тип усього масиву є масивом рядків, де кожен рядок має тип `int[COLS]`. При передачі масиву як аргументу функції він занепадає у покажчик на свій перший рядок: `int matrix[3][4]` занепадає до `int (*)[4]` (покажчик на масив із 4 цілих чисел).

Компілятору для адресації елемента `matrix[i][j]` необхідно знати точний крок рядка (stride у байтах), щоб обчислити фізичну адресу:[^iso-c-n1570]

`адреса arr[i][j] = базова адреса + (i * COLS + j) * sizeof(int)`

Якщо внутрішній розмір `COLS` не вказано (наприклад, помилковий запис `void func(int arr[][])`), компілятор не може визначити множник для індексу рядка `i` під час компіляції і видає помилку синтаксису (incomplete type). Зовнішній же вимір `ROWS` для адресації абсолютно не потрібен, тому його опускають.

### Синтаксичні способи передачі масиву

1. **Фіксований внутрішній розмір (класичний C89/C99):**
   ```c
   // Варіант А: синтаксис масиву
   void process_fixed(int arr[][4], size_t rows) {
       arr[2][3] = 99;
   }

   // Варіант Б: повністю еквівалентний синтаксис покажчика на масив
   void process_fixed_ptr(int (*arr)[4], size_t rows) {
       arr[2][3] = 99;
   }
   ```
   Обидва варіанти генерують абсолютно ідентичний машинний код.

2. **Змінні розмірності (VLA – Variable Length Array, стандарт C99):**
   ```c
   void process_vla(size_t rows, size_t cols, int arr[rows][cols]) {
       arr[2][3] = 99;
   }
   ```
   У цьому випадку параметр `cols` передається раніше за сам масив, і компілятор генерує інструкцію множення в runtime для обчислення зміщення. Зверніть увагу: у стандарті C11 підтримка VLA стала опціональною, а в критичних embedded-системах (MISRA C) VLA заборонені через непередбачуваність навантаження на стек.

3. **Один плоский покажчик (Flat Buffer) з ручною індексацією:**
   ```c
   void process_flat(int *arr, size_t cols) {
       arr[2 * cols + 3] = 99;
   }
   ```
   Це найбільш поширений та портабельний ідіоматичний підхід у прошивках мікроконтролерів (наприклад, для буферів дисплеїв TFT/OLED, матриць датчиків або звукових семплів).

### Адресація на рівні асемблера ARM Cortex-M

Коли розмірності відомі на етапі компіляції (`arr[][4]`), компілятор обчислює зміщення елемента `[2][3]` константно:[^iso-c-n1570]

`зсув = (2 * 4 + 3) * sizeof(int) = 11 * 4 = 44 байти (0x2C)`

На асемблері ARM Thumb-2 запис значення `99` транслюється лише у дві інструкції:

```assembly
MOVS    r1, #99         ; Завантаження значення 99 у регістр r1
STR     r1, [r0, #44]   ; Запис значення за адресою (базова адреса в r0 + 44 байти)
```

Завдяки фіксованому внутрішньому виміру процесор не виконує жодних операцій множення або додавання під час виконання програми.

### Поширена пастка: спроба передати як int **

Часто розробники-початківці намагаються оголосити функцію як `void func(int **arr)`. Це призводить до фатальної помилки:
- `int **` – це покажчик на покажчик (масив покажчиків, кожен з яких веде на окремий виділений у купі рядок).
- Двовимірний масив `int arr[3][4]` – це неперервний суцільний монолітний блок пам’яті з 48 байтів.

Спроба звернення `arr[2][3]` через покажчик `int **` призведе до того, що числове значення перших елементів масиву буде прочитано як адреса пам’яті, а подальше її розіменування негайно викличе виняток `HardFault` на мікроконтролері.[^iso-c-n1570]
