## Short answer

**One-past-the-end pointer** – вказівник на елемент одразу після останнього у масиві: `arr + N` для масиву з N елементів.

За стандартом C: формувати **дозволено**, але <span class="warn">розіменовувати – UB</span>.

Використання: стандартний ідіом кінця: `int *end = arr + N; for(int *p=arr; p!=end; p++)`.

Вказівники далі (arr+N+1 і т.д.) – UB вже при формуванні. Тому: <span class="warn">тільки один елемент "після кінця"</span>.[^embeddedinterviewlab]

## Detailed explanation

### Формальне визначення у стандарті ISO C

У стандарті мови C (ISO/IEC 9899 §6.5.6 p8) поняття **one-past-the-end pointer** означає вказівник, значення якого вказує на уявний елемент, розташований безпосередньо за останнім дійсним елементом масиву.[^iso-c-n1570]

Якщо оголошено масив `T arr[N]`, дійсними елементами є `arr[0]` ... `arr[N-1]`. Вираз `arr + N` або еквівалентний йому `&arr[N]` формує покажчик на елемент з індексом `N`. Стандарт гарантує, що обчислення такого покажчика є цілком легальним і безпечним, доки він не виходить за межі діапазону від першого елемента до одного елемента за кінцем масиву включно.

### Дозволені та заборонені операції з past-the-end покажчиком

Стандарт суворо розмежовує допустимі операції над граничним покажчиком:[^iso-c-n1570]
- **Дозволено:**
  - Обчислення адреси: `int *end = arr + N;` або `&arr[N]`.
  - Порівняння покажчиків: `p != end`, `p < end`, `p == end` (дозволяються реляційні оператори між покажчиками на один і той самий масив або його past-the-end позицію).
  - Віднімання покажчиків: вираз `end - arr` повертає значення типу `ptrdiff_t`, що точно дорівнює кількості елементів `N`.
  - Віднімання цілого числа: `end - 1` повертає коректний покажчик на останній елемент масиву `&arr[N-1]`.
- **Заборонено (Undefined Behavior):**
  - Розіменування: спроба читання чи запису через `*end` або `end[0]` є прямою невизначеною поведінкою, оскільки за цією адресою не існує об’єкта типу `T` даного масиву.
  - Арифметика за межі допустимого діапазону: обчислення `arr + N + 1` або `arr - 1` породжує `undefined behavior` **в момент самого обчислення**, навіть якщо цей покажчик ніколи не буде розіменований.

### Чому стандарт вимагає підтримки one-past-the-end

Ця гарантія введена для реалізації канонічної ідіоми напіввідкритих інтервалів `[begin, end)`:[^iso-c-n1570]
```c
int *end = arr + N;
for (int *p = arr; p != end; ++p) {
    process_sample(*p);
}
```
У такій конструкції лічильник `p` досягає значення `end` на фінальній ітерації. Якби стандарт вважав обчислення `end` помилкою, організація подібних циклів без лічильників індексів була б неможливою.

У мові C++ концепція one-past-the-end стала фундаментом для бібліотеки STL та ітераторів: методи `std::vector::end()`, вільні функції `std::end(arr)` повертають саме past-the-end ітератор, позначаючи кінець діапазону послідовності.[^iso-cpp-n4861]

### Специфіка у вбудованих системах: переповнення адресного простору

У мікроконтролерах із суцільним 32-бітним адресним простором існує рідкісна, але критична апаратна пастка:[^iso-c-n1570]
- Якщо буфер розміщений компонувальником (через linker script) на самому кінці адресного простору пам’яті (наприклад, закінчується за адресою `0xFFFFFFFF`), спроба обчислити покажчик `arr + N` призведе до цілочисельного переповнення адреси та згортання в `0x00000000`.
- Переповнення адреси при арифметиці покажчиків у C є невизначеною поведінкою. Крім того, умова циклу `p < end` перетвориться на `p < 0`, що призведе до нескінченного циклу або збою перевірки.
- Тому в якісних скриптах компонувальника вбудованих систем завжди резервують захисний проміжок у верхній межі адресного простору.
