## Question code

```c
char *p = malloc(5);
strcpy(p, "hello");
p[5] = '\0';
```

## Short answer

<span class="warn">Buffer overflow.</span> `malloc(5)` – 5 байт, а `"hello"` = `{'h','e','l','l','o','\0'}` – 6 байт включно з null-terminator.

`strcpy(p, "hello")` вже переповнює буфер (6 байт у 5-байтний), і `p[5] = '\0'` – шостий запис за межами.

Правильно: `malloc(strlen("hello") + 1)` = `malloc(6)`, або `strncpy(p, "hello", 5); p[4]='\0';` – обрізати якщо треба.[^embeddedinterviewlab]

## Detailed explanation

### Суть проблеми та стандарт ISO C

У наведеному прикладі допущено грубу помилку переповнення буфера (`buffer overflow`), пов’язану з фундаментальною властивістю C-рядків.

Згідно зі стандартом ISO C (ISO/IEC 9899:2011, §7.1.1), рядок у мові C є послідовністю символів, яка обов’язково завершується нульовим байтом-термінатором (`null-terminated byte string`, символ `'\0'` з кодом `0`)[^iso-c-n1570].
Рядковий літерал `"hello"` складається з 5 буквених символів (`'h'`, `'e'`, `'l'`, `'l'`, `'o'`) та 1 неявного завершального нульового символа `'\0'`. Його фактичний розмір у пам’яті (у секції `.rodata`) становить 6 байтів:
```c
sizeof("hello") == 6; // 'h', 'e', 'l', 'l', 'o', '\0'
strlen("hello") == 5; // кількість символів ДО завершального нуля
```

Виклик `malloc(5)` виділяє динамічний блок ємністю рівно 5 байтів (індекси від `p[0]` до `p[4]`).
Функція `strcpy(p, "hello")` копіює всі байти рядка-джерела включно з термінатором (ISO C11, §7.24.2.3)[^iso-c-n1570]. Вона записує 6 байтів у буфер розміром 5 байтів.
Отже:
1. Виклик `strcpy` вже призводить до виходу за межі виділеної пам’яті (`out-of-bounds write`) та невизначеної поведінки (`undefined behavior`)[^iso-c-n1570].
2. Наступний рядок `p[5] = '\0'` є другим записом за межами буфера: елемент з індексом 5 є шостим елементом (адже індексація починається з 0), тобто знаходиться за межами 5-байтового масиву.

### Механізм руйнування купи (Heap Corruption)

В embedded-системах на базі RTOS (FreeRTOS `heap_4.c`, newlib `malloc` або dlmalloc) динамічна купа організована у вигляді зв’язаних блоків пам’яті. Безпосередньо перед кожним блоком даних або одразу за ним аллокатор зберігає службові метадані:
- Розмір виділеного блоку;
- Ознаку зайнятості / звільнення (`allocated flag`);
- Вказівники на попередній та наступний вільний блок (`prev`, `next`).

Запис шостого байта `p[5]` перезаписує перший байт службового заголовка наступного блоку купи.
У мікроконтролерах аварійне завершення (`HardFault`) рідко трапляється безпосередньо в момент виконання `strcpy`. Натомість система зазнає «тихого пошкодження» (`heap corruption`):
- Коли програма викликає наступний `malloc()` або `free()`, менеджер купи намагається розіменувати пошкоджений вказівник або прочитати спотворений розмір блоку.
- Це викликає розіменування невалідного вказівника і генерує `HardFault` чи блокування системи в середині бібліотеки `malloc`[^armv7m-arm]. Діагностувати такий збій украй важко, оскільки місце падіння не має нічого спільного з місцем виникнення помилки.

### Практичні правила безпеки для embedded-систем

1. **Формула виділення пам’яті під рядки:**
   Завжди виділяйте пам’ять за правилом `strlen(src) + 1`:
   ```c
   const char *src = "hello";
   char *p = malloc(strlen(src) + 1);
   if (p != NULL) {
       strcpy(p, src);
   }
   ```

2. **Захисні функції з контролем розміру:**
   - Категорично відмовтеся від використання `strcpy` та `strcat` у промисловому коді.
   - Використовуйте `snprintf`:
     ```c
     snprintf(p, buf_size, "%s", src); // гарантує запис не більше buf_size байтів і додає '\0'
     ```
   - За наявності використовуйте `strlcpy(p, "hello", buf_size)`. При використанні класичної `strncpy` пам’ятайте, що вона не додає `'\0'`, якщо рядок не вмістився.

3. **Статичне виділення пам’яті (Static Allocation):**
   У відповідальних вбудованих пристроях (стандарт MISRA C:2012, правило 21.3) динамічне виділення пам’яті після етапу ініціалізації заборонене для усунення ризиків фрагментації та пошкодження купи. Замість динамічного виділення використовують статичні буфери достатнього фіксованого розміру:
   ```c
   #define GREETING_BUF_SIZE 16
   static char greeting[GREETING_BUF_SIZE];
   ```
