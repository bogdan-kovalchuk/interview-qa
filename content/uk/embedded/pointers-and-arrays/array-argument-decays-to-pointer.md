## Short answer

При передачі масиву у функцію він **автоматично перетворюється** на вказівник на перший елемент (decay).

`int arr[8];` `f(arr)` -> `f(int *)` – функція отримує вказівник.

Наслідки:
- `sizeof(arr)` всередині функції = `sizeof(int*)`, не 32;
- Нема copy – функція отримує доступ до оригінального масиву;
- Нема range checking.

Рішення: `f(int arr[], size_t n)` або у C++: `template<size_t N> f(int (&arr)[N])`.[^embeddedinterviewlab]

## Detailed explanation

При передачі масиву у функцію в мовах C та C++ спрацьовує фундаментальне правило мови: масив ніколи не передається за значенням (by value). Замість цього відбувається автоматичне перетворення типу, відоме як **pointer decay** (розпад масиву у вказівник).[^iso-c-n1570]

### Механізм стандарту: коригування параметрів-масивів

Згідно зі стандартом ISO/IEC 9899 (§6.7.6.3 p7), будь-яке оголошення параметра функції, що має тип «масив `T`» (з фіксованим розміром або без нього), компілятор автоматично перетворює («коригує», adjusts) на тип «вказівник на `T`» (`T *`):[^iso-c-n1570]

```c
void process(int arr[8]); // компілятор переписує це як: void process(int *arr);
void process(int arr[]);  // компілятор переписує це як: void process(int *arr);
```

- Число `8` у квадратних дужках прототипу є суто синтаксичною ілюзією для програміста: компілятор його повністю ігнорує і не здійснює жодної перевірки довжини масиву під час виклику функції.
- У точку виклику передається лише адреса першого елемента масиву (значення покажчика).

### Чому C не копіює масиви за значенням

Історично в мові C масиви не є об’єктами першого класу (first-class objects):[^iso-c-n1570]
- Їх не можна безпосередньо присвоїти (`arr1 = arr2` є помилкою) або повернути з функції як результат виклику.
- Таке рішення було прийнято творцями мови для забезпечення високої продуктивності на комп’ютерах з обмеженими ресурсами (PDP-11): копіювання буферів на стек при кожному виклику переповнило б пам’ять мікроконтролера та призвело б до значних затримок процесора.
- Єдиний спосіб передати масив за значенням у C – це обгорнути його в структуру (`struct Buffer { int data[8]; };`), оскільки структури копіюються побайтово.

### Критичні наслідки decay для безпеки прошивки

Перетворення масиву на вказівник породжує типові проблеми надійності:[^iso-c-n1570]

1. **Стирання інформації про розмір (Size Erasure):**
   - Оператор `sizeof(arr)` всередині викликаної функції повертає не розмір виділеного буфера (наприклад, 32 байти), а розмір самого покажчика (`sizeof(int *)`, що дорівнює 4 байтам на 32-бітному ARM Cortex-M).
   - Найнебезпечніший антипатерн в embedded-коді:
     ```c
     void clear_buffer(uint8_t buf[64]) {
         memset(buf, 0, sizeof(buf)); // ПОМИЛКА: очистить лише 4 байти замість 64!
     }
     ```
2. **Відсутність контролю меж (No Bounds Checking):**
   - Оскільки викликана функція отримує лише «голу» адресу, вона не знає реальної довжини масиву. Звернення за індексами `arr[i]` без явної перевірки лімітів легко призводить до виходу за межі буфера (buffer overflow) та пошкодження сусідніх змінних у RAM.

### Інженерні ідіоми вирішення проблеми

В інженерній практиці embedded-розробки для безпечної роботи з буферами застосовують такі підходи:[^iso-c-n1570] [^iso-cpp-n4861]

- **Явна передача довжини:** канонічний підхід у C – передавати розмір буфера другим аргументом: `void process(int *arr, size_t size);`.
- **Дескриптори буферів:** структури, що об’єднують покажчик на дані та їхній розмір:
  ```c
  typedef struct {
      uint8_t *data;
      size_t len;
  } slice_t;
  ```
- **Специфікатор `static` у C99:** запис `void process(int arr[static 8])` повідомляє компілятору, що вказівник не може бути `NULL` і гарантовано містить щонайменше 8 елементів.[^iso-c-n1570]
- **Посилання на масив у C++:** використання шаблонів із посиланням на фіксований масив повністю запобігає pointer decay і автоматично виводить розмір на етапі компіляції:
  ```cpp
  template <size_t N>
  void process(int (&arr)[N]) {
      // sizeof(arr) повертає N * sizeof(int)
  }
  ```
- **Сучасні типи C++:** використання `std::span` (C++20) або `std::array`, які поєднують безпеку розміру та відсутність динамічного виділення пам’яті.[^iso-cpp-n4861]
