## Question code

```c
int arr[5];
int *p=arr+3;
int *q=arr+1;
printf("%td", p-q);
```

## Short answer

Виведе `2` (перевірка розуміння pointer subtraction).

Справжня пастка: очікують <span class="warn">байтову різницю</span> (8 байтів), але вираз `p - q` повертає **кількість елементів** типу `ptrdiff_t` (`3 - 1 = 2`).

Для отримання байтової різниці (`2 * sizeof(int) = 8`) вказівники явно приводять: `(char*)p - (char*)q` або `(uintptr_t)p - (uintptr_t)q`.[^embeddedinterviewlab]

## Detailed explanation

### Стандартна семантика операції віднімання вказівників

Згідно зі стандартом ISO/IEC 9899 (§6.5.6p9), коли два вказівники, що вказують на елементи одного й того самого масиву (або на елемент одразу за межею масиву `one-past-the-end`), віднімаються один від одного, результатом операції є **різниця їхніх індексів (subscripts)**, тобто кількість елементів масиву між ними, а не різниця фізичних адрес у байтах.[^iso-c-n1570]

У наведеному фрагменті коду:
- `p` вказує на `arr[3]`;
- `q` вказує на `arr[1]`;
- результат виразу `p - q` дорівнює точно 3 - 1 = 2.

Результат має знаковий цілочисельний тип `ptrdiff_t` (визначений у заголовному файлі `<stddef.h>`). Для виведення значень типу `ptrdiff_t` функція `printf` стандарту C99/C11 вимагає специфікатора формату `%td` (§7.21.6.1).[^iso-c-n1570]

### Як віднімання вказівників транслюється на рівень процесора

На апаратному рівні мікропроцесора (наприклад, ARM Cortex-M) адреси завжди є побайтовими:[^embeddedinterviewlab]
- Нехай базовий елемент `arr[0]` розташований за адресою `0x20000000`.
- Оскільки `sizeof(int) == 4`, вказівник `q` (`arr + 1`) зберігає адресу `0x20000004`.
- Вказівник `p` (`arr + 3`) зберігає адресу `0x2000000C`.
- Фізична байтова різниця становить `0x2000000C - 0x20000004 = 8` байтів.

Кількість елементів обчислюється як ділення різниці фізичних адрес на розмір базового типу: `(addr(p) - addr(q)) / sizeof(*p) = 8 / 4 = 2`.

В асемблері ARM Thumb-2 для типів, розмір яких є степенем двійки (2^n), операція ділення замінюється швидким арифметичним зсувом праворуч (`ASRS`):
```assembly
SUBS    r0, r0, r1       @ r0 = адреса p - адреса q (байтова різниця = 8)
ASRS    r0, r0, #2       @ r0 = r0 >> 2 (ділення на 4, результат = 2)
```
Якщо ж розмір елемента не є степенем двійки (наприклад, структура розміром 12 байтів), компілятор виконує ділення через множення на константне число (інверсію за модулем), уникаючи важкої апаратної інструкції ділення `SDIV`.

### Невизначена поведінка (Undefined Behavior) при відніманні

Стандарт чітко формулює обмеження: якщо два вказівники **не вказують на елементи одного й того самого об’єкта чи масиву**, їхнє віднімання є **`undefined behavior`** (ISO/IEC 9899 §6.5.6p9).[^iso-c-n1570] Спроба відняти адреси двох незалежних змінних або буферів у різних секціях пам’яті не гарантує жодного змістовного результату, і компілятор має право вважати таку ситуацію неможливою під час глобальної оптимізації.

### Практичні інженерні випадки: коли потрібні байти

У низькорівневих драйверах (наприклад, конфігурація регістрів довжини транзакції DMA, розмір прийнятого пакета з кільцевого буфера або перевірка залишку вільного пулу пам’яті) розробнику часто потрібна саме фізична байтова довжина. Для цього необхідно явно привести вказівники до байтового типу або цілого числа:[^iso-c-n1570]
```c
size_t byte_diff = (const char *)p - (const char *)q;
/* або через приведення до uintptr_t: */
uintptr_t bytes = (uintptr_t)p - (uintptr_t)q;
```
