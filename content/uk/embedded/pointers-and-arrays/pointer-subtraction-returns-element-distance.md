## Short answer

Відняття двох вказівників одного типу повертає **ptrdiff_t** – кількість елементів між ними (не байт).

`int *p = arr+4; int *q = arr+1; p - q = 3` (три `int`-елементи).

Умова: обидва вказівники мають вказувати на **один масив** (або one-past-the-end). Відняття вказівників що вказують на різні масиви/об’єкти -> <span class="warn">undefined behavior (UB)</span>.

Застосування: `strlen`-подібний підрахунок, offset між елементами буфера.[^embeddedinterviewlab]

## Detailed explanation

Віднімання покажчиків (оператор `-`) є однією з фундаментальних операцій адресної арифметики у мові C, яка регламентується стандартом ISO/IEC 9899 (§6.5.6 Additive operators).[^iso-c-n1570]

### Стандарт мови C та тип ptrdiff_t

Коли два вказівники однакового типу віднімаються один від одного (`p - q`), результатом операції є не різниця їхніх байтових адрес, а **кількість елементів**, розташованих між ними.[^iso-c-n1570]

Математично це виражається співвідношенням:
```text
distance = ((intptr_t)p - (intptr_t)q) / (ptrdiff_t)sizeof(*p)
```

Типом результату є знаковий цілочисельний тип `ptrdiff_t`, визначений у заголовному файлі `<stddef.h>`. Знаковість необхідна тому, що якщо `p` передує `q` у пам’яті, результат буде від’ємним. На типових 32-бітних вбудованих платформах (наприклад, ARM Cortex-M) `ptrdiff_t` зазвичай є псевдонімом для `int32_t` (`int`).[^iso-c-n1570]

### Обчислення на рівні процесора та асемблера ARM Cortex-M

На рівні машинного коду архітектури ARM Cortex-M компілятор виконує дві послідовні дії:
1. Віднімає числові значення адрес за допомогою інструкції `SUBS`.
2. Ділить отриману різницю на розмір елемента `sizeof(*p)`.

Якщо розмір елемента є ступенем двійки (наприклад, для `uint32_t` або `int` розмір становить 4 байти), компілятор оптимізує ділення в операцію арифметичного зсуву вправо на 2 біти (`ASRS`):

```assembly
SUBS    r0, r0, r1     ; r0 = адреса_p - адреса_q (байтова різниця)
ASRS    r0, r0, #2     ; r0 = r0 / 4 (знаковий зсув для int)
```

Для типів, розмір яких не є ступенем двійки (наприклад, структура розміром 12 байтів), компілятор застосовує апаратне ділення (`SDIV` на Cortex-M3/M4/M7) або викликає бібліотечну підпрограму ділення (наприклад, `__aeabi_idiv` на Cortex-M0, де апаратне ділення відсутнє).[^iso-c-n1570]

### Обмеження стандарту та undefined behavior

Стандарт C встановлює дуже жорсткі вимоги до операндів при відніманні покажчиків:[^iso-c-n1570]

1. **Приналежність до одного об’єкта або масиву:** обидва вказівники мають вказувати на елементи того самого масивного об’єкта або на умовний елемент одразу за ним (one-past-the-end). Якщо вказівники адресують два різні незалежні масиви, змінні на стеку або виділені блоки динамічної пам’яті, вираз викликає `undefined behavior`.[^iso-c-n1570]
2. **Сегментація та оптимізації:** компілятор має право вважати, що між вказівниками немає переповнення адресного простору. На оптимізаціях `-O2` або `-O3` компілятор може видалити перевірки діапазонів, якщо розробник порівнює чи віднімає покажчики на різні структури.
3. **Неповні типи:** не можна віднімати вказівники типу `void *` у стандартному C, оскільки тип `void` є неповним і не має розміру (деякі компілятори, як-от GCC, дозволяють це як нестандартне розширення, вважаючи `sizeof(void) == 1`).[^iso-c-n1570]

### Типові пастки у розробці вбудованих систем

- **Очікування байтового розміру:** поширена помилка – обчислення розміру буфера як `size = ptr_end - ptr_start` для передачі у функцію `memcpy`. Якщо вказівники мають тип `uint32_t *`, значення `size` буде в 4 рази меншим за реальну кількість байтів. Для підрахунку байтів покажчики слід явно привести до `const uint8_t *` або `const char *`.
- **Кільцеві буфери:** віднімання покажчика голови від покажчика хвоста коректне лише доти, доки вони знаходяться всередині одного базового масиву. Якщо кільцевий буфер перетинає межу масиву через покажчик, це веде до помилкових розрахунків і порушення вимог стандарту.
