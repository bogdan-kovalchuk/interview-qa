## Short answer

Порівняння `==` та `!=` – завжди **визначено** між будь-якими двома вказівниками одного типу.

Порівняння `<`, `>`, `<=`, `>=` – **визначено лише** якщо обидва вказівники вказують на **один і той самий масив** (або структуру). Порівняння вказівників різних об’єктів -> <span class="warn">undefined behavior (UB) за стандартом</span>.

Практика: більшість платформ дають коректну відповідь навіть для різних об’єктів, але не покладайся на це у portable коді.[^embeddedinterviewlab]

## Detailed explanation

### Вимоги стандарту ISO C: коли реляційне порівняння визначене

У мові C операції порівняння покажчиків розділені на дві принципово різні категорії: перевірка на рівність (`==`, `!=`) та реляційні оператори відношення (`<`, `<=`, `>`, `>=`):

1. **Оператори рівності (`==`, `!=`):** завжди строго визначені для будь-яких двох покажчиків сумісних типів (або при порівнянні з нульовим покажчиком чи `void*`). Вони просто перевіряють, чи вказують обидва покажчики на одну й ту саму адресу пам’яті, чи обидва є `NULL`.[^iso-c-n1570]
2. **Реляційні оператори (`<`, `<=`, `>`, `>=`):** згідно зі стандартом ISO/IEC 9899 (пункт §6.5.8), відношення порядку є визначеною поведінкою **лише** в чітко обмежених випадках:
   - Обидва покажчики вказують на елементи одного й того самого масиву (або на один елемент за його кінцем – past-the-end element). Покажчик на елемент із більшим індексом вважається більшим за покажчик на елемент із меншим індексом.
   - Обидва покажчики вказують на поля однієї й тієї самої структури (`struct`). Поле, оголошене у структурі пізніше, розташовується за вищою адресою, ніж поле, оголошене раніше.

Якщо покажчики посилаються на два абсолютно різні незалежні об’єкти (наприклад, окремі змінні `int a, b;`, елементи двох різних масивів або два блоки з різних викликів `malloc`), результат реляційного порівняння `p1 < p2` є **невизначеною поведінкою (undefined behavior)**.[^iso-c-n1570]

### Чому порівняння різних об’єктів є undefined behavior

Таке обмеження в стандарті C має дві основні причини:

- **Історична (сегментна архітектура пам’яті):** у процесорах із сегментною організацією (наприклад, x86 у реальному режимі 16-біт або деяких DSP) покажчики складаються з пари `сегмент:зміщення`. Два об’єкти можуть знаходитися в різних сегментах пам’яті, де лінійне порівняння зміщень без нормалізації сегментних регістрів фізично позбавлене математичного змісту.
- **Оптимізації сучасних компіляторів:** компілятор C оптимізує код на основі припущення, що програма повністю відповідає стандарту. Якщо оптимізатор GCC чи Clang бачить вираз `if (ptr1 < ptr2)`, він передбачає, що `ptr1` та `ptr2` обов’язково належать до одного масиву. Аналізатор діапазонів (value range analysis) на базі цього припущення може видалити цілі гілки коду, вважаючи неможливими певні комбінації значень, або перевпорядкувати доступ до пам’яті.

### Плоска пам’ять мікроконтролерів, оптимізації та безпечне використання uintptr_t

У сучасних 32-розрядних мікроконтролерах на базі архітектури ARM Cortex-M адреси утворюють єдиний лінійний плоский простір пам’яті від `0x00000000` до `0xFFFFFFFF`. На машинному рівні асемблерна інструкція `CMP R0, R1` із наступним переходом за беззнаковим прапорцем (`BHI` / `BLS`) завжди порівнює числові значення адрес.

Проте написання коду на C із прямим порівнянням адрес різних об’єктів створює приховану загрозу, особливо при підвищенні рівня оптимізації до `-O2` або `-O3`. Це також порушує промисловий стандарт безпеки MISRA C:2012 (правило Rule 18.3 прямо забороняє застосування `>`, `>=`, `<`, `<=` до покажчиків, які не посилаються на один масив).

Якщо в низькорівневому коді прошивки критично необхідно перевірити взаємне розташування буферів – наприклад, для перевірки перекриття областей пам’яті (buffer overlap) у DMA, перевірки потрапляння адреси у Flash-сектор чи валідації меж стека:
```c
#include <stdint.h>

/* Безпечний підхід: приведення до цілочисельного типу адреси uintptr_t */
if ((uintptr_t)buffer_a < (uintptr_t)buffer_b) {
    /* Тут виконується звичайне беззнакове цілочисельне порівняння */
}
```
Приведення покажчиків до цілочисельного типу `uintptr_t` (визначеного в `<stdint.h>`) гарантує коректне числове порівняння фізичних адрес без ризику undefined behavior та небажаних оптимізацій компілятора.
