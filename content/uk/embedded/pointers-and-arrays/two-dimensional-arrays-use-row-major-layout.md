## Short answer

2D масив у C зберігається у **row-major order**: рядки йдуть один за одним у неперервній пам’яті.

`arr[0][0], arr[0][1], arr[0][2], arr[0][3],` `arr[1][0], arr[1][1], arr[1][2], arr[1][3],` `arr[2][0], arr[2][1], arr[2][2], arr[2][3]`

Всього: 3×4×4 = 48 байт. Формула адреси: `&arr[i][j] = arr + i*4 + j` (у елементах). Оптимальна ітерація: рядок за рядком (cache-friendly).[^embeddedinterviewlab]

## Detailed explanation

Багатовимірні масиви в мові C організовані за принципом «масив масивів» (array of arrays). Відповідно до стандарту ISO/IEC 9899 (§6.2.5 p20 та §6.5.2.1), оголошення `int arr[3][4]` визначає масив із трьох елементів, кожен з яких є одновимірним масивом із чотирьох цілих чисел типу `int` (`arr[0]`, `arr[1]`, `arr[2]`).[^iso-c-n1570]

### Організація пам’яті та порядок розміщення елементів

Усі елементи масиву розташовуються в єдиному суцільному (contiguous) блоці адресної пам’яті без проміжків між рядками. Мова C суворо дотримується порядку **row-major order** (лексикографічний порядок за рядками):[^iso-c-n1570]

1. Спочатку послідовно розташовуються 4 елементи нульового рядка: `arr[0][0]`, `arr[0][1]`, `arr[0][2]`, `arr[0][3]`.
2. Безпосередньо за ними розміщуються елементи першого рядка: `arr[1][0]`, `arr[1][1]`, `arr[1][2]`, `arr[1][3]`.
3. Завершують блок елементи другого рядка: `arr[2][0]`, `arr[2][1]`, `arr[2][2]`, `arr[2][3]`.

На 32-бітній архітектурі (наприклад, ARM Cortex-M), де `sizeof(int) == 4`, масив займає `3 * 4 * 4 = 48` неперервних байтів оперативної пам’яті (SRAM) або Flash.[^iso-c-n1570]

### Лінійна формула адресації та асемблерний доступ

Для доступу до довільного елемента `arr[i][j]` компілятор обчислює його лінійне зміщення від базової адреси масиву за формулою:[^iso-c-n1570]

`Адреса(arr[i][j]) = Базова_адреса + (i * N_cols + j) * sizeof(елемент)`

де `N_cols = 4` (кількість стовпців у масиві).

На рівні асемблера ARM Cortex-M обчислення індексу часто оптимізується компілятором без використання інструкцій множення `MUL`. Оскільки кількість стовпців дорівнює 4 (степінь двійки 2^2), множення індексу рядка `i * 4` замінюється швидким логічним зсувом вліво на 2 біти (`LSL #2`):

```assembly
// Приклад завантаження значення arr[i][j] (i в r0, j в r1, база arr в r4)
ADD     r2, r1, r0, LSL #2    // r2 = j + (i << 2) -> загальний індекс елемента
LDR     r3, [r4, r2, LSL #2]   // r3 = *(arr + r2 * 4) -> завантаження 32-бітного слова
```

### Вплив на продуктивність: кеш та вибірка пам’яті

В embedded-системах на базі продуктивних ядер (ARM Cortex-M7, Cortex-A) порядок обходу багатовимірного масиву безпосередньо впливає на роботу апаратного кешу L1 (D-Cache) та Flash prefetch buffer:[^embeddedinterviewlab]

- **Оптимальний обхід (Cache-friendly):** обхід за рядками (зовнішній цикл за `i`, внутрішній за `j`). У цьому випадку звернення до елементів ідуть послідовно адреса за адресою. Одне читання з пам’яті завантажує цілу лінійку кешу (зазвичай 32 байти = 8 значень `int`), і наступні 7 читань відбуваються миттєво з кешу без звернення до зовнішньої шини.
- **Неоптимальний обхід (Cache-unfriendly):** обхід за стовпцями (зовнішній цикл за `j`, внутрішній за `i`). Кожна наступна ітерація стрибає в пам’яті вперед на `4 * sizeof(int) = 16` байтів. Якщо розмір масиву великий, такий патерн спричиняє постійні промахи кешу (cache misses) та суттєве падіння швидкості обробки даних (наприклад, при фільтрації сигналів або роботі з буферами дисплеїв).

### Передача 2D масивів у функції

Оскільки масив `arr` під час передачі у функцію розпадається (decay) на вказівник на перший рядок, сигнатура функції обов’язково повинна містити інформацію про розмір другого виміру:[^iso-c-n1570]

```c
void process_matrix(int (*matrix)[4], size_t rows);
// або альтернативний еквівалентний запис:
void process_matrix(int matrix[][4], size_t rows);
```

Значення кількості стовпців `4` критично необхідне компілятору для генерації коректного коду обчислення адресного кроку між рядками.[^iso-c-n1570]
