## Short answer

Арифметика вказівників завжди враховує **розмір елемента типу**:

`T *p; p + n` -> фізично: `(char*)p + n * sizeof(T)`

Приклади:
- `uint8_t *p; p+1` -> +1 байт
- `uint16_t *p; p+1` -> +2 байти
- `uint32_t *p; p+1` -> +4 байти

Це дозволяє ітерувати масиви природно: `p++` – наступний елемент, незалежно від розміру. Критично у embedded при роботі з register banks і DMA буферами.[^embeddedinterviewlab]

## Detailed explanation

### Концептуальна основа мови C: еквівалентність масивів та вказівників

У мові C масив – це послідовно розташовані в пам’яті однотипні об’єкти без проміжків між ними (contiguous memory block). Відстань між початками двох сусідніх елементів масиву завжди суворо дорівнює `sizeof(T)`[^iso-c-n1570].

Головний принцип дизайну мови полягає в тому, що програміст повинен оперувати концептуальними елементами даних, а не абстрактними байтовими зсувами. Тому правила адресної арифметики (ISO/IEC 9899 §6.5.6) визначають:
- Додавання цілого числа `n` до вказівника `T *p` зміщує адресу на `n` елементів типу `T`:
  `Фізична_адреса = (uintptr_t)p + n * sizeof(T)`
- Операція індексації масиву `arr[i]` за стандартом є синтаксичним цукром для розіменування зі зсувом: `*((arr) + (i))`. Завдяки автоматичному масштабуванню на `sizeof(T)` вираз `arr[i]` гарантовано потрапляє на початок `i`-го елемента незалежно від типу `T`.
- Віднімання двох вказівників одного типу `p2 - p1` повертає знакову цілу величину типу `ptrdiff_t` (визначену в `<stddef.h>`), яка показує кількість елементів між ними:
  `Кількість_елементів = ((uintptr_t)p2 - (uintptr_t)p1) / sizeof(T)`[^iso-c-n1570].

### Апаратне обґрунтування: RISC-архітектура та ARM Cortex-M

Масштабування за `sizeof(T)` не створює додаткових накладних витрат у машинному коді. Навпаки, системи команд сучасних процесорів архітектури ARM спроєктовані для апаратної підтримки саме такої моделі:
- Розміри базових типів становлять 1, 2, 4 або 8 байтів (степені двійки: 2^0, 2^1, 2^2, 2^3).
- Множення на ступінь двійки в двійковій арифметиці еквівалентне логічному зсуву вліво (`LSL`).
- Барельний зсувач (barrel shifter) процесора ARM Cortex-M виконує зсув регістру безпосередньо в конвеєрі під час виконання інструкції доступу до пам’яті за нуль додаткових тактів[^armv7m-arm]:
  - `LDRH r0, [r1, r2, LSL #1]` – зчитування `uint16_t` з адреси `r1 + (r2 << 1)`;
  - `LDR r0, [r1, r2, LSL #2]` – зчитування `uint32_t` з адреси `r1 + (r2 << 2)`.

### Застосування у вбудованих системах (Embedded)

1. **Регістрові масиви периферії**: у мікроконтролерах однотипні апаратні блоки (наприклад, канали прямого доступу до пам’яті DMA або регістри NVIC) нерідко розташовані в адресному просторі безперервно з фіксованим кроком. Створення покажчика на структуру каналу дозволяє переходити між ними за допомогою адресної арифметики:
   ```c
   typedef struct {
       volatile uint32_t CR;   // Конфігурація потоку DMA
       volatile uint32_t NDTR; // Кількість даних для передачі
       volatile uint32_t PAR;  // Периферійна адреса
       volatile uint32_t M0AR; // Базова адреса пам’яті 0
       volatile uint32_t M1AR; // Базова адреса пам’яті 1
       volatile uint32_t FCR;  // Керування чергою FIFO
   } DMA_Stream_TypeDef; // Розмір: 6 * 4 = 24 байти (0x18)

   DMA_Stream_TypeDef *stream = DMA1_Stream0;
   stream++; // Зміщує адресу на 24 байти (0x18), переходячи до DMA1_Stream1
   ```
2. **Кільцеві буфери (Ring Buffers) для комунікацій**: при роботі з чергами повідомлень або структурами пакетів вказівники на елементи дозволяють додавати та вилучати складні структури без обчислення байтових офсетів вручну.

### Підводні камені та заборонені операції

- **Арифметика над void\***: оскільки тип `void` є неповним і не має розміру, стандарт C суворо забороняє вирази `p++` або `p + n` для `void*`[^iso-c-n1570]. Компілятор GCC дозволяє це як розширення (прирівнюючи розмір до 1 байта), але такий код не відповідає стандарту і відхиляється MISRA C. Для байтової арифметики завжди слід використовувати `uint8_t*` або `char*`.
- **Віднімання вказівників із різних масивів**: обчислення `p2 - p1`, якщо вказівники вказують на елементи різних об’єктів, є undefined behavior.
- **Вихід за межі масиву**: переміщення вказівника далі ніж на один елемент за межі масиву (past-the-end) є undefined behavior навіть без спроби розіменування[^iso-c-n1570].
