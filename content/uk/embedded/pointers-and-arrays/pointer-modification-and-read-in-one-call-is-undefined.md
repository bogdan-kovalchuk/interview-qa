## Question code

```c
int arr[5]={1,2,3,4,5};
int *p=arr;
printf("%d %d", *p++, *p);
```

## Short answer

<span class="warn">Undefined behavior</span> – порядок обчислення аргументів `printf` не визначений стандартом.

`p++` – post-increment: повертає поточне значення і збільшує. Але між обчисленням `*p++` і `*p` в межах одного виклику функції немає sequence point. Компілятор може обчислити аргументи у будь-якому порядку.

Результат залежить від компілятора/платформи. Краще: `printf("%d %d", arr[0], arr[1]);`[^embeddedinterviewlab]

## Detailed explanation

Наведений фрагмент коду є класичним прикладом грубої помилки порушення порядку обчислень у мові C, яка призводить до повного `undefined behavior` згідно зі стандартом ISO/IEC 9899 (§6.5 Expressions, пункт 2).[^iso-c-n1570]

### Причина undefined behavior та стандарт ISO C

У стандарті C11 (ISO/IEC 9899:2011, §6.5 p2) закріплено фундаментальне правило:
> «If a side effect on a scalar object is unsequenced relative to either a different side effect on the same scalar object or a value computation using the value of the same scalar object, the behavior is undefined».[^iso-c-n1570]

У виразі `printf("%d %d", *p++, *p)`:
1. Аргумент `*p++` здійснює побічний ефект (side effect) – модифікує значення скалярного об’єкта `p` (інкрементує вказівник), а також повертає старе розіменоване значення `*p`.
2. Аргумент `*p` виконує обчислення значення (value computation) – зчитує поточне значення того самого покажчика `p` для подальшого розіменування.
3. Обидві операції відбуваються над одним і тим самим скалярним об’єктом `p` без будь-якої точки слідування (sequence point) або відношення впорядкування між ними.

Як наслідок, мова не гарантує жодного детермінованого результату: вираз не просто має «невизначений порядок виведення» (unspecified order), а руйнує коректність усієї програми через `undefined behavior`.[^iso-c-n1570]

### Точки слідування (sequence points) та аргументи функцій

Стандарт C (§6.5.2.2 Function calls, p10) чітко розмежовує виклики функцій:[^iso-c-n1570]
- Кома між аргументами функції (`printf(arg1, arg2, arg3)`) є синтаксичним роздільником списку аргументів, а не оператором «кома» (comma operator).
- Вона **не створює** точки слідування (sequence point). Точка слідування виникає лише після повного обчислення всіх аргументів безпосередньо перед передачею керування у тіло викликаної функції.
- Порядок обчислення фактичних аргументів функції є невпорядкованим (unsequenced) відносно один одного.[^iso-c-n1570]

### Генерація коду та конвенція викликів AAPCS (ARM)

На архітектурі ARM Cortex-M згідно зі стандартом викликів AAPCS (Arm Architecture Procedure Call Standard):
- Перші чотири аргументи передаються через регістри `r0`–`r3`.
- Для виклику `printf("%d %d", *p++, *p)` перший аргумент (рядок формату) розміщується в `r0`, другий – у `r1`, третій – у `r2`.
- Компілятор (GCC, Clang або Keil ArmClang) вільний генерувати інструкції завантаження в будь-якому порядку. Наприклад:
  - При обчисленні зліва направо: `r1` отримає `1`, `p` збільшиться, `r2` отримає `2`. Виведеться `1 2`.
  - При обчисленні справа наліво (традиційно для cdecl або розміщення аргументів у зворотному порядку): спочатку зчитується `*p` у `r2` (значення `1`), потім обчислюється `*p++` (значення `1` у `r1`, `p` стає `arr+1`). Виведеться `1 1`.
  - За вищих рівнів оптимізації (`-O2`, `-O3`, LTO) компілятор, знаючи про наявність `undefined behavior`, може видалити частину інструкцій або завантажити випадкове сміття з регістрів.

### Небезпека у прошивках та безпечні патерни

У вбудованих системах подібні помилки часто маскуються під час роботи на налагоджувальних збірках (`-O0`), але катастрофічно ламають функціонал після ввімкнення оптимізацій у релізі (`-Os` або `-O2`):
- **Логування та налагодження:** запис `LOG_DEBUG("byte1: %02x, byte2: %02x", *rx_ptr++, *rx_ptr++)` є некоректним і призводить до спотворення прийнятих пакетів.
- **Читання апаратних FIFO:** розіменування регістрів периферії або індексованих черг у межах одного списку аргументів може викликати втрату синхронізації протоколу.

**Безпечне інженерне рішення:** кожна модифікація стану має бути винесена в окремий вираз із чіткою крапкою з комою (точкою слідування):

```c
int first = *p++;
int second = *p;
printf("%d %d", first, second);
```
