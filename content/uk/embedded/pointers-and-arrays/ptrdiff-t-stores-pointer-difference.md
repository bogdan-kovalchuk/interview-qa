## Short answer

**ptrdiff_t** – знаковий цілочисельний тип для зберігання результату відняття двох вказівників, визначений у `<stddef.h>`. Розмір: відповідає розрядності платформи (32-bit -> 4B, 64-bit -> 8B).

Навіщо: `p - q` дає кількість елементів між вказівниками. Результат – знаковий (може бути від’ємним); Зберігати у `int` може бути недостатньо на 64-bit.

Форматна специфікація: `%td` для `printf`.[^embeddedinterviewlab]

## Detailed explanation

Тип `ptrdiff_t` – це стандартизований знаковий цілочисельний тип даних мови C, призначений для представлення результату віднімання двох покажчиків на елементи одного масиву. Він визначений у заголовному файлі `<stddef.h>` (та `<cstddef>` у C++). Стандарт ISO/IEC 9899 (§7.19 Common definitions, §6.5.6 Additive operators) встановлює вимоги до цього типу.[^iso-c-n1570]

### Чому для різниці покажчиків потрібен окремий тип

Може виникнути питання, чому для різниці покажчиків не використовувати звичайний `int` або `size_t`:

1. **Необхідність знаковості (signedness):** На відміну від `size_t`, який є беззнаковим (`unsigned`) і представляє невід’ємні розміри пам’яті, результат віднімання покажчиків може бути від’ємним. Якщо покажчик `p` передує покажчику `q` у масиві, вираз `p - q` повертає від’ємне число. Використання беззнакового типу призвело б до переповнення та спотворення логіки.
2. **Невідповідність розмірів на 64-бітних платформах:** На багатьох 64-бітних архітектурах (модель даних LP64) тип `int` має розмір 32 біти (4 байти), тоді як покажчики та розміри масивів займають 64 біти (8 байтів). Збереження різниці покажчиків у змінну типу `int` викликає відсікання старших розрядів (truncation) при роботі з великими буферами.
3. **Архітектурна незалежність:** Розмір `ptrdiff_t` гарантовано збігається з розрядністю адресної моделі платформи.

| Архітектура | Розмір покажчика | Тип `int` | Тип `size_t` | Тип `ptrdiff_t` |
|---|---|---|---|---|
| 8-бітний MCU (AVR) | 16 біт (2 байти) | 16 біт (2 байти) | `uint16_t` | `int16_t` |
| 32-бітний MCU (ARM Cortex-M) | 32 біти (4 байти) | 32 біти (4 байти) | `uint32_t` | `int32_t` |
| 64-бітний MPU (ARM Cortex-A / x86_64) | 64 біти (8 байтів) | 32 біти (4 байти) | `uint64_t` | `int64_t` |

### Типові пастки та помилки змішування знаків

Однією з найнебезпечніших помилок у вбудованому ПЗ є порівняння знакового `ptrdiff_t` із беззнаковим `size_t`:[^iso-c-n1570]

```c
ptrdiff_t diff = p - q; // Припустимо, p < q, тоді diff = -1
size_t limit = 10;

if (diff < limit) {
    // УВАГА: За правилами приведення типів C (Usual Arithmetic Conversions)
    // знаковий тип приводиться до беззнакового.
    // -1 перетворюється на 0xFFFFFFFF (на 32 бітах), що набагато більше за 10!
    // Умова дасть FALSE!
}
```

Неявне перетворення типів при порівнянні `diff < limit` часто призводить до обходу захисних перевірок виходу за межі буфера і спричиняє вразливості в прошивках.

### Застосування у прошивках мікроконтролерів

1. **Кільцеві буфери (Ring Buffers / FIFO):** Визначення кількості доступних для читання або запису байтів у драйверах UART, SPI або CAN:
   ```c
   ptrdiff_t available = in_ptr - out_ptr;
   if (available < 0) {
       available += BUFFER_SIZE;
   }
   ```
2. **Аллокатори пам’яті (Arena / Bump Allocators):** Обчислення залишку пам’яті між поточним покажчиком виділення та верхньою межею пулу пам’яті.
3. **Парсери бінарних пакетів:** Контроль залишку необроблених даних у вхідному буфері зв’язку.

Специфікатор формату для функцій сімейства `printf` – строго `%td`.[^iso-c-n1570]
