## Short answer

Масив – це об’єкт із N елементів; у більшості виразів він decay-иться до pointer на перший елемент. У параметрі функції `int a[]` фактично є `int *a`, тому довжина не передається автоматично. `sizeof array` у тій самій scope дає весь розмір масиву, а `sizeof pointer` – лише розмір адреси.[^dou-embedded-interview]

## Detailed explanation

### Фундаментальна різниця між масивом та вказівником у стандарті ISO C

Хоча синтаксис індексації `[]` створює враження взаємозамінності, масив та вказівник є принципово різними сутностями в системі типів мови C (ISO/IEC 9899:2011, §6.2.5, §6.3.2.1, §6.7.6.3)[^iso-c-n1570]:

- **Масив (`Array`):** Це єдиний суцільний блок пам’яті, що містить фіксовану кількість послідовно розташованих об’єктів одного типу (`N * sizeof(T)`). Ім’я масиву є константним позначенням місця розміщення цього блоку в пам’яті; масив не є модифікованим lvalue (`non-modifiable lvalue`), тому йому неможливо присвоїти нове значення (`arr = ptr;` є помилкою компіляції).
- **Вказівник (`Pointer`):** Це самостійна скалярна змінна, яка виділяє власну пам’ять (4 байти на 32-бітному ARM Cortex-M) і зберігає в ній адресу якогось об’єкта[^armv7m-arm]. Вказівник є повноцінним змінним lvalue: його можна переприсвоювати (`ptr = arr; ptr++;`).

### Явище Array Decay (Занепад масиву до вказівника)

Згідно зі стандартом C (§6.3.2.1 clause 3), вираз типу «масив типу `T`» у переважній більшості контекстів автоматично перетворюється (`decays`) на вказівник типу `T*`, який посилається на перший елемент масиву (`&arr[0]`).

**Три стандартизовані винятки, коли array decay НЕ відбувається:**
1. **Оператор `sizeof`:** Вираз `sizeof(arr)` обчислює повний фізичний розмір масиву в байтах. Для `int arr[10]` вираз поверне `10 * sizeof(int) = 40` байтів. На противагу, `sizeof(ptr)` поверне лише розмір адреси (4 байти на 32-бітній системі).
2. **Унарний оператор взяття адреси `&`:** Вираз `&arr` повертає вказівник на весь масив типу `T (*)[N]`, а не вказівник на окремий елемент `T*`. Хоча чисельні значення адрес `arr`, `&arr[0]` та `&arr` збігаються, їхня адресна арифметика кардинально різна: `&arr + 1` змістить адресу на розмір **всього** масиву (на 40 байтів), тоді як `arr + 1` – лише на 4 байти.
3. **Ініціалізація рядковим літералом:** `char str[] = "hello";` резервує масив із 6 байтів і копіює туди байти літерала.

### Масиви у параметрах функцій

У мові C масив неможливо передати у функцію за значенням. Згідно зі стандартом C (§6.7.6.3 clause 7), будь-яке оголошення параметра функції у вигляді масиву компілятор примусово коригує до звичайного вказівника:

```c
void process_buffer(uint8_t buf[256]); // компілятор інтерпретує як: void process_buffer(uint8_t *buf);
void display_data(uint8_t buf[]);     // компілятор інтерпретує як: void display_data(uint8_t *buf);
```

Усередині функції `process_buffer`:
- `sizeof(buf)` поверне **4 байти** (розмір вказівника на 32-бітній платформі), а не 256 байтів! Поширена помилка початківців – писати `size_t len = sizeof(buf) / sizeof(buf[0]);` всередині функції, що призведе до катастрофічно неправильного розрахунку розміру.
- Параметр `buf` є локальною змінною-вказівником, тому операції `buf++` або `buf = NULL` є допустимими.
- **Втрата розміру (Type Decay):** Функція не знає реальної довжини переданого масиву. Тому в C поруч із вказівником завжди обов’язково передають розмір: `void process_buffer(const uint8_t *buf, size_t length)`.

### Робота на рівні пам’яті та асемблера ARM Cortex-M

Різниця між глобальним масивом та глобальним вказівником чітко помітна в генерованому асемблерному коді Thumb-2[^armv7m-arm]:

```c
int arr[4];
int *ptr = arr;
// вираз: arr[1] = 5;
// вираз: ptr[1] = 5;
```

1. **Доступ через масив (`Direct Access`):**
   ```assembly
   LDR     R0, =arr            ; R0 = фіксована адреса масиву (відома лінкеру)
   MOVS    R1, #5
   STR     R1, [R0, #4]        ; прямий запис у arr[1] (зміщення +4 байти)
   ```
2. **Доступ через вказівник (`Double Indirection`):**
   ```assembly
   LDR     R0, =ptr            ; R0 = адреса змінної-вказівника ptr
   LDR     R0, [R0]            ; зчитування фактичної адреси з пам’яті (додатковий load!)
   MOVS    R1, #5
   STR     R1, [R0, #4]        ; запис у цільову пам’ять
   ```

Використання масиву замість вказівника усуває додаткову інструкцію читання пам’яті `LDR` та економить 4 байти оперативної пам’яті на саму змінну покажчика.
