## Short answer

**VLA** (C99) – масив із розміром, визначеним під час виконання програми: `void f(int n) { int arr[n]; }`.

Небезпеки у embedded:

1. <span class="warn">Stack overflow</span>: розмір невідомий під час компіляції, тому неможливо гарантувати достатній обсяг стека;
2. Відсутність константного `sizeof` – неможливо розрахувати worst-case stack usage;
3. Стандарти: MISRA C:2012 забороняє VLA (Rule 18.8), а у C11 VLA оголошено опціональним (`__STDC_NO_VLA__`);
4. Компілятори Clang/GCC дозволяють виявляти такі масиви прапорцем `-Wvla`.

Безпечна альтернатива: статичний буфер максимального розміру з перевіркою граничних значень у рантаймі.[^embeddedinterviewlab]

## Detailed explanation

### Статус VLA у стандартах C та C++

Механізм масивів змінної довжини (Variable Length Array, VLA) було додано у стандарті C99 (ISO/IEC 9899:1999, пункт 6.7.6.2). Він дозволяє оголошувати локальний масив із розміром, що обчислюється під час виконання програми: `void process(size_t n) { uint8_t buf[n]; ... }` [^iso-c-n1570].

Однак уже в стандарті C11 статус VLA було переглянуто: масиви змінної довжини перевели у категорію **опціональних можливостей** (наявність макроса `__STDC_NO_VLA__ == 1` вказує на відсутність підтримки VLA у компіляторі) [^iso-c-n1570].
У стандарті мови C++ масиви змінної довжини **ніколи не входили до офіційного стандарту**; популярні компілятори GCC та Clang підтримують їх виключно як нестандартне розширення мови.

### Чому VLA є небезпечними у вбудованих системах

Використання VLA у мікроконтролерних прошивках створює комплекс критичних інженерних ризиків:

1. **Непередбачуваний Stack Overflow (переповнення стека)**:
   * Пам’ять під VLA завжди виділяється динамічно у поточному стеку викликів (`stack frame`).
   * Вбудовані мікроконтролери мають обмежений обсяг оперативної пам’яті (SRAM), а стек окремої задачі FreeRTOS нерідко налаштований лише на 256–2048 байтів.
   * Якщо розмір n надходить із зовнішнього джерела (довжина кадру з UART, CAN чи мережевого сокета) і перевищує допустимий ліміт, стек миттєво переповнюється, пошкоджуючи змінні сусідніх функцій або дескриптор задачі (TCB).

2. **Неможливість відстеження помилки виділення пам’яті**:
   * Функція динамічного виділення пам’яті (`malloc`) у разі нестачі пулу повертає `NULL`, що дозволяє коректно обробити позаштатну ситуацію. Створення VLA не повертає жодного коду помилки.
   * На асемблерному рівні ARM Cortex-M компілятор множить розмір елемента на n, вирівнює результат по 8-байтовій межі та декрементує покажчик стека `SP`:
     ```assembly
     SUB     sp, sp, r2       @ r2 містить dyn_size
     ```
   * Якщо новий `SP` виходить за межі фізичної SRAM або перетинає стековий бар’єр, апаратний збій виникає не одразу, а пізніше як випадкове спотворення пам’яті або важкий виняток `HardFault`.

3. **Неможливість статичного аналізу глибини стека**:
   * Для сертифікованих вбудованих систем реального часу критично знати максимальну глибину використання стека (Worst-Case Stack Usage).
   * Інструменти статичного аналізу (зокрема утиліта `-fstack-usage` у GCC) не здатні визначити точний розмір стекового кадру функцій із VLA, оскільки значення `sizeof(arr)` обчислюється динамічно в рантаймі.

4. **Заборона промисловими стандартами надійності (MISRA C)**:
   * Стандарт розробки критичного автомобільного та авіаційного ПЗ MISRA C:2012 (правило Rule 18.8) суворо забороняє використання VLA: *«Variable-length array types shall not be used»*.

### Безпечні інженерні альтернативи

* **Статичні буфери максимального розміру**: виділяйте фіксований буфер на етапі компіляції та перевіряйте динамічну довжину перед його заповненням:
  ```c
  #define MAX_PAYLOAD_SIZE 128
  
  int process_packet(size_t n) {
      if (n > MAX_PAYLOAD_SIZE || n == 0) {
          return -1; /* Помилка: розмір перевищує виділений буфер */
      }
      uint8_t buf[MAX_PAYLOAD_SIZE];
      /* безпечна робота з буфером */
      return 0;
  }
  ```
* **Пул статичної пам’яті (Memory Pool)**: якщо буфер потребує великого об’єму, використовуйте заздалегідь виділений пул блоків зі статичною прив’язкою та синхронізацією м’ютексом.
* **Прапорці компілятора**: для запобігання випадковому використанню VLA обов’язково додавайте до параметрів збирання прапорець `-Wvla` або `-Werror=vla`.
