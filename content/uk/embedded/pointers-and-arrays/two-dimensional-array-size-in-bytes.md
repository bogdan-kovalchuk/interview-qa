## Question code

```c
int arr[3][4];
printf("%zu", sizeof(arr));
```

## Short answer

**48** байт.

`arr` – 2D масив: 3 рядки × 4 стовпці × `sizeof(int) = 4` байти = 48B.

`sizeof(arr[0])` = `sizeof(int[4])` = 16B (один рядок), `sizeof(arr[0][0])` = `sizeof(int)` = 4B.

Кількість рядків: `sizeof(arr)/sizeof(arr[0]) = 48/16 = 3`. Цей трюк працює лише у тому ж scope де оголошений масив.[^embeddedinterviewlab]

## Detailed explanation

Оператор `sizeof` у мові C обчислює повний обсяг пам’яті в байтах, необхідний для розміщення об’єкта або типу. Стандарт ISO/IEC 9899 (§6.2.5 Types, §6.5.3.4 The sizeof and _Alignof operators) визначає, що багатовимірні масиви в мові C конструюються рекурсивно як «масиви масивів».[^iso-c-n1570]

### Рекурсивна модель типів та розрахунок розміру

Оголошення `int arr[3][4];` створює масив із 3 елементів, кожен з яких є одномірним масивом із 4 цілих чисел типу `int`:

- Базовий тип елемента: `int`. На типових 32-бітних архітектурах мікроконтролерів (зокрема ARM Cortex-M0/M3/M4/M7, ESP32) розмір `sizeof(int)` становить 4 байти.
- Тип рядка: `int[4]`. Розмір одного рядка дорівнює `4 * sizeof(int) = 4 * 4 = 16` байтів.
- Тип усього масиву: `int[3][4]`. Розмір масиву дорівнює `3 * sizeof(int[4]) = 3 * 16 = 48` байтів.[^iso-c-n1570]

Специфікатор формату `%zu` є стандартним для виведення значень типу `size_t` починаючи зі стандарту C99. Оскільки `sizeof` обчислюється під час компіляції (за винятком VLA), компілятор підставляє числову константу без жодних накладних витрат у runtime.

### Розташування у пам’яті (Row-Major Order)

Згідно з вимогами стандарту C (§6.2.5 p20), усі елементи масиву розташовуються у пам’яті строго послідовно та неперервно за рядками (row-major order), без будь-яких проміжків (padding) між елементами або рядками:[^iso-c-n1570]

| Рядок | Елементи | Зміщення в байтах | Діапазон адрес (при старті з `0x2000`) |
|---|---|---|---|
| `arr[0]` | `arr[0][0]` .. `arr[0][3]` | `+0` .. `+15` | `0x2000`–`0x200F` (16 байтів) |
| `arr[1]` | `arr[1][0]` .. `arr[1][3]` | `+16` .. `+31` | `0x2010`–`0x201F` (16 байтів) |
| `arr[2]` | `arr[2][0]` .. `arr[2][3]` | `+32` .. `+47` | `0x2020`–`0x202F` (16 байтів) |

Завдяки неперервному розташуванню адресне зміщення довільного елемента `arr[i][j]` обчислюється за формулою: адреса = базова адреса + `(i * 4 + j) * sizeof(int)`.

### Ідіоми обчислення розмірностей масиву

У коді прошивок мікроконтролерів часто застосовують ідіоми на основі `sizeof` для автоматичного визначення розмірів буферів та таблиць без «магічних чисел»:[^iso-c-n1570]

```c
size_t total_bytes   = sizeof(arr);                   // 48 байтів
size_t row_bytes     = sizeof(arr[0]);                // 16 байтів
size_t element_bytes = sizeof(arr[0][0]);             // 4 байти

size_t num_rows      = sizeof(arr) / sizeof(arr[0]);         // 48 / 16 = 3 рядки
size_t num_cols      = sizeof(arr[0]) / sizeof(arr[0][0]);   // 16 / 4 = 4 стовпці
size_t total_elems   = sizeof(arr) / sizeof(arr[0][0]);      // 48 / 4 = 12 елементів
```

### Критична пастка: занепад масиву при передачі у функцію

Цей розрахунок працює лише в тому контексті (scope), де сам масив був оголошений. Якщо передати `arr` у функцію:

```c
void process_matrix(int a[3][4]) {
    size_t sz = sizeof(a); // УВАГА: поверне розмір покажчика, а не масиву!
}
```

Відповідно до правила array decay (§6.7.6.3), тип параметра `int a[3][4]` неявно перетворюється компілятором на `int (*a)[4]` (покажчик на масив із 4 елементів). На 32-бітному мікроконтролері `sizeof(a)` поверне 4 байти (розмір адреси), а не 48 байтів. Спроба обчислити кількість елементів всередині функції через `sizeof(a) / sizeof(a[0])` є грубою помилкою, яка призводить до хибних розрахунків розмірів буферів.[^iso-c-n1570]
