## Short answer

Рядок у C – масив символів, де останній елемент = **'\0' (null-terminator)**, байт зі значенням 0.

"hello" складається з `['h','e','l','l','o','\0']` – 6 байтів у пам’яті.

Null-terminator сигналізує стандартним функціям (`strlen`, `strcpy`, `printf %s`), де рядок закінчується. Без '\0' читання виходить за межі буфера та спричиняє UB.

Рядкові літерали автоматично містять '\0'. При ручному заповненні буфера встановлення `buf[n] = '\0';` є обов’язковим.[^embeddedinterviewlab]

## Detailed explanation

### Суть концепції та стандарт ISO C

У мові C відсутній вбудований примітивний тип даних для рядків. Згідно зі стандартом ISO/IEC 9899:201x (C11), пункт 7.1.1, рядок визначається як неперервна послідовність символів, яка завершується та включає перший нульовий символ (`null character`, `\0`, байт зі значенням `0x00`) [^iso-c-n1570].

Такий формат називається нуль-термінованим рядком (або ASCIIZ-рядком). Оскільки структура рядка не зберігає окремого поля з його довжиною (на відміну від рядків Pascal або зрізів у сучасних мовах), нульовий байт виконує критичну роль маркера кінця даних (*sentinel value*). Усі стандартні рядкові функції бібліотеки `<string.h>` (`strlen`, `strcpy`, `strcmp`), а також специфікатор формату `printf("%s", ...)` послідовно читають пам’ять байт за байтом, доки не зустрінуть значення `0x00`.

### Розміщення у пам’яті мікроконтролера

У вбудованих системах на базі ARM Cortex-M фізичне розташування рядка визначається способом його оголошення:

1. **Рядковий літерал**:
   ```c
   const char *str = "hello";
   ```
   Літерал `"hello"` розміщується лінкером у секції константних даних `.rodata`, яка прошивається у постійну пам’ять Flash. У пам’яті він займає рівно 6 байтів:
   `'h' (0x68), 'e' (0x65), 'l' (0x6C), 'l' (0x6C), 'o' (0x6F), '\0' (0x00)`.
   Вказівник `str` зберігає адресу цієї комірки у Flash. Спроба модифікації такого рядка (`((char*)str)[0] = 'H';`) на архітектурах Cortex-M призводить до апаратного винятку `BusFault` або `HardFault`, оскільки Flash-пам’ять апаратно захищена від запису звичайними інструкціями `STR`.

2. **Символьний масив (буфер) в оперативній пам’яті (SRAM)**:
   ```c
   char buf[6] = "hello"; /* розміщується у стеку або секції .data */
   ```
   У цьому випадку виділяється 6 байтів у SRAM, куди копіюються символи разом із нуль-термінатором. Якщо оголосити `char buf[5] = "hello";`, у мові C це допустимо за стандартом (§6.7.9 p14), але масив міститиме лише 5 символів без `\0` [^iso-c-n1570]. Такий буфер не є коректним C-рядком.

### Небезпеки відсутності null-terminator у прошивках

Втрата завершального нульового байта у вбудованому ПЗ призводить до тяжких наслідків:
* **Out-of-bounds Read (витік конфіденційних даних)**: якщо функція `strlen(buf)` або `printf("%s", buf)` обробляє буфер без термінатора, процесор продовжує сканувати наступні адреси пам’яті. Це спричиняє виведення випадкових байтів із оперативної пам’яті у налагоджувальний порт UART або мережу Ethernet (що може розкрити ключі шифрування чи службову телеметрію).
* **HardFault / MemManage Fault**: пошук нульового байта триває доти, доки вказівник не перетне межу виділеної пам’яті SRAM або не звернеться до неіснуючого адресного простору периферії.
* **Buffer Overflow при копіюванні**: функція `strcpy(dest, src)` копіюватиме пам’ять за межами `src`, перезаписуючи змінні, адреси повернення функцій або стекові кадри сусідніх задач RTOS.

### Інженерні рекомендації для розробників вбудованих систем

* **Завжди закладайте додатковий байт під термінатор**: для збереження тексту довжиною N символів розмір буфера повинен бути щонайменше N + 1.
* **Оборонне термінування після прийому**: під час зчитування пакетів через UART, SPI або CAN примусово записуйте нульовий байт наприкінці буфера:
  ```c
  buf[sizeof(buf) - 1] = '\0';
  ```
* **Використовуйте функції з явним обмеженням довжини**: замість небезпечних `sprintf` та `strcpy` використовуйте `snprintf` та функції копіювання з контролем розміру цільового буфера.
* **Розділяйте текстові рядки та бінарні буфери**: якщо дані передаються блоками байтів (наприклад, кадри телеметрії або пакети сенсорів), застосовуйте тип `uint8_t[]` із явною передачею довжини `size_t len`, уникаючи функцій сімейства `str*`.
