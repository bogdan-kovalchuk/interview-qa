## Short answer

`int *p` – вказівник на `int`, тож `p+1` -> +4 байти (один `int`), а `int (*p)[8]` – **вказівник на масив** з 8 `int`, де `p+1` -> +32 байти (один масив із 8 елементів).

Використання: при роботі з 2D масивами: `int arr[3][8]; int (*p)[8] = arr;`. `p[1]` -> другий рядок; `p[1][3]` -> `arr[1][3]`.

Правило читання: `(*p)` -> "вказівник на" (дужки важливі через пріоритет операторів).[^embeddedinterviewlab]

## Detailed explanation

### Синтаксичний розбір та пріоритет операторів

У деклараціях мови C оператор квадратних дужок `[]` (індексація масиву) має вищий пріоритет, ніж унарний оператор `*` (розіменування/оголошення вказівника)[^iso-c-n1570].
Тому наявність круглих дужок кардинально змінює зміст оголошення:
- `int (*p)[8]`: круглі дужки зв’язують `*` безпосередньо з ім’ям змінної `p`. Це означає, що `p` є **вказівником на масив** із 8 цілих чисел типу `int`.
- `int *p[8]`: без дужок індексатор має перевагу, тому вираз декларує **масив із 8 вказівників** на `int`.
- `int *p`: простий вказівник на одиночне значення типу `int` (або на перший елемент одномірного масиву `int`).

### Різниця в адресній арифметиці та розмірах

Обидва типи вказівників на 32-розрядній платформі ARM Cortex-M мають однаковий фізичний розмір: `sizeof(p) == 4` байти[^armv7m-arm]. Проте тип цільового об’єкта (referenced type), на який вони вказують, кардинально відрізняється:
1. Для `int *p`:
   - Цільовим типом є одиночний `int`.
   - Розмір цільового типу: `sizeof(*p) = sizeof(int) = 4` байти.
   - Інкремент `p + 1` зміщує фізичну адресу рівно на 4 байти.
2. Для `int (*p)[8]`:
   - Цільовим типом є повноцінний масив `int[8]`.
   - Розмір цільового типу: `sizeof(*p) = sizeof(int[8]) = 8 * 4 = 32` байти.
   - Інкремент `p + 1` зміщує фізичну адресу одразу на 32 байти вперед[^iso-c-n1570].

### Робота з двовимірними масивами у пам’яті

Багатовимірні масиви в мові C розміщуються в пам’яті послідовно рядок за рядком (row-major order):
```c
int matrix[3][8];
int (*p)[8] = matrix; // array decay: matrix перетворюється на вказівник на свій перший рядок
```
При такій ініціалізації:
- `p` вказує на початок нульового рядка `matrix[0]`.
- `p + 1` зміщує адресу на 32 байти і вказує точно на початок першого рядка `matrix[1]`.
- Розіменування `*p` повертає сам масив `int[8]`, який у більшості виразів розпадається (array decay) до вказівника на свій перший елемент (`int*`).
- Подвійний індекс `p[i][j]` транслюється компілятором у фізичну адресу:
  `Базова_адреса + i * (8 * sizeof(int)) + j * sizeof(int)`.

Якщо спробувати виконати некоректне присвоєння `int *ptr = matrix;`, сучасний компілятор згенерує попередження або помилку невідповідності типів (`incompatible pointer type`), оскільки тип `matrix` розпадається саме до `int (*)[8]`, а не до `int*`.

### Застосування у вбудованих системах (Embedded)

1. **Обробка блочних буферів DMA та комунікаційних протоколів**:
   У драйверах Ethernet, CAN FD або відеодисплеїв дані надходять фіксованими пачками (наприклад, кадри по 8 слів). Вказівник на масив дозволяє індексувати цілі пакети:
   ```c
   uint32_t dma_rx_buffer[NUM_PACKETS][PACKET_WORDS];
   uint32_t (*packet_ptr)[PACKET_WORDS] = dma_rx_buffer;
   // packet_ptr[k] адресує k-й пакет цілком
   ```
2. **Передача двовимірних матриць у функції**:
   При передачі матриці фіксованої ширини у функцію параметр `void process_matrix(int arr[][8], size_t rows)` компілятором інтерпретується саме як `void process_matrix(int (*arr)[8], size_t rows)`. Це зберігає сувору типізацію та правильний крок обчислення зміщень для рядків матриці.
