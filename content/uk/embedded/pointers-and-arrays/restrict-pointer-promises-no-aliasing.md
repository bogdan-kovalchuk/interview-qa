## Short answer

`restrict` (C99) – кваліфікатор вказівника, що гарантує компілятору: через цей вказівник і через жоден інший вказівник у цій функції **не відбувається aliasing** (перекриття областей пам’яті).

Приклад: `void add(int * restrict dst, const int * restrict src, int n)`.

Дає компілятору дозвіл на агресивну оптимізацію (векторизація, підкачка у регістри). Важливо для DSP, crypto, memcpy-like функцій. Якщо aliasing все ж є – undefined behavior (UB).[^embeddedinterviewlab]

## Detailed explanation

Кваліфікатор `restrict` введений у стандарті C99 (ISO/IEC 9899, §6.7.3 Type qualifiers, §6.7.3.1 Formal definition of restrict) для вирішення класичної проблеми оптимізації компілятора – накладання покажчиків (pointer aliasing).[^iso-c-n1570]

Кваліфікатор `restrict` може застосовуватися виключно до покажчиків на типи об’єктів. Він є формальною декларацією розробника перед компілятором: протягом усього часу життя даного покажчика доступ до об’єкта, на який він посилається (прямо або опосередковано), здійснюватиметься **тільки** через цей покажчик або вирази, безпосередньо похідні від нього.

Жоден інший покажчик у цій самій області видимості (scope) не посилається на ту саму область пам’яті або на пам’ять, що перекривається з нею.[^iso-c-n1570]

### Проблема Pointer Aliasing та чому вона сповільнює код

Розглянемо функцію векторного додавання двох масивів без використання 
estrict:

`c
void vector_add(int *dst, const int *src, size_t n) {
    for (size_t i = 0; i < n; i++) {
        dst[i] += src[i];
    }
}
`

З точки зору стандарту C, компілятор зобов’язаний припустити найгірший сценарій: пам’ять масивів dst та src може частково перекриватися (наприклад, виклик ector_add(ptr + 1, ptr, 10)). У такому разі запис у dst[i] може змінити значення наступного елемента src[i + 1] (виникає залежність між ітераціями – loop-carried dependency).

Через цю потенційну невизначеність оптимізатор **не має права** вважати ітерації незалежними. Компілятор вимушений або генерувати повільний скалярний цикл із послідовними читаннями й записами у пам’ять на кожній ітерації, або вставляти важкі перевірки перекриття адрес у runtime (loop versioning), що збільшує розмір коду та навантажує конвеєр.

### Що змінює кваліфікатор restrict

Додавши 
estrict:

`c
void vector_add_optimized(int * restrict dst, const int * restrict src, size_t n) {
    for (size_t i = 0; i < n; i++) {
        dst[i] += src[i];
    }
}
`

Компілятор отримує формальну гарантію, що масиви за адресами dst та src не перекриваються в пам’яті. Завдяки цьому компілятор застосовує агресивні оптимізації:[^iso-c-n1570]

1. **Автовекторизація (auto-vectorization):** На ядрах ARM Cortex-M4/M7/M33 компілятор може задіяти SIMD-інструкції для паралельної обробки елементів за один такт, а на ядрах Cortex-M55/M85 з технологією Helium (M-Profile Vector Extension) – задіяти 128-бітні векторні регістри без будь-яких runtime-перевірок перекриття.
2. **Розгортання циклів (loop unrolling) та планування інструкцій:** Інструкції завантаження src та збереження у dst вільно переставляються місцями (instruction scheduling), усуваючи простої конвеєра процесора.
3. **Кешування у регістрах:** Якщо один із покажчиків посилається на скалярне значення, компілятор може безпечно винести читання у процесорний регістр перед циклом, знаючи, що запис у вихідний масив його не змінить.

### Практичне значення для DSP та бібліотеки CMSIS-DSP

У цифровій обробці сигналів (DSP), криптографії та обробці аудіо/зображень швидкодія є критичною. Бібліотека ARM CMSIS-DSP повсюдно використовує `restrict` (або макроси компілятора `__restrict`) у функціях швидкого перетворення Фур’є (FFT), КІХ-фільтрах (FIR) та матричній алгебрі:

```c
void arm_fir_f32(const arm_fir_instance_f32 * S,
                 const float32_t * restrict pSrc,
                 float32_t * restrict pDst,
                 uint32_t blockSize);
```

Класичний приклад у стандартній бібліотеці C – різниця між функціями копіювання пам’яті:
- `void *memcpy(void * restrict s1, const void * restrict s2, size_t n);` – забороняє перекриття областей пам’яті; компілятор генерує максимально швидкий код блочного копіювання.
- `void *memmove(void *s1, const void *s2, size_t n);` – не має `restrict`, коректно обробляє перекриття, але працює повільніше.

### Наслідки порушення контракту: Undefined Behavior

Якщо розробник передасть у функцію покажчики з перекриттям пам’яті, порушивши контракт `restrict`, виникає **undefined behavior** (§6.7.3.1). Компілятор не генерує жодних перевірок у runtime; оптимізований машинний код прочитає застарілі значення з регістрів або виконає запис у непередбачуваному порядку, що призведе до спотворення даних без повідомлень про помилку.[^iso-c-n1570]
