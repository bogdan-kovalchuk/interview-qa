## Short answer

**Function pointer** – вказівник на функцію: зберігає адресу коду функції для виклику через нього.

Синтаксис: `return_type (*name)(param_types);` Приклад: `void (*isr)(void) = &my_handler;`

Виклик: `(*isr)();` або просто `isr();` (обидва коректні).

Застосування у embedded: ISR dispatch tables, state machine transitions, RTOS task functions, callback API (`HAL_UART_RegisterCallback`).[^embeddedinterviewlab]

## Detailed explanation

Покажчик на функцію (function pointer) – це змінна, яка зберігає адресу виконуваного машинного коду функції в пам’яті програм (Flash або RAM) замість адреси даних. Стандарт ISO/IEC 9899 (§6.3.2.1, §6.5.2.2) регламентує роботу з покажчиками на функції, визначаючи перетворення ідентифікатора функції (function designator) на покажчик на цю функцію.[^iso-c-n1570]

### Правила синтаксису оголошення

У мові C оператор виклику функції `()` має вищий пріоритет, ніж оператор розіменування `*`. Через це дужки навколо імені покажчика є обов’язковими:

- `return_type (*name)(param_types);` – оголошення покажчика на функцію.
- `return_type *name(param_types);` – оголошення звичайної функції, яка повертає покажчик.

Для спрощення читання коду та уникнення помилок в embedded-розробці прийнято створювати псевдоніми типів через `typedef`:

```c
// Оголошення типу callback-функції для обробника UART
typedef void (*uart_rx_callback_t)(uint8_t received_byte);

// Використання типу у структурі драйвера
typedef struct {
    uart_rx_callback_t on_rx;
    uint32_t baudrate;
} uart_driver_t;
```

Присвоєння адреси функції та її виклик мають дві рівноправні форми згідно зі стандартом C (§6.3.2.1):

```c
void my_handler(uint8_t data) { /* ... */ }

uart_rx_callback_t cb1 = &my_handler; // Явне взяття адреси
uart_rx_callback_t cb2 = my_handler;  // Автоматичний decay ідентифікатора функції

(*cb1)(0xAA); // Явне розіменування
cb2(0x55);    // Неявний виклик (рекомендований сучасний стиль)
```

Обидва синтаксиси виклику генерують абсолютно ідентичний машинний код.

### Особливості архітектури ARM Cortex-M: біт Thumb Mode

У мікроконтролерах архітектури ARM Cortex-M виконується виключно набір інструкцій Thumb/Thumb-2. Це вимагає важливої особливості представлення адрес функцій:[^iso-c-n1570]

- Усі адреси функцій, які завантажуються у покажчики на функції, мають молодший біт (LSB, біт 0), примусово встановлений у `1`.
- Цей біт не є реальною частиною фізичної адреси команди (команди вирівняні щонайменше на 2 байти), а слугує індикатором режиму для інструкцій непрямого переходу `BX` (Branch and Exchange) та `BLX` (Branch with Link and Exchange).
- Якщо спробувати викликати функцію через покажчик з очищеним бітом 0 (`address & ~1`), процесор Cortex-M спробує перемкнутися в класичний стан ARM (ARM state), який не підтримується ядром, і негайно викличе виняток `UsageFault` (помилка `INVSTATE`).

Таблиця векторів переривань Cortex-M, розташована на початку Flash-пам’яті (`0x08000000` або `0x00000000`), фактично є масивом таких покажчиків на функції (Reset_Handler, NMI_Handler, HardFault_Handler тощо), де кожна адреса має біт 0, встановлений у 1.

### Патерни використання в embedded-системах

1. **Callback API драйверів периферії:** Дозволяє відокремити апаратний рівень (HAL/LL) від логіки застосунку. При виникненні переривання драйвер викликає зареєстрований користувацький callback без опитування (polling).
2. **Таблиці переходів скінченного автомата (State Machine):** Замість громіздких конструкцій `switch-case` створюється таблиця переходів у вигляді масиву покажчиків `void (*state_table[STATE_MAX])(event_t *ev);`, що гарантує виконання переходу за константний час `O(1)`.
3. **Таблиці віртуальних методів (vtable) у C:** Забезпечують поліморфізм для драйверів однакового класу (наприклад, драйвери Flash-пам’яті з різними інтерфейсами SPI, QSPI).

### Безпека та типові помилки

- **Виклик NULL-покажчика:** Якщо callback не зареєстрований, виклик покажчика зі значенням `NULL` призводить до стрибка за нульовою адресою і виклику `HardFault`. Перед викликом обов’язкова перевірка: `if (cb != NULL) cb(data);`.
- **Невідповідність сигнатури (type mismatch):** Приведення покажчика на функцію до несумісної сигнатури та його подальший виклик є undefined behavior. Порушення ABI (наприклад, AAPCS – ARM Architecture Procedure Call Standard) руйнує регістри та стек.[^iso-c-n1570]
