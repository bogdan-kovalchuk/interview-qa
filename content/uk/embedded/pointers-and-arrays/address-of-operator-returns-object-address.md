## Short answer

Оператор `&` (address-of) повертає **адресу об’єкта** у пам’яті – значення типу "вказівник на тип об’єкта".

`int x = 5; int *p = &x;` – `p` тепер вказує на `x`.

Не можна взяти адресу:
- виразів без lvalue (`&(a+b)` – помилка);
- `register` змінних;
- bit-field полів структури.

Типи: `&int` -> `int*`, `&arr` -> `int(*)[N]` (вказівник на масив, не на елемент).[^embeddedinterviewlab]

## Detailed explanation

Унарний оператор взяття адреси `&` (address-of operator) є одним із базових операторів мов C та C++. Згідно зі стандартом ISO/IEC 9899 (§6.5.3.2), операндом оператора `&` має бути вираз, що позначає функцію або об’єкт (lvalue), який не має класу зберігання `register` і не є бітовим полем структури.[^iso-c-n1570]

### Що повертає оператор `&` та як формується тип

Результатом виразу `&E` є значення, що представляє адресу в пам’яті об’єкта або функції, позначеної операндом `E`:[^iso-c-n1570]

- **Скалярні типи:** якщо операнд `x` має тип `T` (наприклад, `int`), то результатом виразу `&x` є значення типу «вказівник на `T`» (`int *`).
- **Функції:** для функції `void isr_handler(void)` вираз `&isr_handler` повертає вказівник на функцію типу `void (*)(void)` (хоча в більшості виразів ім’я функції неявно перетворюється на вказівник і без явного оператора `&`).
- **Масиви:** якщо `arr` оголошено як масив з `N` елементів типу `T` (`int arr[10]`), то вираз `&arr` повертає **вказівник на весь масив** типу `int (*)[10]`, а не `int *`.[^iso-c-n1570] Хоча чисельне значення адреси `&arr` збігається з адресою першого елемента `&arr[0]`, їхні типи принципово різні, що безпосередньо впливає на крок адресної арифметики.

### До чого стандарт забороняє застосовувати оператор `&`

Стандарт C накладає три суворих обмеження на операнд унарного `&`:[^iso-c-n1570]

1. **Вирази без lvalue (rvalue-вирази):**
   - Неможливо взяти адресу літеральної константи (`&42` або `&3.14f`), проміжного результату арифметичних операцій (`&(a + b)`) або результату виклику функції, що повертає значення за копією (`&get_val()`). Ці значення не мають постійної ідентифікованої адреси в адресній пам’яті процесора.
2. **Бітові поля структур (Bit-fields):**
   - У структурах виду `struct Flags { unsigned int flag : 1; };` окремі біти упаковані всередині машинних слів. Архітектури сучасних мікропроцесорів мають побайтову адресацію пам’яті (мінімальна адресовна одиниця – байт). Окремий біт не має власної адреси, тому вираз `&flags.flag` заборонений стандартом і викликає помилку компіляції (§6.7.2.1).[^iso-c-n1570]
3. **Змінні з класом зберігання `register`:**
   - Специфікатор `register int reg_var;` явно забороняє отримання адреси об’єкта (§6.7.1). Навіть якщо компілятор через брак фізичних регістрів розмістить змінну на стеку в SRAM, спроба виконати `&reg_var` призведе до помилки компіляції.[^iso-c-n1570]

### Відмінності та нюанси в мові C++

У мові C++ семантика оператора взяття адреси має важливі розширення:[^iso-cpp-n4861]

- **Перевантаження оператора (`operator&`):** користувацький клас може перевантажити унарний оператор `&`, повертаючи так званий smart pointer, проксі-об’єкт або інше значення. Щоб гарантовано отримати справжню машинну адресу екземпляра класу незалежно від наявності перевантаженого `operator&`, у стандартній бібліотеці C++11 передбачено утиліту `std::addressof(obj)`.[^iso-cpp-n4861]
- **Вказівники на члени класу:** вираз `&MyClass::data_member` повертає не фізичну адресу в SRAM, а вказівник на член класу типу `int MyClass::*`, що логічно є зміщенням (offset) поля від початку екземпляра об’єкта.[^iso-cpp-n4861]

### Використання оператора `&` в Embedded C

У низькорівневому та драйверному програмуванні взяття адреси застосовується постійно:[^iso-c-n1570]

- **Передача структур конфігурації:** передача вказівника на структуру дескриптора периферії (`HAL_UART_Init(&huart1)`) запобігає витратному копіюванню великих блоків через стек процесора.
- **Розрахунок зміщень:** стандартний макрос `offsetof(type, member)` базується на синтаксичному взятті адреси поля структури від нульового покажчика `((size_t)&(((type *)0)->member))`.
- **Налаштування каналів DMA:** для запуску передачі даних у регістри каналу DMA записують фізичну адресу буфера в пам’яті `DMA->CPAR = (uint32_t)&ADC1->DR;` та `DMA->CMAR = (uint32_t)&adc_buffer[0];`.
