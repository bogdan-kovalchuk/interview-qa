## Question code

```c
int arr[4]={0};
int *p=arr;
p+=5;
*p=1;
```

## Short answer

<span class="warn">Так, undefined behavior (UB)</span> (навіть без розіменування).

Формування вказівника `p += 5` виходить за межі масиву більш ніж на 1: `arr` має 4 елементи, тому валідні вказівники: `arr` до `arr+4` (включно "one-past-the-end"). Вираз `arr+5` – це UB вже при формуванні адреси.

One-past-the-end (`arr+4`) – дозволено формувати, але <span class="warn">не розіменовувати</span>.[^embeddedinterviewlab]

## Detailed explanation

Наведений фрагмент коду містить фундаментальну пастку мови C, пов’язану з правилами адресної арифметики: невизначена поведінка (`undefined behavior`) виникає ще до спроби запису в пам’ять – у момент обчислення виразу `p += 5`.[^iso-c-n1570]

### Межі адресної арифметики в стандарті ISO C

Відповідно до стандарту ISO/IEC 9899 (§6.5.6 Additive operators, пункт 8), додавання цілого числа до покажчика регламентується суворими правилами:[^iso-c-n1570]

> «Якщо покажчик і результат вказують на елементи одного масиву або на один елемент за останнім елементом масиву, обчислення не повинно викликати переповнення; інакше поведінка є невизначеною.»

Для масиву `int arr[4]` легітимними значеннями покажчиків є адреси елементів:
- `arr + 0` (адреса `&arr[0]`),
- `arr + 1` (адреса `&arr[1]`),
- `arr + 2` (адреса `&arr[2]`),
- `arr + 3` (адреса `&arr[3]`),
- `arr + 4` (адреса так званого елемента **one-past-the-end**).

Значення `p += 5` зміщує покажчик на 5 позицій вперед (на `5 * sizeof(int) = 20` байтів). Оскільки масив складається лише з 4 елементів, адреса `arr + 5` виходить за межі дозволеного стандартом діапазону. За стандартом мови C, **undefined behavior виникає вже на етапі обчислення самого покажчика** `p += 5`, навіть якщо операція розіменування ніколи не буде виконана.[^iso-c-n1570]

### Чому формування адреси за межами one-past-the-end є UB

1. **Архітектурні особливості адресації:** В історичних сегментних моделях пам’яті (наприклад, у 16-бітному режимі реального часу x86) або на спеціалізованих цифрових сигнальних процесорах (DSP) із кільцевими адресними буферами формування адреси за межами сегмента викликає апаратне переривання процесора або апаратне переповнення адресного регістра.
2. **Оптимізації компілятора:** Сучасні оптимізуючі компілятори (GCC, Clang) аналізують межі масивів. Якщо компілятор фіксує вихід за межі масиву, він має право вважати такий фрагмент коду недосяжним (`dead code elimination`) і повністю видалити навколишні перевірки чи наступні інструкції, що руйнує логіку прошивки.[^embeddedinterviewlab]

### Розіменування: порушення захисту пам’яті мікроконтролера

Оператор `*p = 1;` є другою фатальною помилкою – спробою запису за межами виділеного об’єкта (out-of-bounds write / stack buffer overflow):[^iso-c-n1570]

- Масив `arr[4]` розміщується у стек-фреймі поточної функції в SRAM.
- Зміщення на 20 байтів адресує пам’ять за межами масиву. Залежно від вирівнювання та оптимізації компілятора, запис `*p = 1` перезаписує сусідні локальні змінні, збережений покажчик кадру (`R7`/`R11`) або регістр зв’язку `LR` (Link Register), де зберігається адреса повернення з функції.
- Під час виходу з функції процесор спробує виконати перехід за пошкодженою адресою з регістру `LR`, що призведе до переходу в невідому пам’ять і негайного спрацьовування апаратного виключення `HardFault` на ARM Cortex-M.[^embeddedinterviewlab]

### Призначення та обмеження покажчика one-past-the-end

Стандарт C навмисно дозволяє існування покажчика на один елемент за кінцем масиву (`arr + 4`), щоб забезпечити можливість побудови стандартних циклів обходу:

```c
for (int *ptr = arr; ptr < arr + 4; ++ptr) {
    // Безпечний доступ до *ptr
}
```

У такій конструкції в момент виходу з циклу `ptr` дорівнює `arr + 4`. Стандарт гарантує, що такий покажчик можна формувати та порівнювати, проте **розіменовувати його суворо заборонено** (`* (arr + 4)` є `undefined behavior`).[^iso-c-n1570]
