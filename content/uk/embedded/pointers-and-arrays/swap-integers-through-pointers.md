## Short answer

```c
void swap(int *a, int *b) {
    int tmp = *a;
    *a = *b;
    *b = tmp;
}
```

Виклик: `int x=5, y=10; swap(&x, &y);` -> `x=10, y=5`.

Без tmp через XOR: `*a^=*b; *b^=*a; *a^=*b;` – але <span class="warn">якщо `a == b`, значення обнулиться</span> (обидва вказівники на один об’єкт, а `x ^ x == 0`). Передавай завжди адреси (через `&` у caller), не значення.[^embeddedinterviewlab]

## Detailed explanation

Обмін значеннями двох цілочисельних змінних через покажчики – це фундаментальна ідіома мови C, яка ілюструє концепцію передачі параметрів за адресою (pass-by-pointer/pass-by-reference) та роботу з оперативною пам’яттю на рівні регістрів мікроконтролера.[^iso-c-n1570]

### Класична реалізація та механізм передачі за вказівником у C

У мові C всі аргументи функцій передаються виключно за значенням (pass-by-value) згідно зі стандартом ISO/IEC 9899 (§6.5.2.2 Function calls).[^iso-c-n1570]
Якщо спробувати написати `void naive_swap(int a, int b)`, функція отримає копії локальних змінних, і будь-які модифікації завершаться зі знищенням фрейму стека без зміни змінних викликаючого коду (caller).

Щоб змінити змінні у викликаючій функції:
1. Викликаючий код передає адреси змінних за допомогою унарного оператора взяття адреси `&` (наприклад, `swap(&x, &y);`).
2. Функція приймає покажчики `int *a` та `int *b`.
3. За допомогою оператора розіменування `*` функція читає та перезаписує значення безпосередньо за отриманими адресами пам’яті:

```c
void swap(int *a, int *b) {
    int tmp = *a; // Збереження старого значення першої змінної
    *a = *b;      // Запис значення другої змінної за адресою першої
    *b = tmp;     // Запис збереженого значення за адресою другої
}
```

### Генерація асемблерного коду для ARM Cortex-M

На типовому 32-бітному ядрі ARM Cortex-M (з урахуванням конвенції викликів AAPCS):
- Вказівник `a` передається у регістрі `r0`, а вказівник `b` – у регістрі `r1`.
- За наявності окремої функції компілятор генерує всього 5 інструкцій машинного коду:

```assembly
swap:
    LDR     r2, [r0]    ; r2 = *a (tmp)
    LDR     r3, [r1]    ; r3 = *b
    STR     r3, [r0]    ; *a = r3 (*b)
    STR     r2, [r1]    ; *b = r2 (tmp)
    BX      lr          ; Повернення з функції
```

Якщо компілятор вбудовує функцію (inline-підстановка при `-O2` або `-O3`), операція обміну часто виконується без жодних інструкцій роботи з пам’яттю – оптимізатор просто перейменовує використання регістрів процесора (register renaming) або використовує одну проміжну інструкцію копіювання `MOV`.

### Пастка XOR-swap при співпадінні адрес (Aliasing Trap)

Популярний трюк зі співбесід – обмін без проміжної змінної через побітове виключне АБО (XOR swap):
```c
void xor_swap(int *a, int *b) {
    *a ^= *b;
    *b ^= *a;
    *a ^= *b;
}
```

У реальних прошивках мікроконтролерів цей трюк є **небезпечним антипатерном**:[^iso-c-n1570]
- **Співпадіння покажчиків (self-aliasing):** якщо викликати функцію з однаковими адресами (`swap(&arr[i], &arr[j])`, де `i == j`, наприклад у внутрішніх циклах сортування QuickSort), `a` та `b` вказують на одну й ту саму комірку пам’яті. На першому кроці `*a ^= *b` число виконує XOR саме із собою (`x ^ x == 0`). У результаті змінна безповоротно **обнуляється** замість збереження свого значення.
- **Зниження продуктивності конвеєра:** ланцюжок інструкцій XOR створює жорстку залежність за даними (RAW – Read After Write hazard), що зупиняє суперскалярні конвеєри сучасних процесорів (наприклад Cortex-M7). Класичний варіант із тимчасовою змінною `tmp` дає компілятору можливість виконувати завантаження `LDR` паралельно.

### Захисне програмування та узагальнений обмін

У надійному вбудованому ПЗ функція `swap` повинна захищатися від розіменування нульових покажчиків:
```c
void safe_swap(int *a, int *b) {
    if (a == NULL || b == NULL || a == b) {
        return;
    }
    int tmp = *a;
    *a = *b;
    *b = tmp;
}
```
Для узагальненого обміну довільних типів даних (структур сенсорів, конфігураційних буферів) у мові C використовують `void *` разом із `sizeof` та `memcpy`.
