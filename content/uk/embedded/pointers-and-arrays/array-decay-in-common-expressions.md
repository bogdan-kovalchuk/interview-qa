## Short answer

**Array decay** – автоматичне перетворення масиву на вказівник на його перший елемент.

Відбувається у більшості виразів:
- При передачі у функцію: `f(arr)` -> функція отримує `int*`;
- У арифметиці: `arr+1` -> `int*`;
- При присвоєнні: `int *p = arr`.

Наслідок: функція <span class="warn">втрачає інформацію про розмір</span> масиву. Тип стає `int*`, а не `int[N]`.[^embeddedinterviewlab]

## Detailed explanation

Термін **array decay** (розпад масиву) позначає неявне перетворення типу виразу в мовах C та C++, під час якого об’єкт типу «масив з N елементів типу T» автоматично перетворюється на значення типу «вказівник на T» (`T *`), що містить адресу першого елемента масиву (`&arr[0]`).[^iso-c-n1570]

### Чому відбувається decay: семантика мови C

За стандартом ISO/IEC 9899 (§6.3.2.1 p3), будь-який вираз типу масиву в більшості синтаксичних контекстів автоматично перетворюється на rvalue-вказівник:[^iso-c-n1570]

- Масив у C є неперервною послідовністю однакових елементів у пам’яті, але не є самостійним першокласним значенням: його не можна скопіювати звичайним оператором присвоєння (`arr1 = arr2;` є нелегальним виразом).
- Отриманий у результаті decay вказівник є тимчасовим значенням (rvalue). Тому вирази на кшталт `arr++` або `arr = ptr` викликають помилку компіляції: ім’я масиву не є модифікованим lvalue.

### Основні контексти, у яких виникає array decay

Decay відбувається практично в усіх виразах, де фігурує ім’я масиву (за винятком операндів `sizeof`, `_Alignof`, унарного `&` та ініціалізації масиву рядковим літералом):[^iso-c-n1570]

1. **Індексація через квадратні дужки (`[]`):**
   - Згідно зі стандартом ISO C (§6.5.2.1), операція індексації масиву `arr[i]` за нормативним визначенням є тотожною виразу розіменування зі зміщенням:
     ```c
     arr[i]  <==>  *((arr) + (i))
     ```
   - Щоб виконати додавання покажчика та цілого числа `arr + i`, масив `arr` зобов’язаний пройти decay до типу `T *`.
   - Наслідком цієї семантики є знаменита властивість комутативності: вираз `i[arr]` у C є абсолютно валідним і повертає те саме значення, що й `arr[i]`, оскільки `*(arr + i)` еквівалентно `*(i + arr)`.
2. **Передача аргументів у функцію:**
   - При виклику `process(arr)` вираз `arr` розпадається до покажчика на перший елемент. Усі виклики функцій у C приймають масив як звичайний покажчик на початок блоку пам’яті.
3. **Адресна арифметика:**
   - Будь-які операції зсуву (`arr + 1`, `arr - 2`, знаходження різниці адрес двох елементів `ptr - arr`) вимагають перетворення масиву на покажчик перед виконанням арифметики.
4. **Присвоєння та ініціалізація вказівників:**
   - У конструкції `int *p = arr;` ім’я масиву перетворюється на вказівник `&arr[0]`, значення якого записується в змінну `p`.
5. **Операції порівняння (`==`, `!=`, `<`, `>`):**
   - У виразі `if (arr1 == arr2)` або `if (arr == ptr)` порівнюються не елементи масивів, а їхні числові адреси в пам’яті після decay. Для побайтового порівняння вмісту буферів в embedded-коді слід використовувати `memcmp()`.
6. **Тернарний умовний оператор (`?:`):**
   - У виразі `condition ? arr1 : arr2` результатом стає покажчик типу `T *`, оскільки обидва операнди зазнають decay.

### Інженерні наслідки для вбудованих систем (Embedded Systems)

- **Нульовий оверхед під час виконання (Zero Runtime Overhead):** операція decay існує суто на етапі компіляції в системі типів. Компілятор не генерує додаткових машинних інструкцій: адреса базового масиву завантажується в регістр процесора (інструкцією `ADR` або `LDR r0, =arr` в архітектурі ARM).[^iso-c-n1570]
- **Втрата контролю розміру:** після decay тип `int[N]` стирається до `int *`. Викликана функція втрачає будь-яку інформацію про кількість елементів у буфері, що вимагає явної передачі довжини для захисту від переповнення буфера (buffer overflow).
