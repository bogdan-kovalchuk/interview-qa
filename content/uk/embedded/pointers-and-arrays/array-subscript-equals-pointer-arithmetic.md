## Question code

```c
int arr[4]={10,20,30,40};
printf("%d %d",*(arr+3), arr[3]);
```

## Short answer

Обидва виводять `40`.

`*(arr+3)` -> pointer arithmetic: зсув на 3 елементи, розіменування = `arr[3] = 40`. `arr[3]` -> subscript operator, за визначенням = `*(arr+3)`.

Вони **ідентичні за стандартом**. Компілятор генерує однаковий машинний код для обох варіантів.[^embeddedinterviewlab]

## Detailed explanation

### Стандарт C: тотожність індексації та арифметики вказівників

У мові C оператор індексації масиву `[]` строго визначений через арифметику вказівників і розіменування. За стандартом ISO/IEC 9899 (C11, пункт 6.5.2.1 Array subscripting, параграф 2): вираз `E1[E2]` за визначенням повністю ідентичний виразу `(*((E1) + (E2)))`.[^iso-c-n1570]

У наведеному фрагменті обидва вирази звертаються до четвертого елемента масиву:
- `*(arr + 3)` явно обчислює адресу зі зміщенням у 3 елементи типу `int` і розіменовує її;
- `arr[3]` компілятор транслятора розгортає в той самий вираз `*(arr + 3)`;
- Обидва вирази повертають значення `40`.[^embeddedinterviewlab]

Під час обчислення `arr + 3` масив затухає (decay) до вказівника на свій нульовий елемент `&arr[0]` (пункт 6.3.2.1).[^iso-c-n1570] До базової адреси додається зміщення `3 * sizeof(int)`. На 32-розрядній архітектурі зі значенням `sizeof(int) == 4` це становить зсув на 12 байтів уперед.

### Внутрішнє представлення в AST та генерація машинного коду

На етапі побудови абстрактного синтаксичного дерева (AST) компілятор C зводить синтаксис квадратних дужок до вузла непрямого доступу за розрахованою адресою. Для обох форм запису оптимізатор генерує абсолютно однаковий проміжний код ідентичної структури.

Для мікроконтролера на базі архітектури ARM Cortex-M обидва вирази транслюються в одну і ту саму асемблерну інструкцію завантаження з безпосереднім зміщенням:

```assembly
LDR R0, [R1, #12]   ; R1 містить базову адресу arr, зміщення #12 (3 * 4 байти)
```

Компілятор не створює додаткових інструкцій або накладних витрат: байтовий код є бінарно ідентичним незалежно від обраного стилю запису.

### Комутативність додавання та феномен 3[arr]

Оскільки операція бінарного додавання над вказівником і цілим числом є комутативною (`a + b == b + a`), вираз `*(arr + 3)` повністю еквівалентний виразу `*(3 + arr)`. Розкриваючи це твердження у зворотний бік через визначення індексації, отримуємо синтаксично валідний вираз `3[arr]`.[^iso-c-n1570]

Цей вираз також повертає значення `40` і успішно збирається будь-яким стандартним компілятором C. Він наочно доводить, що квадратні дужки в C не прив’язані до об’єкта «масив» як у мовах високого рівня (C#, Java), а є симетричним оператором зміщення адреси.

### Рекомендації стандартів кодування (MISRA C)

Незважаючи на технічну еквівалентність, використання арифметики вказівників замість індексації в прикладному та системному коді суворо регламентується стандартами функціональної безпеки:

- **MISRA C:2012 (правило 18.4):** наполегливо рекомендує надавати перевагу нотації `arr[i]` над `*(arr + i)` при роботі з масивами. Індексація наочно передає намір розробника, демонструючи, що обробляється елемент відомої колекції.
- **Статичний аналіз:** інструменти перевірки коду (Coverity, Polyspace, Cppcheck) набагато ефективніше верифікують межі буферів та виявляють помилки out-of-bounds, коли доступ оформлено через `arr[i]`, тоді як розіменування складних виразів арифметики вказівників підвищує ймовірність пропуску дефекту.
- **Читабельність:** екзотичні конструкції на зразок `3[arr]` або глибоко вкладені зміщення `*(*(p + i) + j)` суворо забороняються у виробничих кодових базах як джерело помилок супроводу.
