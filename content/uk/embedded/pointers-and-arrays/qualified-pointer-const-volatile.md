## Short answer

Qualifier – частина типу вказівника, що вказує на властивості даних або самого вказівника.

`const int *p` – qualifier на дані: не можна змінити `*p`. Можна дати менш qualified вказівник: `int *p` -> `const int *q = p` (додавання const – OK), зворотне -> warning/error.

`volatile uint32_t *reg` – кожен доступ реально виконується (для registers).

Правило: можна **додавати** qualifier при присвоєнні, але <span class="warn">не знімати</span> без explicit cast.[^embeddedinterviewlab]

## Detailed explanation

### Кваліфікатори типу у стандарті C

Стандарт ISO/IEC 9899 (§6.7.3) визначає чотири базові кваліфікатори типів (`type qualifiers`): `const`, `volatile`, `restrict` та `_Atomic`.[^iso-c-n1570] Кваліфікатор може належати або до самого вказівника як змінної, або до типу об’єкта, на який цей вказівник посилається.

Для однозначного розуміння кваліфікованих вказівників застосовується правило читання оголошень **праворуч-ліворуч** (від імені ідентифікатора):[^iso-c-n1570]
1. `const int *p` (або еквівалентний запис `int const *p`): «вказівник на константне ціле». Сам вказівник `p` можна переміщати (`p++`), але модифікація даних через нього `*p = 10;` заборонена на етапі компіляції.
2. `int * const p`: «константний вказівник на ціле». Адреса, збережена у `p`, фіксована і не може змінюватися після ініціалізації (`p++` є помилкою), проте дані за цією адресою змінювати дозволено (`*p = 10;`).
3. `const int * const p`: «константний вказівник на константні дані». Ні адресу, ні дані модифікувати не можна.
4. `volatile uint32_t *reg`: «вказівник на мінливе (volatile) значення». Звернення за адресою `*reg` не може бути викинуте або кешоване компілятором у регістрі процесора.

### Кваліфікатори у розробці прошивок (Embedded MMIO)

Для роботи з регістрами апаратної периферії мікроконтролерів (наприклад, у CMSIS-хедерах для STM32 або NXP) застосовується комбінація кваліфікаторів:[^embeddedinterviewlab]
```c
/* Базовий макрос доступу до регістра або оголошення вказівника: */
#define UART0_DR  (*(volatile uint32_t *)0x4000C000)
volatile uint32_t * const UART0_PTR = (volatile uint32_t *)0x4000C000;
```
- Кваліфікатор `volatile` вказує компілятору, що значення в регістрі даних периферії може змінюватися незалежно від коду (апаратно при надходженні байта по лінії RX) або що кожен запис має сторонній фізичний ефект (відправка байта по TX). Компілятор зобов’язаний генерувати реальні інструкції `LDR`/`STR` для кожного звернення.
- Кваліфікатор `const` після зірочки (`* const`) захищає сам покажчик-змінну від випадкового перезапису фіксованої адреси периферії в пам’яті (забороняє `UART0_PTR = ...`).
- Якщо регістр апаратури доступний лише для читання (Read-Only статусний регістр), дані оголошують як `const volatile uint32_t *`: значення змінюється апаратно (`volatile`), але спроба програмного запису викличе помилку компіляції (`const`).

### Правила сумісності та поширення кваліфікаторів (Qualification Conversion)

Згідно зі стандартом C (§6.5.16.1), операція присвоєння вказівників дозволена, якщо обидва операнди вказують на сумісні типи, і тип, на який вказує лівий операнд, має всі кваліфікатори типу правого операнда (дозволено неявно **додавати** кваліфікатори):[^iso-c-n1570]
- `int *p; const int *cp = p;` – цілком коректно. Ми розширюємо гарантії безпеки: звичайні дані тепер доступні через покажчик лише для читання.
- `const int *cp; int *p = cp;` – порушення стандарту (попередження або помилка компілятора). Спроба відкинути (`cast away`) кваліфікатор `const` без явного приведення заборонена, а якщо оригінальний об’єкт реально розміщений у Flash-пам’яті, спроба запису через знятий `const` призведе до фатального `HardFault`.[^embeddedinterviewlab]

### Небезпека багаторівневих вказівників (Multi-level Pointers)

Поширена пастка полягає у спробі неявного перетворення `int **` на `const int **`:[^iso-c-n1570]
```c
int *p;
const int **pp = &p; /* Заборонено стандартом C! */
```
Якби це було дозволено, через `*pp` можна було б записати адресу справжньої константи `const int c = 10; *pp = &c;`, після чого модифікувати константу через початковий неконстантний вказівник `*p = 20;`. Тому стандарт C (§6.5.16.1) суворо забороняє таку неявну конвертацію для багаторівневих вказівників.[^iso-c-n1570]
