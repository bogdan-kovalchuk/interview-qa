## Question code

```c
int x=42;
void *p=&x;
printf("%d", *(int*)p);
```

## Short answer

`42`.

Операція `void *p = &x;` виконує дозволене у C неявне перетворення: `p` зберігає адресу `x`, але інформація про конкретний тип стирається.

Вираз `*(int*)p` виконує явне приведення до `int*` із подальшим розіменуванням. Це коректно, оскільки `p` адресує реальний об’єкт типу `int`.

Приведення до невідповідного типу (наприклад, `*(float*)p`) призводить до UB через порушення strict aliasing. Головне правило: вказівник `void*` слід приводити назад до того типу, з якого він був отриманий.[^embeddedinterviewlab]

## Detailed explanation

### Стандартні правила використання вказівників void*

Програма виведе число **42**. Цей приклад ілюструє базові принципи роботи з універсальними покажчиками (`void*`) у мові C.

Згідно зі стандартом ISO/IEC 9899:201x (C11), пункт 6.2.5 (пункт 19) та пункт 6.3.2.3 (пункт 1), тип `void*` є універсальним покажчиком на об’єкт (*pointer to void*) [^iso-c-n1570]. Стандарт гарантує:
1. **Неявне перетворення**: покажчик на будь-який тип об’єкта може бути неявно перетворений на `void*` і навпаки без застосування явного приведення типів (у мові C++ для зворотного перетворення обов’язковим є явний вираз `static_cast<int*>(p)`).
2. **Гарантія кругового перетворення (Round-trip conversion)**: перетворення вказівника на об’єкт у `void*` і подальше перетворення назад до початкового типу гарантовано повертає вказівник, повністю ідентичний оригінальному [^iso-c-n1570].

### Чому не можна розіменовувати void* напряму

Тип `void` є неповним типом (*incomplete type*), розмір якого у стандарті не визначено. Через це пряме розіменування `*p` або адресна арифметика `p++` для покажчика типу `void*` заборонені стандартом ISO C і призводять до помилки компіляції (компілятор GCC підтримує арифметику над `void*` лише як нестандартне розширення, де `sizeof(void) == 1`).

Щоб виконати читання або запис, компілятор повинен володіти вичерпною інформацією про тип:
* Скільки байтів слід завантажити з пам’яті (1, 2, 4 чи 8 байтів).
* Яку машинну інструкцію згенерувати (`LDRB`, `LDRH` чи `LDR`).
* Як інтерпретувати отримані біти (знакове ціле, беззнакове число чи число з рухомою комою).

Вираз `(int*)p` відновлює повний тип вказівника, після чого оператор `*` коректно зчитує 4 байти зі значенням 42.

### Використання void* у вбудованих системах

У мікроконтролерних системах покажчики `void*` є незамінними для реалізації універсальних механізмів:
* **Параметри задач у RTOS**: у FreeRTOS функція створення задачі має сигнатуру:
  ```c
  BaseType_t xTaskCreate(TaskFunction_t pxTaskCode,
                         const char * const pcName,
                         configSTACK_DEPTH_TYPE usStackDepth,
                         void * const pvParameters, /* Універсальний вказівник на контекст задачі */
                         UBaseType_t uxPriority,
                         TaskHandle_t * const pxCreatedTask);
  ```
  Користувач передає адресу структури з параметрами як `void*`, а всередині задачі перетворює її на покажчик конкретного типу.
* **Драйвери DMA та циклічні буфери**: робота з блоками сирої пам’яті незалежно від типу переданих корисних даних.

### Пастки та небезпеки у прошивках

1. **Приведення до несумісного типу (Strict Aliasing та вихід за межі)**: якщо `p` зберігає адресу `int`, а його приводять до `float*` або `double*`, розіменування порушує правило `strict aliasing` або спричиняє вихід за межі виділеного об’єкта через зчитування більшого обсягу пам’яті.
2. **Апаратні помилки вирівнювання (Alignment Faults)**: покажчик `void*` може вказувати на довільну непарну адресу (наприклад, байт у масиві зв’язку). Приведення його до `uint32_t*` та спроба розіменування на процесорах ARM Cortex-M0/M0+ спричинить апаратний виняток `HardFault`, оскільки ядро не підтримує неідеально вирівняний доступ (*unaligned access*).
3. **Втрата кваліфікатора const (`const discarding`)**: якщо змінна була оголошена як `const int x = 42;`, неявне приведення до `void*` замість `const void*` стирає константність. Спроба запису через `*(int*)p = 100;` призведе до апаратного винятку `BusFault` або `HardFault`, якщо об’єкт розташований у постійній пам’яті Flash (`.rodata`). Завжди використовуйте `const void*` для даних, призначених виключно для читання!
