## Question code

```c
char str[] = "hello";
char *p = str;
while(*p) p++;
printf("%td", p-str);
```

## Short answer

`5`.

`str` decay-ується до `char*`, тож цикл йде до `'\0'`: після `'h','e','l','l','o'` – `*p = '\0'` (false) – зупинка циклу. `p` вказує на null-terminator.

`p - str` = 5 елементів = `strlen("hello")`. Це стандартний спосіб реалізації `strlen` через pointer arithmetic, `%td` для `ptrdiff_t`.[^embeddedinterviewlab]

## Detailed explanation

Фрагмент коду демонструє класичну ідіому мови C для визначення довжини текстового рядка шляхом переміщення покажчика до кінцевого нуль-термінатора та наступного обчислення різниці адрес.[^iso-c-n1570]

### Покроковий аналіз виконання коду

1. **Ініціалізація масиву `str`:**
   Рядковий літерал `"hello"` копіюється в локальний масив `char str[]`. Відповідно до стандарту ISO/IEC 9899 (§6.7.9 Initialization), розмір масиву визначається автоматично і дорівнює 6 байтам: 5 друкованих символів `'h'`, `'e'`, `'l'`, `'l'`, `'o'` та обов’язковий нуль-термінатор `'\0'` (байт зі значенням `0x00`).
2. **Ініціалізація покажчика `p`:**
   Вираз `char *p = str;` ініціалізує покажчик адресою нульового елемента масиву `&str[0]` унаслідок неявного перетворення імені масиву на покажчик (array-to-pointer decay, §6.3.2.1 p3).[^iso-c-n1570]
3. **Робота циклу `while(*p) p++;`:**
   - На кожній ітерації перевіряється умова `*p`: значення поточного байта інтерпретується як логічний вираз. Будь-який ненульовий символ є істинним (`true`).
   - Оператор `p++` зміщує вказівник на наступний байт у пам’яті (оскільки `sizeof(char) == 1`).
   - Коли покажчик досягає кінця рядка, `*p` зчитує символ `'\0'`, що дорівнює 0 (`false`). Цикл негайно завершується.
   - У результаті виконання циклу вказівник `p` зупиняється рівно на комірці пам’яті, що містить нуль-термінатор (тобто `p == &str[5]`).

### Різниця покажчиків та специфікатор %td

Операція віднімання покажчиків `p - str` регламентується стандартом ISO/IEC 9899 (§6.5.6 Additive operators, пункт 9):[^iso-c-n1570]

- Оскільки обидва покажчики вказують на елементи одного масиву (включаючи допустиму позицію на нуль-термінатор як останній елемент `str[5]`), операція є повністю коректною і повертає числову різницю їхніх індексів: `5 - 0 = 5`.
- Типом результату віднімання покажчиків є знаковий цілочисельний тип `ptrdiff_t`, оголошений у заголовному файлі `<stddef.h>`.
- У стандарті C99 для виведення значень типу `ptrdiff_t` у функції `printf` введено спеціальний специфікатор довжини `t`, який використовується разом із `d` або `i` (`%td`). Використання `%d` замість `%td` є порушенням типу аргументу на 64-бітних платформах, де `ptrdiff_t` є 64-бітним (`int64_t`), а `%d` очікує 32-бітний `int`.[^iso-c-n1570]

### Реалізація strlen та машинний код ARM Cortex-M

Наведений алгоритм лежить в основі стандартної функції `strlen()` з `<string.h>`:[^embeddedinterviewlab]

```c
size_t my_strlen(const char *s) {
    const char *p = s;
    while (*p) {
        p++;
    }
    return (size_t)(p - s);
}
```

На процесорах ARM Cortex-M такий цикл транслюється у компактний набір інструкцій Thumb-2 із використанням побайтового завантаження з автоінкрементом:

```assembly
// r0 містить адресу str
    MOV     r1, r0          // r1 = p = str
.L_loop:
    LDRB    r2, [r1], #1    // r2 = *p; p = p + 1 (пост-інкремент)
    CMP     r2, #0          // перевірка на '\0'
    BNE     .L_loop         // якщо не нуль, перехід до наступної ітерації
    SUB     r0, r1, r0      // r0 = p - str
    SUBS    r0, r0, #1      // корекція, оскільки LDRB виконав інкремент після '\0'
```

У високопродуктивних бібліотеках C для embedded (Newlib, glibc) стандартний `strlen` зазвичай оптимізують шляхом зчитування даних словами по 32 або 64 біти (word-at-a-time) за допомогою бітової магії виявлення нульового байта (алгоритм Алана Майкрофта), що суттєво зменшує кількість звернень до шини пам’яті.[^embeddedinterviewlab]
