## Question code

```c
char *p = "hello";
printf("%zu", sizeof(p));
```

## Short answer

**4** (на 64-bit – 8).

`p` – вказівник типу `char*`, тож `sizeof(p) = sizeof(char*) = 4` на 32-bit. Не розмір рядка, не 6 (з '\0'), а лише розмір вказівника.

Для розміру рядка: `strlen(p) + 1` = 6 (з null-terminator) або `strlen(p)` = 5.

Порівняй: `char arr[] = "hello"; sizeof(arr) = 6` – тут масив, не вказівник.[^embeddedinterviewlab]

## Detailed explanation

Вираз `sizeof(p)` для вказівника, ініціалізованого рядковим літералом, є однією з класичних концептуальних перевірок на технічних співбесідах з мови C, яка виявляє розуміння різниці між типами даних та механізмом роботи оператора `sizeof`.[^iso-c-n1570]

### Поведінка оператора sizeof у стандарті ISO C

Відповідно до стандарту ISO/IEC 9899 (§6.5.3.4 The sizeof and _Alignof operators), унарний оператор `sizeof` обчислює розмір пам’яті (в байтах), який займає об’єкт або тип операнда.[^iso-c-n1570]

Ключові властивості оператора `sizeof`:
1. **Обчислення під час компіляції (Compile-Time Evaluation):** Оператор `sizeof` оцінюється компілятором виключно на основі статичного типу виразу на етапі компіляції (за винятком масивів змінної довжини VLA, введених у C99).
2. **Тип виразу `p`:** У рядку `char *p = "hello";` змінна `p` оголошена як вказівник на символ (`char *`). Вона зберігає числове значення адреси початку рядкового літерала в сегменті пам’яті констант (`.rodata` у Flash-пам’яті).
3. **Оцінка операнда:** Для виразу `sizeof(p)` компілятор оцінює не розмір того, на що вказує адреса, і не довжину рядка, а виключно розмір самої змінної `p` – тобто `sizeof(char *)`.[^iso-c-n1570]

На 32-бітній архітектурі мікроконтролерів (наприклад, ARM Cortex-M, ESP32, RISC-V 32) адреси пам’яті є 32-бітними, тому `sizeof(char *)` завжди дорівнює **4 байтам**. На 64-бітних платформах результат становить 8 байтів.[^iso-c-n1570]

### Порівняння: покажчик проти масиву символів

Плутанина часто виникає через візуальну схожість оголошення покажчика та масиву, ініціалізованих літералом:[^embeddedinterviewlab]

```c
// Випадок 1: Вказівник
char *p = "hello";
sizeof(p); // Повертає 4 байти (розмір змінної-покажчика в пам’яті)

// Випадок 2: Масив
char arr[] = "hello";
sizeof(arr); // Повертає 6 байтів (розмір усього масиву з урахуванням '\0')
```

- У випадку масиву `arr` тип виразу – `char[6]`. Літерал копіюється у виділений на стеку або в `.data` масив із 6 байтів: `'h'`, `'e'`, `'l'`, `'l'`, `'o'`, `'\0'`. Оператор `sizeof(arr)` обчислює повний обсяг цього масиву.
- У випадку `p` виділяється лише 4-байтна змінна для збереження адреси, яка вказує на незмінний літерал у Flash.

### Як правильно визначати розмір та довжину рядка

Якщо необхідно дізнатися фактичну довжину тексту за покажчиком під час виконання програми, стандарт мови C передбачає спеціалізовані функції бібліотеки `<string.h>`:[^iso-c-n1570]

1. **`strlen(p)`:**
   Повертає кількість друкованих символів до першого нуль-термінатора `'\0'`. Для `"hello"` результат дорівнює `5`. Функція працює за час O(N) шляхом побайтового сканування пам’яті.
2. **`strlen(p) + 1`:**
   Повертає загальний розмір буфера в байтах, необхідний для копіювання чи збереження рядка з урахуванням нуль-термінатора (дорівнює `6`). Цей вираз є обов’язковим для розрахунку розміру пам’яті при виклику `malloc()` або запобіганні переповненню буферів (`buffer overflow`).[^embeddedinterviewlab]

### Специфікатор формату %zu

Оператор `sizeof` завжди повертає беззнакове ціле число типу `size_t` (ISO/IEC 9899, §6.5.3.4 p4). Для правильного та переносного виведення `size_t` через `printf` стандарт C99 ввів специфікатор `%zu`. Використання застарілих специфікаторів `%d` або `%u` є дефектом несумісності типів на 64-бітних платформах, де `size_t` є 64-бітним, а `%u` очікує 32-бітне значення.[^iso-c-n1570]
