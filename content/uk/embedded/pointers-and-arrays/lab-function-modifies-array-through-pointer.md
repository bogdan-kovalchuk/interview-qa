## Question code

```c
void f(int *p, int n){
  p[0]=99;
} int a[3]={1,2,3};
f(a,3);
printf("%d",a[0]);
```

## Short answer

`99`.

`a` decay-ується до вказівника. Функція `f` отримує `int*` – вказівник на перший елемент `a[0]`. `p[0] = 99` – змінює `a[0]` у caller.

Масиви у C передаються by reference (через вказівник на перший елемент) – функція може змінювати оригінальні дані. Якщо потрібне тільки читання: `const int *p`.[^embeddedinterviewlab]

## Detailed explanation

### Покроковий механізм виконання та стандарти C

Код демонструє модифікацію елементів масиву всередині викликаної функції:[^iso-c-n1570]
1. При виклику `f(a, 3)` ідентифікатор масиву `a` автоматично зазнає розпаду (pointer decay) згідно з ISO/IEC 9899 (§6.3.2.1 p3), перетворюючись на вираз типу `int*`, що містить адресу першого елемента `&a[0]`.
2. Аргумент передається за значенням (pass-by-value): параметр `p` функції `f` отримує копію числового значення адреси початку масиву.
3. Вираз `p[0] = 99` згідно з §6.5.2.1 p2 за стандартом еквівалентний операції `*(p + 0) = 99` або просто `*p = 99`. Відбувається розіменування адреси та прямий запис нового значення `99` у ту комірку пам’яті, де зберігається перший елемент `a[0]`.
4. Після повернення керування у викликаючий контекст функція `printf` виводить оновлене значення `a[0]`, тобто число `99`.

### Робота на рівні регістрів та інструкцій ARM Cortex-M

На рівні двійкового коду архітектури ARM Cortex-M процедура виклику відповідає стандарту AAPCS (ARM Architecture Procedure Call Standard):
- У функції-викликачі (caller) адреса масиву `a` на стеку або у секції даних завантажується в регістр `r0`, а число `3` – у регістр `r1`.
- Виконується інструкція переходу зі збереженням адреси повернення `BL f`.
- Тіло функції `f` компілюється у компактну послідовність інструкцій Thumb-2:
  ```assembly
  MOVS r2, #99
  STR  r2, [r0, #0]
  BX   lr
  ```
Інструкція `STR` (Store Register) здійснює прямий 32-бітний запис константи `99` за адресою, збереженою в регістрі `r0`. Масив не дублюється у пам’яті, а операція запису змінює оригінальний буфер.

### Модель пам’яті: pass-by-value для вказівника та емуляція pass-by-reference

У мові C формально відсутня передача параметрів за посиланням (pass-by-reference) – абсолютно всі змінні передаються виключно за значенням (pass-by-value):[^iso-c-n1570]
- Якщо у функції `f` змінити сам покажчик (наприклад, `p = NULL;` або `p++;`), це зачепить лише локальну копію покажчика на стеку або у регістрі `r0` і жодним чином не вплине на вихідний масив `a` у caller.
- Проте, коли копія покажчика розіменовується для запису (`*p = ...`), змінюється пам’ять за вказаною адресою. Таким чином, передача покажчика у C слугує ідіомою для емуляції передачі об’єктів за посиланням.

### Принцип найменших привілеїв та const-correctness у прошивках

Здатність функції змінювати вміст масиву через покажчик створює суттєві ризики для надійності прошивки:[^iso-c-n1570]
- Якщо викликана функція призначена лише для читання даних (наприклад, обчислення контрольної суми CRC або передача по UART), її аргумент обов’язково повинен містити кваліфікатор `const`:
  ```c
  void process(const int *p, int n);
  ```
- Кваліфікатор `const` гарантує, що компілятор виявить будь-яку випадкову спробу запису `p[0] = 99` ще на етапі компіляції.
- Крім того, функція з неконстантним параметром `int *p` не може безпечно приймати константні буфери, розташовані у Flash-пам’яті (`.rodata`). Спроба виконати інструкцію запису `STR` у простір Flash-пам’яті мікроконтролера STM32 апаратно згенерує помилку шини та викличе `HardFault`.
