## Short answer

`void (*handlers[8])(void)` – масив із 8 function pointers.

Використання:
- **Software interrupt router**: `handlers[irq_id]();`;
- **State machine**: `state_fn[current_state]();`;
- **Protocol parser**: `cmd_handlers[cmd_id](payload);`;
- **Bootloader jump**: таблиця точок входу у Flash.

Переваги: O(1) dispatch, легко розширювати через зміну таблиці. Cortex-M Vector Table – апаратна реалізація цього патерну.[^embeddedinterviewlab]

## Detailed explanation

### Синтаксис оголошення та типізація масивів вказівників на функції

Оголошення `void (*handlers[8])(void)` описує масив із восьми елементів, кожен із яких є вказівником на функцію, що не приймає аргументів і повертає `void`.[^iso-c-n1570] Згідно з правилами розбору деклараторів C, квадратні дужки `[8]` мають вищий пріоритет над зірочкою розіменування `*`. Круглі дужки навколо `*handlers[8]` необхідні: без них запис `void *handlers[8](void)` трактувався б компілятором як неприпустимий масив функцій, що повертають нетипізований вказівник `void*`.

Для підвищення надійності та читабельності системного коду масиви зворотних викликів оголошують через `typedef`:

```c
typedef void (*irq_handler_t)(void);
static const irq_handler_t handlers[8] = {
    isr_uart_rx,
    isr_uart_tx,
    isr_timer_overflow,
    /* ... */
};
```

### Архітектурні сценарії використання в embedded-системах

Масиви вказівників на функції є ключовим патерном побудови архітектури прошивок:

1. **Диспетчеризація пакетів та команд протоколу (jump table):** замість громіздких конструкцій `switch-case` або каскадів `if-else`, обробник протоколу здійснює прямий перехід за опкодом: `cmd_table[opcode](payload);`. Це гарантує стабільний час диспетчеризації O(1) незалежно від кількості підтримуваних команд.
2. **Табличні кінцеві автомати (FSM state table):** стан автомата є індексом у таблиці функцій обробки поточного стану `state_handlers[current_state](event_ctx)`.
3. **Апаратна таблиця векторів переривань (Vector Table):** в архітектурі ARM Cortex-M початкова адреса пам’яті (або зміщення у VTOR) фізично представлена масивом 32-розрядних слів, перше з яких є початковим показником стека (MSP), а всі наступні – вказівниками на функції-обробники апаратних винятків (Reset, NMI, HardFault, SysTick та периферійні IRQ).[^embeddedinterviewlab]

### Розміщення таблиць диспетчеризації у Flash-пам’яті (.rodata)

У мікроконтролерах із суворими обмеженнями оперативної пам’яті (SRAM) таблиці диспетчеризації обов’язково позначають специфікаторами `static const`. Це сигналізує лінкеру про можливість зберегти масив безпосередньо в секції постійної пам’яті (`.rodata` у Flash) без копіювання в RAM під час запуску системи:[^gcc-gccint-sections]

```c
static const cmd_handler_t dispatch_table[CMD_MAX] = { ... };
```

Якщо опустити `const`, масив опиниться в секції `.data` або конструюватиметься на стеку під час кожного входу у функцію, марнуючи циклічний ресурс пам’яті та виділений стек.

### Безпека виконання: перевірка меж, валідація NULL та інструкції переходу

Виклик через неперевірений індекс або неініціалізований елемент несе критичні ризики для безпеки вбудованого пристрою:

- **Контроль діапазону:** обов’язкова перевірка `if (cmd_id >= CMD_MAX)` перед індексацією таблиці. Вихід за межі масиву прочитає довільне слово пам’яті та спробує виконати його як адресу інструкцією непрямого переходу `BLX`, викликавши HardFault.
- **NULL-безпека:** кожен незаповнений слот таблиці має або ініціалізуватися безпечною функцією-заглушкою за замовчуванням (`default_stub_handler`), або явно перевірятися перед викликом: `if (dispatch_table[id] != NULL) dispatch_table[id]();`.
- **Конвеєр та передбачення переходів:** непрямі виклики (`BLX Rm`) не можуть бути вбудовані компілятором (inline) і в ядрах Cortex-M4/M7 можуть скидати конвеєр інструкцій у разі хибного передбачення цільової адреси переходу.
