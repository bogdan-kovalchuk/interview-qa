## Short answer

**Перший – безпечний**. `if(p)` ≡ `if(p != NULL)` – перевірка перед розіменуванням. Якщо `p == NULL` -> умова false, `*p` не виконується.

<span class="warn">Другий – undefined behavior (UB)</span>: `*p = 5` при `p == NULL` -> HardFault на Cortex-M.

Але: перевірка NULL не захищає від dangling pointer або wild pointer – вони ненульові, але невалідні; NULL-check – необхідна, але недостатня умова безпеки.[^embeddedinterviewlab]

## Detailed explanation

Порівняння цих двох фрагментів коду зачіпає ключові поняття стандарту C: семантику нульового покажчика, умови безпечного розіменування та межі захисту, який забезпечує перевірка на `NULL`. Стандарт ISO/IEC 9899 (§6.3.2.3 Pointers, §6.5.3.2 Address and indirection operators) чітко визначає поведінку в обох випадках.[^iso-c-n1570]

### Порівняльний аналіз виразів

1. **Варіант 1: `int *p = NULL; if (p) *p = 5;`**
   - Константа `NULL` розгортається в нульовий покажчик (null pointer constant, наприклад `((void *)0)` або `0`).
   - Умова `if (p)` є скороченим записом перевірки `if (p != NULL)`.
   - Оскільки змінна `p` ініціалізована значенням `NULL`, умова перевірки повертає хибу (`false` / `0`).
   - Тіло умови `*p = 5;` ніколи не виконується.
   - Поведінка програми повністю детермінована, коректна та безпечна.

2. **Варіант 2: `int *p = NULL; *p = 5;`**
   - Покажчик зі значенням `NULL` розіменовується напряму.
   - Згідно з ISO/IEC 9899 (§6.5.3.2 p4), розіменування нульового або невалідного покажчика є **невизначеною поведінкою (undefined behavior)**.[^iso-c-n1570]

### Що відбувається на рівні мікроконтролера ARM Cortex-M

На настільних ОС (Linux, Windows) звернення за адресою `0` перехоплюється блоком управління пам’яттю (MMU) і викликає негайне завершення процесу (`Segmentation fault`). Проте на мікроконтролерах ARM Cortex-M ситуація суттєво відрізняється:[^iso-c-n1570]

- **Карта пам’яті:** Адреса `0x00000000` є реальною фізичною адресою. У багатьох мікроконтролерах (наприклад, STM32 після старту за замовчуванням) адреса `0x00000000` відображає початок Flash-пам’яті (alias для `0x08000000`), де зберігаються початкове значення покажчика стека (MSP) та таблиця векторів переривань.
- **Спроба запису (`*p = 5`):** Запис у Flash-пам’ять без попереднього апаратного розблокування та налаштування контролера Flash викликає апаратну помилку шини. Процесор негайно генерує апаратний виняток `HardFault` (або `BusFault` / `MemManage`).
- **Спроба читання (`int x = *p`):** Якщо виконати читання за покажчиком `NULL`, процесор успішно прочитає значення першого слова таблиці векторів (початковий SP) без жодного апаратного збою. Це надзвичайно підступний сценарій, коли помилка залишається непоміченою, але програма оперує спотвореними даними.
- **Захист через MPU:** Щоб уникнути цього, в надійних прошивках блок захисту пам’яті (MPU – Memory Protection Unit) конфігурують так, щоб перші 32 байти пам’яті (або нульова сторінка) мали заборону на доступ (no-access). Тоді будь-яка спроба читання чи запису за покажчиком `NULL` гарантовано викликає `MemManageFault`.

### Чому перевірка if (p) є необхідною, але недостатньою

Помилка багатьох інженерів полягає в переконанні, що захисна перевірка `if (p != NULL)` гарантує валідність покажчика. Насправді покажчик може містити невалідну адресу, будучи відмінним від `NULL`:[^iso-c-n1570]

1. **Дикий покажчик (wild pointer):** Неініціалізована локальна змінна `int *p;` містить сміття, що залишилося на стеку (наприклад `0x20005F12`). Перевірка `if (p)` успішно пройде, оскільки значення не дорівнює нулю, але спроба запису призведе до руйнування пам’яті (memory corruption).
2. **Висячий покажчик (dangling pointer):** Покажчик, який посилався на динамічну пам’ять, звільнену через `free(p)`, або на локальну змінну, час життя якої завершився. Покажчик залишається ненульовим, але вказує на невалідну область пам’яті.
3. **Невирівняний покажчик (misaligned pointer):** Покажчик, отримати доступ до якого неможливо через апаратні обмеження вирівнювання ядра Cortex-M0.

### Інженерні правила безпеки

- Завжди ініціалізувати покажчики при оголошенні: `int *p = NULL;`.
- Зануляти покажчик одразу після звільнення ресурсу: `free(p); p = NULL;`.
- Використовувати статичні аналізатори коду та перевірки часу налагодження: `assert(p != NULL);`.[^iso-c-n1570]
