## Question code

```c
char *s = "hello";
s[0] = 'H';
```

## Short answer

Рядковий літерал `"hello"` зберігається у **.rodata** (Flash/read-only). `s` вказує на цю read-only область.

Запис `s[0] = 'H'` -> <span class="warn">undefined behavior</span>: на ПК – segfault, на MCU – HardFault (якщо MPU захищає Flash) або тихий запис у Flash (що не спрацьовує).

Правильно: `char arr[] = "hello";` – компілятор копіює рядок у writable масив (stack або .data). Тоді `arr[0] = 'H'` – легально.[^embeddedinterviewlab]

## Detailed explanation

### Статус рядкових літералів у стандарті C

Згідно зі стандартом ISO/IEC 9899 (§6.4.5 String literals, пункт 7):
"Якщо програма намагається модифікувати такий масив, поведінка є невизначеною (undefined behavior)"[^iso-c-n1570].

В історичній мові C рядковий літерал формально має тип `char[]` (масив мутабельних символів), а не `const char[]`, як у C++. Це зроблено заради зворотної сумісності зі старим кодом, написаним до стандартизації C89. Через це компілятор дозволяє присвоїти адресу рядкового літерала звичайному неконстантному вказівнику `char *s = "hello";` без обов’язкового попередження. Проте логічно цей масив є незмінним.

Крім того, компіляторам дозволено об’єднувати однакові рядкові літерали (string literal pooling). Якщо кілька частин програми використовують `"hello"`, лінкер може виділити для них єдину копію в пам’яті. Модифікація такого рядка в одному місці зламала б логіку всіх інших частин програми.

### Розміщення в пам’яті мікроконтролера та асемблер

У вбудованих системах на базі ARM Cortex-M скрипт компонування (linker script) розміщує рядкові літерали в константній секції `.rodata` або безпосередньо в секції виконуваного коду `.text`:
- Фізично ці секції розташовані в незалежній Flash-пам’яті (ROM), адреси якої зазвичай починаються з `0x08000000` (на STM32) або `0x00000000`[^armv7m-arm].
- Змінна `s` створюється в стеку (SRAM) і містить 32-бітну адресу рядка у Flash.
- Операція `s[0] = 'H'` транслюється в інструкцію запису байта в пам’ять: `STRB r1, [r0]`[^armv7m-arm].

### Наслідки спроби запису на різних платформах

1. **Мікроконтролери без MPU (типовий випадок Cortex-M3/M4)**:
   Внутрішня Flash-пам’ять мікроконтролера апаратно призначена лише для читання інструкцій та констант через шину I-Code/D-Code. Інструкція `STRB` не може змінити стан комірки Flash (для запису у Flash потрібна складна послідовність розблокування спеціального контролера Flash memory controller зі стиранням сторінок). Контролер шини фіксує спробу недозволеного доступу і генерує апаратну помилку `BusFault`, яка за замовчуванням переходить у `HardFault`[^armv7m-arm].
2. **Мікроконтролери з активним MPU**:
   Якщо простір Flash налаштовано як Read-Only, ядро негайно перериває виконання інструкції та викликає обробник `MemManageFault`.
3. **Операційні системи з віртуальною пам’яттю (Linux / Windows / RTOS з MMU)**:
   Секція `.rodata` відображається в сторінки пам’яті без права на запис (Read-Only). Спроба запису викликає апаратне виключення MMU (Page Fault), яке операційна система транслює у сигнал аварійного завершення `SIGSEGV` (Segmentation Fault).

### Правильні інженерні патерни

1. **Якщо рядок константний**: завжди захищати вказівник кваліфікатором `const`:
   ```c
   const char *s = "hello";
   ```
   У такому разі спроба `s[0] = 'H'` викличе помилку компіляції (`error: assignment of read-only location`), що запобігає виникненню фатальних помилок у рантаймі.
2. **Якщо потрібен змінний буфер**: оголошувати рядок як масив:
   ```c
   char s[] = "hello";
   s[0] = 'H'; // Повністю легально!
   ```
   У цьому випадку компілятор виділяє 6 байтів у стеку (або в оперативній пам’яті `.data`) і копіює початкові символи з Flash у RAM під час ініціалізації. Оскільки SRAM відкрита для читання та запису, модифікація окремих символів є повністю безпечною.
