## Short answer

**Вказівник** – змінна, яка зберігає адресу іншого об’єкта або функції в пам’яті.[^dou-embedded-interview] Наприклад: `int x = 10; int *p = &x;`. Оператор `&` бере адресу, а `*p` розіменовує вказівник і дає доступ до значення.

Вказівники потрібні для передачі об’єктів у функції без копіювання, роботи з масивами, динамічною пам’яттю, callback-ами, структурами даних і memory-mapped регістрами. Небезпеки: `NULL`, dangling pointer, вихід за межі масиву, неправильне приведення типів.

## Detailed explanation

### Суть концепції та стандарт ISO C

Вказівник (`pointer`) у мові C є похідним типом даних (`derived type`), значенням якого виступає адреса пам’яті об’єкта або функції (ISO/IEC 9899:2011, §6.2.5 clause 20)[^iso-c-n1570].

Оголошення вказівника має вигляд `T *ptr;`, де:
- `T` – це базовий тип (`referenced type`), на який вказує покажчик;
- `ptr` – власне змінна-вказівник, яка зберігає числове значення адреси.

Базовий тип `T` є критично важливим для компілятора з двох причин:
1. **Семантика розіменування**: визначає, скільки байтів процесор повинен зчитати або записати при виконанні операції непрямого доступу `*ptr` (наприклад, 1 байт для `uint8_t*`, 4 байти для `uint32_t*`), а також як інтерпретувати прочитані біти (ціле число зі знаком, без знака чи число з плаваючою комою).
2. **Арифметика вказівників**: операція `ptr + 1` зміщує фізичну адресу на `sizeof(T)` байтів у пам’яті.

Вказівник на тип `void*` є універсальним вказівником на «сиру» пам’ять. Він може зберігати адресу будь-якого об’єкта даних, але не може бути безпосередньо розіменований або використаний в арифметиці без явного приведення до конкретного типу.

### Робота на рівні пам’яті та асемблера ARM Cortex-M

На фізичному рівні мікроконтролера вказівник є звичайним 32-бітним числом (адресою в пам’яті), яке зберігається в одному з регістрів процесора (`R0`–`R12`) або у слоті стека SRAM[^armv7m-arm].

Робота через вказівник створює додатковий рівень непрямої адресації (`indirection`):

```c
uint32_t x = 0xAA;
uint32_t *p = &x;
uint32_t val = *p;
```

Компілятор ARM GCC транслює цей код у дві окремі інструкції завантаження пам’яті:

```assembly
LDR     R0, [SP, #p_offset] ; Крок 1: зчитування адреси x зі змінної p в регістр R0
LDR     R1, [R0]            ; Крок 2: розіменування адреси – завантаження значення x в R1
```

Безпосереднє звернення до локальної змінної вимагає лише однієї інструкції (`LDR R1, [SP, #x_offset]`), тоді як доступ через вказівник вимагає спочатку зчитати адресу, а потім дані за нею.

### Застосування вказівників в Embedded-розробці

1. **Memory-Mapped I/O (MMIO):** Прямий доступ до конфігураційних та статусних регістрів мікроконтролера через приведення апаратної адреси:
   ```c
   #define RCC_AHB1ENR (*((volatile uint32_t*)0x40023830))
   RCC_AHB1ENR |= (1U << 0); // увімкнення тактування порту GPIOA
   ```
2. **Передача даних за посиланням (Pass-by-Reference):** Передача вказівника на великі структури або масиви (буфери DMA, пакети Ethernet, дескриптори) уникає накладних витрат часу та пам’яті стека на глибоке копіювання даних.
3. **Колбеки та поліморфізм:** Вказівники на функції дозволяють реалізовувати архітектуру підписки на події, таблиці драйверних операцій (HAL `struct file_operations`) та віртуальні таблиці.
4. **Організація динамічних структур:** Побудова кільцевих буферів (ring buffer), зв’язаних списків задач у планувальниках RTOS (FreeRTOS `List_t`).

### Ризики та правила безпеки

- **Нульовий вказівник (`NULL pointer`):** На ARM Cortex-M адреса `0x00000000` фізично існує і відображає початкове значення покажчика стека (MSP) у Flash-пам’яті. Читання за нульовою адресою не викличе апаратного збою, але прочитає сміття, а спроба запису викличе `BusFault`[^armv7m-arm]. Завжди перевіряйте вказівники на `NULL` перед використанням.
- **Висячий вказівник (`Dangling pointer`):** Посилання на локальну змінну, стек якої було зруйновано після виходу з функції, або на вивільнений динамічний блок.
- **Вирівнювання (`Alignment`):** Розіменування 32-бітного вказівника за адресою, некратною 4, спричиняє `HardFault` на ядрах ARM Cortex-M0/M0+.
