## Question code

```c
void *p = malloc(10);
p++;
```

## Short answer

<span class="warn">НІ, це невалідний стандартний C</span> (constraint violation). Стандарт забороняє pointer arithmetic на `void*` – розмір елемента невідомий (sizeof(void) не визначений), тому компілятор має видати діагностику.

GCC дозволяє як extension: трактує `sizeof(void) = 1`, тому `p++` -> +1 байт. З `-pedantic-errors`: помилка.

Правильно: перед arithmetic – cast до конкретного типу: `uint8_t *bp = (uint8_t*)p; bp++;`[^embeddedinterviewlab]

## Detailed explanation

Операція інкременту покажчика типу `void *` (`p++`) є **невалідною у стандартному C** і становить пряме порушення правил мови (constraint violation). Стандарт ISO/IEC 9899 чітко регламентує умови застосування адитивних операторів до покажчиків.[^iso-c-n1570]

### Неповний тип void у стандарті ISO C

Згідно з ISO/IEC 9899 (§6.2.5 Types, p19), тип `void` є неповним типом (incomplete type), який за своєю природою ніколи не може бути доповненим (cannot be completed). Об’єктів типу `void` не існує, і пам’ять під них виділити неможливо.

Відповідно до §6.5.3.4 (The sizeof and _Alignof operators), оператор `sizeof` заборонено застосовувати до неповних типів або виразів, що мають неповний тип. Тобто вираз `sizeof(void)` у чистому стандартному C не має числового значення і є синтаксичною помилкою.

Далі, стандарт ISO/IEC 9899 (§6.5.6 Additive operators, p2) визначає обмеження для операцій додавання та віднімання: для додавання один з операндів повинен бути покажчиком на повністю визначений тип об’єкта (complete object type). Оскільки `void` не є повним типом об’єкта, операції `p + 1`, `p++`, `p += 1` над змінною типу `void *` порушують обмеження стандарту. Відповідно до §5.1.1.3, компілятор, що відповідає стандарту, зобов’язаний видати діагностичне повідомлення (error або warning).[^iso-c-n1570]

### Розширення GNU C (GCC Extension) та його підступність

Компілятори GCC та Clang історично містять власне нестандартне розширення мови (GNU extension): вони фіктивно прирівнюють `sizeof(void) == 1`. Метою цього розширення було спрощення низькорівневої роботи з сирими байтовими буферами в ядрі Linux та системних бібліотеках:

```c
// У режимі розширень GCC (за замовчуванням):
void *ptr = buffer;
ptr++; // Компілюється без помилок, зсуваючи покажчик на 1 байт
```

Проте покладання на цю поведінку в embedded-розробці створює серйозні проблеми:[^iso-c-n1570]

1. **Втрата портабельності:** Код відмовляється компілюватися комерційними вбудованими компіляторами, такими як IAR Embedded Workbench, Keil ARMCC/Arm Compiler 6 у строгому режимі, або TI Code Composer Studio.
2. **Прапорці суворої відповідності:** При ввімкненні прапорців `-std=c99 -pedantic-errors` або `-std=c11 -pedantic` компілятор GCC негайно зупиняє збірку з повідомленням про помилку: `error: wrong type argument to increment`.
3. **C++ сумісність:** У стандартному C++ (ISO/IEC 14882) арифметика покажчиків над `void *` суворо заборонена, навіть за наявності розширень. Спроба скомпілювати цей код C++ компілятором призведе до помилки.

### Портабельне та безпечне рішення для embedded-прошивок

Для побайтового проходження буфера необхідно явно перетворювати покажчик на тип, розмір якого гарантовано дорівнює одному байту:

```c
void *p = malloc(10);
if (p == NULL) {
    return;
}

// Стандартний портабельний спосіб:
uint8_t *byte_ptr = (uint8_t *)p;
byte_ptr++;

// Або використання char*:
char *char_ptr = (char *)p;
char_ptr++;
```

Використання `uint8_t *` (з заголовка `<stdint.h>`) або `unsigned char *` є стандартизованим і повністю портабельним. Крім того, стандарт C (§6.5 p7) прямо дозволяє доступ до будь-яких об’єктів у пам’яті через покажчики на символьні типи (`char`, `unsigned char`, `uint8_t`), не порушуючи правил суворого псевдонімування (strict aliasing).

### Стандарти безпеки (MISRA C)

У промисловій розробці критичного ПЗ (автомобільна, авіаційна техніка) стандарт **MISRA C:2012** (Rule 18.4) вимагає: «Оператори `+`, `-`, `+=`, `-=` не повинні застосовуватися до виразів типу покажчика, якщо тільки цей покажчик не вказує на елемент масиву». Застосування арифметики до `void *` заборонене правилом MISRA C:2012 Rule 11.8 та загальними правилами типізації.[^iso-c-n1570]
