## Question code

```c
int x=10;
int *p=&x;
int **pp=&p;
**pp=20;
printf("%d",x);
```

## Short answer

`20`.

Ланцюжок: `pp` -> `&p` (адреса вказівника `p`), `*pp` -> розіменування = сам вказівник `p` (адреса `x`), `**pp` -> подвійне розіменування = значення `x`.

`**pp = 20` -> запис 20 у `x` через ланцюжок, тож `x` стає 20. Всі три: `x`, `*p`, `**pp` тепер = 20.[^embeddedinterviewlab]

## Detailed explanation

### Рівні непрямої адресації та фізична модель пам’яті

Програма виведе `20`. Цей приклад ілюструє роботу багаторівневої непрямої адресації (pointer indirection), де подвійний покажчик (pointer to pointer) розіменовується двічі для запису значення в первинну змінну.

Розглянемо фізичне розташування змінних у стеку 32-розрядного мікроконтролера ARM Cortex-M:
1. Змінна `x` типу `int` займає 4 байти пам’яті (наприклад, за адресою `0x20000004`) і містить початкове значення `10`.
2. Одинарний покажчик `p` типу `int*` займає 4 байти за сусідньою адресою `0x20000008` і зберігає адресу змінної `x`, тобто число `0x20000004`.[^iso-c-n1570]
3. Подвійний покажчик `pp` типу `int**` займає 4 байти за адресою `0x2000000C` і зберігає адресу покажчика `p`, тобто число `0x20000008`.

Під час обчислення виразу `**pp = 20`:
- Перше розіменування `*pp` зчитує вміст за адресою `0x20000008` і отримує значення покажчика `p` (адресу `0x20000004`).
- Друге розіменування `**pp` звертається за отриманою адресою `0x20000004`, яка є коміркою пам’яті самої змінної `x`.
- Оператор присвоєння записує туди нове значення `20`.

Після цього вирази `x`, `*p` та `**pp` є трьома різними шляхами доступу до однієї й тієї самої комірки пам’яті, тож усі вони повертають `20`.

### Різниця між модифікацією вказівника (*pp) та кінцевого значення (**pp)

Критично важливо не плутати операції одного та двох рівнів розіменування:

- **Одинарне розіменування (`*pp = new_ptr`):** модифікує сам проміжний покажчик `p`. Наприклад, якщо написати `*pp = &y;`, покажчик `p` перенаправляється на іншу змінну `y`, тоді як значення змінної `x` залишається незмінним.
- **Подвійне розіменування (`**pp = new_val`):** залишає покажчик `p` незмінним (він як вказував на `x`, так і вказує), але змінює значення цільового об’єкта `x`.

### Машинне представлення на ARM Cortex-M та накладні витрати

На машинному рівні архітектури ARMv7-M вираз `**pp = 20` компілюється в послідовність із двох інструкцій завантаження (`LDR`) та однієї інструкції збереження (`STR`):[^armv7m-arm]

```thumb
LDR  R0, [SP, #pp_offset]   ; R0 = значення pp (адреса p: 0x20000008)
LDR  R1, [R0]               ; R1 = значення *pp (адреса x: 0x20000004)
MOVS R2, #20                ; R2 = константа 20
STR  R2, [R1]               ; Запис значення 20 за адресою x (**pp = 20)
```

Кожен рівень непрямої адресації вимагає окремого звернення до системної шини. Якщо вказівники розміщені в різних областях пам’яті (наприклад, Flash, внутрішня SRAM та зовнішня SDRAM), це може призводити до затримок конвеєра (pipeline stalls) та промахів кешу даних (D-Cache misses) на високопродуктивних процесорах на зразок Cortex-M7. Тому в критичних за часом секціях (ISR, цифрова обробка сигналів) подвійні покажчики зазвичай кешують у локальні одинарні покажчики, щоб уникнути повторного розіменування в циклах.
