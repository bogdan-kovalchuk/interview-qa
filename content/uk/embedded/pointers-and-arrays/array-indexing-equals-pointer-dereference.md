## Question code

```c
int arr[3] = {1,2,3};
printf("%d %d", arr[2], *(arr+2));
```

## Short answer

Обидва вирази виводять **3** і є повністю еквівалентними за стандартом C.

`arr[2]` -> стандарт визначає як `*(arr+2)`: до адреси `arr` додається `2 * sizeof(int) = 8` байт, потім розіменовується.

Тому навіть `2[arr]` -> `*(2+arr)` -> 3 – теж коректно (через комутативність додавання, хоча й нечитабельно).[^embeddedinterviewlab]

## Detailed explanation

### Формальне визначення індексації масиву у стандарті C

У мові C оператор квадратних дужок `[]` не є самостійною апаратною операцією вибірки з пам’яті, а являє собою «синтаксичний цукор» для комбінації арифметики вказівників і подальшого розіменування. Відповідно до стандарту ISO/IEC 9899 (C11, пункт 6.5.2.1 Array subscripting), вираз виду `E1[E2]` за визначенням повністю ідентичний виразу `(*((E1) + (E2)))`.[^iso-c-n1570]

У наведеному фрагменті:
- `arr[2]` розкривається транслятором у `*(arr + 2)`;
- `*(arr + 2)` явно виконує ту саму послідовність дій;
- Обидва вирази повертають lvalue третього елемента масиву, значенням якого є `3`.[^embeddedinterviewlab]

### Механізм pointer decay та масштабування адреси

Обчислення виразу `*(arr + 2)` складається з двох послідовних кроків стандарту C:

1. **Array decay (затухання масиву):** згідно з ISO/IEC 9899 (пункт 6.3.2.1), у більшості виразів ідентифікатор масиву `arr` неявним чином перетворюється на вказівник на його перший елемент (`&arr[0]`) з типом `int*`.[^iso-c-n1570]
2. **Арифметика вказівників (pointer arithmetic):** за пунктом 6.5.6 стандарту, додавання цілого числа `2` до вказівника на тип `int` автоматично масштабує цілочисельний операнд на розмір базового типу об’єкта. Фізична адреса обчислюється як:
   `адреса = (uintptr_t)arr + 2 * sizeof(int)`.
   На 32-розрядній платформі ARM Cortex-M, де `sizeof(int) == 4`, базовий вказівник зміщується рівно на 8 байтів уперед. Розіменування за допомогою унарного оператора `*` зчитує 4-байтне машинне слово за новою адресою.

### Комутативність додавання та феномен 2[arr]

Оскільки операція бінарного додавання `+` у мові C є комутативною, вираз `E1 + E2` строго дорівнює `E2 + E1`. Відповідно:
`arr[2] == *(arr + 2) == *(2 + arr) == 2[arr]`.

Синтаксично коректний запис `2[arr]` є легітимним з точки зору компілятора C, оскільки в індексації один із операндів має бути вказівником, а інший – цілим числом, причому порядок їхнього запису в квадратних дужках стандартом не фіксується.[^iso-c-n1570] Проте у реальних embedded-проєктах використання форм на зразок `2[arr]` категорично відкидається стандартами кодування (зокрема MISRA C:2012, правило 18.4) через критичне зниження читабельності та підвищення ризику помилок сприйняття.

### Машинна генерація коду в embedded-компіляторах

На рівні компілятора (GCC або Clang для архітектури ARM Cortex-M) вирази `arr[2]` та `*(arr + 2)` породжують повністю однаковий асемблерний код без жодних розбіжностей:

```assembly
LDR R0, [R1, #8]    ; R1 містить базову адресу arr; зміщення #8 (2 * 4 байти)
```

Якщо індекс є змінною `i`, процесор використовує адресацію зі зсувом регістра:

```assembly
LDR R0, [R1, R2, LSL #2]  ; R1 = базова адреса, R2 = індекс i, LSL #2 множить на 4
```

Апаратне ядро ARM виконує множення індексу на 4 за допомогою barrel shifter безпосередньо в циклі виконання інструкції `LDR`, що гарантує гранично ефективний доступ до елементів за фіксований час O(1).
