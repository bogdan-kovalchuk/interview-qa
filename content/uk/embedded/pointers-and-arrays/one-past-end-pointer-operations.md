## Short answer

**One-past-the-end** – вказівник на елемент одразу після масиву: `int *end = arr + N`. За стандартом C – легальний.

Дозволено:
- **Формувати** (адреса коректна);
- **Порівнювати**: `p != end`, `p <= end`;
- **Віднімати** від іншого вказівника у масиві.

Заборонено:
- <span class="warn">Розіменовувати</span>: `*end` -> UB;
- <span class="warn">Збільшувати далі</span>: `end+1` -> UB.

Стандартна ідіома: `for(int *p=arr; p!=arr+N; p++)`[^embeddedinterviewlab]

## Detailed explanation

### Визначення стандарту та семантика концепції

Згідно зі стандартом ISO/IEC 9899 (§6.5.6p8), під час адресної арифметики з масивами вважається, що масив має один фіктивний додатковий елемент, розташований безпосередньо після останнього дійсного елемента масиву.[^iso-c-n1570] Вказівник на цей уявний елемент називається **«one-past-the-end» pointer** (вказівник за межу масиву).

Формування адреси `int *end = arr + N;` (де `N` – кількість елементів масиву `arr[N]`) є повністю легальним і строго визначеним поведінкою стандарту.[^iso-c-n1570] Ця концепція є фундаментальною для мов C та C++, оскільки саме на ній побудовано напіввідкриті діапазони `[begin, end)`, що лежать в основі ітераторів стандартної бібліотеки (STL) та канонічних циклів обходу буферів.

### Дозволені операції над вказівником за межу

Стандарт чітко регламентує безпечні дії над таким вказівником:[^iso-c-n1570]
1. **Обчислення адреси:** вирази `arr + N` та `&arr[N]` є повністю коректними для отримання значення адреси.
2. **Операції порівняння (Relational & Equality Operators):** дозволено виконувати перевірки рівності `p != end`, `p == end`, а також реляційні операції `p < end` та `p <= end` (ISO/IEC 9899 §6.5.8p5).[^iso-c-n1570]
3. **Віднімання вказівників (Pointer Subtraction):** вираз `end - p` повертає різницю у вигляді кількості елементів між вказівниками типу `ptrdiff_t` (ISO/IEC 9899 §6.5.6p9).[^iso-c-n1570]
4. **Приведення типів:** допускається конвертація у вказівник на `void *` або беззнаковий цілочисельний тип `uintptr_t` для системних перевірок або передачі в API дескрипторів.

### Категорично заборонені дії (Undefined Behavior)

Будь-яка спроба вийти за межі гарантій стандарту призводить до `undefined behavior`:[^iso-c-n1570]
- **Розіменування (Dereferencing):** Операції `*end` або `end[0]` заборонені. Пам’ять за адресою `end` не належить масиву: там може розташовуватися інша критична змінна, службові структури купи або взагалі неіснуюча чи апаратно захищена область адресного простору MCU (що викликає `HardFault`).[^embeddedinterviewlab]
- **Подальший інкремент:** Вирази `end + 1` або `++end` є грубим порушенням стандарту. Стандарт гарантує коректність адресної арифметики **лише до одного елемента за межу**. Навіть без спроби розіменування, саме обчислення адреси `end + 1` призводить до `undefined behavior`.[^iso-c-n1570]

### Архітектурні особливості та специфіка Embedded

У мікроконтролерних системах без віртуальної пам’яті (наприклад, ARM Cortex-M або RISC-V) слід враховувати такі аспекти:[^embeddedinterviewlab]
- **Граничні адреси пам’яті (Memory Boundary Wraparound):** Якщо масив розміщено в самому кінці доступного адресного простору (наприклад, на верхній межі внутрішньої SRAM `0x2001FFFF`), спроба створити `one-past-the-end pointer` призведе до переповнення 32-бітної адреси та згортання в `0x20020000` (що може бути невідображеним регіоном) або навіть у `0x00000000`. У такому разі перевірка `p < end` стане хибною. Надійні скрипти компонувальника (linker scripts) завжди залишають службовий запас на межах сегментів RAM.
- **DMA дескриптори:** Багато апаратних модулів DMA та контролерів мережевих буферів оперують кінцевими адресами за принципом `End Address = Start + Length`, де кінцева адреса вказує саме на перший байт поза буфером, що повністю узгоджується із семантикою `one-past-the-end`.
