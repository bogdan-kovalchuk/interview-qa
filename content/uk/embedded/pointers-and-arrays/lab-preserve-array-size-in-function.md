## Short answer

Оскільки масив decay-ується до вказівника, розмір <span class="warn">не передається автоматично</span>. Варіанти:

1) **Явний параметр**: `void f(int *arr, size_t n)` – найпростіше;
2) **Sentinel value**: null-terminator для рядків, спеціальне значення;
3) **Struct + масив**: `struct { int *data; size_t len; }`;
4) C++ **std::span** або `std::array<int,N>`.

Захист: `_Static_assert(sizeof(arr) != sizeof(int*), "Use real array")` у caller.[^embeddedinterviewlab]

## Detailed explanation

### Проблема втрати розміру: pointer decay у стандарті C

У мовах C та C++ масив не є об’єктом першого класу і не може передаватися у функцію за значенням. Згідно зі стандартом ISO/IEC 9899 (§6.7.6.3 p7), будь-який параметр функції, оголошений як масив (`T arr[N]` або `T arr[]`), компілятор автоматично перетворює («коригує») на покажчик на перший елемент (`T *arr`).[^iso-c-n1570]

Унаслідок цього явища, відомого як **pointer decay**, інформація про кількість елементів та загальний розмір буфера безповоротно втрачається для викликаної функції: оператор `sizeof(arr)` повертає розмір самого покажчика (`sizeof(int*)`, що дорівнює 4 байтам на 32-бітному ARM Cortex-M), а не розмір виділеного масиву.

### Класичні інженерні підходи у C

Для збереження або передачі розміру масиву в мові C застосовують такі рішення:[^iso-c-n1570]
- **Явна передача довжини окремим аргументом:**
  Канонічний підхід у C-розробці:
  ```c
  void process(int *arr, size_t len);
  ```
  Функція отримує гарантовану кількість дійсних елементів для контролю меж ітерацій.
- **Структура-дескриптор (Slice):**
  Об’єднання покажчика на буфер і його довжини в єдину структуру:
  ```c
  typedef struct {
      int *data;
      size_t len;
  } int_slice_t;

  void process(int_slice_t slice);
  ```
  Такий дескриптор передається за значенням (8 байтів на 32-бітній платформі) або за константним покажчиком, усуваючи ризик розсинхронізації буфера та його розміру.
- **Значення-термінатор (Sentinel value):**
  Спеціальне маркерне значення кінця послідовності (як нульовий символ `\0` у рядках або покажчик `NULL` у масиві команд). Недоліком є необхідність лінійного обходу пам’яті для визначення розміру та висока вразливість до виходу за межі пам’яті у разі пошкодження термінатора.

### Розширені можливості C99: специфікатор static та VLA-нотація

Стандарт C99 запропонував додаткові синтаксичні засоби для контролю довжини:[^iso-c-n1570]
- **Специфікатор `static` у списку параметрів:**
  ```c
  void process(int arr[static 16]);
  ```
  Цей запис повідомляє компілятору, що вказівник `arr` не є `NULL` і вказує на масив, що містить щонайменше 16 елементів. Це дозволяє оптимізатору розгортати цикли та використовувати векторні інструкції, а статичному аналізатору – попереджати про передачу замалих буферів.
- **VLA-нотація параметрів:**
  ```c
  void process(size_t n, int arr[n]);
  ```
  Параметр довжини передує параметру-масиву, що документує залежність і підтримується діагностикою компіляторів GCC та Clang.

### Сучасні підходи у C++: безпека без накладних витрат

У кодових базах C++ для вбудованих систем проблема вирішується з повною безпекою типів і нульовими накладними витратами:[^iso-cpp-n4861]
- **Передача посилання на фіксований масив через шаблон:**
  ```cpp
  template <size_t N>
  void process(int (&arr)[N]) {
      // Розмір N виводиться компілятором автоматично, sizeof(arr) == N * sizeof(int)
  }
  ```
- **Контейнер фіксованого розміру `std::array`:**
  ```cpp
  void process(const std::array<int, 16> &arr);
  ```
- **Неволодіючий вигляд `std::span` (C++20):**
  `std::span<int>` інкапсулює покажчик на довільний неперервний буфер та його довжину, дозволяючи приймати як звичайні масиви C, так і `std::array` чи динамічні буфери без копіювання пам’яті.[^iso-cpp-n4861]
