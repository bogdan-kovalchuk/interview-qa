## Short answer

Розмір вказівника залежить від адресного простору архітектури й ABI, а не від типу, на який він вказує.[^dou-embedded-interview] На 32-bit системі зазвичай `sizeof(void*) == 4`, на 64-bit – `8`, на 16-bit – `2`.

`int *`, `char *` і `struct Foo *` зазвичай мають однаковий розмір у межах однієї платформи, бо всі зберігають адресу. У embedded можуть бути нюанси з різними memory spaces або function pointers, тому правильна відповідь: перевіряти через `sizeof(pointer)` для конкретного компілятора й цілі.

## Detailed explanation

### Стандарт ISO C та детермінанти розміру вказівника

Згідно зі стандартом ISO C (ISO/IEC 9899:2011, §6.2.5 та §6.3.2.3), розмір вказівника не залежить від типу даних, на який він посилається, а визначається виключно розрядністю апаратної адресної шини цільової архітектури та моделлю даних двійкового інтерфейсу додатків (Application Binary Interface, ABI)[^iso-c-n1570].

Стандарт встановлює важливі гарантії щодо сумісності представлення вказівників:
- Вказівники на некваліфікований тип `void*` та символьні типи `char*` мають однаковий розмір і однакове бітове представлення.
- Усі вказівники на структури або об’єднання мають однакове представлення та однакові вимоги до вирівнювання (`alignment`) незалежно від внутрішнього наповнення структури.
- Вказівники на різні кваліфіковані версії одного типу (наприклад, `const int*` та `int*`) мають однаковий розмір.
- **Але**: стандарт C не гарантує, що вказівник на об’єкт даних (`data pointer`) та вказівник на функцію (`function pointer`) мають однаковий розмір або сумісне бітове представлення, що особливо актуально для гарвардських архітектур мікроконтролерів.

### Моделі даних ABI у мікроконтролерах та процесорах

Вбудовані системи стикаються з різними моделями даних ABI:

1. **32-бітні платформи (ARM Cortex-M, RISC-V RV32, ESP32, MIPS32):**
   - Модель даних: **ILP32** (`int`, `long`, `pointer` мають розмір 32 біти / 4 байти)[^armv7m-arm].
   - Розмір вказівника: **рівно 4 байти** (`sizeof(void*) == 4`). Адресує до 4 ГБ лінійного простору, вміщуючись у будь-який загальний 32-бітний регістр ядра (R0–R12).

2. **64-бітні платформи (ARM Cortex-A, AArch64, RISC-V RV64, x86-64):**
   - Модель даних: **LP64** у Linux/Embedded Linux (`int` – 32 біти; `long` та `pointer` – 64 біти / 8 байтів).
   - Розмір вказівника: **8 байтів** (`sizeof(void*) == 8`).

3. **8-бітні та 16-бітні мікроконтролери (AVR, PIC, MSP430, 8051):**
   - Базовий вказівник займає **2 байти** (16 біт), що дозволяє адресувати до 64 КБ даних у RAM.
   - **Гарвардська архітектура (AVR ATmega, 8051):** Простір Flash (код і константи) фізично відділений від SRAM (дані). Для звернення до Flash використовують модифікатори типу `PROGMEM` або спеціальні вказівники. Якщо мікроконтролер має більше ніж 64 КБ Flash (наприклад, ATmega2560), вказівники на функції або розширені вказівники на пам’ять програм (`far pointers`) мають розмір 3 байти (24 біти) і потребують особливих інструкцій завантаження (`ELPM`), що робить їх несумісними за розміром зі звичайними 16-бітними вказівниками на RAM.

### Особливості вказівників на методи в C++

Якщо у прошивці мікроконтролера використовується мова C++, слід розрізняти звичайний вказівник на вільну функцію та вказівник на метод класу (pointer-to-member-function):
- Вказівник на статичний метод або C-функцію на ARM Cortex-M займає 4 байти.
- Вказівник на нестатичний метод класу містить зміщення `this`, індекс у віртуальній таблиці (`vtable`) або ознаку віртуальності. У компіляторі ARM GCC його розмір становить **8 байтів** (на 32-бітній платформі) або навіть 16 байтів, що нерідко призводить до прихованих витрат пам’яті.

### Інженерні рекомендації щодо типізації

- Ніколи не зберігайте вказівник у змінній типу `unsigned int` або `unsigned long`, якщо код призначений для перенесення між 32-бітними та 64-бітними цілями.
- Використовуйте стандартні типи з заголовкового файлу `<stdint.h>`:
  ```c
  uintptr_t addr = (uintptr_t)ptr; // беззнаковий цілий тип, що гарантовано вміщує вказівник
  intptr_t s_addr = (intptr_t)ptr; // знаковий аналог
  ```
- Для вимірювання різниці між двома вказівниками завжди використовуйте `ptrdiff_t` з `<stddef.h>`.
