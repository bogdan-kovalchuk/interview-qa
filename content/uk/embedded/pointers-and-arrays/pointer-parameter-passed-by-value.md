## Question code

```c
void advance(char *p, int n){
  p += n;
}
```

## Short answer

<span class="warn">НІ.</span> У C параметри передаються **за значенням**. Функція отримує копію вказівника `p`. `p += n` змінює локальну копію, але не оригінальний вказівник у caller-і.

Для зміни caller-ського pointer: потрібен double pointer: `void advance(char **p, int n){ *p += n; }` Виклик: `advance(&cursor, 5);`

Класична помилка при реалізації парсерів і потокових обробників.[^embeddedinterviewlab]

## Detailed explanation

### Принцип передачі аргументів за значенням у мові C

У мові C абсолютно всі аргументи функцій передаються **виключно за значенням (pass-by-value)** (ISO/IEC 9899 §6.5.2.2).[^iso-c-n1570] Вказівники не є винятком з цього правила:
- Коли функція викликається як `advance(cursor, 5)`, створюється локальна копія значення адреси, що міститься в змінній `cursor`.
- Всередині тіла функції параметр `p` є окремою локальною змінною. Вираз `p += n` змінює значення лише цієї локальної копії адреси.
- Після повернення з функції значення оригінальної змінної `cursor` у викликаючій функції (`caller`) залишається абсолютно незмінним.[^embeddedinterviewlab]

### Механіка роботи на рівні регістрів ARM Cortex-M (AAPCS)

Згідно зі стандартом викликів ARM Architecture Procedure Call Standard (AAPCS):[^embeddedinterviewlab]
1. Перші чотири аргументи передаються через регістри загального призначення `r0`–`r3`.
2. Під час виклику функції `advance(cursor, 5)` значення `cursor` поміщається в регістр `r0`, а число `5` – у регістр `r1`.
3. Всередині функції виконується інструкція додавання:
   ```assembly
   ADD    r0, r0, r1    @ r0 тепер містить нову адресу
   BX     lr            @ повернення без збереження значення у пам’ять caller-а
   ```
4. Регістр `r0` після повернення з функції `void` просто ігнорується, а змінна `cursor` у викликаючому коді, що зберігалася в іншому регістрі або на стеку, зберігає своє початкове значення.

### Способи виправлення помилки

Існує три стандартні інженерні розв’язки цієї проблеми:

1. **Передача покажчика на покажчик (Double Pointer):**
   Функція приймає адресу самого вказівника, що дозволяє модифікувати його значення за місцем виклику:
   ```c
   void advance(char **p, int n) {
       if (p != NULL && *p != NULL) {
           *p += n;
       }
   }
   /* Виклик: advance(&cursor, 5); */
   ```
2. **Повернення оновленого покажчика (Functional Style):**
   Функція повертає обчислену адресу як результат виконання, перекладаючи збереження на викликаючий код:
   ```c
   char *advance(const char *p, int n) {
       return (char *)(p + n);
   }
   /* Виклик: cursor = advance(cursor, 5); */
   ```
3. **Використання посилань у мові C++ (Pass-by-Reference):**
   Якщо проект компілюється як C++, вказівник можна передати за посиланням:
   ```cpp
   void advance(char *&p, int n) {
       p += n;
   }
   /* Виклик: advance(cursor, 5); */
   ```

### Пастки у розробці драйверів та парсерів протоколів

Ця помилка є однією з найпоширеніших у коді вбудованих систем при реалізації:
- **Парсерів потокових протоколів:** розбір NMEA-повідомлень GPS, AT-команд GSM/Wi-Fi модемів або пакетів Modbus, де функція споживання токена `parse_token(char *stream)` повинна зрушити вказівник на наступне поле, але через передачу за значенням розбір зациклюється на першому токені.
- **Однозв’язних списків та черг повідомлень RTOS:** функції видалення елемента виду `list_remove(node_t *head)`, де зміна голови списку не відображається в глобальній структурі драйвера, викликаючи витік пам’яті або розрив ланцюжка дескрипторів.
