## Question code

```c
int *p;
*p = 5;
```

## Short answer

`p` – <span class="warn">wild pointer</span>: неініціалізований вказівник містить garbage-адресу (випадкове значення зі стека).

Запис `*p = 5` -> undefined behavior: може перезаписати випадкову область пам’яті, іншу змінну, або спричинити <span class="warn">HardFault</span> на Cortex-M (якщо адреса поза RAM).

Захист: завжди ініціалізуй вказівники: `int *p = NULL;` або одразу `int *p = &x;`[^embeddedinterviewlab]

## Detailed explanation

### Статус неініціалізованих змінних у стандарті C

Локальна змінна `int *p` має автоматичну тривалість зберігання (automatic storage duration). За стандартом ISO/IEC 9899 (§6.7.9 Initialization, пункт 10), якщо об’єкт з автоматичною тривалістю зберігання не ініціалізовано явно, його початкове значення є невизначеним (indeterminate value)[^iso-c-n1570].

Такий вказівник називають диким (wild pointer). Він містить випадковий набір бітів (сміття), що залишився в цій комірці стека від попередніх викликів функцій. Будь-яка спроба розіменування вказівника з невизначеним значенням (`*p = 5`) класифікується стандартом як невизначена поведінка (undefined behavior)[^iso-c-n1570].

### Апаратні наслідки на мікроконтролерах ARM Cortex-M

На апаратному рівні процесор транслює запис `*p = 5` в інструкцію `STR r0, [r1]`, де `r0 = 5`, а в `r1` знаходиться неініціалізована адреса[^armv7m-arm]. Наслідки залежать від того, яке саме випадкове число виявилося в `r1`:
1. **Апаратний збій шини (Precise BusFault / HardFault)**:
   - Якщо адреса потрапляє у невідображену область адресної карти (unmapped memory) або зарезервований простір (reserved space).
   - Якщо адреса потрапляє у простір Flash-пам’яті (`0x08000000` на STM32), яка апаратно заблокована для прямих інструкцій запису `STR`.
   - Якщо адреса є непарною, а ядро не підтримує невирівняний доступ (наприклад, Cortex-M0/M0+ генерує `HardFault` при спробі 32-бітного запису за адресою, не кратній 4)[^armv7m-arm].
2. **Виключення захисту пам’яті (MemManageFault)**:
   - Якщо в мікроконтролері активовано модуль MPU (Memory Protection Unit) і адреса потрапляє в регіон, заборонений для запису поточному рівню привілеїв.
3. **Тихе руйнування пам’яті (Silent Memory Corruption)**:
   - Найнебезпечніший сценарій: адреса випадково вказує на валідну ділянку SRAM. Запис значення 5 перезапише критичні змінні програми, структуру TCB операційної системи RTOS або збережену адресу повернення (Link Register) у фреймі стека. Збій програми відбудеться значно пізніше в зовсім іншій підсистемі, що робить налагодження надзвичайно важким.
4. **Непередбачуване спрацювання периферії**:
   - Якщо адреса потрапляє в діапазон регістрів MMIO (`0x40000000`–`0x5FFFFFFF`), запис може випадково скинути конфігурацію тактування (RCC), вимкнути таймер або перевести піни GPIO в небажаний стан.

### Оптимізації компілятора навколо Undefined Behavior

Сучасні компілятори (GCC, Clang) при оптимізаціях `-O2` або `-Os` аналізують потік даних. Якщо компілятор виявляє запис через неініціалізований вказівник, він спирається на аксіому стандарту: коректна C-програма ніколи не виконує undefined behavior.
Компілятор може:
- вважати цю ділянку коду недосяжною і повністю видалити весь блок або всю функцію;
- вставити замість коду аварійну інструкцію `UDF` (Undefined instruction);
- видалити перевірки, які слідують після цього рядка.

### Інженерні заходи запобігання

У вбудованих системах діють суворі правила стандарту MISRA C (зокрема Rule 9.1 – "Об’єкти не повинні читатися або використовуватися до їхньої ініціалізації"):
1. Завжди явно ініціалізувати вказівники при оголошенні: `int *p = NULL;` або негайно пов’язувати з цільовою змінною `int *p = &x;`.
2. Використовувати прапорці компілятора `-Wall -Wextra -Wuninitialized -Werror`.
3. Використовувати статичні аналізатори коду (Clang-Tidy, Cppcheck, PC-lint) у пайплайнах CI для автоматичного виявлення неініціалізованих вказівників.
