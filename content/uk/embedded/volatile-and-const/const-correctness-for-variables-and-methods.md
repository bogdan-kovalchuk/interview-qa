## Short answer

Константність – це частина типу, яку компілятор враховує під час перевірки доступу.[^dou-embedded-interview] Якщо об’єкт або параметр оголошений `const`, запис через цей шлях заборонений: `void f(const int *p)` може читати `*p`, але не змінювати його.

У C++ `const` також використовується для методів: `int get() const` означає, що метод не змінює логічний стан об’єкта. Можна зняти const через cast, але якщо початковий об’єкт був реально const, запис призводить до undefined behavior. Добра практика: ставити `const` на вхідні дані, які функція не змінює.

## Detailed explanation

### Статична перевірка константності компілятором

Константність у C та C++ є частиною системи типів і перевіряється на етапі статичного аналізу коду під час компіляції[^iso-c-n1570]. Об’єкт або шлях доступу, кваліфікований як `const`, формує non-modifiable lvalue. Компілятор дозволяє неявне приведення від некваліфікованого типу до кваліфікованого (`int*` перетворюється на `const int*`), оскільки це безпечне звуження прав доступу, але забороняє зворотне неявне перетворення. Це запобігає передачі константних об’єктів у функції, здатні їх модифікувати.

### Семантика const-методів у C++ та mutable

У мові C++ концепція const-correctness поширюється на методи класів[^iso-cpp-n4861]. Якщо метод оголошено з суфіксом `const`:

```cpp
class Sensor {
public:
    uint16_t read_value() const;
private:
    uint16_t cached_raw;
    mutable uint32_t access_count;
};
```

У тілі методу покажчик `this` отримує тип `const Sensor*`. Будь-яка спроба змінити поле `cached_raw` викликає помилку компіляції. Поле `access_count` позначене як `mutable`, що дозволяє оновлювати його навіть у const-контексті, не порушуючи логічної константності об’єкта (наприклад, для ведення внутрішньої статистики, діагностики або захоплення м’ютекса)[^iso-cpp-n4861].

### Зняття константності та наслідки на рівні пам’яті

Зняття константності за допомогою `const_cast` або C-style приведення дозволяє обійти перевірку компілятора, але не змінює фізичні властивості пам’яті:

1. Якщо оригінальний об’єкт був створений як неконстантний (`int x = 10; const int *p = &x;`), зняття константності з `p` і подальший запис формально допускаються стандартом[^iso-c-n1570].
2. Якщо оригінальний об’єкт спочатку був визначений як `const` (`const int x = 10;`), спроба модифікації призводить до `undefined behavior`[^iso-c-n1570].

У мікроконтролерах об’єкти з кваліфікатором `const` глобальної або статичної тривалості зберігання лінкер розміщує у секції `.rodata` у Flash. Апаратна спроба запису за адресою Flash-пам’яті без попереднього стирання контролером Flash викликає виключення процесора (наприклад, `BusFault` або `HardFault` на ARM Cortex-M).

### Інженерні рекомендації для firmware API

- Завжди приймайте вхідні буфери через вказівник на константу: `int send_packet(const uint8_t *payload, size_t len);`. Це дозволяє передавати дані безпосередньо з Flash (`.rodata`) без необхідності виділяти проміжний буфер у RAM.
- Помилкове ігнорування `const` у сигнатурах функцій розмиває межі контракту API: розробникам доводиться вдаватися до небезпечних приведень типів, щоб викликати функцію з константними даними.
