## Short answer

Забороняє змінювати значення через це ім’я після ініціалізації: на спробу запису компілятор видасть помилку.[^dou-embedded-interview]

Варіанти: `const int x = 5;` – константна змінна; `const int *p` – вказівник на константу (дані захищені); `int * const p` – константний вказівник (адреса захищена); `const int * const p` – обидва захищені.

В embedded `const` не гарантує конкретного місця зберігання. У багатьох toolchain такі дані кладуть у `.rodata` у Flash, але це залежить від ABI, linker script і платформи. У C++ метод, оголошений як `void get() const`, гарантує, що не змінює стан об’єкта.

## Detailed explanation

### Семантика const у стандарті C та C++

Кваліфікатор типу `const` вказує компілятору, що відповідний об’єкт або шлях доступу є незмінним після ініціалізації (read-only lvalue)[^iso-c-n1570]. Якщо програма намагається виконати явну модифікацію через const-ідентифікатор, компілятор зобов’язаний видати діагностичне повідомлення про помилку під час трансляції. При цьому стандарт чітко розрізняє модифікацію через шлях доступу та константність самого об’єкта: спроба модифікації змінної, яка спочатку була оголошена як `const` (наприклад, шляхом зняття константності кастом), є `undefined behavior`[^iso-c-n1570].

### Варіанти розташування const та правило читання

У поєднанні з вказівниками положення ключового слова визначає, що саме захищено від змін. Загальне правило – читати оголошення справа наліво:

- `const int *p` або `int const *p`: вказівник на константні дані (`low-level const`). Сам вказівник можна перенаправити на іншу адресу (`p = &y;`), але спроба змінити значення розіменуванням `*p = 10;` викликає помилку компілятора.
- `int * const p`: константний вказівник (`top-level const`). Адреса, на яку вказує `p`, фіксується при ініціалізації і не може бути змінена (`p = &y;` – помилка), але дані за цією адресою модифікувати дозволено (`*p = 10;`).
- `const int * const p`: константний вказівник на константні дані. Захищені як значення, так і адреса.

У C++ `const` після сигнатури методу (`void read_status() const;`[^iso-cpp-n4861]) гарантує, що метод не змінює логічний стан об’єкта, надаючи покажчику `this` тип `const ClassName*`. Модифікувати дозволено лише поля з модифікатором `mutable`.

### Розміщення в пам’яті мікроконтролера та асемблер

У вбудованих системах глобальні та статичні константи (`static const uint32_t table[...]`) компонувальник (linker) зазвичай розміщує у секції `.rodata` у Flash-пам’яті мікроконтролера, заощаджуючи обмежену оперативну пам’ять (SRAM). На рівні інструкцій ARM Cortex-M доступ до таких даних транслюється в пряме завантаження з адреси у Flash через інструкцію `LDR`:

```assembly
LDR  R0, =0x08001000  @ адреса таблиці в секції .rodata (Flash)
LDR  R1, [R0, #4]      @ пряме читання константи з пам’яті Flash
```

Якщо ж константа є локальною змінною всередині функції, компілятор за наявності оптимізації може взагалі не виділяти під неї комірку пам’яті, застосовуючи constant propagation або використовуючи безпосередній операнд (`MOVS R0, #5`).

### Типові пастки у прошивках

1. **`const` у C не є константою часу компіляції**: У мові C оголошення `const int N = 10;` створює змінну тільки для читання, а не вираз часу компіляції (constant expression). Тому `int arr[N];` у C99 розглядається як VLA (Variable Length Array), що виділяє пам’ять на стеку під час виконання.
2. **`const` не захищає від апаратних змін**: Якщо memory-mapped регістр статусу периферії доступний лише для читання процесором, правильне його оголошення – `volatile const uint32_t *`, де `const` захищає від помилкового запису кодом, а `volatile` змушує компілятор перечитувати значення з апаратного регістра[^iso-c-n1570].
