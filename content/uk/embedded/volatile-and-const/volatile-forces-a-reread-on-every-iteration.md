## Question code

```c
volatile uint8_t rx_done = 0;

while (rx_done == 0) { }
```

## Short answer

Кожна оцінка volatile-виразу `rx_done` є доступом до volatile-об’єкта за правилами абстрактної машини; що саме є таким доступом, визначає реалізація C.[^iso-c-n1570]

Це дає змогу main loop спостерігати зміни від ISR у підтримуваному toolchain; DMA потребує також узгодженого з платформою доступу до пам’яті та кешу. Без `volatile` компілятор може повторно використати попереднє значення, оскільки в циклі немає запису в `rx_done`.[^iso-c-n1570]

Для простого прапорця `uint8_t` це може бути достатньо для окремих доступів у конкретній реалізації, але `volatile` не гарантує атомарність, синхронізацію чи безпеку складних read-modify-write операцій.[^iso-c-n1570]

## Detailed explanation

`volatile` позначає об’єкт, значення якого може змінюватися поза звичайним потоком виконання програми, або доступ до якого має побічний ефект. У прикладі `rx_done` має volatile-qualified type, тому читання в умові циклу не можна трактувати так само, як читання звичайної змінної: реалізація має зберігати семантику volatile-доступів абстрактної машини. Стандарт C водночас залишає реалізації визначенням те, що саме вважається таким доступом.[^iso-c-n1570]

Це важливо для memory-mapped I/O та для змінної, яку змінює interrupt handler. Звичайне зчитування без `volatile` може бути підняте з циклу або повторно використане з регістра CPU, адже компілятор не бачить запису у тілі циклу. Кваліфікатор повідомляє про зовнішню зміну і вимагає зберегти відповідну семантику доступу. Він сам по собі не описує протокол між main loop та ISR, не робить операцію атомарною і не є повним бар’єром пам’яті.[^iso-c-n1570]

У bare-metal системі компілятор і MCU toolchain мають документувати, як volatile-доступи співвідносяться з апаратними операціями. Для DMA окремо враховують кешування, бар’єри та узгодження пам’яті, передбачені конкретним MCU; одного `volatile` для узгодження кешу може бути недостатньо. Якщо прапорець оновлює ISR, перевіряють також допустимий розмір атомарного доступу на цільовому процесорі.[^iso-c-n1570]

Приклад циклу завершується лише тоді, коли інша частина системи справді встановлює `rx_done` і доступ до нього має очікувану для платформи семантику. Інакше цикл може нескінченно чекати навіть із правильним кваліфікатором. Також слід розглянути timeout або інший шлях виходу, якщо периферія не завершить операцію.

**Типові помилки:**

- вважати `volatile` засобом взаємного виключення або заміною атомарної операції;
- стверджувати, що він сам очищує або узгоджує DMA cache;
- кваліфікувати змінну volatile, але читати її через некваліфікований lvalue.[^iso-c-n1570]

Приклад показує саме повторні читання в polling loop; він не доводить, що будь-який ISR/DMA обмін без додаткових платформних правил є коректним.
