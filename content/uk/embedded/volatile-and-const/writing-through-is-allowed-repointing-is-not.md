## Question code

```c
int x = 1, y = 2;
int * const p = &x;
*p = 3;
p = &y;
```

## Short answer

**`*p = 3` скомпілюється, `p = &y` не скомпілюється.**

`int * const p` означає const pointer to int. Адреса, збережена в `p`, незмінна, але сам об’єкт `x` можна змінювати.

Правило: якщо `const` праворуч від `*`, захищений pointer; якщо ліворуч від `*`, захищені дані.[^iso-c-n1570]

## Detailed explanation

`int * const p` є незмінним вказівником на змінний `int`: після ініціалізації адресу в `p` не можна перепризначити, але об’єкт за цією адресою можна змінювати через `*p`. У прикладі `p` ініціалізовано адресою `x`, тож `*p = 3` записує число 3 у `x`.[^iso-c-n1570]

Причина в тому, що `const` застосовано до самого вказівника. У декларації `int * const p` об’єкт `p` має кваліфікований тип; оператор присвоєння не може змінювати об’єкт із таким типом після його ініціалізації. Натомість вираз `*p` має тип `int`, тому він є змінюваним lvalue, якщо адреса вказує на доступний для запису об’єкт.[^iso-c-n1570]

Це не означає, що `p` вказує на незмінні дані: `x` можна змінити і через `*p`, і безпосередньо як `x`. Присвоєння `p = &y` є помилкою, бо змінювало б адресу; треба оголосити інший вказівник або прибрати `const`, якщо перепризначення справді потрібне. Саме значення адреси після ініціалізації не можна замінити.[^iso-c-n1570]

Приклад: коли функція отримує фіксований буфер, але має змінювати його байти, параметр на кшталт `uint8_t * const data` виражає незмінну локальну адресу та змінювані дані. Це обмеження діє лише в межах оголошеного об’єкта-вказівника, а не на всі можливі псевдоніми буфера. Типова помилка – читати оголошення справа наліво без урахування зірочки; визначте окремо, чи кваліфіковано `p`, чи тип `*p`.[^iso-c-n1570]
