## Short answer

**`const` дає компілятору змогу діагностувати запис через const-qualified lvalue.** У стандарті C це порушення обмеження мови, для якого реалізація мусить видати діагностику; стандарт не вимагає, щоб кожна така діагностика неодмінно зупиняла збірку.[^iso-c-n1570]

Наприклад, parser із `const uint8_t *frame` не може змінити байт через цей вказівник. Але це не робить пам’ять фізично read-only і не налаштовує MPU.

Правило: `const` документує контракт читання та допомагає діагностувати помилкові присвоєння; це не апаратний захист пам’яті.[^iso-c-n1570]

## Detailed explanation

`const` кваліфікує тип об’єкта або lvalue, а компілятор перевіряє операції над виразами з цим типом. Якщо `frame` має тип `const uint8_t *`, сам вказівник можна перенаправити, але байт, на який він вказує, не можна змінити виразом `*frame = value`. У C це обмеження мови: відповідна програма потребує діагностики від реалізації, однак стандарт не наказує конкретний текст повідомлення чи обов’язкове припинення компіляції.[^iso-c-n1570]

Кваліфікатор стосується саме об’єкта, на який веде вказівник. Наприклад, `uint8_t * const frame` робить незмінним сам вказівник, але дозволяє змінювати байти через нього; `const uint8_t *frame` дозволяє змінити адресу `frame`, але забороняє змінювати байти через цей доступ. Обидва кваліфікатори можна поєднати, якщо незмінними мають бути і адреса, і доступ до даних.[^iso-c-n1570]

Це захист на рівні типів, а не атрибут фізичної пам’яті: він не встановлює MPU permissions і не усуває інший вказівник, який дозволяє запис. Якщо об’єкт спочатку оголошено неконстантним, його значення може змінитися через інший alias, поки цей код читає його. Якщо ж сам об’єкт визначено з const-qualified типом, спроба змінити його через cast і запис має undefined behavior. Отже, `const` допомагає виявити помилку в місці доступу, але не замінює апаратного захисту чи коректного контролю спільного стану.[^iso-c-n1570]

Приклад:

```c
void parse(const uint8_t *frame, size_t length);
```

Такий інтерфейс повідомляє викликачеві, що `parse` читає буфер і не має записувати його через `frame`. Типова помилка – вважати `const` гарантією незмінності буфера для всієї програми; контракт діє лише через відповідний кваліфікований доступ.[^iso-c-n1570]
