## Short answer

**`volatile const`** описує об’єкт, який програма не має права змінювати через цей lvalue, але який може змінитися без участі програми.[^iso-c-n1570]

Типовий приклад: read-only status register. Firmware тільки читає; hardware може оновлювати біти стану. `volatile` кваліфікує доступ відповідно до правил реалізації, а `const` забороняє запис через цей тип.[^iso-c-n1570]

Embedded-правило: для апаратних read-only регістрів використовуй pointer to `volatile const` data, якщо це відповідає документації MCU.[^iso-c-n1570]

## Detailed explanation

`volatile const` – це кваліфікований тип, у якому `const` і `volatile` описують різні властивості одного об’єкта. `const` не дозволяє програмі модифікувати об’єкт через lvalue цього типу. `volatile` вказує, що значення може змінюватися способами, невідомими реалізації, або мати невідомі побічні ефекти; вирази, які посилаються на такий об’єкт, обчислюються згідно з абстрактною машиною. Що саме є volatile access, визначається реалізацією.[^iso-c-n1570]

На вбудованому пристрої типовий приклад – status register, де периферія змінює біти незалежно від коду програми. Програма читає його, щоб побачити подію чи поточний стан, але не повинна писати до нього через цю декларацію. `const` тут не означає, що апаратура не може змінити біти: це обмеження доступу з боку програми через конкретний тип. Воно також не замінює захисту пам’яті чи перевірки прав на рівні MCU.[^iso-c-n1570]

Якщо об’єкт не volatile-qualified, компілятор може виходити з правил мови про звичайний об’єкт, значення якого змінює сама програма. Такий код може некоректно описувати регістр, який оновлює периферія. `volatile` повідомляє про цю зовнішню взаємодію, однак не є загальним наказом «не оптимізувати»: воно стосується доступів до volatile-об’єкта, а не всіх сусідніх обчислень. Зокрема, volatile не гарантує атомарності, порядку між незалежними операціями на всіх платформах або синхронізації з interrupt чи DMA.[^iso-c-n1570]

Приклад типу для лише читаного статусу:

```c
volatile const uint32_t * const status =
    (volatile const uint32_t *)STATUS_ADDRESS;
uint32_t current = *status;  // читати можна
```

Тут зовнішній pointer фіксований, а `*status` не можна призначити нове значення. Використовуй саме таку декларацію лише якщо reference manual підтверджує ширину доступу, адресу та семантику читання. Деякі регістри очищують прапорці при читанні або вимагають окремих операцій; самі ключові слова C цього не описують. Також звір volatile поведінку з документацією компілятора для цільової архітектури.[^iso-c-n1570]
