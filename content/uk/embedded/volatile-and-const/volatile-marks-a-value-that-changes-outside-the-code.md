## Short answer

**`volatile`** позначає об’єкт, доступ до якого має бути спостережуваним для реалізації C відповідно до її правил доступу до `volatile`.

Зазвичай це не дає компілятору прибрати потрібне читання або запис чи замінити повторне читання збереженим значенням. Точне поняття доступу до `volatile` частково визначає реалізація C, тому звіряйся з документацією компілятора й платформи. Для memory-mapped registers це важливо: читання може повертати стан периферії, а запис запускати апаратну дію.

Правило: `volatile` застосовують для об’єктів із зовнішньо спостережуваними доступами, а не як загальний засіб синхронізації чи гарантію атомарності.[^iso-c-n1570]

## Detailed explanation

`volatile` – це кваліфікатор типу, який повідомляє компілятору, що читання або запис об’єкта має значення поза звичайною логікою програми. Стандарт C не задає універсальне апаратне значення для кожного такого доступу: те, що саме вважається доступом до `volatile`-об’єкта, визначає реалізація. Тому для конкретного MCU важливі правила компілятора та карта регістрів виробника.[^iso-c-n1570]

Типовий приклад – регістр периферії за фіксованою адресою. Читання може отримати новий стан таймера, а запис – підтвердити переривання або запустити передачу. Якщо компілятор вважав би таке читання звичайною змінною, він міг би використати раніше прочитане значення й не звернутися до пристрою знову. `volatile` робить саме цей доступ видимим компілятору згідно з ABI та розширеннями реалізації; воно не налаштовує адресу, ширину чи побічні ефекти регістра за тебе.[^iso-c-n1570]

Такий самий намір трапляється зі змінною, яку змінює ISR, або буфером DMA: асинхронна подія не є звичайним присвоєнням у поточній гілці C-коду. Проте ці випадки залежать від моделі переривань, DMA та пам’яті конкретної платформи. Для сигналів стандарт C окремо визначає обмежене правило з `volatile sig_atomic_t`; його не слід автоматично переносити на MCU ISR.[^iso-c-n1570]

`volatile` не забезпечує взаємного виключення, атомарності складеної операції чи синхронізації потоків. Для цих задач потрібні атомарні типи або платформні критичні секції. Також воно не є універсальним memory barrier для звичайної пам’яті: порядок між volatile- і non-volatile-доступами може потребувати окремого бар’єра компілятора чи апаратури.[^gcc-volatile]

Приклад: якщо status register позначений volatile, кожне окреме читання в циклі опитування відбувається як доступ до регістра за правилами реалізації. Якщо ж звичайне поле структури лише іноді читають у програмі, додавання `volatile` не виправляє конкурентний доступ і може завадити оптимізації без користі.

**Типова помилка:** оголосити всі змінні `volatile` «для надійності». Спершу визнач, хто саме змінює об’єкт і яку гарантію потрібно отримати; для синхронізації одного кваліфікатора недостатньо.[^iso-c-n1570]
