## Short answer

`const` задає read-only семантику для компілятора: об’єкт не можна змінювати через const-qualified ім’я після ініціалізації: `const int x = 5;`. Це не гарантує розміщення у Flash або ROM: воно залежить від toolchain, linker script і платформи.

Вказівники читають справа наліво: `const int *p` – незмінні дані; `int * const p` – незмінний вказівник; `const int * const p` – обидва. `const` не завжди є compile-time constant, а запис у реально const-об’єкт дає undefined behavior.[^dou-embedded-interview]

## Detailed explanation

### Вплив на синтаксис та оптимізацію компілятора

Оголошення змінної з кваліфікатором `const` накладає на неї обмеження read-only на рівні компілятора[^iso-c-n1570]. Ініціалізація є єдиним моментом, коли такій змінній присвоюється значення; будь-який наступний запис через її ім’я є порушенням обмежень типу (constraint violation) і викликає помилку компіляції. 

Оскільки компілятор вважає значення незмінним, оптимізатор може виконати агресивні трансформації коду:
- **Constant folding та propagation**: вирази з участю `const`-змінних обчислюються під час збирання.
- **Інлайнінг значень**: компілятор генерує інструкції з безпосередніми операндами (immediate values), уникаючи звернень до пам’яті через шину. Наприклад, в асемблері ARM Cortex-M замість завантаження значення з пам’яті (`LDR`) підставляється інструкція `MOVS R0, #100`.

### Розміщення в адресній карті мікроконтролера

Фізичне розташування `const`-змінної залежить від її тривалості зберігання (storage duration), архітектури та конфігурації компонувальника (linker script):
- **Глобальні та статичні змінні**: розміщуються в секції `.rodata` (read-only data). Скрипт лінкера зазвичай проектує цю секцію безпосередньо у внутрішню пам’ять Flash мікроконтролера. Це звільняє критично обмежену оперативну пам’ять (SRAM).
- **Локальні змінні у функціях**: мають автоматичну тривалість зберігання. Компілятор може розташувати їх у регістрах загального призначення або на стеку в SRAM. `const` тут слугує виключно захистом від випадкової модифікації логікою функції.

### Зв’язування (linkage) у C проти C++

Важливою відмінністю є область видимості та зв’язування глобальних `const`-змінних:
- У **мові C** глобальна змінна `const int buffer_size = 256;` за замовчуванням має зовнішнє зв’язування (`external linkage`)[^iso-c-n1570]. Оголошення її в заголовному файлі без ключового слова `static` або `inline` призведе до помилки компонувальника про подвійне визначення символу (`multiple definition`), якщо хедер підключено до кількох `.c` файлів.
- У **мові C++** глобальні `const`-змінні за замовчуванням мають внутрішнє зв’язування (`internal linkage`)[^iso-cpp-n4861], що аналогічно неявному `static const`.

### Наслідки спроби обходу константності

Якщо розробник виконує примусове приведення типу для зняття константності (`*(int*)&const_var = 42;`) для змінної, спочатку визначеної як `const`, стандарт мови класифікує це як `undefined behavior`[^iso-c-n1570]. В embedded-середовищі, якщо така змінна розташована у Flash, спроба запису на рівні ядра ARM викликає апаратне виключення `HardFault`. Якщо ж змінна розміщена на стеку, запис може змінити пам’ять, але компілятор, заздалегідь оптимізувавши наступні читання, все одно може використовувати старе закешоване значення.
