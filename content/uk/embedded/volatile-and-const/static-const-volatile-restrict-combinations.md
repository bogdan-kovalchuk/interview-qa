## Short answer

`static` керує linkage або storage duration, `const` забороняє зміну через цей lvalue, `volatile` змушує реально виконувати access, а `restrict` обіцяє відсутність aliasing для оптимізації. Для MMIO типовий pointer: `volatile uint32_t *`; для read-only register може бути `volatile const uint32_t *`. `static const` часто кладе таблиці у flash/rodata, а `restrict` доречний у DSP/buffer code, якщо контракт справді виконується.[^dou-embedded-interview]

## Detailed explanation

### Призначення кожного специфікатора та кваліфікатора

У мові C ці чотири ключові слова регулюють принципово різні аспекти поведінки даних[^iso-c-n1570]:
- `static`: керує зв’язуванням (linkage) або тривалістю зберігання (storage duration). На рівні файлу задає внутрішнє зв’язування (`internal linkage`), обмежуючи видимість символу поточною одиницею трансляції. Всередині функції створює змінну зі статичною тривалістю зберігання, яка ініціалізується один раз і зберігає стан між викликами.
- `const`: кваліфікатор типу, що робить об’єкт доступним лише для читання (read-only lvalue), захищаючи від запису на етапі компіляції.
- `volatile`: кваліфікатор типу, що забороняє компілятору усувати, змінювати кратність або кешувати звернення до об’єкта, трактуючи кожне звернення як спостережуваний побічний ефект.
- `restrict`: кваліфікатор вказівника (введений у C99), який декларує компілятору, що впродовж часу життя даного покажчика доступ до відповідного об’єкта пам’яті буде здійснюватися виключно через нього (відсутність aliasing)[^iso-c-n1570].

### Практичні комбінації в Embedded-системах

1. `static const`:
   - *Використання*: локальні таблиці перерахунку (LUT), дескриптори драйверів або рядкові константи.
   - *Ефект*: символ прихований усередині модуля (не засмічує глобальну таблицю символів лінкера), а дані розміщуються у Flash-пам’яті (секція `.rodata`), зберігаючи дефіцитну RAM.

2. `volatile const` (або `const volatile`):
   - *Використання*: апаратні регістри статусу, які змінюються лише кремнієм (наприклад, регістр прапорців периферії `USART_ISR` або регістр Device ID).
   - *Ефект*: `const` запобігає спробі програми випадково записати дані в read-only регістр, а `volatile` змушує компілятор генерувати реальне читання на кожному кроці, уникаючи оптимізації[^iso-c-n1570].

3. `static volatile`:
   - *Використання*: змінні-прапорці для обміну даними між обробником переривання (ISR) та функціями того самого `.c` файлу.
   - *Ефект*: видимість змінної обмежена поточним файлом (інкапсуляція), а компілятор завжди читає її зі статичної пам’яті SRAM.

4. `restrict` разом із `const`:
   - *Використання*: сигнатури функцій цифрової обробки сигналів (DSP), копіювання чи фільтрації:
   ```c
   void fir_filter(float * restrict out,
                   const float * restrict in,
                   const float * restrict coeffs,
                   size_t n);
   ```
   - *Ефект*: компілятор гарантує, що запис у масив `out` не може змінити значення у вхідних буферах `in` та `coeffs`. Це дозволяє агресивно використовувати конвеєр, векторизацію (SIMD) та регістрове кешування без перечитування пам’яті.

### Безглузді або заборонені комбінації

- `restrict` дозволено застосовувати виключно до вказівників на об’єкти (або параметрів-масивів функцій). Оголошення на кшталт `restrict int x;` є порушенням обмежень за стандартом C[^iso-c-n1570].
- Поєднання `const` та `restrict` на самому покажчику (`int * const restrict p`) має сенс, але подвійне використання на не-покажчиках є невалідним.
