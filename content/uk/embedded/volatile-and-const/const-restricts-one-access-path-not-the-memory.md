## Short answer

**`const` забороняє модифікувати об’єкт через цей lvalue, але не доводить фізичної незмінності пам’яті.**

Об’єкт без визначення як `const` можна передати функції через `const T *`, щоб ця функція не змінювала його через цей параметр. `const volatile` описує доступ, за якого firmware не записує через цей шлях, але значення може змінити hardware.[^iso-c-n1570]

`const` є обмеженням типізованого доступу C; фактичні дозволи пам’яті залежать від пристрою та його конфігурації.[^iso-c-n1570]

## Detailed explanation

У C `const` кваліфікує тип lvalue: вираз через такий доступ не можна використовувати для модифікації об’єкта. Це не перетворює пам’ять на фізично незмінну і не захищає її від усіх інших агентів. Наприклад, звичайний змінюваний буфер можна передати як `const T *` функції, яка лише читає його; інший код зберігає можливість змінювати той самий об’єкт.[^iso-c-n1570]

`const` не є механізмом захисту пам’яті. Воно не налаштовує MPU, не змінює властивості Flash і саме по собі не забороняє hardware або DMA оновити регіон. Під час читання memory-mapped регістра, який може змінитися незалежно від програми, окремо потрібен `volatile` згідно з правилами MCU та toolchain.[^iso-c-n1570]

**Приклад:** параметр `const uint8_t *data` каже функції, що вона не змінюватиме байти через `data`; це не означає, що початковий буфер глобально immutable. Натомість `const volatile uint32_t *status` не дозволяє функції записати через цей вказівник і позначає кожен доступ як volatile. Чи потрібен саме цей тип, визначає інтерфейс пристрою.[^iso-c-n1570]

**Типова помилка:** плутати обмеження API з дозволами апаратури. Використовуй `const` у параметрах для функцій-читачів і `volatile` для об’єктів зі спеціальною зовнішньою семантикою доступу. Коли потрібен реальний захист, застосовуй апаратні механізми пам’яті, а не покладайся на qualifier C.[^iso-c-n1570]
