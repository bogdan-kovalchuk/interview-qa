## Question code

```c
int x = 1, y = 2;
const int *p = &x;
p = &y;
*p = 3;
```

## Short answer

**`p = &y` скомпілюється, `*p = 3` не скомпілюється.**

`const int *p` означає pointer to const int. Const стосується даних, на які вказує `p`, а не самого pointer. Тому pointer можна змінити, але запис через нього заборонений.

Правило: якщо `const` ліворуч від `*`, захищені pointed-to data.[^iso-c-n1570]

## Detailed explanation

`const int *p` є змінним вказівником на `int`, який не можна змінювати через цей вираз доступу. Кваліфікатор `const` належить типу об’єкта, на який вказує `p`, а не самому вказівнику. У прикладі `p` спочатку зберігає адресу `x`, а потім отримує адресу `y`; обидві адреси мають сумісний тип `int *`, який можна перетворити на `const int *`.[^iso-c-n1570]

Після присвоєння `p = &y` вираз `*p` позначає об’єкт `y`, але його тип через цей шлях доступу є `const int`. Тому `*p = 3` порушує обмеження мови: оператор присвоєння вимагає змінюваний lvalue зліва. Це діагностична помилка компіляції, а не правило, яке робить сам `y` незмінним: якщо `y` оголошено звичайним `int`, його можна змінити через інше придатне ім’я.[^iso-c-n1570]

Важлива межа: `const` тут обмежує спосіб доступу через `p`; воно не створює копію даних і не гарантує фізичний захист пам’яті. Перетворити `const int *` на `int *` без явного зняття кваліфікатора не можна; навіть явне приведення не робить запис коректним, якщо початковий об’єкт сам був оголошений `const`.[^iso-c-n1570]

Приклад: після `p = &y` читання `int value = *p;` дозволене, а `*p = 3;` має бути відхилене компілятором. Типова помилка – сприйняти `const` як заборону перепризначати `p`; перевіряйте, до якого саме типу в оголошенні належить кваліфікатор.[^iso-c-n1570]
