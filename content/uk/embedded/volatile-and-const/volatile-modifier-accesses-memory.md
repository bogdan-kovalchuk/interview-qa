## Short answer

Забороняє компілятору кешувати значення змінної в регістрі або прибирати доступ як "зайвий" – при кожному зверненні виконується реальне читання/запис.[^dou-embedded-interview]

Використовується коли значення може змінитися поза звичайним потоком виконання:
- **Регістри периферії**: `volatile uint32_t *GPIOA = (uint32_t *)0x40020000;`
- **Змінна, яку змінює ISR**: `volatile bool flag = false;`
- **Signal handler** або hardware status flag.

Для потоків сам по собі `volatile` <span class="warn">не є синхронізацією</span>: не гарантує atomicity, ordering або mutual exclusion. Для цього потрібні `mutex`, critical section або atomics.

## Detailed explanation

### Модель пам’яті та правило as-if

Модифікатор `volatile` є кваліфікатором типу в стандарті C, який змінює спосіб доступу компілятора до об’єкта[^iso-c-n1570]. За замовчуванням компілятор керується правилом «якщо» (as-if rule): код транслюється так, щоб забезпечити кінцевий результат, оптимізуючи або усуваючи проміжні читання та записи в пам’ять, якщо вони здаються зайвими. Доступ до об’єктів із кваліфікатором `volatile` стандарт класифікує як спостережувану поведінку (observable behavior), яку компілятор зобов’язаний зберегти в точності так, як написано у вихідному коді[^iso-c-n1570].

### Поведінка на рівні машинного коду та асемблера

Розглянемо типовий цикл очікування апаратного прапорця:

```c
// Варіант без volatile
uint32_t *flag_ptr = (uint32_t *)0x40020000;
while (*flag_ptr == 0) {}

// Варіант із volatile
volatile uint32_t *vflag_ptr = (volatile uint32_t *)0x40020000;
while (*vflag_ptr == 0) {}
```

При рівні оптимізації `-O2` для архітектури ARM Cortex-M компілятор генерує різний асемблерний код:
- Без `volatile`: компілятор зчитує комірку один раз інструкцією `LDR R0, [R1]` до входу в цикл. Якщо там був нуль, генерується нескінченна інструкція переходу на саму себе (`B .`), блокуючи мікроконтролер навічно.
- З `volatile`: компілятор генерує інструкцію читання `LDR R0, [R1]` на **кожній** ітерації всередині циклу, забезпечуючи реакцію програми на зовнішню зміну сигналу в пам’яті.

### Синтаксис покажчиків із volatile

Подібно до `const`, кваліфікатор `volatile` застосовується або до самих даних, або до адреси:
- `volatile uint32_t *p`: вказівник на дані, що можуть змінюватися апаратурою. Сам вказівник можна змінювати. За цим принципом у CMSIS поля структур периферії мають кваліфікатор `__IO` (`volatile`): `#define GPIOA ((GPIO_TypeDef *)0x40020000)`.
- `uint32_t * volatile p`: сам вказівник змінюється непередбачувано (наприклад, перемикається обробником переривання), але дані за адресою вважаються звичайними.
- `volatile uint32_t * const p`: константний вказівник на апаратний регістр (адреса зафіксована у Flash, значення в пам’яті є volatile).

### Межі застосування та хибні очікування

Головна небезпека полягає у спробі використовувати `volatile` як інструмент синхронізації потоків в RTOS або між ядрами:
1. `volatile` не робить операції неподільними (non-atomic). Операція `flag = flag + 1` розбивається на зчитування, модифікацію та запис. Якщо переривання виникне між `LDR` та `STR`, результат буде пошкоджено.
2. `volatile` не забороняє перевпорядкування не-volatile операцій навколо нього. Компілятор може перенести запис звичайної змінної за запис volatile-прапорця, що призведе до гонитви даних (data race). Крім того, `volatile` не вставляє апаратні бар’єри пам’яті (`DMB`, `DSB`), які необхідні процесорам з апаратним конвеєром і буферами запису.
