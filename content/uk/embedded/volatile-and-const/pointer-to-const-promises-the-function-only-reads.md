## Short answer

**Функція отримує pointer to const `uint8_t`**: вона може пересувати pointer, але не може змінювати байти буфера через `buf`.

Наприклад, `void uart_write(const uint8_t *buf, size_t len)` документує, що переданий buffer буде лише прочитаний. Це дозволяє передавати як mutable RAM buffer, так і read-only flash table.

Якщо функція задумана лише для читання даних, `const T *` виражає це обмеження в її інтерфейсі; сам по собі такий тип не робить об’єкт незмінним через інші доступні до нього шляхи.[^iso-c-n1570]

## Detailed explanation

`const uint8_t *buf` оголошує `buf` як pointer на `uint8_t`, доступний для читання через цей pointer. У C кваліфікатор `const` належить до типу об’єкта, на який вказує `*buf`, тому присвоєння на кшталт `buf[0] = value` є порушенням обмежень мови, тоді як змінити саме значення pointer можна. Це властивість доступу через конкретний вираз, а не обіцянка, що байти фізично незмінні: інша змінна чи пристрій можуть змінити ту саму пам’ять.[^iso-c-n1570]

У параметрі функції масивний запис не зберігається як масив: параметр `uint8_t buf[]` коригується до pointer. Тому `const uint8_t *buf` корисний для API, який читає передані байти, наприклад для передачі буфера в UART-драйвер або обчислення контрольної суми. Компілятор не дозволить функції випадково записати через `buf`, а виклик можна зробити і з mutable буфером, і з об’єктом, оголошеним як `const`.[^iso-c-n1570]

Це не перевірка довжини і не гарантія доступності пам’яті: контракт функції все одно має визначати, скільки байтів дозволено читати та як довго pointer лишається чинним. Також не слід прибирати `const` приведенням типу лише для обходу діагностики: запис через отриманий некваліфікований lvalue в об’єкт, який справді оголошено `const`, має undefined behavior.[^iso-c-n1570]

**Приклад:** для `void uart_write(const uint8_t *buf, size_t len)` функція може читати `buf[i]` для `i < len`, але не може присвоїти нове значення `buf[i]`. Водночас локальна копія аргументу `buf` може бути пересунута вперед під час обходу даних.

**Типові помилки:**
- трактувати `const` як властивість усієї пам’яті, а не доступу через цей pointer;
- вважати, що `const` забороняє змінити сам pointer;
- забути передати правильний `len` і вийти за межі буфера.
