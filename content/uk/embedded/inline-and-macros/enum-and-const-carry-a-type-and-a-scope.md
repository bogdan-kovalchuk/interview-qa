## Short answer

**`enum`-перелічувачі та об’єкти `const` є оголошеннями C з типом і областю видимості**, тоді як `#define` підставляє токени на етапі preprocessing і не створює C-ідентифікатор із типом.[^iso-c-n1570]

`enum { MAX_CH = 8 };` задає integer constant expression. Об’єкт `const` має оголошений тип, але у C не є integer constant expression для межі звичайного масиву.[^iso-c-n1570]

Обирай `enum` для перелічуваних цілих констант, `const` для типізованого об’єкта, а `#define` – коли потрібна саме дія препроцесора.[^iso-c-n1570]

## Detailed explanation

`enum` і `const` використовують звичайні правила мови C: оголошення має тип, а видимість і область дії імені залежать від місця оголошення. Макрос `#define`, натомість, належить до окремого простору імен препроцесора та працює як підстановка токенів; він не має типу C і не може перевірятися компілятором як звичайне значення до підстановки.[^iso-c-n1570]

Перелічувачі зручні для невеликого набору цілих значень або compile-time параметрів. Наприклад, `enum { MAX_CH = 8 };` дає іменоване ціле значення, яке можна використати у виразі сталої цілочисельної величини, зокрема у звичайній декларації масиву. Ім’я `MAX_CH` при цьому все одно займає звичайний простір імен і має область видимості згідно з місцем визначення; `enum` не створює окремої «локальної» категорії назв автоматично.[^iso-c-n1570]

`const` оголошує об’єкт із кваліфікованим типом, тож компілятор може перевіряти сумісність типів і правила доступу. Але в C об’єкт `const int n = 8;` сам по собі не є integer constant expression для межі масиву на рівні file scope. Це відрізняється від C++ і часто дивує під час перенесення коду. Також не слід стверджувати, що `const` завжди займає фізичну пам’ять: реалізація може оптимізувати зберігання, якщо поведінка програми лишається спостережно еквівалентною.[^iso-c-n1570]

Приклад:

```c
enum { BUFFER_SIZE = 16 };
const int runtime_limit = 12;
int buffer[BUFFER_SIZE];
```

Тут межа `buffer` є сталою цілочисельною величиною завдяки перелічувачу; `runtime_limit` має тип `const int`, але не замінює його в такому контексті стандартного C. На block scope C має також variable length arrays, якщо реалізація їх підтримує, але це окрема властивість мови й не робить `const` integer constant expression.[^iso-c-n1570]

Макрос лишається доречним для умовної компіляції, склеювання токенів, stringification або констант, потрібних до компіляції C-виразів. Для звичайних іменованих значень краще спершу розглянути оголошення `enum` чи типізованого об’єкта. Не варто обирати конструкцію лише за тим, чи показує її конкретний debugger: доступність і вигляд debug info залежать від параметрів збірки та інструментів.[^iso-c-n1570]

**Типова помилка:** казати, що `enum` не забруднює глобальну область імен, або що `const` обов’язково резервує пам’ять. Обидва твердження перебільшують гарантії C; вибір слід обґрунтовувати потрібним типом, областю видимості та вимогою constant expression.[^iso-c-n1570]
