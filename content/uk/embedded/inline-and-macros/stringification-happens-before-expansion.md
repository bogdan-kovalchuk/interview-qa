## Question code

```c
#define STR(x) #x
```

## Short answer

<span class="warn">`#` стрінгіфікує написання аргументу без попереднього розгортання</span>, тому `STR(__LINE__)` дає рядок `"__LINE__"`.

Щоб отримати номер рядка як текст, додай проміжний рівень: спершу розгорни макрос, потім стрінгіфікуй:

```c
#define STR(x) #x
#define XSTR(x) STR(x)
// XSTR(__LINE__) expands to the current line number as a string
```

Це стандартний двоступеневий шаблон для стрінгіфікації розгорнутого аргументу.[^iso-c-n1570]

## Detailed explanation

Пастка виникає через особливий порядок підстановки параметрів function-like макроса. Звичайний параметр спершу повністю розгортається, а тоді вставляється у список заміни; але параметр, безпосередньо перед яким стоїть `#`, не розгортається. Оператор створює рядок із написання аргументу на цьому етапі.[^iso-c-n1570]

Тому виклик `STR(__LINE__)` підставляє у `#x` саме токен `__LINE__`. Результат – рядковий токен `"__LINE__"`, а не десяткове число. `__LINE__` є predefined macro, значенням якого є номер поточного source line після врахування `#line`; це значення з’являється тільки тоді, коли аргумент проходить звичайне розгортання макросів.[^iso-c-n1570]

Двоступеневий шаблон розділяє ці дії. Зовнішній макрос приймає аргумент без `#` біля параметра, тому спершу розгортає його, а потім передає отриманий токен внутрішньому макросу, що виконує стрінгіфікацію. Через це `XSTR(__LINE__)` дає рядок із фактичним номером рядка, де стоїть виклик, а не фіксоване значення з прикладу.[^iso-c-n1570]

**Приклад:**

```c
#define STR(x) #x
#define XSTR(x) STR(x)
#define COUNT 25
STR(COUNT)   /* "COUNT" */
XSTR(COUNT)  /* "25" */
```

Проблема помітна в діагностичних макросах: повідомлення містить буквальне ім’я макроса замість номера рядка чи значення конфігурації. Щоб уникнути цього, залишай `#` у внутрішньому макросі, а розгортання доручи зовнішньому. Перевіряй обидва результати препроцесування на простому прикладі; не роби висновок із вигляду початкового коду, бо фінальний рядок утворюється під час трансляції.[^iso-c-n1570]

**Типові помилки:**

- Вважати, що `#` спершу виконує розгортання, а потім перетворює результат на рядок.
- Записати `#` у зовнішньому макросі й очікувати, що вкладений виклик змінить цей порядок.[^iso-c-n1570]
