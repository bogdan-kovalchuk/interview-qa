## Question code

```c
#define ERR_LIST(X) \
  X(ERR_NONE, "OK") \
  X(ERR_TIMEOUT, "Timeout")
```

## Short answer

Той самий список розгортають двічі з різним `X`:

```c
#define AS_ENUM(n, s) n,
typedef enum { ERR_LIST(AS_ENUM) } err_t;

#define AS_STR(n, s) [n] = s,
static const char *const names[] = { ERR_LIST(AS_STR) };
```

Один список – два згенерованих об’єкти. Новий код помилки додається в одному місці, і `enum`, і `names[]` оновлюються разом.[^iso-c-n1570]

## Detailed explanation

X-macro – це список, який передають макросу-обробнику, щоб згенерувати з тих самих записів кілька фрагментів C-коду. У прикладі `ERR_LIST(X)` не зберігає значення самостійно: під час кожного виклику препроцесор підставляє визначення `X` для кожного запису.

Під час першого розгортання `AS_ENUM` перетворює аргумент `n` на елемент переліку, а `s` не використовує. Друге розгортання з `AS_STR` утворює designated initializers масиву: значення `n` стає індексом, а `s` – рядком. Тому `ERR_TIMEOUT` має однакове числове значення в `enum` та позицію в таблиці назв; додавання запису до списку оновлює обидва результати з одного місця.[^iso-c-n1570]

Це техніка препроцесора, а не окремий механізм мови для зв’язування типу переліку з масивом. Стандарт C задає заміну параметрів макросу та обробку директив, але не перевіряє, що будь-які окремо оголошені об’єкти мають узгоджений зміст.[^iso-c-n1570]

**Типові помилки:**
- Вважати, що X-macro саме по собі перевіряє межі масиву або унікальність кодів. Це треба забезпечити дизайном списку чи окремими перевірками.
- Забути кому в `AS_ENUM` або коми між ініціалізаторами, через що розгортання стає некоректним.
- Використовувати індекс `enum` як позицію масиву, якщо значення перелічувачів задано не послідовно від нуля.

Для прикладу `ERR_NONE = 0` і `ERR_TIMEOUT = 1` утворюють щільні індекси. Якщо ж кодам призначити `10` та `20`, масив із двох елементів вже не може бути проіндексований цими значеннями без іншого відображення. Отже, перед застосуванням треба вирішити, чи перелік означає індекси, чи лише зовнішні коди помилок; для другого випадку краще генерувати таблицю пар або функцію пошуку. Такий вибір робить припущення явним і не дозволяє помилково читати за межами масиву.
