## Question code

```c
static inline uint32_t set_bit(uint32_t v, unsigned n) {
  return v | (1u << n);
}
```

## Short answer

**Типізовані параметри й однократне обчислення аргументів.**

Макрос `#define SET_BIT(v,n) ((v) | (1u << (n)))` у цьому простому випадку може працювати, але препроцесор не перевіряє типи параметрів і може підставити аргумент у кілька місць. `static inline` функція приймає типізовані параметри, а кожен аргументний вираз обчислюється один раз; компілятор може inline-ити її, але це не гарантується.

Для наведеного зсуву `n` має бути меншим за ширину типу лівого операнда; межу треба забезпечити окремо.[^iso-c-n1570]

## Detailed explanation

`static inline` дає звичайну функцію з параметрами оголошених типів, тоді як макрос лише підставляє токени до компіляції. Тому компілятор може діагностувати несумісний тип аргументу для функції, а вираз, переданий як аргумент, обчислюється один раз під час виконання виклику. У макросі ж параметр може трапитися в replacement list кілька разів і відповідний вираз буде підставлено стільки ж разів.[^iso-c-n1570]

Це особливо корисно для bit helper, який змінює регістр або обчислює маску з аргументу. Проте `inline` є підказкою компілятору, а не вимогою генерувати код без виклику; так само доступність і якість debug information залежать від компілятора та режиму збірки. Отже, типізація й контроль оцінювання аргументів є мовними властивостями функції, а оптимізація та відлагодження – властивостями інструментів.

Є й межа коректності самого зсуву: для `1u << n` значення `n` має бути невід’ємним і меншим за ширину promoted left operand. Тип `unsigned int` не зобов’язаний мати 32 біти на кожній платформі, отже для helper, який має працювати з `uint32_t`, слід обрати операнд із потрібною шириною й відхиляти індекс поза діапазоном. Саме `static inline` не усуває undefined behaviour від некоректного shift count.[^iso-c-n1570]

**Типові помилки:**

- Приписувати `inline` гарантію оптимізації або наявності символу для debugger; це визначає toolchain і прапорці.
- Вважати функцію автоматично безпечною для будь-якого індексу біта. Перевіряйте межу зсуву та ширину типу.
- Передавати volatile-регістр через макрос, який згадує параметр двічі; прочитайте регістр один раз або використайте типізовану функцію з відповідною семантикою.
