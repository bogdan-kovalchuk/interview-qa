## Short answer

**X-macro – це список, визначений один раз, який розгортають у різних контекстах**.

Класична задача: тримати синхронними `enum` і таблицю рядків/обробників. Список елементів описують через макрос `X(...)`, а потім по-різному визначають `X`, щоб згенерувати enum, масив імен, switch тощо.

Додавання елемента до єдиного списку оновлює кожне місце генерації, якщо всі такі місця використовують цей список.[^gcc-cpp-overview]

## Detailed explanation

X-macro – це прийом із препроцесором, у якому елементи даних записані один раз як виклики макросу-мітки, зазвичай `X(...)`, а той самий список кілька разів включається з різними визначеннями `X`. Сам список не задає одну структуру даних; кожне розгортання інтерпретує його рядки у своєму контексті.[^gcc-cpp-overview]

Наприклад, список команд може містити `X(START)` і `X(STOP)`. В одному місці визначте `X(name)` як елемент enum, а в іншому – як рядковий літерал для таблиці назв. Коли список зміниться, препроцесор підставить новий елемент в усі місця, які його використовують, тож кілька паралельних переліків легше тримати узгодженими. Макропроцесор робить звичайну підстановку токенів до компіляції, тому результати все одно мають утворювати синтаксично коректний C-код.[^gcc-cpp-overview]

Умовний приклад списку:

```c
#define COMMANDS(X) X(START) X(STOP)

#define AS_ENUM(name) CMD_##name,
enum Command { COMMANDS(AS_ENUM) };
#undef AS_ENUM

#define AS_TEXT(name) #name,
const char *command_names[] = { COMMANDS(AS_TEXT) };
#undef AS_TEXT
```

Такий підхід зменшує ризик, що enum і таблиця матимуть різний порядок або кількість записів, але не забезпечує автоматично повної узгодженості типів чи семантики. Потрібні перевірки розміру таблиць, повторів назв і відповідності порядку; також згенерований фрагмент може бути складнішим для читання та діагностики компілятора. Для короткого списку, який не має кількох похідних представлень, звичайний enum або масив може бути яснішим.

**Типові помилки:**

- Називати X-macro окремою мовною можливістю; це домовленість поверх макропроцесора.
- Припускати, що список гарантує семантичну коректність усіх розгортань.
- Не скасувати локальне визначення `X` через `#undef` після включення списку.
