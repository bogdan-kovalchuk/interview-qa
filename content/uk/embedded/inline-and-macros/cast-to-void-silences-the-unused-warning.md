## Question code

```c
#define UNUSED(x) ((void)(x))
```

## Short answer

**Приведення виразу до `void` явно відкидає його значення**; GCC документує прийом для `-Wunused-value` і невикористаної локальної змінної, а діагностики залежать від прапорців та компілятора.[^gcc-warning-options-unused]

Макрос `UNUSED(x)` з кодового фрагмента застосовує cast і до параметра, наприклад `UNUSED(ctx)` у callback. Вираз `x` усе одно обчислюється: його побічні ефекти не зникають лише через приведення до `void`.[^gcc-warning-options-unused]

Це не універсальний спосіб вимкнути попередження про параметр; для `-Wunused-parameter` GCC документує атрибут `unused`. Придушуй діагностику локально лише за навмисного невикористання.[^gcc-warning-options-unused]

## Detailed explanation

Cast `(void)(x)` перетворює значення виразу на `void`, явно показуючи, що подальше значення результату не потрібне. Макрос `UNUSED(x)` є лише зручним записом цього cast: препроцесор підставляє переданий аргумент у вираз, а потім компілятор обробляє його за звичайними правилами C.[^iso-c-n1570]

У GCC такий cast є документованим способом прибрати попередження про результат виразу, який інакше не використовується, і показаний також для локальної змінної. Але різні `-Wunused-*` діагностики мають окремі правила: наприклад, попередження про параметр функції в GCC вмикається відповідними прапорцями, а для деяких випадків документація радить атрибут `unused`. Не варто обіцяти, що макрос прибере будь-яке попередження на будь-якому toolchain.[^gcc-warning-options-unused]

Важлива межа: cast відкидає результат, але не скасовує обчислення аргументу. Якщо передати `UNUSED(read_register())`, функція буде викликана; якщо аргумент має side effect на кшталт `counter++`, він відбудеться. Тому макрос не повинен використовуватися як спосіб «видалити» небажану операцію.[^iso-c-n1570]

У callback це доречно, коли API вимагає параметр, а конкретна реалізація його свідомо не використовує. Інша проста можливість – не давати параметру імені, якщо його тіло справді не читає його, або використати підтримуваний компілятором атрибут. Наприклад, локальна змінна, приведена до `void`, демонструє саме намір відкинути її значення:

```c
int value = 0;
(void)value;
```

**Типова помилка:** вставити `UNUSED(x)` до того, як зрозуміло, чому `x` не використовується. Спершу перевір, що параметр не забули обробити; після цього обери механізм, який підтримує цільовий компілятор, і залиш локальний намір поруч із параметром.
