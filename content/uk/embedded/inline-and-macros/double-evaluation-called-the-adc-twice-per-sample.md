## Question code

```c
#define FILT(s) ((s) + ((adc_read() - (s)) >> 3))
```

## Short answer

Макрос підставляє параметр `s` у replacement list двічі, тому переданий як аргумент виклик `adc_read()` обчислюється двічі; крім цього, тіло прямо містить ще один виклик `adc_read()`.[^iso-c-n1570]

Якщо кожен виклик цієї функції запускає нове перетворення, формула змішує різні семпли; точна поведінка залежить від реалізації `adc_read()`. Зчитай вимір один раз у локальну змінну або передай стабільне значення у `static inline` функцію.[^iso-c-n1570]

## Detailed explanation

Function-like макрос підставляє аргументи як послідовності preprocessing tokens. Якщо параметр ужито в replacement list двічі, вираз аргументу опиниться в розгорнутому коді двічі; на відміну від звичайної функції, макрос не створює одну типізовану копію значення аргументу.[^iso-c-n1570] Це важливо, коли вираз має побічний ефект: змінює змінну, читає периферійний регістр із read-to-clear поведінкою або викликає функцію.

У наведеному `FILT(s)` параметр `s` повторено у двох місцях. Якщо викликати `FILT(adc_read())`, препроцесор підставить `adc_read()` в обидва місця, а тіло макросу має ще й окремий `adc_read()`. Отже, після підстановки буде три виклики функції, якщо всі відповідні операнди обчислюються. Чи означає кожен виклик нову конверсію АЦП, залежить від контракту драйвера: функція може запускати вимір, повертати готовий результат або читати буфер.[^iso-c-n1570]

Саме ця різниця часто породжує нестабільність: послідовні виміри можуть відрізнятися через зміну аналогового сигналу, шум, час дискретизації або стан периферії. Не можна стверджувати, що будь-який повторний виклик обов’язково дасть новий чи «шумніший» семпл без документації конкретної функції. Але код уже не використовує один і той самий знімок даних, і це може порушити математичне припущення фільтра.[^iso-c-n1570]

Приклад:

```c
static inline int filt(int sample)
{
    return sample + ((adc_read() - sample) >> 3);
}

int sample = adc_read();
int result = filt(sample);
```

Тут аргумент `sample` обчислено до виклику й у тілі функції використовується його одне передане значення; однак приклад усе ще читає ADC ще раз усередині функції. Якщо задум фільтра вимагає саме одного виміру на оновлення, передай у функцію також попередній стан і новий семпл, не викликаючи ADC зсередини неї. Inline функції зазвичай простіше перевіряти як звичайні функції, проте компілятор не зобов’язаний буквально вбудовувати їхній код.[^iso-c-n1570]

**Типові помилки:** рахувати лише входження `adc_read()` у вихідному рядку виклику й забути його появу в тілі макросу; або приписувати повторному читанню конкретний шум без знання контракту HAL. Щоб перевірити підстановку, подивись `-E` output, а потім окремо перевір API читання ADC і таймінг вимірів.[^gcc-cpp-invocation]
