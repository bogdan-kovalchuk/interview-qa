## Question code

```c
#ifndef SENSOR_H
#define SENSOR_H
/* вміст header */
#endif
```

## Short answer

**Include guard запобігає повторному включенню header** у той самий translation unit.

Без нього повторне включення може повторити визначення типу чи об’єкта і спричинити діагностичну помилку; сумісні повторні оголошення функцій самі по собі дозволені. Під час першого проходу `SENSOR_H` визначається, а наступні рази умовний блок пропускається.

Використовуй guard із назвою, достатньо унікальною для проєкту, щоб уникнути зіткнення макросів.[^iso-c-n1570]

## Detailed explanation

Include guard – це умовний блок у header-файлі, який дозволяє препроцесору включити його вміст лише один раз у межах одного translation unit. Поширена форма починається з `#ifndef`, визначає відповідний макрос через `#define`, а закривається `#endif`.[^iso-c-n1570]

Директива `#include` текстуально включає вміст названого файлу в місце директиви. Якщо той самий header досяжний кількома шляхами графа включень, без захисту його вміст оброблявся б повторно. Guard використовує спільний стан препроцесора: перше включення бачить невизначений макрос і визначає його; на кожному наступному включенні умова вже хибна, тож тіло пропускається.[^iso-c-n1570]

Приклад:

```c
#ifndef SENSOR_H
#define SENSOR_H
struct Sensor { int value; };
#endif
```

Без guard повторне визначення структури може порушити правила мови. Водночас не кожне повторення оголошення є помилкою: сумісні оголошення тієї самої функції в одному translation unit можуть повторюватися. Тому точніше казати, що guard прибирає небажану повторну обробку header, а не що він обов’язково потрібен для кожного прототипу.[^iso-c-n1570]

Ім’я guard має бути специфічним: якщо два різні header використовують той самий макрос, включення першого помилково вимкне вміст другого. Часто до назви додають ім’я проєкту, директорії або файлу. Також не кожен header задуманий для одноразового включення: деякі навмисно параметризують повторну обробку макросами, тому їхній контракт потрібно читати окремо.[^iso-c-n1570]

**Типові помилки:**

- Використати надто загальне ім’я на кшталт `COMMON_H`, яке може зіткнутися з іншим файлом.
- Вважати, що guard захищає між окремими translation units: макроси препроцесора мають окремий стан під час компіляції кожного з них.[^iso-c-n1570]
