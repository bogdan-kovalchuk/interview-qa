## Question code

```c
static void (*rx_cb)(uint8_t);

void uart_isr(void) {
    rx_cb(0x55);
}
```

## Short answer

<span class="warn">Callback може бути не зареєстрований, а його вказівник – дорівнювати `NULL`.</span>

Якщо ISR викличе нульовий або невалідний `rx_cb`, це undefined behaviour за правилами C; стандарт не визначає, чи MCU згенерує HardFault, зависне або проявить інший наслідок. Такий дефект може бути складно відтворити, якщо переривання настає лише у вузькому часовому вікні.

Захист: установи no-op або перевіряй `if (rx_cb != NULL)`, а реєстрацію виконай до дозволу відповідного interrupt. Конкретний порядок і синхронізацію узгодь із правилами платформи.[^iso-c-n1570]

## Detailed explanation

У цьому прикладі `rx_cb` зберігає адресу функції, яку ISR викликає для кожного отриманого байта. Наявність змінної ще не означає, що вона вже містить адресу придатної функції: у C об’єкт зі static storage duration без явного ініціалізатора спочатку отримує null pointer value, а автоматична локальна змінна без ініціалізатора не має гарантованого корисного значення. Виклик через null або інший невалідний function pointer має undefined behaviour; C не обіцяє конкретний апаратний fault.[^iso-c-n1570]

Ризик виникає через порядок запуску. Якщо периферія або interrupt controller дозволяє UART interrupt раніше, ніж встановлено callback, перший байт може привести до виклику ще не готового вказівника. На одній платі це може проявитися як HardFault, на іншій – як перехід за хибною адресою чи інша поломка. Такі наслідки залежать від MCU і реалізації, а не є окремою гарантією мови C.

Безпечна послідовність зазвичай така: спочатку встановити валідний callback або no-op, очистити застарілий стан периферії, а потім дозволити джерело переривання. Якщо callback оновлюють після запуску, потрібен визначений платформою спосіб узгодити запис із ISR: наприклад, коротко заборонити саме це переривання навколо заміни. Саме `volatile` не робить складену операцію реєстрації атомарною і не задає універсальних правил синхронізації з hardware ISR.

Приклад: до ввімкнення UART interrupt ініціалізаційний код може присвоїти `rx_cb = uart_rx_handler`; альтернативно, початкове значення може вказувати на функцію, що безпечно ігнорує байт. Якщо відсутність обробника є помилкою конфігурації, перевірка `NULL` може зафіксувати цю помилку, але ISR повинен мати визначену безпечну дію.

**Типові помилки:**

- Увімкнути interrupt, а callback зареєструвати пізніше, сподіваючись, що байт не надійде.
- Вважати HardFault гарантованим наслідком: це лише один із можливих проявів на конкретній платформі.
- Замість плану ініціалізації додати тільки `volatile` до вказівника.[^iso-c-n1570]
