## Short answer

**Вказівник на функцію** може посилатися на функцію певного типу й використовуватися для її непрямого виклику. Тип функції визначає тип повернення та список параметрів; стандарт C не вимагає, щоб такий вказівник був звичайною числовою адресою машинного коду.[^iso-c-n1570]

На відміну від object pointer, function pointer має тип вказівника на функцію, а не на об’єкт даних. Код може вибрати сумісну функцію й викликати її через вказівник; її представлення залежить від реалізації.[^iso-c-n1570]

Правило: тип функції має бути сумісним із типом виклику; схожий запис декларацій цього не гарантує.[^iso-c-n1570]

## Detailed explanation

Вказівник на функцію має тип, похідний від функціонального типу, і дозволяє зберегти вибір функції в змінній, полі структури або параметрі. Його можна викликати оператором виклику, наприклад `callback(value)`, або спершу явно розіменувати; у виразі виклику ці форми мають однакову дію. У C функціональний designator автоматично перетворюється на вказівник на функцію, крім кількох визначених контекстів.[^iso-c-n1570]

Вказівник на функцію не слід ототожнювати з вказівником на дані. Мова гарантує окремі типи та операції для цих категорій, але не обіцяє однакове машинне представлення чи придатність для перетворень між ними. Тому не можна загалом зберігати функціональний вказівник у `void *` або друкувати його як числову адресу, ніби це портативна адреса RAM чи Flash. Конкретна ABI може визначати додаткові правила, але вони не є універсальною властивістю C.[^iso-c-n1570]

Сумісність типу важлива для безпечного непрямого виклику. Опис типу охоплює тип повернення і параметри; сумісність визначається правилами мови, а не лише тим, що «аргументи начебто підходять». Виклик через несумісний тип функції має undefined behaviour. Якщо API використовує callback, оголоси його тип явно й передавай функцію з сумісною сигнатурою.[^iso-c-n1570]

Приклад:

```c
typedef int (*compare_fn)(const void *, const void *);
int compare_bytes(const void *a, const void *b);
compare_fn compare = compare_bytes;
int order = compare(left, right);
```

Тут `compare` може вибирати реалізацію порівняння під час виконання. Типова помилка – кастом прибрати попередження про невідповідну сигнатуру; cast не робить несумісну функцію сумісною й не виправляє виклик.[^iso-c-n1570]
