## Short answer

<span class="warn">Indirect calls приховують control flow від читача, debugger-а і деяких static analyzers.</span>

Замість явного `switch` видно лише `handlers[state](...)`. Якщо table ініціалізується runtime або змінюється, важче визначити, які функції можуть викликатися. Це може ускладнити перевірку; правила конкретного проєкту можуть окремо обмежувати такі виклики.

Захист: роби таблиці `static const`, іменуй handlers явно, перевіряй state bounds і документуй transition table.[^iso-c-n1570]

## Detailed explanation

Function pointer table може ускладнити аналіз state machine, бо місце виклику не називає конкретну функцію напряму: ціль визначається значенням таблиці під час виконання. У виразі `handlers[state](event)` спершу треба встановити допустимість `state`, потім з’ясувати, яка функція записана в цьому елементі, і лише тоді можна простежити її ефекти. У явному `switch` перелік переходів зазвичай видно поруч із логікою стану.

Це не означає, що непрямі виклики заборонені або що кожен static analyzer не здатен їх обробити. Статичний аналіз може відновити цілі, коли таблиця має незмінну ініціалізацію; коли її заповнюють або змінюють під час виконання, точність залежить від видимості всіх записів і можливостей конкретного інструмента. У C тип вказівника визначає допустимий тип функції для виклику, але сам тип не гарантує, що індекс таблиці перебуває в межах масиву.[^iso-c-n1570]

Наприклад, якщо для станів `IDLE`, `READ` і `ERROR` є три функції, таблиця з явними позначеними елементами допомагає зіставити кожен стан із handler-ом. Перед індексацією потрібно окремо перевірити, що значення стану належить визначеному діапазону; інакше читання поза межами масиву вже є помилкою незалежно від читабельності виклику.[^iso-c-n1570]

**Типові помилки:**

- Приписувати прихований control flow самому function pointer, хоча складність виникає через динамічно змінюваний набір цілей.
- Вважати `static const` заміною перевірки індексу. Константна таблиця не робить некоректний `state` безпечним.
- Стверджувати, що використання callback автоматично порушує MISRA чи унеможливлює certification: це залежить від застосованих правил, конфігурації аналізатора й вимог конкретної системи.

Щоб полегшити перевірку, зберігайте таблицю незмінною, якщо це підходить моделі, називайте функції за станами й тримайте перелік переходів поруч із визначенням станів. Якщо таблиця має змінюватися, централізуйте її оновлення та перевіряйте всі шляхи запису.
