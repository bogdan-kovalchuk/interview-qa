## Short answer

Через пару `callback + context pointer`.

Приклад: `timer_start(timer, on_timeout, &app);` – driver зберігає адресу функції та адресу об’єкта стану. Коли timer спрацьовує, він передає збережений context у callback; callback перетворює `void *` назад на `struct App *` і читає об’єкт через правильний тип. C дозволяє перетворити вказівник на об’єкт у `void *` і назад із збереженням початкового значення.[^iso-c-n1570]

Правило: callback не повинен здогадуватись про global instance; context робить залежність явною.[^iso-c-n1570]

## Detailed explanation

Callback – це вказівник на функцію, яку API викликає пізніше, а context pointer – вказівник на дані, потрібні цій функції. У C немає вбудованого замикання, яке автоматично захоплює локальні змінні, тому пара «функція плюс дані» є поширеним способом передати стан без global variables. API зберігає обидва значення, а під час події викликає функцію та передає їй context. Типовий контракт має вигляд `void (*callback)(void *)` разом із полем `void *context`.[^iso-c-n1570]

Наприклад, програма може зареєструвати `on_timeout` і адресу структури `app`. Коли таймер спрацює, driver передає збережений вказівник callback-функції. Усередині callback `void *` перетворюють назад на `struct App *`, а тоді звертаються до полів. Перетворення вказівника на об’єкт у `void *` і назад визначене C зі збереженням значення вказівника; це не означає, що будь-який довільний `void *` можна безпечно трактувати як будь-яку структуру.[^iso-c-n1570]

Приклад застосування: один і той самий `on_timeout` можна зареєструвати для кількох таймерів, передавши кожному окрему структуру стану. Це робить залежності явними та дозволяє повторно використовувати функцію; воно також усуває гонитву за спільною глобальною змінною, хоча саме по собі не робить доступ до стану потокобезпечним. Тривалість життя об’єкта має охоплювати весь час, поки API може викликати callback: адреса локальної змінної, що вже вийшла з області видимості, стає висячою.[^iso-c-n1570]

Уявімо, що callback отримав context для лічильника таймера. Він перетворює його на вказівник правильного типу, збільшує лічильник і може оновити прапорець стану. Окремий екземпляр структури на кожен таймер дає незалежний стан, тоді як одна спільна структура навмисно об’єднує його. У багатозадачній системі передавання адреси не замінює синхронізацію, якщо callback і основний код одночасно змінюють ті самі поля.[^iso-c-n1570]

**Типові помилки:**

- Передати адресу тимчасового об’єкта, строк життя якого завершиться до callback.
- Перетворити `void *` на непов’язаний тип і розіменувати його.
- Вважати, що context автоматично копіюється: зазвичай API зберігає лише адресу, тож зміни об’єкта буде видно через той самий вказівник.

Перед реєстрацією перевіряють сигнатуру callback, тип об’єкта, який передається, і момент, коли API припиняє зберігати адресу. Якщо API дозволяє, зручніше оголосити типізований wrapper, щоб помилки типу було легше помітити під час компіляції.[^iso-c-n1570]
