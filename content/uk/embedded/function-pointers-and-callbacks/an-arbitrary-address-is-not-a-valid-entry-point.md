## Short answer

<span class="warn">Саме перетворення довільного цілого числа на function pointer не робить адресу валідною функцією.</span>

У C перетворення integer у pointer має implementation-defined результат: адреса може не бути вирівняна, не вказувати на об’єкт чи функцію потрібного типу або бути trap representation. Виклик function pointer несумісного типу також має undefined behavior.[^iso-c-n1570]

Захист: викликай лише відомий entry point із сумісною сигнатурою та правилами ABI платформи; перехід до іншого образу виконуй лише за документованою процедурою конкретного MCU.[^embeddedinterviewlab] [^iso-c-n1570]

## Detailed explanation

У C адресу машинного коду не можна вважати функцією лише тому, що вона записана у function pointer. Якщо джерелом адреси є ціле число, стандарт визначає результат такого перетворення як implementation-defined: він може не бути належно вирівняним, не вказувати на сутність потрібного типу або бути trap representation. Тобто поведінка залежить від реалізації та її моделі адресації, а саме приведення типів не перевіряє, що за адресою починається виконуваний код.[^iso-c-n1570]

Є й окрема вимога до типу виклику. C дозволяє перетворити pointer на одну функцію на pointer іншого function type і назад, але якщо через перетворений pointer викликати функцію з несумісним типом, це undefined behavior. Параметри, тип результату та calling convention мають узгоджуватися з реальним entry point, інакше код може прочитати аргументи не з тих регістрів або неправильно повернути керування. Для конкретної архітектури додатково діють правила її ABI та інструкцій виклику.[^iso-c-n1570]

Наприклад, таблиця команд bootloader може зберігати адресу функції, але її не слід трактувати як універсальну адресу без перевірки формату таблиці, версії інтерфейсу, сигнатури та вимог MCU. Викликай адресу лише тоді, коли документація платформи підтверджує, що це коректний entry point із потрібною сигнатурою та calling convention.[^iso-c-n1570]

**Типова помилка:** вважати будь-яке значення з Flash або регістра «адресою функції» й одразу викликати його. Симптомом може стати fault, стрибок у дані чи некоректний стан після повернення, але точний прояв залежить від MCU. Використовуй функції, оголошені з потрібною сигнатурою, або перевірену платформну процедуру переходу; не вигадуй ABI вручну.[^iso-c-n1570]

Приклад: якщо таблиця містить callback `int (*)(void *)`, викликати адресу як `void (*)(void)` не можна вважати безпечним навіть тоді, коли обидва pointers однаково представлені в конкретному debug-виводі. Такий збіг байтів не доводить сумісність типів чи коректність entry point.[^iso-c-n1570]
