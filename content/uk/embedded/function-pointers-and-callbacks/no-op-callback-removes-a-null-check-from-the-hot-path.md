## Short answer

Обидва варіанти валідні, але no-op callback може спростити hot path.

Якщо callback опційний і викликається часто, driver може ініціалізувати його функцією `static void noop(void *ctx) { (void)ctx; }`. Тоді код виклику не має гілки `if (cb)`. Але це має бути документовано, щоб callback pointer ніколи не залишався uninitialized.[^iso-c-n1570]

Правило: для простого API перевірка на `NULL` часто зрозуміліша; для dispatch table no-op entry може спростити спільний шлях виклику, але не гарантує виграшу швидкодії.[^iso-c-n1570]

## Detailed explanation

No-op callback – це коректна функція з потрібною сигнатурою, яка нічого не робить; її можна призначити замість відсутнього обробника, щоб викликати callback без окремої перевірки на кожному шляху виконання.[^iso-c-n1570]

У C функція та вказівник на функцію – різні сутності: вказівник має конкретний тип, що включає тип результату й параметрів, і виклик через нього передає керування відповідній функції. Тому no-op має точно відповідати очікуваній сигнатурі. Наприклад, якщо API зберігає `void (*cb)(void *ctx)`, no-op теж приймає `void *ctx`, навіть коли не використовує його. У звичайному C-коді можна записати `(void)ctx;`, щоб явно позначити параметр як навмисно невикористаний.[^iso-c-n1570]

Перевірка `if (cb != NULL)` робить відсутність callback явною і підходить для простого API, де ця гілка не створює проблеми. No-op зручний, коли таблиця обробників має завжди містити викличний запис або коли однакова послідовність викликів спрощує логіку. Сам факт усунення гілки не доводить, що програма стала швидшою: це залежить від компілятора, архітектури й частоти викликів.

Приклад: драйвер може встановити no-op під час ініціалізації, а клієнт пізніше замінить його реальним обробником. Якщо callback зберігається в спільному стані, правила заміни під час роботи мають також визначати, як уникати гонки з перериванням.

**Типові помилки:**

- Передати no-op з несумісним типом функції або приховати різницю небезпечним приведенням типу.
- Вважати, що no-op виконує обов’язкову роботу, наприклад підтверджує подію чи звільняє ресурс.
- Прибрати перевірку, але забути гарантовано ініціалізувати callback до першого виклику.[^iso-c-n1570]
