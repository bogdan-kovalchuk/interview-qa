## Short answer

**Scoped і strongly-typed: не конвертується неявно в `int` і не засмічує namespace.**

`Status::Ok` не сплутати з іншим переліком, і `if (status)` не скомпілюється випадково. Це ловить цілий клас помилок порівняння/перетворення.

Правило: для кодів помилок і станів використовуй `enum class`, а не голий `enum`.[^embeddedinterviewlab]

## Detailed explanation

### Проблеми класичного нетипізованого `enum` (C-style enum)

Класичні переліки, успадковані з мови C, мають три серйозні недоліки в контексті надійності прошивок:
1. **Засмічення області видимості (Unscoped)**: ідентифікатори переліку експортуються безпосередньо в ту область видимості, де визначено сам перелік. Значення на зразок `OK`, `ERROR`, `TIMEOUT` часто конфліктують між різними підсистемами (наприклад, драйвером I2C, протоколом Modbus та операційною системою FreeRTOS), змушуючи розробників додавати громіздкі префікси на кшталт `DRV_I2C_STATUS_OK`.
2. **Неявне приведення до цілого типу (Implicit decay to `int`)**: звичайний `enum` неявно конвертується в `int`[^iso-cpp-n4861]. Це дозволяє випадково порівняти несумісні типи (наприклад, код помилки `ErrorCode::TIMEOUT` зі станом світлодіода `LedState::ON`) або виконати хибну логічну перевірку:
```cpp
enum Status { OK = 0, ERROR = 1 };
Status s = OK;
if (s) { /* Код не виконається, оскільки OK == 0 трактується як false! */ }
```
3. **Невизначений базовий розмір**: у стандарті C базовий цілочисельний тип обирається компілятором (зазвичай це 32-бітний знаковий `int`), що марнує пам’ять у таблицях та мережевих пакетах.

### Переваги `enum class` (Scoped Enumerations)

Стандарт C++11 увів суворо типізовані переліки з власною областю видимості (`enum class` або `enum struct`)[^iso-cpp-n4861]:
- **Ізоляція простору імен**: елементи доступні лише через префікс імені переліку: `Status::Ok`, `Status::Timeout`. Жодних колізій імен у глобальній області видимості.
- **Відсутність неявних перетворень**: `enum class` не конвертується автоматично в `int` або в інший перелік. Спроба порівняння `if (Status::Ok == Color::Red)` або передачі в функцію, що очікує число, викликає помилку компіляції (`cannot convert 'Status' to 'int'`).
- **Явне приведення тільки через `static_cast`**: якщо дійсно необхідно отримати числовий код (наприклад, для передачі регістром по SPI або збереження в EEPROM), застосовують явне приведення: `static_cast<uint8_t>(Status::Ok)`.

### Контроль розміру в RAM та асемблер ARM Cortex-M

Синтаксис `enum class` дозволяє явно вказати базовий тип (`underlying type`):
```cpp
enum class SensorStatus : uint8_t {
    Ready   = 0x01,
    Busy    = 0x02,
    Error   = 0xFF
};
```
Це надає критичні апаратні гарантії:
1. **Мінімізація пам’яті**: змінна `SensorStatus` займає рівно 1 байт (`sizeof(SensorStatus) == 1`), що усуває вирівнювання до 4 байтів всередині щільно упакованих структур даних і буферів обміну.
2. **Ефективні інструкції процесора**: процесор ARM Cortex-M використовує однобайтові інструкції завантаження та збереження (`LDRB`/`STRB`), оптимізуючи розмір Flash-коду та використання регістрів:
```assembly
LDRB r0, [r1, #0]   ; Завантаження 1 байта статусу з пам’яті
CMP  r0, #1         ; Порівняння зі значенням SensorStatus::Ready
BEQ  .L_handle_ok
```

### Вичерпний аналіз у `switch` та атрибут `[[nodiscard]]`

Сучасні компілятори (GCC, Clang) з увімкненим прапорцем `-Wswitch` перевіряють, чи всі значення `enum class` оброблені в конструкції `switch`:
- Якщо один зі статусів пропущено і немає гілки `default`, компілятор генерує попередження (яке при `-Werror` стає блокуючою помилкою збирання).
- Додавання атрибута `[[nodiscard]]` до оголошення переліку змушує викликача обов’язково обробити повернутий статус, виключаючи мовчазне ігнорування збоїв апаратних транзакцій:
```cpp
[[nodiscard]] enum class DriverError : uint8_t {
    None,
    BusBusy,
    Nack,
    Timeout
};
```
