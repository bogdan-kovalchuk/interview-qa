## Short answer

**Zero-overhead обгортка над C-масивом з `.size()`, `.at()` (з bounds checking) і сумісністю з `<algorithm>`.**

Він не decay-иться у вказівник при передачі, знає свій розмір і працює з `std::sort`/`std::find`. Розмір і layout ідентичні C-масиву.

Правило: у C++ embedded `std::array` повністю заміняє `T[]` як дефолтний контейнер.[^embeddedinterviewlab]

## Detailed explanation

### Внутрішня будова та гарантії нульових витрат (Zero-Overhead)

Контейнер `std::array<T, N>` із заголовка `<array>` є еталонним втіленням філософії C++ щодо абстракцій без додаткових накладних витрат (zero-overhead abstraction)[^iso-cpp-n4861]. Стандарт визначає `std::array` як агрегатний тип (aggregate class), єдиним полем якого є звичайний сирий масив елементів:
```cpp
template <typename T, std::size_t N>
struct array {
    T _elems[N]; // прямий сирий буфер у пам’яті
    // набір constexpr inline методів
};
```
Завдяки цьому гарантуються такі низькорівневі властивості:
- **Ідентичний розмір пам’яті**: Вираз `sizeof(std::array<T, N>)` точно дорівнює `sizeof(T) * N`. Немає жодних прихованих службових полів, лічильників довжини в RAM або покажчиків.
- **Ідентичне вирівнювання**: Значення `alignof(std::array<T, N>)` точно дорівнює `alignof(T)`.
- **Сумісність компонування (Standard Layout)**: Розташування байтів у пам’яті строго відповідає мові C. Отримати прямий покажчик на буфер для передачі у функцію вендорського HAL (наприклад, `HAL_UART_Transmit`) можна через метод `.data()` за нуль тактів: `arr.data()`.
- **Нульовий час доступу**: Усі методи доступу (`operator[]`, `data()`, `size()`, `begin()`, `end()`) позначені як `constexpr` та `inline`. При оптимізації (`-O2` / `-Os`) компілятор розгортає індексацію в пряму базово-індексну адресацію Cortex-M (`LDR r0, [r1, r2, LSL #2]`), формуючи такий самий асемблерний код, як і для сирого масиву `T[]`.

### Чому `std::array` кращий за сирий C-масив `T[]`

Незважаючи на ідентичне розміщення в пам’яті, `std::array` вирішує фундаментальні недоліки класичних масивів мови C:

1. **Запобігання згасанню покажчика (Pointer Decay)**:
   При передачі сирого масиву у функцію `void process(uint8_t buf[])` C неявно перетворює аргумент на звичайний покажчик `uint8_t*`. Інформація про розмір масиву безповоротно втрачається, що змушує передавати розмір окремим параметром `size_t len` і створює ризик передачі неправильного значення. На противагу цьому, `std::array` передається як повноцінний тип за посиланням `const std::array<uint8_t, 64>& buf`. Компілятор перевіряє розмір на етапі збірки, унеможливлюючи передачу буфера невідповідної довжини.

2. **Повноцінна семантика значень (Value Semantics)**:
   Сирі масиви C заборонено копіювати через оператор присвоювання (`a = b` не компілюється) або повертати з функції за значенням. `std::array` поводиться як звичайний об’єкт: його можна копіювати (`arr1 = arr2`), повертати з функції (завдяки механізму RVO – Return Value Optimization це відбувається без зайвого копіювання пам’яті) та порівнювати операторами рівності (`==`, `!=`).

3. **Підтримка безпечного доступу з перевіркою меж (`.at()`)**:
   Доступ через `operator[]` працює без перевірок для максимальної швидкодії. Проте для критичних ділянок валідації вхідних пакетів є метод `.at(index)`, який виконує перевірку виходу за межі діапазону (bounds check). При `-fno-exceptions` вихід за межі призводить до виклику `abort()`, запобігаючи неконтрольованому читанню або запису за межами виділеної пам’яті.

4. **Безшовна інтеграція з STL-алгоритмами**:
   `std::array` надає стандартний інтерфейс ітераторів (`begin()`, `end()`, `cbegin()`, `cend()`), що дозволяє безпосередньо передавати його в алгоритми `<algorithm>`:
   ```cpp
   std::sort(arr.begin(), arr.end());
   auto it = std::find(arr.begin(), arr.end(), target);
   ```
   Також `std::array` нативно підтримує range-based `for`-цикли без потреби в нестандартних макросах на зразок `ARRAY_SIZE()`.

### Розміщення в пам’яті мікроконтролера: Flash проти RAM

Контейнер `std::array` дозволяє чітко керувати секціями пам’яті:
- Якщо масив оголошено як `static constexpr std::array<uint32_t, 256> lut = { ... };`, компілятор розміщує його виключно у секції `.rodata` у Flash-пам’яті мікроконтролера[^iso-cpp-n4861]. Він не споживає жодного байта дефіцитної RAM і готовий до використання відразу після подачі живлення.
- Якщо масив оголошено як локальна змінна всередині функції, він створюється на стеку.
- Якщо масив оголошено як `static std::array<uint8_t, 1024> rx_buf;`, він розміщується в секції `.bss` у RAM із нульовою ініціалізацією під час старту.
