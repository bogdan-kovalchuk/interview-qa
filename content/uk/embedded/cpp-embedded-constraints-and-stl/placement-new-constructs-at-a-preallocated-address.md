## Question code

```cpp
alignas(Sensor) static uint8_t buf[sizeof(Sensor)];
Sensor* s = new (buf) Sensor(config);
// потім вручну: s->~Sensor();
```

## Short answer

**Placement new конструює об’єкт за наперед виділеною адресою, без heap.**

Пам’ять – static-буфер чи memory-mapped регіон. `delete` тут не застосовний: деструктор треба викликати явно (`s->~Sensor()`).

Правило: placement new + явний dtor = динамічне конструювання без купи.[^embeddedinterviewlab]

## Detailed explanation

### Принцип роботи placement new та заголовок `<new>`

У класичному виразі `new T(...)` мова C++ виконує дві послідовні дії: виділяє неініціалізований блок сирої пам’яті через виклик глобальної функції `operator new(sizeof(T))` (яка за замовчуванням звертається до системної купи через `malloc`), а потім викликає конструктор типу `T` над цією пам’яттю[^iso-cpp-n4861].

У вбудованих системах виділення пам’яті з динамічної купи (heap) часто суворо заборонене через недетермінований час виконання, небезпеку вичерпання RAM та ризик зовнішньої фрагментації пам’яті. Механізм `placement new` дозволяє розділити виділення сирої пам’яті та конструювання об’єкта[^iso-cpp-n4861].

Для використання `placement new` необхідно підключити заголовок `<new>`. Стандарт визначає цю перевантажену версію оператора як inline-функцію, що не виділяє пам’ять, а лише повертає переданий їй покажчик:
```cpp
void* operator new(std::size_t, void* ptr) noexcept {
    return ptr;
}
```
Після повернення адреси компілятор генерує інструкції виклику конструктора безпосередньо за вказаною адресою. Це дозволяє створювати повноцінні C++ об’єкти з конструкторами у статично виділених буферах (`.bss`), на стеку, у попередньо нарізаних пулах фіксованого розміру (memory pools) або у спеціальних апаратних зонах пам’яті (наприклад, non-volatile backup SRAM чи пам’ять DMA-дескрипторів).

### Вирівнювання (alignment) та розмір буфера

Використання сирого масиву байтів як сховища для об’єкта вимагає суворого дотримання двох критеріїв: розміру та вирівнювання:
1. **Розмір**: Буфер повинен мати розмір не менше за `sizeof(T)`.
2. **Вирівнювання**: Адреса буфера повинна бути кратна `alignof(T)`.

Звичайний масив `uint8_t buf[sizeof(Sensor)]` компілятор може розмістити за будь-якою довільною байтовою адресою. На процесорах з архітектурою ARM Cortex-M звернення до некратних адрес для багатобайтних типів (`uint32_t`, `double`, покажчики) або призводить до значного падіння продуктивності, або викликає апаратне виключення `UsageFault` (UNALIGN trap, якщо в регістрі `CCR` виставлено біт `UNALIGN_TRP`)[^iso-cpp-n4861].

Для гарантії правильного вирівнювання слід обов’язково використовувати специфікатор `alignas`:
```cpp
alignas(Sensor) static uint8_t sensor_buf[sizeof(Sensor)];
Sensor* s = new (sensor_buf) Sensor(config);
```

### Керування життєвим циклом: чому `delete` заборонений

Для об’єктів, сконструйованих через `placement new`, стандартний оператор `delete s;` викликати суворо заборонено:
- Звичайний вираз `delete s;` спочатку викликає деструктор `s->~Sensor()`, а потім викликає `operator delete(s)`, який спробує повернути пам’ять системному алокатору купи (`free()`).
- Оскільки пам’ять буфера розташована у статичній секції або на стеку, спроба її звільнення через `free()` призведе до миттєвого руйнування службових заголовків менеджера пам’яті (heap corruption) або переходу мікроконтролера в `HardFault`.

Завершення життєвого циклу об’єкта має відбуватися виключно шляхом явного виклику деструктора[^iso-cpp-n4861]:
```cpp
s->~Sensor();
```
Після виклику деструктора об’єкт вважається знищеним, проте сам байтовий буфер залишається валідним і може бути повторно використаний для розміщення нового об’єкта через черговий виклик `placement new`.

### Повторне використання пам’яті та `std::launder`

Якщо в один і той самий буфер послідовно конструюються об’єкти, клас яких містить `const`-члени або посилання (`T&`), оптимізатор компілятора (GCC/Clang на рівнях `-O2` чи `-Os`) має право припустити, що значення таких полів ніколи не змінюються протягом роботи програми.

Щоб запобігти зчитуванню застарілих даних із регістрів замість пам’яті після реконструювання нового екземпляра, стандарт C++17 ввів функцію `std::launder` із заголовка `<new>`[^iso-cpp-n4861]:
```cpp
s->~Sensor();
Sensor* new_s = new (sensor_buf) Sensor(new_config);
Sensor* safe_s = std::launder(new_s);
```
У більшості простих вбудованих структур даних це надлишково, але для складних драйверів з незмінними конфігураційними полями використання `std::launder` запобігає прихованим помилкам оптимізації компілятора.
