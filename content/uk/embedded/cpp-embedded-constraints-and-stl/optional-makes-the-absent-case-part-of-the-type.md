## Short answer

**Зберігає значення inline (без heap), робить випадок «немає значення» явним у системі типів.**

Це зменшує ризик null-dereference: перед доступом до `*opt` треба перевірити `opt.has_value()`. Наприклад, `std::optional<FaultCode>` краще показує «fault є/немає», ніж null-сигналізація.

Правило: для «значення може бути відсутнє» – `std::optional`, а не sentinel/null-вказівник.[^embeddedinterviewlab]

## Detailed explanation

### Проблема нульових покажчиків та sentinel-значень у C

У класичному коді на C для повернення результату функції, який може бути відсутнім (наприклад, опитування датчика температури чи пошук пакета в буфері), використовують два основні підходи, кожен з яких несе серйозні ризики:

1. **Сигнальні значення (Sentinel Values / Magic Numbers)**:
   Функція повертає значення типу `int16_t`, де значення на зразок `-1`, `0xFFFF` або `INT16_MIN` позначає помилку. Цей підхід (in-band error signalling) створює небезпечну двозначність: якщо датчик вимірює від’ємну температуру, значення `-1` є цілком валідним вимірюванням, а не помилкою. Компілятор не може перевірити, чи обробив викликаючий код сигнальне значення.
2. **Нульові покажчики (`nullptr`)**:
   Функція повертає покажчик `T*`, повертаючи `nullptr` за відсутності даних. Це змушує розміщувати об’єкт або у статичній пам’яті (втрачається реентрабельність), або в купі. Розіменування `nullptr` на мікроконтролері ARM Cortex-M є критичним: якщо за адресою `0x00000000` розташована Flash-пам’ять із вектором початкового покажчика стека (Initial SP), контролер не викличе апаратну помилку відразу, а тихо прочитає сміттєві дані зі стартового вектора.

### Як влаштований `std::optional<T>` усередині

Шаблон `std::optional<T>` із заголовка `<optional>` (введений у C++17) елегантно вирішує цю проблему, роблячи можливість відсутності значення частиною системи типів[^iso-cpp-n4861].

Внутрішня структура `std::optional` зберігає значення прямо всередині свого об’єкта (inline storage) без звернення до купи:
```cpp
template <typename T>
class optional {
    union {
        char _dummy;
        T _val; // пам’ять для T виділяється inline
    };
    bool _has_value; // прапорець наявності валідного значення
};
```
Ключові технічні характеристики:
- **Фіксований розмір і відсутність купи**: Розмір `sizeof(std::optional<T>)` становить `sizeof(T) + sizeof(bool)` плюс байти вирівнювання (padding). Для 32-бітного типу `sizeof(std::optional<uint32_t>)` зазвичай дорівнює 8 байтам.
- **Керування конструктором**: Якщо об’єкт `optional` створюється порожнім (`std::nullopt`), конструктор типу `T` взагалі не викликається, а поле `_has_value` встановлюється в `false`. Конструктор типу `T` виконується лише тоді, коли об’єкт дійсно ініціалізується даними через `placement new` у внутрішній буфер `_val`.
- **Автоматичний деструктор**: При виході `optional` з області видимості деструктор `T::~T()` викликається автоматично тільки тоді, коли об’єкт містив валідне значення (`_has_value == true`).

### Безпека API та типові пастки у прошивках

`std::optional` надає набір методів для безпечного та детермінованого доступу до даних:
- **Явна перевірка наявності**:
  ```cpp
  std::optional<float> temp = read_temperature();
  if (temp) { // або if (temp.has_value())
      update_pid_controller(*temp);
  }
  ```
  Користувач не може випадково використати `temp` як `float` без явного розіменування, що змушує розробника врахувати випадок збою зчитування.
- **Безпечне значення за замовчуванням (`.value_or()`)**:
  Метод `temp.value_or(25.0f)` дозволяє лаконічно повернути резервне значення у разі відсутності вимірювання в один рядок без розгалужень `if-else`.
- **Пастка: розіменування через `operator*` без перевірки**:
  Виклик `*opt` над порожнім `optional` є невизначеною поведінкою (UB)[^iso-cpp-n4861].
- **Пастка: виклик `.value()` при `-fno-exceptions`**:
  У hosted C++ метод `.value()` викидає виняток `std::bad_optional_access` при зверненні до порожнього об’єкта. При вимкнених винятках у прошивці мікроконтролера цей виклик призводить до аварійної зупинки `std::abort()`. Тому у вбудованому коді слід використовувати комбінацію `if (opt) { ... *opt ... }` або метод `.value_or()`.
