## Question code

```text
arm-none-eabi-g++ -mcpu=cortex-m4 -mthumb -Os \
  -fno-exceptions -fno-rtti -fno-threadsafe-statics \
  -fno-use-cxa-atexit -fno-unwind-tables \
  -std=c++17 -Wall -Werror
```

## Short answer

**`-Os` (оптимізація за розміром) + набір `-fno-*`, що прибирають C++-runtime-важкі фічі, + `-std=c++17`.**

Це дає компактний детермінований код без винятків, RTTI, unwind-таблиць і thread-safe static guard-блокувань.

Правило: знати ці прапорці напам’ять – типове очікування на embedded C++ інтерв’ю.[^embeddedinterviewlab]

## Detailed explanation

### Базові компоненти рядка компіляції для мікроконтролерів

У проєктах для мікроконтролерів (зокрема лінійки ARM Cortex-M) рядок виклику компілятора `arm-none-eabi-g++` складається з кількох взаємопов’язаних функціональних груп прапорців[^iso-cpp-n4861]:
1. **Цільова архітектура процесора**:
   - `-mcpu=cortex-m4 -mthumb`: вказує компілятору генерувати набір інструкцій Thumb-2 для ядра Cortex-M4.
   - `-mfloat-abi=hard -mfpu=fpv4-sp-d16`: задіює апаратний модуль обчислень із плаваючою комою (FPU) через регістри `s0-s31` замість програмної емуляції у софтверній бібліотеці.
2. **Рівень оптимізації та стандарт мови**:
   - `-Os`: оптимізація розміру бінарного файлу (Size optimization). Для мікроконтролерів це базовий вибір, оскільки зменшення розміру коду у Flash критично важливе і часто покращує попадання в кеш інструкцій та Flash prefetch.
   - `-std=c++17` або `-std=c++20`: активація сучасних мовних можливостей (`constexpr`, `std::string_view`, `std::span`, Structured Binding).

### Прапорці усунення runtime-механізмів C++ (`-fno-*`)

Найважливіша частина для embedded-інженера – розуміння прапорців, які вимикають важку інфраструктуру стандартного C++ runtime:
- **`-fno-exceptions` та `-fno-unwind-tables`**:
  Повністю видаляють таблиці розгортання стека (`.ARM.exidx`, `.ARM.extab`) та runtime-підсистему обробки винятків. Це заощаджує 15–40 КБ пам’яті Flash і гарантує детермінований час виконання коду без непередбачуваних пауз на `unwinding`.
- **`-fno-rtti`**:
  Вимикає генерацію структур `std::type_info` та текстових назв класів для поліморфних типів. Усуває накладні витрати на `dynamic_cast` та `typeid`, зберігаючи класичну роботу віртуальних таблиць (`vtable`).
- **`-fno-threadsafe-statics`**:
  За замовчуванням стандарт C++ вимагає потокобезпечної ініціалізації локальних статичних змінних (Magic Statics). Компілятор генерує навколо них виклики функцій `__cxa_guard_acquire` та `__cxa_guard_release`, які потребують підтримки м’ютексів або атоміків операційної системи. Прапорець вимикає ці виклики, замінюючи їх звичайною умовною перевіркою прапорця.
- **`-fno-use-cxa-atexit`**:
  Запобігає реєстрації деструкторів глобальних і статичних об’єктів через системну функцію `__cxa_atexit`. Оскільки прошивка мікроконтролера виконується в нескінченному циклі `while (1)` і ніколи не завершується поверненням з `main()`, код очищення при виході є абсолютно марним і лише витрачає RAM та Flash.

### Секціонування та видалення мертвого коду компонувальником

Для того щоб лінкер міг викинути будь-яку невикористану функцію або глобальну константу, застосовують зв’язку компілятора та компонувальника:
- Компілятор: `-ffunction-sections -fdata-sections`. Кожна функція розміщується у власній секції (наприклад, `.text.uart_init`), а кожна змінна – у `.data.my_var` або `.rodata.lut`.
- Компонувальник: `-Wl,--gc-sections` (Garbage Collection Sections). Лінкер аналізує дерево викликів від точки входу (`Reset_Handler`) і повністю видаляє всі незв’язані секції з фінального ELF/HEX/BIN файлу.
- Бібліотеки: `--specs=nano.specs` підключає полегшену бібліотеку Newlib-nano, а `--specs=nosys.specs` надає заглушки для системних POSIX-викликів (`_sbrk`, `_read`, `_write`).

### Діагностика та строгість компіляції

У промисловому коді обов’язково використовують набір суворих попереджень:
`-Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror`. Це унеможливлює випадкові втрати точності при перетвореннях типів (наприклад, неявне приведення 32-бітного значення в 8-бітний регістр периферії) та конфлікти імен змінних.
