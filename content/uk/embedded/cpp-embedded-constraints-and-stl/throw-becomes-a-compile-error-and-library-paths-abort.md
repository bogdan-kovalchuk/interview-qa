## Short answer

<span class="warn">У власному коді `throw`/`try`/`catch` зазвичай стають compile error; library-шляхи, які мали кинути виняток, часто завершуються `abort()`.</span>

Це не «магічне прибирання» помилок: шлях із `vector::at()` out-of-range може аварійно зупинити систему замість обробленого винятку.

Захист: аудитуй throwing API (application programming interface) стандартної бібліотеки й замінюй їх на явні перевірки/статуси.[^embeddedinterviewlab]

## Detailed explanation

### Поведінка власного коду при прапорці -fno-exceptions

При компіляції програми з прапорцем `-fno-exceptions` компілятор повністю блокує конструкції обробки винятків у користувацькому коді[^gcc-fexceptions]:
- Будь-яка спроба написати блок `try { ... } catch (...) { ... }` завершується помилкою компілятора (`error: exception handling disabled, use -fexceptions to enable`).
- Пряме використання ключового слова `throw expr;` у коді програми так само викликає помилку компіляції.

Завдяки цьому розробник захищений від випадкового використання механізму винятків у власних функціях. Проте головна прихована пастка криється у стандартній бібліотеці C++ (STL).

### Пастка стандартної бібліотеки: std::abort() замість винятків

Реалізації стандартної бібліотеки C++ (libstdc++ від GNU або libc++ від LLVM) спроєктовані відповідно до міжнародного стандарту ISO C++[^iso-cpp-n4861], де багато операцій за специфікацією зобов’язані викидати винятки при виникненні позаштатних ситуацій.

Коли прапорець `-fno-exceptions` активний, код стандартної бібліотеки не позбавляється перевірок, а внутрішні точки генерації винятків перенаправляються на спеціальні службові функції-хуки компілятора:
- `std::__throw_out_of_range_fmt(...)` – при виході за межі діапазону;
- `std::__throw_bad_alloc()` – при вичерпанні пам’яті в `operator new`;
- `std::__throw_bad_optional_access()` – при невалідному доступі до `std::optional`.

За замовчуванням у runtime без винятків ці функції друкують діагностичне повідомлення в потік помилок (якщо він підключений) та негайно викликають `std::abort()` або `std::terminate()`[^iso-cpp-n4861].

На мікроконтролері виклик `std::abort()` зазвичай реалізований як аварійна зупинка процесора: вхід у нескінченний цикл `while(1)`, спрацьовування апаратного виключення `HardFault` або системний reset за таймаутом апаратного сторожового таймера (Watchdog Timer).

### Приклади прихованих аварійних шляхів у STL

1. **Метод `vector::at()` проти `vector::operator[]`**:
   - `vec[i]` у C++ не перевіряє межі масиву (undefined behavior при виході за межі).
   - `vec.at(i)` перевіряє межі і за стандартом кидає `std::out_of_range`. При `-fno-exceptions` некоректний індекс миттєво викликає `std::abort()`, викликаючи повну зупинку мікроконтролера замість обробки помилки.
2. **Метод `std::optional::value()`**:
   - Виклик `opt.value()` для порожнього об’єкта викидає виняток у звичайному C++. При `-fno-exceptions` це призводить до аварійного завершення системи.
   - Безпечна альтернатива: перевірка `if (opt.has_value())` або метод `opt.value_or(default_value)`.
3. **Метод `std::variant::get<T>()`**:
   - Спроба отримати тип, який не є активним у даний момент, призводить до аварійного переривання роботи прошивки.
   - Безпечна альтернатива: `std::get_if<T>(&var)`, який повертає покажчик або `nullptr`.
4. **Виділення динамічної пам’яті**:
   - Звичайний оператор `new MyClass()` при браку RAM кидає `std::bad_alloc`, що при `-fno-exceptions` викликає `abort()`.
   - Альтернатива: `new (std::nothrow) MyClass()`, який у разі невдачі повертає нульовий покажчик `nullptr`.

### Практичні правила захисту у прошивках

- **Аудит стандартної бібліотеки**: заборонити в командних стандартах використання методів, які мають поведінку throwing API (зокрема `vector::at()`, `string::at()`, `optional::value()`).
- **Явні попередні умови (Precondition Checking)**: завжди перевіряти індекси, розміри та валідність стану перед зверненням до контейнерів.
- **Власний обробник аварій**: перевизначити функцію `std::terminate()` або перехопити хук паніки, щоб зберегти критичний лог (crash dump) в енергонезалежну пам’ять Flash або EEPROM перед перезавантаженням пристрою.
