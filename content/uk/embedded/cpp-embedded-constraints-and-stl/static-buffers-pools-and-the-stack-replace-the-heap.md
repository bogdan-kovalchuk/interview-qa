## Short answer

**Static allocation, placement new, fixed-size memory pools, stack allocation.**

Усі об’єкти мають static/automatic storage; немає `new`/`delete`. Pool дає O(1) без фрагментації; стек – для локальних, але невеликих (стеки 1–4 КБ).

Правило: у безпеко-критичному embedded heap або заборонений, або лише на етапі ініціалізації.[^embeddedinterviewlab]

## Detailed explanation

### Чому динамічна купа (heap) заборонена у прошивках

Використання динамічної пам’яті (`malloc`, `free`, `new`, `delete`) у вбудованих системах несе критичні загрози надійності:
1. **Зовнішня фрагментація пам’яті (Memory Fragmentation)**:
   Після серії виділень і звільнень блоків різного розміру вільна пам’ять виявляється розбитою на безліч дрібних ізольованих фрагментів. Навіть якщо сумарний обсяг вільної RAM перевищує необхідний, запит на новий суцільний буфер зазнає невдачі через відсутність одного неперервного сегмента (Out of Memory). Пристрій аварійно зупиняється через дні або місяці після запуску.
2. **Недетермінованість часу виконання**:
   Алгоритми алокації загального призначення (first-fit, best-fit, buddy allocator) переглядають списки вільних блоків за час, який неможливо точно передбачити. Це порушує вимоги систем жорсткого реального часу (Hard Real-Time).
3. **Накладні витрати пам’яті (Metadata Overhead)**:
   Кожен блок у купі потребує службового заголовка (від 4 до 16 байтів) для збереження свого розміру та зв’язків. Для сотень дрібних об’єктів ці метадані витрачають значну частину дефіцитної RAM.
4. **Витоки пам’яті (Memory Leaks)**:
   Втрата одного вказівника призводить до незворотної деградації пам’яті контролера.

Галузеві стандарти функціональної безпеки (MISRA C/C++, AUTOSAR, DO-178C, IEC 61508) суворо забороняють використання dynamic heap після завершення фази початкової ініціалізації системи.

### Основні альтернативні стратегії виділення пам’яті

1. **Статичне виділення (Static / BSS Storage)**:
   - Усі черги RTOS, дескриптори завдань, драйвери та буфери зв’язку оголошуються як глобальні або статичні змінні (`static`).
   - Пам’ять під них виділяється компілятором і лінкером у секціях `.data` та `.bss`.
   - Точний обсяг споживання RAM відомий ще на етапі компіляції з карти пам’яті (`.map` файл). Якщо пам’яті не вистачає, збірка падає відразу, усуваючи ризик несподіваного вичерпання RAM під час роботи пристрою.
2. **Алокація на стеку (Automatic / Stack Storage)**:
   - Локальні змінні створюються на стеку функції. Виділення та звільнення здійснюються за 1 машинний такт зсувом покажчика стека (`SUB sp, sp, #size` та `ADD sp, sp, #size`).
   - **Застереження**: у мікроконтролерах розміри стеків завдань RTOS або переривань вкрай обмежені (зазвичай від 512 байтів до 4 КБ). Розміщення великих буферів або глибока рекурсія на стеку призводить до переповнення стека (Stack Overflow) та руйнування пам’яті сусідніх завдань.
3. **Пули пам’яті фіксованого розміру (Fixed-Size Block Pools / Slab Allocator)**:
   - Буфер ділиться на фіксовану кількість однакових комірок (наприклад, 16 блоків по 64 байти). Вільні блоки зв’язані в однозв’язний список (free list).
   - Алокація та повернення блоку виконуються за гарантований постійний час O(1) простим переставленням покажчика голови списку.
   - Повністю усувається зовнішня фрагментація пам’яті. Такий механізм реалізовано в більшості RTOS (наприклад, `osMemoryPool` у CMSIS-RTOS або `Memory Pools` у Zephyr RTOS).
4. **Арена / Монотонний алокатор (Arena / Bump Allocator)**:
   - Пам’ять виділяється послідовно зі заздалегідь визначеного масиву зсувом одного покажчика вперед. Окреме звільнення елементів не підтримується; вся арена скидається назад до початку одномоментно після завершення транзакції або обробки кадру.
5. **Оператор placement new у C++**:
   - Дозволяє викликати конструктор об’єкта C++ безпосередньо у заздалегідь виділеному статичному буфері без звернення до купи[^iso-cpp-n4861]:
     ```cpp
     alignas(SensorDriver) static uint8_t driver_storage[sizeof(SensorDriver)];
     SensorDriver* driver = new (driver_storage) SensorDriver(config);
     ```

### Стратегія одноразової ініціалізації (Initialization-Only Heap)

Якщо конфігурація системи залежить від зовнішніх параметрів (наприклад, читання конфігураційного файлу з Flash під час увімкнення), допускається виділення пам’яті з купи виключно у функції `main()` до старту планувальника RTOS. Після запуску операційної системи та переходу в робочий режим будь-які виклики `malloc`/`new` апаратно або програмно блокуються.
