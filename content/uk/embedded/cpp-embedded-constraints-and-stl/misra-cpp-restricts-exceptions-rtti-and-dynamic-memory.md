## Short answer

**MISRA (Motor Industry Software Reliability Association) C++ обмежує exception-based control flow, dynamic allocation, RTTI (run-time type information), небезпечні casts, `goto`, складну ієрархію успадкування та сирі unions.**

Мета – детермінізм, аналізованість і контрольований data/control flow. Конкретні формулювання залежать від версії стандарту й профілю проєкту, тому на співбесіді краще казати «обмежує/регламентує», а не «забороняє все».

Правило: MISRA C++ – про передбачуваність; під неї пишуть із return codes, static allocation і мінімумом runtime-магії.[^embeddedinterviewlab]

## Detailed explanation

### Філософія та призначення стандарту MISRA C++

Стандарти MISRA C++ розробляються асоціацією Motor Industry Software Reliability Association (MISRA) для створення безпечного, надійного та детермінованого програмного забезпечення в safety-critical системах (автомобільна галузь за стандартом ISO 26262, промислова автоматика IEC 61508, медичні прилади та авіоніка)[^misra-cpp-2008][^misra-cpp-2023].

Головна мета MISRA C++ – усунути або суворо обмежити використання конструкцій мови C++, які можуть призвести до невизначеної поведінки (Undefined Behavior), неоднозначної поведінки (Unspecified Behavior), прихованого вичерпання ресурсів або недетермінованого часу реакції системи на події.

### Ключові сфери обмежень у MISRA C++

1. **Динамічне виділення пам’яті (Heap Allocation)**:
   - *Суть*: суворо забороняється або критично обмежується використання `malloc`, `free`, глобальних операторів `new` та `delete` після завершення початкової фази завантаження системи[^misra-cpp-2008].
   - *Причина*: динамічна пам’ять веде до недетермінованого часу виконання операцій виділення, фрагментації купи та ризику вичерпання пам’яті (`OutOfMemory`), що неприпустимо для систем реального часу.
   - *Рішення*: застосування статичних масивів, пулів пам’яті (`fixed-size memory pools`) та буферів на стеку.

2. **Механізм обробки винятків (Exceptions)**:
   - *Суть*: обмежується управління потоком виконання через винятки. У ранніх правилах винятки часто заборонялися повністю (через прапорець `-fno-exceptions`); у MISRA C++:2023 дозволяються лише локальні винятки за умови, що кожен виняток гарантовано обробляється, а деструктори суворо позначені як `noexcept`[^misra-cpp-2023].
   - *Причина*: небезпека витоку необробленого винятку в `std::terminate()`, непередбачуваний час розкрутки стека (stack unwinding) та оверхед Flash-пам’яті під таблиці обробки.
   - *Рішення*: повернення статусних кодів помилок, `std::optional` або `std::expected` (C++23) чи власні структури результату (`Result<T, E>`).

3. **RTTI та динамічне приведення типів**:
   - *Суть*: заборона або суворе обмеження `dynamic_cast` та `typeid`[^misra-cpp-2008].
   - *Причина*: збереження текстових рядків імен типів та таблиць типів у Flash роздуває бінарний образ, а пошук зв’язків успадкування під час виконання порушує часові обмеження жорсткого реального часу.
   - *Рішення*: використання compile-time поліморфізму (шаблони, концепції, CRTP) або явна типізація через перерахування (`enum class`).

4. **Перетворення типів і сирі покажчики**:
   - Заборонено використання C-style приведень типу виду `(Type)val`; дозволені лише явні оператори C++ (`static_cast`, `const_cast`).
   - Використання `reinterpret_cast` суворо регламентується (дозволено лише для доступу до апаратних регістрів пам’яті за конкретними фізичними адресами).
   - Заборонені нетипізовані `union` для маніпуляцій з бітовим представленням (type punning); рекомендується використання `std::variant` або `std::bit_cast` (C++20).

5. **Ієрархії класів та керування потоком**:
   - Заборонено віртуальне успадкування (virtual base classes) та множинне успадкування реалізації через складність обчислення зміщень у пам’яті.
   - Заборонено використання оператора `goto`, нескінченних циклів без чітких умов виходу та прихованих побічних ефектів у логічних виразах.

### Практичне значення для інженера

Формулювання «MISRA забороняє все у C++» на співбесіді сприймається як ознака поверхневих знань. MISRA не забороняє мову, а визначає безпечну дисципліновану підмножину: використання класів без віртуальності для інкапсуляції, шаблонів для усунення дублювання, `constexpr` для обчислень на етапі компіляції та RAII для автоматичного управління критичними секціями апаратних засобів.
