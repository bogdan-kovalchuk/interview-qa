## Short answer

`extern "C"` використовується в C++, щоб сказати компілятору застосувати C linkage для функцій або змінних.[^dou-embedded-interview] Головний ефект – вимкнення C++ name mangling, тобто ім’я символу в object/shared library буде сумісне з C.

Це потрібно, коли C++ код викликає C-бібліотеку або C код має викликати функцію, написану на C++. Типовий header пишуть так: `#ifdef __cplusplus extern "C" { #endif` ... `#ifdef __cplusplus } #endif`, але сам код функції лишається C++ кодом, а ABI і назва символу стають C-сумісними.

## Detailed explanation

### Проблема декорування імен (Name Mangling) у C++

У мові C++ реалізовано механізми, відсутні в мові C: перевантаження функцій (function overloading), простори імен (`namespace`), класи та методи. Щоб розрізняти функції з однаковими ідентифікаторами, але різними типами параметрів, компілятор C++ виконує процедуру декорування імен (name mangling)[^iso-cpp-n4861]:
```cpp
void timer_set(uint32_t ticks);
void timer_set(float seconds);
```
В об’єктному файлі ELF ці функції отримують унікальні низькорівневі символи згідно з правилами ABI (наприклад, Itanium C++ ABI): перша стає `_Z9timer_setj`, а друга – `_Z9timer_setf`.

У мові C перевантаження функцій відсутнє, тому компілятор C генерує символ, що буквально відповідає імені функції у вихідному коді: `timer_set`[^iso-c-n1570]. Якщо C++ код намагається викликати функцію з C-бібліотеки, скомпільованої C-компілятором, компілятор C++ генерує запит на декороване ім’я `_Z9timer_setj`. Компонувальник не знаходить такого символу в таблиці імен і завершує збирання помилкою: `undefined reference to 'timer_set(unsigned int)'`.

### Призначення специфікатора extern "C"

Конструкція `extern "C"` задає для компілятора C++ угоду про зв’язування мови C (C linkage)[^iso-cpp-n4861]. Вона вимикає декорування імен для зазначених оголошень і змушує компілятор використовувати прості незаймані імена символів у таблиці ELF:
```cpp
extern "C" {
    void timer_set(uint32_t ticks);
    void HardFault_Handler(void);
}
```
Ключові властивості `extern "C"`:
1. **Тіло функції залишається повноцінним C++**: розміщення визначення функції всередині блоку `extern "C"` не обмежує її внутрішню реалізацію. Всередині функції можна використовувати шаблони, класи, RAII-обгортки, лямбди та стандартні алгоритми – C-сумісним стає лише зовнішній символ для компонувальника.
2. **Заборона перевантаження**: всередині блоку `extern "C"` заборонено оголошувати дві функції з однаковим ім’ям, оскільки без name mangling їхні символи будуть колідувати.
3. **Змінні**: застосування до глобальної змінної також експортує її «чисте» C-ім’я в таблицю символів.

### Патерн крос-мовної сумісності #ifdef __cplusplus

Щоб один і той самий заголовний файл (`.h`) міг бути підключений як C-компілятором (у файлах `.c`), так і C++-компілятором (у файлах `.cpp`), використовують препроцесорну обгортку:
```c
#ifndef BSP_TIMER_H
#define BSP_TIMER_H

#include <stdint.h>

#ifdef __cplusplus
extern "C" {
#endif

void BSP_Timer_Init(uint32_t frequency_hz);
void BSP_Timer_Start(void);

#ifdef __cplusplus
}
#endif

#endif // BSP_TIMER_H
```
Макрос `__cplusplus` автоматично визначається стандартом лише тоді, коли файл компілюється як C++[^iso-cpp-n4861]. Компілятор C не бачить синтаксису `extern "C"`, який для нього є невідомим і спричинив би помилку `syntax error`, а бачить звичайні C-прототипи.

### Критична роль у bare-metal та обробниках переривань

У розробці для мікроконтролерів (зокрема ARM Cortex-M) `extern "C"` виконує життєво важливу функцію:
- **Таблиця векторів переривань**: у стартап-файлі (`startup_stm32.s` або `startup.c`) вектори переривань оголошені як слабкі C-символи: `Reset_Handler`, `NMI_Handler`, `SysTick_Handler`, `USART1_IRQHandler`.
- Якщо розробник реалізує обробник переривання у файлі `.cpp` без блоку `extern "C"`, компілятор зманглить його ім’я (наприклад, у `_Z17USART1_IRQHandlerv`).
- Компонувальник не пов’яже зманглений символ із вектором переривання у стартап-таблиці. У результаті вектор залишиться вказувати на стандартний слабкий обробник за замовчуванням (`Default_Handler` / нескінченний цикл `while (1)`), і при першому ж перериванні периферії процесор зависне.
