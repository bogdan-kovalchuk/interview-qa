## Question code

```c
oven_state_t step(oven_state_t s, oven_event_t e) {
  switch (s) {
  case STATE_IDLE:
    if (e == EVT_START) return STATE_HEATING;
    break;
  // ... інші стани
  }
  return s; // no transition
}
```

## Short answer

**Вкладений `switch` по стану, всередині – перевірка події і повернення нового стану.**

Переваги: легко крокувати в дебагері, а перевірка всіх `enum` case може виявити пропущений перехід. Якщо переходу немає – повертаємо поточний стан.[^iso-c-n1570]

Правило: enum+switch – найкращий вибір для невеликих FSM.[^embeddedinterviewlab]

## Detailed explanation

State machine на `enum` і `switch` подає автомат як значення поточного стану та функцію, що обробляє подію й повертає наступний стан. У прикладі `step` не змінює прихований глобальний стан: вона обчислює результат із двох аргументів, тому її поведінку легко перевіряти окремими тестами.[^iso-c-n1570]

Зовнішній `switch` обирає набір правил для поточного стану. Усередині нього перевіряються події, які мають значення саме в цьому стані. `return` означає перехід; `break` виходить із відповідної гілки, після чого функція повертає `s`, тобто лишається в поточному стані. Для кожного стану варто явно визначити поведінку подій, які не утворюють переходу.

Наприклад, `EVT_START` переводить `STATE_IDLE` у `STATE_HEATING`, тоді як інша подія в `STATE_IDLE` залишає автомат у спокої. Обробник події може також виконувати side effect, наприклад увімкнути вихід нагрівача; тоді важливо відокремити обчислення переходу від зміни апаратного стану або чітко задокументувати їхній порядок.

Компілятор може попередити про неперелічені значення `enum` залежно від налаштувань діагностики, але `default` іноді приховує таке попередження. Тому корисно вирішити, як обробляти некоректне значення стану, і налаштувати warnings для проєкту. Для невеликого автомата `switch` зазвичай читабельний; універсально найкращого способу немає – важливі розмір переходів, вимоги до часу й можливість перевірити кожну гілку.[^iso-c-n1570]

**Типові помилки:**

- Забути `break` або `return` і ненавмисно продовжити виконання наступних case.
- Плутати відсутність переходу з переходом у спеціальний стан помилки.
- Виконувати довгу чи блокувальну роботу всередині `step`, ускладнюючи передбачуваність часу.
