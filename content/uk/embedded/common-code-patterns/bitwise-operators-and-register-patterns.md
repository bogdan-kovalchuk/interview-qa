## Short answer

Основні побітові оператори: `&` AND, `|` OR, `^` XOR, `~` NOT, `<<` зсув вліво, `>>` зсув вправо.[^dou-embedded-interview]

Типові embedded-патерни: перевірити біт – `reg & (1u << n)`; встановити – `reg |= (1u << n)`; скинути – `reg &= ~(1u << n)`; перемкнути – `reg ^= (1u << n)`; створити маску – `(1u << width) - 1`. Для регістрів бажано використовувати unsigned типи, щоб уникати сюрпризів зі знаковими зсувами.

## Detailed explanation

### Базові оператори мови C та їхня семантика

Мова C визначає шість побітових операторів, які працюють виключно з цілочисельними типами [^iso-c-n1570]:
- `&` (Bitwise AND): результат містить одиницю лише у тих розрядах, де обидва операнди мають 1. Застосовується для фільтрації, перевірки та виділення окремих бітів або масок.
- `|` (Bitwise OR): результат містить 1, якщо хоча б один з операндів має 1 у відповідному розряді. Використовується для встановлення прапорців та об’єднання бітових полів.
- `^` (Bitwise XOR): результат містить 1 там, де значення бітів операндів різняться. Застосовується для перемикання станів (toggle), розрахунку контрольних сум (CRC, парність) та простого симетричного маскування.
- `~` (Bitwise NOT): унарний порозрядний оператор інверсії, що перетворює всі нулі на одиниці, а одиниці – на нулі (доповнення до одиниці).
- `<<` (Left Shift): зсуває біти вліво, заповнюючи молодші вивільнені розряди нулями. Зсув на `n` бітів для невід’ємних чисел еквівалентний множенню на 2 у степені `n`.
- `>>` (Right Shift): зсуває біти вправо. Для типів без знака (`unsigned`) старші розряди завжди гарантовано заповнюються нулями (логічний зсув).

### Цілочисельне підвищення (Integer Promotion) та пастки знакового зсуву

Згідно зі стандартом ISO C (§6.5.7) [^iso-c-n1570], перед обчисленням бітових операцій над типами, меншими за `int` (`uint8_t`, `uint16_t`, `char`), компілятор виконує цілочисельне підвищення (`integer promotion` до `int` або `unsigned int`). Це створює низку небезпечних ситуацій у низькорівневому коді:

1. **Інверсія вузьких типів без знака**: якщо оголошено `uint8_t flag = 0x01;`, вираз `~flag` підвищується до 32-бітного знакового `int` і набуває значення `0xFFFFFFFE`. Якщо цей вираз напряму передати у функцію, яка приймає `uint32_t`, або використати у виразі порівняння на зразок `if (~flag == 0xFE)`, умова виявиться хибною, оскільки `0xFFFFFFFE != 0x000000FE`.
2. **Знаковий зсув та Undefined Behavior**:
   - Зсув вліво від’ємного числа або зсув, що призводить до переповнення знакового розряду (`x << n`, де `x < 0` або результат не вміщується у знаковий тип), є невизначеною поведінкою (`undefined behavior`) [^iso-c-n1570]. Наприклад, вираз `1 << 31` на 32-розрядній системі є формальним UB, оскільки константа `1` має тип `int`. Коректно писати суфікс без знака: `1U << 31`.
   - Зсув від’ємного знакового числа вправо (`signed >> n`) є специфічним для реалізації (`implementation-defined`): переважна більшість процесорів виконує арифметичний зсув (дублюючи знаковий біт), проте стандарт дозволяє й логічний зсув.
3. **Зсув на неприпустиму кількість розрядів**: зсув на від’ємне число або на величину, рівну чи більшу за ширину типу в бітах (наприклад, `val << 32` для 32-бітної змінної), є прямим `undefined behavior` [^iso-c-n1570]. На архітектурі ARM процесорні інструкції зсуву враховують лише молодший байт операнда, а на архітектурі x86 – лише молодші 5 бітів лічильника.

### Патерни маніпуляції бітовими полями

При взаємодії з апаратними регістрами значення часто записуються у багатобітові поля (групи з декількох послідовних бітів):

```c
// Виділення бітового поля (Unsigned Bitfield Extraction)
#define UART_CR_MODE_POS   (8U)
#define UART_CR_MODE_WIDTH (4U)
#define UART_CR_MODE_MASK  (((1U << UART_CR_MODE_WIDTH) - 1U) << UART_CR_MODE_POS)

uint32_t get_uart_mode(uint32_t cr_val) {
    return (cr_val & UART_CR_MODE_MASK) >> UART_CR_MODE_POS;
}

// Запис значення у бітове поле без зміни сусідніх прапорців
void set_uart_mode(volatile uint32_t *cr_reg, uint32_t mode) {
    uint32_t val = *cr_reg;
    val &= ~UART_CR_MODE_MASK;                         // Очищення цільового поля
    val |= (mode << UART_CR_MODE_POS) & UART_CR_MODE_MASK; // Накладання нового значення
    *cr_reg = val;
}
```

### Апаратне прискорення в інструкціях ARM Cortex-M

Компілятори для вбудованих систем ефективно транслюють мовні конструкції маніпуляцій з бітами у спеціалізовані інструкції набору Thumb-2 архітектури ARMv7-M [^armv7m-arm]:
- `BIC` (Bit Clear): очищує біти за заданою маскою без потреби окремо обчислювати інверсію в проміжному регістрі (`BIC r0, r0, r1`).
- `UBFX` (Unsigned Bit Field Extract): витягує бітове поле довільної довжини з довільної позиції та поміщає його у молодші розряди з нульовим доповненням за один такт процесора.
- `BFI` (Bit Field Insert): копіює молодші біти одного регістра безпосередньо у вибране бітове вікно іншого регістра за один такт.
- `CLZ` (Count Leading Zeros): апаратно рахує кількість старших нульових бітів, що дозволяє за один такт знаходити пріоритет переривань або виконувати логарифмування за основою 2.
