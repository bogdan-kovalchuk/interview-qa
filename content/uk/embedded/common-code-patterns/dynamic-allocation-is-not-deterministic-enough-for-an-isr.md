## Short answer

<span class="warn">`malloc` може мати змінну затримку, тож його придатність для ISR залежить від контракту allocator і платформи.</span>

C не встановлює загальної заборони виклику `malloc` з ISR. Для системи з жорстким часовим бюджетом виділіть буфер наперед, якщо allocator не гарантує обмежену затримку й безпечний виклик у цьому контексті.[^iso-c-n1570]

Степінь двійки потрібен лише для оптимізації індексів маскою, а не для кожного ring buffer.

## Detailed explanation

`malloc` виділяє блок пам’яті під час виконання, але мова C не задає для нього ані верхньої межі часу, ані правил виклику з апаратного ISR.[^iso-c-n1570]

Звичайний allocator може шукати вільний блок і змінювати метадані купи; час залежить від її стану, а реалізація може використовувати блокування. Якщо ISR перериває код, який утримує таке блокування, виклик allocator може зависнути або порушити його внутрішній стан. Спеціалізований allocator може мати інші гарантії, тому перевіряють саме документацію конкретної платформи: допустимий контекст, reentrancy, часову межу та поведінку при нестачі пам’яті.[^iso-c-n1570]

У real-time системі важлива передбачувана верхня межа затримки, а не твердження, що кожна динамічна алокація неодмінно фрагментує пам’ять. Якщо кількість і розмір буферів відомі, виділення під час ініціалізації прибирає роботу з купою з критичного шляху. Власник буфера також має визначити синхронізацію, переповнення та час життя пам’яті.

Наприклад, ISR може записувати байти у попередньо виділений ring buffer, а main читати їх пізніше. Місткість обирають з огляду на найбільший потік даних і затримку обробки; це не обов’язково степінь двійки. Такий розмір зручний лише якщо алгоритм використовує маску для обертання індексу, а тип індексу та його переповнення також враховано.

**Типові помилки:**

- проголошувати `malloc` забороненим у кожному ISR без перевірки реалізації;
- вважати статичний буфер автоматичним захистом від гонок і переповнення;
- округлювати розмір до степеня двійки, коли цього не вимагає спосіб обчислення індексу.

Якщо allocator не має перевірених гарантій для ISR, передайте запит на виділення до main/task або використайте буфер, підготовлений під час ініціалізації.
