## Question code

```c
typedef struct {
  err_t    code;
  uint16_t line;      // __LINE__
  uint32_t timestamp; // tick
} err_info_t;
```

## Short answer

**Структура помилки може зберігати код разом із діагностичним контекстом.**

Наприклад, `record_error(code, __LINE__)` може зберегти місце виявлення збою; глобальний `last_error` містить лише останній запис і потребує узгодження при конкурентному доступі.

Такий контекст корисний для діагностики, якщо його поля, розмір і правила доступу відповідають платформі.[^iso-c-n1570]

## Detailed explanation

`err_info_t` – це структура, яка зберігає результат помилки разом із діагностичними даними, потрібними для її пошуку. На відміну від одного `err_t`, вона може передати код, номер рядка та час події одним значенням. Саме формат і поля структури визначає проєкт; стандарт C не задає універсального типу помилки чи вмісту такого запису.[^iso-c-n1570]

`__LINE__` – стандартний макрос препроцесора, що розгортається в номер поточного рядка вихідного файла. Його варто передавати в точці, де виявлено помилку, а не зберігати як доказ точної причини: реальна причина може бути раніше, а макрос залежить від розташування виклику в коді. Поле `timestamp` у прикладі – умовний лічильник tick; щоб інтерпретувати його, треба знати джерело, частоту, розрядність і правила переповнення лічильника.[^iso-c-n1570]

У невеликому MCU-проєкті один запис може бути дешевим і корисним, якщо його безпечно оновлює потрібний контекст. Глобальний `last_error` зберігає лише останню подію: наступна помилка перезапише попередню, а паралельний доступ із ISR та основного коду потребує окремого узгодження. У циклічному буфері можна зберегти кілька подій, але потрібні політика заповнення та захист від гонок. Розмір і атомарність запису залежать від цільової платформи та ABI, тому не слід вважати складене присвоєння атомарним.

Приклад: якщо запис містить `code = ERR_TIMEOUT`, `line = 84` і tick `12500`, журнал дозволяє відшукати місце виявлення помилки й співвіднести її з іншими подіями. Це ще не пояснює, чому периферія не відповіла: контекстом можуть бути також ідентифікатор транзакції, канал або стан автомата. Обирайте поля, які допомагають відтворити збій, і не записуйте чутливі дані.

**Типові помилки:**

- Вважати `__LINE__` номером рядка, де першопричина виникла, хоча він показує лише рядок розгортання макросу.
- Називати глобальну змінну журналом усіх помилок, хоча вона зберігає тільки останній запис.
- Вважати timestamp зрозумілим без одиниць, частоти tick і поведінки при переповненні.

Отже, error struct корисна, коли додатковий контекст виправдовує пам’ять і складність узгодження; її поля мають відповідати реальним задачам діагностики.
