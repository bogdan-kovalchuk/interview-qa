## Short answer

Базові операції: пошук символу або підрядка, порівняння, копіювання, конкатенація, розбиття на токени, reverse, перевірка паліндрому, підрахунок частот символів.[^dou-embedded-interview] У C треба особливо стежити за `\0`, розміром буфера й переповненням.

Відомі алгоритми: **KMP** для пошуку підрядка за O(n+m), **Rabin-Karp** з rolling hash, **Boyer-Moore** для швидкого пошуку на практиці, Trie для множини рядків, Levenshtein distance для схожості рядків. Для embedded часто важливі прості алгоритми без heap і з контрольованим часом виконання.

## Detailed explanation

### Безпека та обмеження роботи з рядками в мові C

У мові C рядки представлені як неперервні масиви байтів, що завершуються нульовим символом-термінатором (`null-terminated string`, `\0`, §7.24 ISO C) [^iso-c-n1570].

У вбудованих системах обробка рядків пов’язана з підвищеними ризиками відмови ПЗ:
- **Переповнення буфера (Buffer Overflow)**: функції стандартної бібліотеки `strcpy`, `strcat`, `sprintf` не контролюють межі цільового масиву. У разі надходження довших даних із зовнішнього інтерфейсу (UART, Ethernet) вони перетирають суміжні змінні або стек, що веде до вразливостей безпеки чи аварійних збоїв (`HardFault`). Їх обов’язково замінюють на захищені варіанти з явною вказівкою ліміту буфера: `strncpy`, `strlcpy`, `snprintf`.
- **Відсутність термінатора**: якщо рядок обрізано без додавання `\0`, наступні виклики `strlen()` чи `printf()` читатимуть пам’ять за межами масиву до першого випадкового нуля.
- **Реентрантність у RTOS**: стандартна функція `strtok()` зберігає внутрішній стан у статичній змінній бібліотеки C і не є потокобезпечною. У багатозадачному середовищі або обробниках переривань слід застосовувати суворо реентрантну версію `strtok_r()`.

### Класичні алгоритми пошуку підрядка

1. **Наївний алгоритм (Brute Force)**:
   - Порівнює зразок із текстом посимвольно зі зсувом на одну позицію. Складність у найгіршому випадку складає `O(n * m)`, але вимагає `O(1)` пам’яті.
   - Для коротких шаблонів у мікроконтролерах (наприклад, перевірка префікса `AT+` у модемі) наївний пошук часто є найкращим рішенням завдяки компактному машинному коду та відсутності накладних витрат на попередні обчислення.
2. **Алгоритм Кнута–Морріса–Пратта (KMP)**:
   - Часова складність лінійна: `O(n + m)`. Використовує попередньо обчислений масив префікс-функції розміром `m` для уникнення повернення назад по тексту.
   - *Ідеальний для потокової обробки (Stream Processing)*: оскільки KMP ніколи не зчитує вхідний текст повторно назад, він незамінний для пошуку сигнатур або маркерів синхронізації безпосередньо у потоці байтів, що надходять з переривання UART або кільцевого буфера DMA, без накопичення великих пакетів у RAM.
3. **Алгоритм Бойєра–Мура (Boyer-Moore)**:
   - Порівнює символи шаблону справа наліво і виконує евристичні стрибки за правилом «поганого символу» та «хорошого суфікса». У середньому працює за сублінійний час `O(n / m)`, проте потребує помітного обсягу пам’яті під таблиці зсувів.
4. **Алгоритм Рабіна–Карпа (Rabin-Karp)**:
   - Використовує ковзний геш (`rolling hash`) для швидкого порівняння геш-значень вікна тексту з гешем патерну за `O(1)`. Зручний при одночасному пошуку множини однакових за довжиною маркерів або ключів конфігурації.

### Потоковий парсинг протоколів через кінцеві автомати (FSM)

У практичній embedded-розробці класичні бібліотечні функції пошуку рядків (`strstr`) часто виявляються непридатними, оскільки вимагають збереження всього повідомлення в пам’яті.

Для типових текстових протоколів (наприклад, обробка потокових AT-команд для стільникових модемів у Zephyr RTOS [^zephyr-introduction], розбір речень NMEA 0183 у GPS/GNSS приймачах або HTTP/JSON у вузлах IoT) стандартом є побудова посимвольного скінченного автомата (Finite State Machine, FSM):
- Символи обробляються безпосередньо в момент надходження з апаратної черги.
- Стан автомата визначає очікування стартового символу (наприклад, `$` для NMEA), поля команди, даних та контрольної суми.
- Це мінімізує використання RAM до кількох байтів стану автомата та унеможливлює зависання через переповнення буфера.
