## Short answer

<span class="warn">`volatile` не робить `count++` атомарним і не надає синхронізації між ISR та main.</span>

Інкремент є read-modify-write: переривання між читанням і записом може призвести до втрати оновлення. `volatile` впливає на доступи до volatile-об’єкта за правилами реалізації, але не гарантує атомарність чи міжконтекстне впорядкування; правила взаємодії ISR з C-кодом залежать від реалізації.[^iso-c-n1570]

Використайте документований atomic type або коротку критичну секцію, сумісну з цільовою платформою; `volatile` саме по собі для цього недостатньо.[^iso-c-n1570]

## Detailed explanation

`volatile` змушує реалізацію дотримуватися правил доступу до volatile-об’єктів, але не перетворює складену операцію на атомарну й не є загальним засобом синхронізації.[^iso-c-n1570]

`count++` концептуально читає старе значення, обчислює нове та записує його. Якщо main прочитав 5, потім ISR прочитав 5 і записав 6, а main після повернення теж записав 6, одне з двох збільшень загубиться. Компілятор може виконувати volatile-доступи відповідно до вимог мови й реалізації, але `volatile` не обіцяє, що операція неподільна на рівні процесора чи шини.[^iso-c-n1570]

Є ще межа застосовності: ISO C описує сигнали, але не визначає універсальну модель апаратних переривань для кожної embedded-платформи. Тому треба з’ясувати правила компілятора, ABI та MCU, зокрема ширину атомарного доступу й те, як ISR може спільно звертатися до змінної.[^iso-c-n1570]

**Типові помилки:**

- вважати `volatile` синонімом atomic або memory barrier;
- припускати, що окремий load/store гарантує неподільність усього `count++`;
- переносити поведінку одного MCU на інший без перевірки документації.

Якщо платформа надає lock-free atomic type, перевірте його гарантії та придатність для ISR. Інакше коротко маскуйте відповідне переривання навколо всієї критичної секції, зберігаючи й відновлюючи попередній стан маски. Інший варіант – структура даних, де ISR і main володіють різними індексами, але й там слід перевірити атомарність і порядок доступів для цільової архітектури.
