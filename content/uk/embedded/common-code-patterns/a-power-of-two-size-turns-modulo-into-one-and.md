## Question code

```c
#define RB_SIZE 64
#define RB_MASK (RB_SIZE - 1)
```

## Short answer

**Для `SIZE`, що є степенем двійки, `(index + 1) & MASK` еквівалентне циклічному переходу через остачу від ділення; швидкість залежить від цілі й компілятора.**

У Cortex-M0 немає апаратних інструкцій ділення, але фіксоване прискорення для `%` залежить від згенерованого коду та задачі. Степінь двійки дозволяє замінити остачу від ділення на бітову маску.

Для показаного макросу `RB_SIZE` дорівнює 64, тому `RB_MASK` дорівнює 63. Перевіряй умову степеня двійки й діапазон індексу; вимірюй продуктивність на потрібній збірці.[^arm-divide]

## Detailed explanation

Розмір буфера-кільця часто обирають степенем двійки, бо тоді переходом за межу можна керувати маскою. Для `SIZE = 64` значення `SIZE - 1` має молодші шість бітів, установлених у 1; операція AND залишає лише ці біти. Отже, для невід’ємного індексу послідовні значення циклічно проходять 0–63.[^iso-c-n1570]

Це еквівалентне остачі від ділення на розмір лише за умови, що розмір – ненульовий степінь двійки, а індекс має очікуваний беззнаковий тип. Маска для іншого розміру не дає циклу по всіх його позиціях. У прикладі `RB_SIZE` дорівнює 64, тому `RB_MASK` дорівнює 63; переповнення типу індексу теж треба врахувати, щоб `index + 1` не створював неочікуваного результату.[^iso-c-n1570]

Практична перевага – просте обчислення wrap-around без операції остачі у вихідному коді. Але компілятор може оптимізувати ділення на константу, а різні ядра мають різні можливості: Cortex-M0 не має апаратних інструкцій ділення, тож універсальна цифра на кшталт «у 10–20 разів» без виміру необґрунтована. Перевіряй assembly або вимірюй саме свою збірку, якщо час критичний.[^arm-divide]

Приклад: для `SIZE = 8` маска дорівнює 7. Індекс 7 після просування стає `(7 + 1) & 7`, тобто 0; індекс 5 стає 6. Для кільцевої черги, що залишає одну позицію порожньою, маска обчислює наступну позицію, а окрема перевірка вирішує, чи можна записувати.
