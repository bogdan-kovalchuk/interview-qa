## Question code

```c
uint16_t adc_read(uint8_t ch) {
  if (ch >= NUM_CH) return UINT16_MAX; // "invalid"
  // ...
}
```

## Short answer

<span class="warn">Працює лише якщо sentinel-значення ніколи не буває валідним даним.</span>

Якщо `UINT16_MAX` – легітимне показання ADC (analog-to-digital converter), викликач не відрізнить помилку від реального максимуму. Стандарт визначає `UINT16_MAX` як максимальне значення типу `uint16_t`, коли цей точний тип доступний; він не резервує це значення як помилку.[^iso-c-n1570]

Захист: sentinel – для випадків, де спеціальне значення фізично неможливе; інакше – return code + output pointer.[^embeddedinterviewlab]

## Detailed explanation

Sentinel – це значення, яким функція позначає особливий стан замість звичайного результату. Воно безпечне лише тоді, коли контракт гарантує, що таке значення не може бути коректними даними. Інакше результат має дві можливі інтерпретації, а викликач не має способу їх розрізнити.

У фрагменті функція повертає `uint16_t`, а `UINT16_MAX` означає «канал некоректний». Але ADC із 16-бітним результатом може законно виміряти повну шкалу, числове значення якої дорівнює максимуму цього типу. Отже, для цього входу перевірка викликача `value == UINT16_MAX` помилково класифікує успішне вимірювання як помилку. Назва константи сама по собі не створює резерву в домені даних.[^iso-c-n1570]

Для беззнакового типу з `N` бітами всі `2^N` комбінацій є значеннями типу. Sentinels підходять, якщо предметна область справді виключає одне з них: наприклад, формат явно обмежує вимір до меншого діапазону. Це припущення має бути документоване й однаково дотримане всіма виробниками та споживачами даних. Зміна діапазону датчика або конфігурації ADC може порушити його.

Коли всі значення можуть бути валідними, відокремте статус від даних: функція повертає `bool` чи код помилки, а результат записує через вихідний покажчик; або використайте структуру з полями статусу й результату. Тоді успішне максимальне вимірювання не плутається зі збоєм. Перевірте статус до читання вихідного значення та визначте, чи воно має бути змінене при помилці.

Приклад: у випадку успіху функція повертає `true` і записує будь-яке значення `uint16_t` у `*out`; для хибного каналу повертає `false`. Викликач перевіряє логічний результат, а не вгадує стан за вмістом вимірювання.

**Типова помилка:** перевірити, що sentinel рідко трапляється в поточному наборі даних, і вважати його неможливим. Потрібна гарантія з контракту всього домену, а не частотне спостереження.

Це класичний випадок, коли помилка не спричиняє аварії, а тихо перетворює коректне граничне значення на втрату або відхилення даних.
