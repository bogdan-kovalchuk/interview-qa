## Question code

```c
typedef enum {
  ERR_OK = 0, ERR_TIMEOUT, ERR_CRC, ERR_BUSY, ERR_PARAM
} err_t;

err_t sensor_read(uint8_t a, uint16_t *out);
```

## Short answer

**Функція повертає `err_t`, а дані віддає через output-pointer.**

Коли API визначає `ERR_OK = 0`, перевірка `if (result) { /* error */ }` означає «будь-який ненульовий код – помилка»; C цього значення не нав’язує, його задає сам API. Кожна гілка помилки повертає конкретний код.[^iso-c-n1570]

Правило: return codes – дефолтний патерн, бо робить статус явним, але викликач усе одно має перевірити результат.[^iso-c-n1570]

## Detailed explanation

У цьому шаблоні функція повертає код стану, а результат операції записує через вказівник, переданий викликачем. Це розділяє два різні результати: чи вдалося виконати операцію та які дані вона отримала. Тип `err_t` дає назви можливим станам, а параметр `uint16_t *out` вказує на комірку, у яку функція може записати значення.[^iso-c-n1570]

Функція має визначити контракт для `out`: чи дозволений нульовий вказівник, чи вихідне значення змінюється при помилці та чи мусить викликач передавати адресу придатного об’єкта. Якщо нуль не дозволений, його слід перевірити на вході й повернути `ERR_PARAM`. Якщо операція може завершитися помилкою після часткового обчислення, безпечніше записувати результат лише після успішного завершення, щоб невдалий виклик не залишав частково оновлені дані.

**Приклад:**

```c
err_t sensor_read(uint8_t address, uint16_t *out) {
    if (out == NULL) return ERR_PARAM;
    uint16_t value;
    if (!read_sensor_register(address, &value)) return ERR_TIMEOUT;
    *out = value;
    return ERR_OK;
}
```

Викликач спочатку зберігає код повернення, перевіряє його, а потім читає `out` лише за успіху. Сам тип вказівника не забезпечує пам’ять і не перевіряє її розмір: передавання недійсної адреси та розіменування її спричиняє undefined behavior у C.[^iso-c-n1570]

**Типові помилки:**

- Ігнорувати код повернення й використовувати неініціалізований результат.
- Записувати вихідне значення до перевірки всіх умов успіху.
- Не описати, чи можна передати `NULL`, або чи зберігається старий результат після помилки.

Return code не змушує компілятор перевіряти результат: він лише робить помилку явною в API. Викликачі все одно мають дотримуватися домовленості й перевіряти повернене значення.
