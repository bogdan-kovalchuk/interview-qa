## Short answer

**Таблиця вказівників на функції пов’язує кожен стан FSM з його handler-ом; додавання стану потребує узгоджено змінити enum, таблицю та переходи.**

Це відокремлює диспетчеризацію від логіки обробників, але не гарантує автоматично відсутність змін в інших місцях. Розміщення `static const` таблиці у Flash залежить від MCU, компілятора та linker script.[^iso-c-n1570]

Перед викликом перевірте індекс стану й наявність ненульового вказівника на handler.

## Detailed explanation

Таблиця вказівників на функції зберігає відповідність між значенням стану FSM і функцією, яка цей стан обробляє; C дозволяє оголошувати й викликати функції через сумісні вказівники.[^iso-c-n1570]

Замість довгого `switch` диспетчер бере handler за індексом поточного стану й викликає його. Кожен handler залишається окремою функцією, тому додавання поведінки може не вимагати редагування наявних handler-ів. Проте це не гарантія «відкритості без модифікацій»: новий стан зазвичай також потребує значення enum, запису таблиці та переходів, які ведуть до нього. Межі масиву мають відповідати кількості станів.

Наприклад, таблиця з 12 станами для контролера HVAC може містити по одному handler-у для кожного стану. Новий режим defrost потребує окремого handler-а і запису таблиці, а також перевірки умов переходу з інших станів. Якщо код індексує таблицю зовнішнім або пошкодженим значенням, перевірте його до доступу, інакше можливий виклик не тієї функції або читання поза межами масиву.[^iso-c-n1570]

`static const` описує тривалість зберігання та незмінність через цей ідентифікатор у C, але саме по собі не гарантує, що таблиця лежатиме у Flash: це залежить від memory map, toolchain і linker script.[^iso-c-n1570] Для пристрою з обмеженою RAM перевірте map-файл зібраного образу.

**Типові помилки:**

- називати таблицю гарантовано розміщеною у Flash лише через `const`;
- забути синхронно оновити перелік станів, таблицю та переходи;
- викликати елемент за неперевіреним індексом або неініціалізованим вказівником.

Таблиця найкорисніша, коли відповідність «стан – handler» стабільна й проста. Якщо потрібні складні умови переходу або різні дані станів, явний `switch` чи структура з даними може бути зрозумілішою.
