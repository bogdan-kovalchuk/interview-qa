## Short answer

Операція віднімання в апаратному забезпеченні реалізується як додавання доповнення: `B - A = B + NOT(A) + 1`. Інверсія операнда `NOT(A)` формує лише зворотний (одиничний) код. Для перетворення його на справжній доповняльний код необхідно додати одиницю через вхід перенесення `Cn = 1`, інакше отриманий результат буде рівно на 1 меншим за правильний.[^floyd-digital-fundamentals]

## Detailed explanation

У цифровій схемотехніці та процесорних блоках операція арифметичного віднімання майже ніколи не реалізується за допомогою окремого апаратного блоку віднімача. Замість цього використовується спільний паралельний суматор, а віднімання зводиться до операції додавання від’ємного числа, представленого в системі доповняльного коду (two's complement):[^mano-logic-computer-design]

`A - B = A + (-B)`

### Математичний перехід від зворотного до доповняльного коду

Для `n`-розрядного двійкового числа `B` від’ємний еквівалент `-B` у доповняльному коді за математичним визначенням дорівнює доповненню до базису `2^n`:[^floyd-digital-fundamentals]

`-B = 2^n - B = (2^n - 1 - B) + 1`

Величина `(2^n - 1 - B)` являє собою двійкове число, отримане порозрядною інверсією всіх бітів числа `B` (заміна одиниць на нулі та нулів на одиниці), що називається зворотним (одиничним, one's complement) кодом і позначається як `NOT(B)` або `\bar{B}`.

Таким чином, для отримання справжнього доповняльного коду до інвертованого значення необхідно обов’язково додати одиницю:[^mano-logic-computer-design]

`-B = NOT(B) + 1`

Підставляючи це співвідношення у вихідне рівняння віднімання, отримуємо фундаментальне правило двійкового віднімання на суматорі:

`A - B = A + NOT(B) + 1`

### Апаратна роль вхідного перенесення Carry-In

Класичний повний багаторозрядний суматор має три вхідні порти: шини операндів `X` та `Y`, а також однобітний вхід початкового перенесення молодшого розряду `C_in` (або `C_n`). Він виконує операцію:[^patterson-hennessy-cod]

`Sum = X + Y + C_in`

Для виконання віднімання апаратні ресурси суматора конфігуруються таким чином:
1. На вхід `X` безпосередньо подається операнд `A`.
2. На вхід `Y` подається порозрядна інверсія операнда `B`, яка формується внутрішніми інверторами АЛП або масивом керованих елементів XOR (`B_i XOR 1 = NOT B_i`).
3. Для додавання обов’язкової математичної одиниці (`+ 1`) використовується вже наявний у структурі суматора вхід початкового перенесення: на нього подається сигнал `C_in = 1`.

Якщо вхідний сигнал `C_in` знехтувати або залишити на рівні логічного нуля (`C_in = 0`), суматор обчислить значення `A + NOT(B) + 0`, що строго дорівнює `A - B - 1`. Результат кожної операції віднімання виявиться систематично зміщеним на -1 відносно правильного математичного значення.[^floyd-digital-fundamentals]

### Реалізація в мікросхемах 74F382 та 74x181

У мікросхемі АЛП 74F382 для операцій віднімання (код `S = 010` для `A - B` та код `S = 001` для `B - A`) документація прямо зазначає виконувану функцію у вигляді:[^floyd-digital-fundamentals]

`F = A - B - 1 + Cn`

З цієї формули чітко видно:
- При подачі `Cn = 1` (додавання одиниці доповнення) вираз перетворюється на чисте віднімання `F = A - B`.
- При подачі `Cn = 0` мікросхема виконує операцію віднімання з урахуванням попередньої позики (Borrow): `F = A - B - 1`.

У класичній мікросхемі 74x181 при роботі з прямими рівнями даних вхід перенесення є інверсним (`\bar{C}_n`). Тому для отримання операції `A - B` на вивід `\bar{C}_n` подають активний низький рівень (LOW, тобто 0 В), що внутрішньо відповідає логічній одиниці перенесення.

### Вихідний прапорець Carry-Out як індикатор позики

При виконанні операції віднімання через додавання доповнення вихідне перенесення `C_out` суматора виступає апаратним індикатором відношення операндів:[^patterson-hennessy-cod]
- Якщо `A ≥ B`, сума `A + NOT(B) + 1` перевищує або дорівнює `2^n`, що викликає переповнення розрядної сітки та формування сигналу `C_out = 1`. Це вказує на те, що результат є додатним, і позика з вищого байта не потрібна (No Borrow).
- Якщо `A < B`, вихідне перенесення не формується (`C_out = 0`), що сигналізує про від’ємний результат операції та необхідність здійснення позики (Borrow = 1) для багатобайтних операцій.
