## Task

Дано список замкнених інтервалів `(start, end)` зі `start <= end`. Поверни найкоротший список
інтервалів, який покриває рівно ту саму множину точок. Інтервали, що перетинаються або торкаються,
зливаються в один. Вхід не відсортований і не має змінюватись. Порядок результату – за початком.

## Constraints

- `0 <= len(intervals) <= 10**5`; координати цілі.
- Дотичні інтервали вважаються такими, що перетинаються: `(1, 2)` і `(2, 3)` зливаються в `(1, 3)`.
- Вхідний список має лишитись незміненим.
- Результат відсортований за початком і не містить двох інтервалів, що перетинаються чи торкаються.

## Short answer

**Відсортуй інтервали за початком, потім пройди один раз, розширюючи останній збережений інтервал,
поки наступний починається не пізніше, ніж той закінчується.** Решта – бухгалтерія: новий інтервал
додається лише тоді, коли починається строго після поточного кінця. Сортування домінує у вартості
з `O(n log n)`, а прохід додає `O(n)`.[^cpython-listsort-notes] Без попереднього сортування інтервал
може зливатися з побаченим набагато раніше, і одного проходу вже не досить.

## Detailed explanation

Задача належить до сімейства, яке стає простим після одного рішення про порядок: сортуй за
координатою, яка робить потрібне відношення локальним. Щойно інтервали впорядковані за початком,
інтервал може перетинатися лише з блоком, що безпосередньо йому передує, тож лінійного проходу з одним
елементом стану – поточним злитим інтервалом – достатньо. У цьому вся ідея, і інтерв'юер шукає саме
її, а не цикл.

Впорядкування за початком і робить інваріант істинним: кожен уже виданий інтервал починається не
пізніше за той, що розглядається, тож якщо новий починається після поточного кінця, він починається
й після кінця всього виданого раніше, і поточний блок можна закрити остаточно. Сортування за кінцем –
інший, теж коректний алгоритм для іншої задачі: максимальної кількості інтервалів, що не
перетинаються.

Порівняння кортежів уже дає правильний порядок, тож key-функція не потрібна; якщо інтервали є
об'єктами, `key` зберігає стабільність сортування і дозволяє не визначати порівняння на
класі.[^py314-sorting-howto]

## Examples

```text
[(1, 3), (2, 6), (8, 10), (15, 18)]  ->  [(1, 6), (8, 10), (15, 18)]
[(1, 4), (4, 5)]                     ->  [(1, 5)]
[(1, 10), (2, 3)]                    ->  [(1, 10)]
[]                                   ->  []
```

## Solution

```python
def merge_intervals(intervals: list[tuple[int, int]]) -> list[tuple[int, int]]:
    """Merge overlapping or touching intervals; the input list is not modified."""
    if not intervals:
        return []

    merged: list[tuple[int, int]] = []
    for start, end in sorted(intervals):
        if merged and start <= merged[-1][1]:
            last_start, last_end = merged[-1]
            merged[-1] = (last_start, max(last_end, end))
        else:
            merged.append((start, end))
    return merged
```

`sorted` повертає новий список, тож вхід викликача лишається недоторканим. `max` – це те, що обробляє
повністю вкладений інтервал: без нього `(1, 10)`, за яким іде `(2, 3)`, вкоротився б до `(1, 3)`.
Заміна `start <= merged[-1][1]` на `<` реалізує іншу домовленість, за якої дотичні інтервали
лишаються окремими.

## Complexity

Час – `O(n log n)`: сортування домінує, а прохід є одним лінійним проходом з `O(1)` роботи на
інтервал.[^cpython-listsort-notes] Пам'ять – `O(n)` на відсортовану копію і результат; сам прохід
використовує константну додаткову пам'ять. На вході, який уже відсортований або складений з кількох
відсортованих ділянок, сортування в CPython близьке до лінійного, тож практична вартість падає, не
змінюючи оцінки.

## Edge cases

- Порожній вхід повертає порожній список.
- Один інтервал повертається без змін.
- Повністю вкладений інтервал: `(1, 10)`, потім `(2, 3)` дає `(1, 10)`.
- Дотичні інтервали зливаються за цією специфікацією, і саме ця межа є місцем, де вимогу треба
  підтвердити, а не припустити.
- Вироджений інтервал зі `start == end` є валідним входом і зливається штатно.
- Дубльовані інтервали згортаються в один.
- Список викликача лишається незміненим після виклику.

```python
import pytest

from intervals import merge_intervals


@pytest.mark.parametrize(
    "given, expected",
    [
        ([], []),
        ([(1, 3)], [(1, 3)]),
        ([(1, 3), (2, 6), (8, 10), (15, 18)], [(1, 6), (8, 10), (15, 18)]),
        ([(1, 4), (4, 5)], [(1, 5)]),
        ([(1, 10), (2, 3)], [(1, 10)]),
        ([(5, 6), (1, 2)], [(1, 2), (5, 6)]),
        ([(1, 1), (1, 1)], [(1, 1)]),
    ],
)
def test_merge_intervals(given, expected):
    assert merge_intervals(given) == expected


def test_input_is_not_modified():
    given = [(3, 4), (1, 2)]
    merge_intervals(given)
    assert given == [(3, 4), (1, 2)]
```

## Evaluation guide

### Expected signals

- Сортує за початком перед проходом і може сказати, чому саме сортування робить один прохід достатнім.
- Називає складність `O(n log n)` за часом з домінуванням сортування і `O(n)` додаткової пам'яті
  на результат.
- Обробляє випадок вкладення, коли наступний інтервал закінчується раніше за поточний, не вкорочуючи
  результат.
- Питає, чи треба зливати дотичні інтервали на кшталт `(1, 2)` і `(2, 3)`, замість вгадувати.

### Red flags

- Вкладений цикл, що порівнює кожну пару, поданий як задумане розв'язання.
- Мутує список викликача через `intervals.sort()` і не помічає цього.
- Пише `merged[-1][1] = end` без максимуму і тим втрачає вкладений інтервал.

### Level-up follow-up

Попросити потокову версію: інтервали надходять по одному, вже впорядковані за початком, і споживач
має видавати кожен злитий блок щойно той більше не зможе вирости. Це показує, чи кандидат розуміє
інваріант, чи лише пам'ятає шаблон.
