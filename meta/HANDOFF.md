# Промпт для агента, який продовжує роботу

Скопіюйте цей файл цілком як стартове завдання, або скажіть агенту: «прочитай `meta/HANDOFF.md`
і працюй за ним».

---

Ти продовжуєш проєкт `interview-qa` – двомовну (EN/UK) базу знань питань для технічних інтерв'ю,
яка живить публічний сайт на GitHub Pages і згенеровані колоди Anki. Одне питання = один файл =
одна сторінка = одна картка.

**Це особистий проєкт власника для підготовки до інтерв'ю, який буде публічним.** Одна людина
пише, вона ж рецензує, вона ж вчить картки. Команди, редколегії й сторонньої аудиторії немає.
Читай усі оцінки ризиків із цією поправкою: там, де успадкований документ каже «учні», йдеться
про власну колекцію власника. Процес, виправданий лише наявністю другої людини, тут не потрібен –
`AGENTS.md`, розділ «What this project is, and how big it is».

Проєкт наприкінці M0: документація й рішення готові, є дев'ять двомовних пілотів у `content/`,
коду конвеєра ще немає.

## Читай у цьому порядку, перш ніж щось робити

1. `meta/PIPELINE.md` – наскрізна картина: як питання стає сторінкою, карткою і колодою.
2. `meta/LIFECYCLE.md` – **нормативна таблиця**. Має пріоритет над усіма іншими документами.
3. `AGENTS.md` – інваріанти й ієрархія документів.
4. `meta/adr/` – прийняті рішення 0001–0012. Зміна, що суперечить ADR, потребує нового ADR.
5. `meta/CONTENT_SPEC.md`, `NAMING.md`, `RUBRIC.md`, `I18N.md`, `QUALITY_GATES.md`.
6. `meta/ROADMAP.md` – де ми і що далі.

## Як тут працюють

- **Не пушити** без явного дозволу власника. Remote налаштований, upstream навмисно не заданий.
- **Типографіка:** en dash U+2013, ніколи em dash U+2014.
- **Мова:** `meta/` – українською, `README.md` і код – англійською, технічні терміни в
  українському тексті лишаються англійськими (`event loop`, `GIL`, `move semantics`).
- **Ніколи не лишай два живі описи однієї поведінки.** Змінив правило – знайди і виправ усі інші
  місця, де воно сформульоване. Саме цей клас дефектів коштував проєкту цілого етапу.

## Що вже вирішено і не переглядається

| | |
|---|---|
| Репозиторій | `interview-qa`, стандартна адреса GitHub Pages, **без власного домену** |
| Генератор | Astro Starlight; `site/` – єдина частина на Node |
| Мови | EN+UK, `defaultLocale: en` |
| Посилання в контенті | токен `qid:<id>`, **ніколи готовий URL** – через base path `/interview-qa/` |
| Сайт читає | згенероване дзеркало `site/src/content/docs/`, а не `content/` |
| Note type | новий чистий `Interview QA Basic`, `model_id 1600000000001`, 5 полів |
| GUID | детермінований від `id`, сіль `iqa:v1:` |
| Білдер | `genanki` (MIT), не `anki` (AGPL) |
| Anki | пакет = напрямок, колода = тема, тег = фасет |
| Ліцензія | один MIT на код і контент |

## Що виміряно, а не припущено

Не переказуй документацію Anki – ці факти перевірені на реальних колекціях і задокументовані
в `meta/migration/anki-compatibility-report.md` та `anki-tag-refresh.md`:

- правка будь-якого поля нотатки зберігає розклад повторень (20 карток з реальною історією);
- імпорт не переміщує наявні картки між колодами і не змінює їх стан;
- імпорт **ніколи не видаляє** нотаток – звідси механізм `withdrawn`;
- теги **замінюються повністю**: тег, якого немає в пакеті, зникає з нотатки;
- зміна `model_id` при тому самому GUID **не** дає «ignored updates» – вона тихо зливає note types,
  зсуває поля на інші ord і створює зайві картки. Це гірше, ніж помилка, бо непомітно;
- вбудовані шрифти працюють на AnkiDroid: перевірено на пристрої, усі 5 гарнітур × latin + кирилиця.

## Наступні кроки

Порядок робіт, критерії завершення кожної фази й точки зупинки – **`meta/WORK_PROGRAMME.md`**.
Не дублюй його тут і не вигадуй власний порядок.

Коротко: фаза A – дев'ять пілотів, щоб зламати специфікацію; B – виправлення й заморожування
схеми; C – M1; D – M2; E – M3; F – M4, міграція 392 карток.

**Кожна фаза закінчується звітом і зупинкою.** Наступна починається після «продовжуй» від власника.

## Пастки, на які вже наступали

- **Не** міняй `model_id`, поля чи кількість шаблонів після першого опублікованого пакета – див.
  виміряний наслідок вище. Сам тип уже обрано: новий чистий `Interview QA Basic`, і predecessor-
  модель не успадковується (ADR-0010 §1).
- **Не** пиши root-relative URL у контенті: на GitHub Pages `/q/...` веде на корінь домену.
- **Не** перевіряй посилання на dev-сервері – тільки на production-збірці з `base=/interview-qa`.
- **Не** відроджуй `legacy_card_id` і мапу GUID: 392 нотатки не існують у жодній колекції,
  зберігати нема для кого (ADR-0011). На новому `model_id` успадкований GUID ще й небезпечний –
  це єдина комбінація, здатна дати structural merge.
- Стрілки `←` U+2190 і `→` U+2192 **не покриті** підмножинами шрифтів. Щойно з'являться в тексті –
  дадуть fallback. Кандидат у правило валідатора.
- `type::Definition` і `level::Junior` у старій колоді мають **нуль** карток, тож їхня мапа
  і критерії `RUBRIC.md` для junior не перевірені на жодному реальному питанні.

## Чого не роби

- Не публікуй нічого назовні без прямого дозволу.
- Не називай зроблене готовим, якщо воно не перевірене. У цьому проєкті кілька разів виявлялося,
  що переказ документації суперечить вимірюванню – міряй.
- Не чіпай `meta/migration/legacy/` як чинну специфікацію. Це вхід для M4, і після міграції
  каталог зникає.
