Чому Big O недостатньо для прогнозу latency без розміру input, constants та memory-access behavior?	<span class="key">Big O описує лише асимптотичне зростання, відкидаючи constants, які на практичних розмірах можуть переважити різницю класів, і не враховує cache-friendly доступ до пам'яті.</span> По-перше, на конкретному розмірі <code>n</code> алгоритм <code>O(n log n)</code> з великим coefficient може бути повільнішим за <code>O(n²)</code> з малим. По-друге, contiguous memory layout (наприклад, <code>list</code> чи <code>array</code>) використовує CPU cache ефективно, тоді як pointer-chasing у <code>linked list</code> чи розріджений hash-table дають cache misses, що уповільнює виконання в рази. Як shallow та deep copying можуть збільшити allocation cost у hot path?	<span class="key">І shallow, і deep copy створюють нові об'єкти, але shallow копіює лише верхній контейнер (вкладені об'єкти — shared), тоді як deep рекурсивно копіює все, значно збільшуючи allocation у hot path.</span> <code>copy.copy(x)</code> — один новий контейнер, посилання на вкладені об'єкти спільні з оригіналом. <code>copy.deepcopy(x)</code> — новий об'єкт для кожного вкладеного рівня, плюс overhead tracking вже скопійованих об'єктів для коректної обробки циклічних посилань. Чому більше workers може погіршити throughput через contention, context switching та downstream saturation?	<span class="key">Кількість workers понад оптимальну створює конкуренцію за спільні ресурси (GIL, memory allocator, I/O-дескриптори), додаткові context switches та перевантажує downstream-системи.</span> Для CPU-bound задач у GIL-enabled CPython додаткові threads не дають паралелізму, а лише збільшують contention за GIL і перемикання між потоками. Чому <code>lru_cache</code> небезпечно застосовувати до function, result якої залежить від current time, randomness, external mutable state чи side effects?	<span class="key"><code>lru_cache</code> зберігає результат виключно за комбінацією аргументів, тому для non-pure function повертає застаріле або некоректне значення, а side effects на cache hit взагалі пропускаються.</span> Декоратор припускає, що функція є детермінованою: однакові аргументи ⇒ однаковий результат.
