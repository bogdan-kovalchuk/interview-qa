Яка time complexity коду <code>for i in range(n):<br>&nbsp;&nbsp;for j in range(i): work()</code> і яка сума її пояснює?	<span class="key">Time complexity — O(n²), explained by the triangular sum 0 + 1 + 2 + … + (n−1) = n(n−1)/2.</span> Inner loop runs <code>i</code> times for each <code>i</code> from 0 to n−1, giving n(n−1)/2 total calls to <code>work()</code>. Verified with Python 3.14: n=10 → 45 calls, n=100 → 4950 calls. The constant factor ½ is dropped in Big O notation.	topic::21_algorithms_data_structures type::Code level::Middle scope::Overview card::PYI_21_001 ref::TV_COMPUTER_SCIENCE_ALGORITHMES_04 source::PythonDocs source::Community
Чому в Big O відкидають constants і lower-order terms, але вони все ще важливі для real input sizes?	<span class="key">Big O describes growth rate as n → ∞, where the dominant term overwhelms constants and lower-order terms.</span> For example, 3n² + 5n + 100 simplifies to O(n²) because for large n the quadratic term dominates. However, for real finite inputs the constant factor and lower-order terms determine actual runtime — an O(n²) algorithm with a small constant may outperform O(n log n) at practical n values.	topic::21_algorithms_data_structures type::Contrast level::Middle scope::Overview card::PYI_21_002 ref::TV_COMPUTER_SCIENCE_ALGORITHMES_04 source::PythonDocs source::Community
Коли для потоку jobs обрати hash table для lookup by ID, а коли min-heap для постійного вилучення найменшого priority?	<span class="key"><code>dict</code> gives O(1) average lookup by key; <code>heapq</code> min-heap gives O(log n) push/pop and O(1) peek at the smallest element.</span> Choose a hash table when the primary operation is finding or updating a job by its unique ID. Choose a min-heap when you repeatedly need to extract the job with the lowest priority — a heap does not support O(1) arbitrary lookup by ID.<div class="source">Джерело: <a href="https://docs.python.org/3.14/library/heapq.html">Python 3.14: heapq</a></div>	topic::21_algorithms_data_structures type::Scenario level::Middle scope::Overview card::PYI_21_003 ref::TV_COMPUTER_SCIENCE_DATA_STRUCTURES_04 source::PythonDocs source::Community
Коли <code>deque</code> кращий за <code>list</code> для queue або sliding-window algorithm?	<span class="key"><code>deque</code> provides O(1) append and pop from both ends, while <code>list</code> costs O(n) for <code>pop(0)</code> or <code>insert(0, v)</code> because elements must be shifted in memory.</span> For a FIFO queue or sliding-window algorithm that adds/removes at the front, <code>collections.deque</code> avoids the linear cost. Use <code>list</code> when you only append/pop at the end (stack) or need O(1) indexed access.<div class="source">Джерело: <a href="https://docs.python.org/3.14/library/collections.html">Python 3.14: collections</a></div>	topic::21_algorithms_data_structures type::Scenario level::Middle scope::Overview card::PYI_21_004 ref::TV_COMPUTER_SCIENCE_DATA_STRUCTURES_10 source::PythonDocs source::Community
Які preconditions потрібні для binary search і чому вставка в sorted list все ще може бути O(n)?	<span class="key">Binary search requires a sorted sequence; <code>bisect</code> finds the insertion point in O(log n), but <code>list.insert()</code> shifts elements in O(n).</span> The precondition is a sorted input — <code>bisect_left</code> and <code>bisect_right</code> rely on <code>__lt__</code> ordering. Even though the search step is logarithmic, inserting into a <code>list</code> still requires moving up to n elements, making the total insertion cost O(n).<div class="source">Джерело: <a href="https://docs.python.org/3.14/library/bisect.html">Python 3.14: bisect</a></div>	topic::21_algorithms_data_structures type::Mechanism level::Middle scope::Overview card::PYI_21_005 ref::TV_COMPUTER_SCIENCE_ALGORITHMES_06 source::PythonDocs source::Community
Коли для graph traversal обрати BFS, а коли DFS?	<span class="key">BFS explores level-by-level with a queue and finds the shortest path in unweighted graphs; DFS goes depth-first with a stack and uses less memory on narrow graphs.</span> Choose BFS when you need the shortest path or level-order traversal. Choose DFS for topological sorting, cycle detection, or when the target is deep but the graph is wide — DFS memory is O(depth) vs BFS O(width).	topic::21_algorithms_data_structures type::Contrast level::Middle scope::Overview card::PYI_21_006 ref::TV_COMPUTER_SCIENCE_ALGORITHMES_13 source::PythonDocs source::Community
Як мемоїзація або bottom-up dynamic programming змінює complexity recursive solution з overlapping subproblems?	<span class="key">Memoization or bottom-up DP reduces exponential-time recursion with overlapping subproblems to polynomial time by solving each unique subproblem only once.</span> For example, naive recursive Fibonacci is O(2ⁿ), but with a memo table each of the n subproblems is computed once → O(n) time and O(n) space. The trade-off is extra memory for the cache versus recomputation.	topic::21_algorithms_data_structures type::Mechanism level::Senior scope::Overview card::PYI_21_007 ref::TV_COMPUTER_SCIENCE_ALGORITHMES_18 source::PythonDocs source::Community
