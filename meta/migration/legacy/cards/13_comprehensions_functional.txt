Яку scope має iteration variable у list comprehension на Python 3 і чи замінює вона однойменний outer variable?	<span class="key">Iteration variable у list comprehension виконується в окремій неявній вкладеній scope і не витікає в enclosing scope.</span> Тому однойменна зовнішня змінна зберігає своє значення: після <code>x = 99; result = [x for x in range(3)]</code> змінна <code>x</code> дорівнює <code>99</code>, а не <code>2</code>. Це відрізняє comprehension від звичайного циклу <code>for</code>, де iteration variable залишається в поточній scope.<div class="source">Джерело: <a href="https://docs.python.org/3.14/reference/expressions.html#displays-for-lists-sets-and-dictionaries">Python 3.14: Displays for lists, sets and dictionaries</a></div>	topic::13_comprehensions_functional type::Mechanism level::Middle scope::Core card::PYI_13_001 ref::OFFICIAL source::PythonDocs
У якому порядку обчислюються clauses у comprehension з кількома <code>for</code> та <code>if</code>?	<span class="key">Clauses обчислюються зліва направо, як вкладені цикли: кожен <code>for</code> — новий рівень вкладеності, а <code>if</code> фільтрує на поточному рівні.</span> Результат еквівалентний вкладеним <code>for</code>/<code>if</code> блокам зліва направо, де вираз-результат обчислюється щоразу на найглибшому рівні. Наприклад, <code>[(i,j) for i in range(3) for j in range(2) if (i+j) % 2 == 0]</code> дає <code>[(0, 0), (1, 1), (2, 0)]</code>.<div class="source">Джерело: <a href="https://docs.python.org/3.14/reference/expressions.html#displays-for-lists-sets-and-dictionaries">Python 3.14: Displays for lists, sets and dictionaries</a></div>	topic::13_comprehensions_functional type::Mechanism level::Middle scope::Core card::PYI_13_002 ref::OFFICIAL source::PythonDocs
Чому iteration variable comprehension не витікає в containing scope, але target assignment expression у comprehension може зв’язуватися в containing scope?	<span class="key">Comprehension створює окрему неявну scope для iteration variable, але <code>:=</code> (assignment expression) спеціально прив'язує свій target у containing scope, оминаючи цю ізоляцію.</span> Наприклад, після <code>[y := x for x in data]</code> ім'я <code>y</code> доступне поза comprehension, тоді як <code>x</code> — ні. <span class="warn">Якщо в containing scope є <code>nonlocal</code> або <code>global</code> декларація для цього імені, <code>:=</code> її поважає.</span><div class="source">Джерело: <a href="https://docs.python.org/3.14/reference/expressions.html#displays-for-lists-sets-and-dictionaries">Python 3.14: Displays for lists, sets and dictionaries</a></div>	topic::13_comprehensions_functional type::Trap level::Senior scope::Core card::PYI_13_003 ref::OFFICIAL source::PythonDocs
Чому groups, які повертає <code>itertools.groupby()</code>, потрібно спожити або матеріалізувати до переходу до наступної group?	<span class="key">Кожна group — це iterator, який shares the underlying iterable з <code>groupby()</code>; при переході до наступної групи попередній iterator стає порожнім.</span> Тому збереження об'єкта group без матеріалізації (наприклад, у <code>list</code>) призведе до порожнього результату при подальшому споживанні. <span class="warn">Типова помилка: <code>groups = [(k, g) for k, g in groupby(data, key)]</code>, після якої всі <code>g</code> вже вичерпані.</span><div class="source">Джерело: <a href="https://docs.python.org/3.14/library/itertools.html#itertools.groupby">Python 3.14: itertools.groupby</a></div>	topic::13_comprehensions_functional type::Trap level::Middle scope::Core card::PYI_13_004 ref::OFFICIAL source::PythonDocs
У який момент generator expression обчислює свої elements і як це впливає на exceptions та side effects?	<span class="key">Generator expression створює iterator негайно, але обчислює кожен element лише на момент виклику <code>next()</code> (lazy evaluation).</span> Це означає, що exceptions та side effects відкладаються до моменту споживання, а не виникають при створенні виразу. Наприклад, <code>g = (1/x for x in data)</code> не підніме <code>ZeroDivisionError</code> до першого <code>next(g)</code> на елементі <code>x == 0</code>.<div class="source">Джерело: <a href="https://docs.python.org/3.14/howto/functional.html#generators">Python 3.14: Functional Programming HOWTO — Generators</a></div>	topic::13_comprehensions_functional type::Mechanism level::Middle scope::Core card::PYI_13_005 ref::TV_PYTHON_FUNCTIONAL_PROGRAMMING_02 source::PythonDocs source::Community

Функція <code>retry(operation)</code> має прийняти behavior ззовні: як first-class function дозволяє передати operation без її негайного виклику?	<span class="key">У Python функції є об'єктами першого класу: можна передати посилання на функцію (без дужок <code>()</code>), і <code>retry</code> викличе її всередині, коли потрібно.</span> Наприклад, <code>retry(fetch_data)</code> передає callable, а <code>retry(fetch_data())</code> передала б уже виконаний результат. <code>retry</code> може приймати <code>operation: Callable[[], T]</code> та викликати <code>operation()</code> у циклі спроб.<div class="source">Джерело: <a href="https://docs.python.org/3.14/howto/functional.html#functions-are-first-class-objects">Python 3.14: Functional Programming HOWTO — Functions are first class objects</a></div>	topic::13_comprehensions_functional type::Scenario level::Middle scope::Core card::PYI_13_008 ref::TV_PYTHON_FUNCTIONAL_PROGRAMMING_03 source::PythonDocs source::Community
Як <code>functools.partial</code> змінює call interface без негайного виклику wrapped callable?	<span class="key"><code>functools.partial</code> повертає новий callable-об'єкт, у якому частину positional або keyword arguments «заморожено», але оригінальна функція не викликається до виклику partial-об'єкта.</span> Додаткові arguments при виклику доповнюють заморожені; нові keyword arguments мають пріоритет над попередньо заданими. Коли <code>singledispatch</code> краще від extensible <code>if/elif</code> chain і за яким argument воно обирає implementation?	<span class="key"><code>singledispatch</code> обирає implementation за типом першого аргументу, використовуючи MRO для знаходження найближчого зареєстрованого типу.</span> Він кращий за <code>if/elif</code> chain, коли потрібна extensibility: нові типи реєструються через <code>@fn.register(type)</code> без модифікації існуючого коду (open/closed principle). Коли comprehension зазвичай читабельніший за <code>map()</code> або <code>filter()</code>, а коли callable composition перемагає?	<span class="key">Comprehension перемагає, коли потрібно поєднати фільтрацію й трансформацію в одному виразі або коли логіка вимагає inline-умови.</span> <code>map()</code> та <code>filter()</code> читабельніші, коли вже існує готовий named callable — наприклад, <code>map(str, nums)</code> або <code>filter(os.path.exists, paths)</code> — бо не потребують <code>lambda</code>. Comprehension також краще передає структуру даних (list/set/dict), тоді як <code>map</code>/<code>filter</code> завжди повертають iterator.<div class="source">Джерела: <a href="https://docs.python.org/3.14/howto/functional.html">Python 3.14: Functional Programming HOWTO</a>; <a href="https://docs.python.org/3.14/reference/expressions.html#displays-for-lists-sets-and-dictionaries">Python 3.14: Displays</a></div>	topic::13_comprehensions_functional type::Contrast level::Middle scope::Core card::PYI_13_011 ref::TV_PYTHON_FUNCTIONAL_PROGRAMMING_06 source::PythonDocs source::Community
Як initializer визначає result <code>functools.reduce()</code> для empty iterable і як left-to-right grouping змінює result неасоціативної operation?	<span class="key">Без initializer порожнє iterable дає <code>TypeError</code>; з initializer — результатом стає сам initializer, навіть якщо iterable порожній.</span> <code>reduce()</code> застосовує функцію зліва направо: <code>reduce(sub, [1, 2, 3])</code> обчислює <code>((1-2)-3) = -4</code>, а не <code>1-(2-3) = 2</code>. Для неасоціативних операцій (віднімання, ділення) порядок групування визначає результат, тому <code>reduce</code> завжди фіксує left-fold семантику. Додавання initializer зсуває стартовий акумулятор: <code>reduce(sub, [1, 2, 3], 0)</code> → <code>(((0-1)-2)-3) = -6</code>.<div class="source">Джерело: <a href="https://docs.python.org/3.14/library/functools.html">Python 3.14: functools</a></div>	topic::13_comprehensions_functional type::Mechanism level::Senior scope::Core card::PYI_13_012 ref::TV_PYTHON_FUNCTIONAL_PROGRAMMING_06 source::PythonDocs source::Community
