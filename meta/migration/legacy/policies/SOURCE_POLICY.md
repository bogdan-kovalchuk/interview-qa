# Політика джерел

## Пріоритет джерел

1. Офіційна документація Python відповідної стабільної версії.
2. Python Language Reference та Data Model.
3. PEP для мотивації, специфікації й історії зміни.
4. Вихідний код або тести CPython для implementation-specific деталей.
5. Документація інструмента для оглядових тем.
6. Community-ресурси — для пошуку кандидатів у картки, але не як єдина перевірка спірного факту.

## Фіксація джерела

Для кожної теми створюється бриф у `sources/notes` за шаблоном
`authoring/templates/TOPIC_BRIEF_TEMPLATE.md`. У ньому зберігаються URL, версія, дата доступу,
межі теми та твердження, які потребують окремої перевірки.

У самій картці посилання обов’язкове, коли твердження:

- залежить від версії Python;
- стосується CPython, а не специфікації Python;
- описує продуктивність або thread-safety;
- часто подається суперечливо в interview-ресурсах;
- отримане лише з community-джерела.

## Заборони

- Не переносити чужі відповіді дослівно без дозволу ліцензії.
- Не використовувати випадковий interview-блог як остаточний доказ.
- Не створювати посилання, DOI, PEP або номер версії «з пам’яті» ШІ.
- Не змішувати поведінку різних версій в одній відповіді без явного пояснення.
- Не трактувати результат одного запуску як гарантію мови, якщо це implementation detail.

## Актуальність

- Загальне рев’ю колоди: перед кожним активним циклом підготовки.
- Версійні, concurrency та CPython-картки: після кожного feature release Python.
- Картки з community-джерел: перевіряти частіше та замінювати офіційними джерелами, коли можливо.
