# Спадщина `python_interview_questions`

Усе, що перенесено з попереднього проєкту перед його видаленням. Це **вхід для міграції M4**,
а не чинна специфікація. Після завершення M4 цей каталог зникає цілком.

Оригінальний репозиторій заархівовано як `Desktop/python_interview_questions-archive.bundle`
(749 КБ, повна історія з 22 комітів, перевірено `git bundle verify`). Відновити:

```
git clone python_interview_questions-archive.bundle відновлений-репо
```

Стан на момент перенесення: коміт `2372bb7`, тег `baseline-2026-09-03`, 392 картки, 23 теми.

---

## Що тут живе

### `cards/` – 23 TSV, 392 готові картки

**Головний актив.** Це основа майбутнього треку `python`. Формат: `Front⇥Back⇥Tags`, п'ять
директив у заголовку файлу, HTML у полях.

Конвертер M4 читає саме їх. Мапа старих тегів у нові фасети – `../tag-mapping.md`.

Що конвертер отримає автоматично: `Front`, `Short answer` (зі старого `Back`), джерела з
`<div class="source">`. Що доведеться дописувати вручну: усі решта секцій нової схеми, які
стануть `TODO`.

### `front-sources.csv` – провенанс 392 карток

`card_id, topic_tag, card_file, front_sha256, community_answer_ref, official_refs, source_role,
back_status`.

Потрібен, бо нова специфікація вимагає `source_id` і прив'язку тверджень до джерел. Без цього
файлу джерела для 392 карток довелося б відкривати наново.

### `code-checks.csv` – 29 перевірених прикладів

`card_id, python_version, mode, evidence, status`. Прямо лягає на нові поля `execution` і на
ворота `example-executed`.

### `front-coverage-plan.csv`, `coverage.csv`

Плановані кластери й статуси тем. Опора для мапи при міграції; після M4 – історія.

### `apkg-note-identity.csv`, `anki-smoke.csv`

`card_id → anki_guid` і журнал smoke-тестів імпорту. **Історична довідка.**
GUID звідси **не використовуються**: проєкт перейшов на детерміновані GUID від нових `id`
(ADR-0006, і причина – у `../anki-compatibility-report.md`).

### `policies/`

Специфікації попереднього проєкту: `CARD_SPEC`, `SOURCE_POLICY`, `DECISIONS`,
`FRONT_PROVENANCE`, `TAXONOMY`, `QUALITY_GATES`, `NOTE_TYPE_TEMPLATE`, `manifest.json`,
`legacy-AGENTS.md`.

**Усі замінені** чинними документами в `meta/`. Лишені як матеріал: у них є вистраждані правила,
частину яких ще не перенесено в нову специфікацію. Читати – так, посилатися як на чинне – ні.

### `research/`

Три дослідницькі записки. Одна з них, `apkg-generation-and-update-strategy.md`, містить
**спростоване** твердження про «ignored updates» при зміні note type – саме ту помилку, яку
виміряв експеримент J. Лишена як приклад того, чому припущення треба міряти.

### `scripts/`

Валідатори й білдери попереднього конвеєра. Архітектура нового валідатора інша (pydantic,
нова схема), але логіка перевірок TSV, провенансу і структури проєкту тут працююча – варто
прочитати перед тим, як писати `tools/iqa/validate.py`.

### `reviews/`

`EXHAUSTIVE_PROJECT_REVIEW.md` і `PROJECT_REVIEW_PROMPT.md` – рев'ю попереднього проєкту
і промпт, яким його робили.
