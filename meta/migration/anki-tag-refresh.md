# Експеримент F: що імпорт робить з тегами

Довимірювання після M0.4, де F вийшов `inconclusive` через некоректний harness.

Питання було одне:

> Коли пакет оновлює наявну нотатку, що стається з тегом, який є в нотатці, але **немає** в пакеті?

## Середовище

| Параметр | Значення |
|---|---|
| ОС | Windows 11 |
| Python | 3.14.2 |
| `anki` | 26.8.1 |
| `genanki` | 0.13.1 |
| Fixture | контрольована колекція, 3 нотатки на `Interview QA Basic` (`model_id 1600000000001`) |
| Harness | `packaging/anki/spike/run_tag_refresh.py` |
| Докази | `packaging/anki/spike/tag-refresh-evidence.json` |

Вимірювання виконано на власній фікстурі, а не на даних власника.

## Результат

**Теги замінюються повністю. Тег, якого немає в пакеті, видаляється з нотатки.**

| Нотатка | Теги до | Теги після |
|---|---|---|
| `x-tags-0001` | `drop::b`, `keep::a`, `qid::x-tags-0001` | `add::c`, `keep::a`, `qid::x-tags-0001` |
| `x-tags-0002` | `keep::todo`, `qid::x-tags-0002`, **`todo::short-answer`** | `added::todo-cleared`, `keep::todo`, `qid::x-tags-0002` |
| `x-tags-0003` | `keep::role`, `qid::x-tags-0003`, `role::python-backend` | `added::role-cleared`, `keep::role`, `qid::x-tags-0003` |

Тобто: `keep::*` збережено, `drop::b` і `role::python-backend` **видалено**, нові додано.

### Випадок, від якого залежить звітність

| | |
|---|---|
| тег `todo::short-answer` був у нотатці | так |
| тег присутній у новому пакеті | ні |
| тег лишився після імпорту | **ні** |
| зникає самостійно | **так** |

## Наслідки для ADR

### ADR-0009

**Підтверджено.** Твердження, що правка тегів безпечна, тепер виміряне, а не припущене. Рядок
«Твердження про безпечне оновлення тегів лишається невиміряним» у
`meta/migration/anki-compatibility-report.md` більше не чинний.

### ADR-0008

**Підтверджено.** Фільтровані колоди за тегом `role::` працюють як задумано: коли питання виходить
зі складу програми, тег зникає при наступному оновленні, і колода перестає його показувати.
Ручного прибирання не потрібно.

### PROGRESS_TRACKING.md

**Підтверджено.** Припущення, що теги `todo::` зникають самі, коли умова знята, справджується.

## Обмеження вимірювання

Harness запускав два сценарії з мітками `intended` і `desktop_default`, але **обидва з однаковим
набором опцій** (`merge_notetypes=true`, `update_notes=ALWAYS`, `update_notetypes=ALWAYS`,
`with_scheduling=false`, `with_deck_configs=false`). Тобто фактично зроблено **одне** вимірювання,
а не два.

Отже поведінка **штатного шляху**, коли користувач просто відкриває `.apkg` подвійним кліком і
приймає діалог імпорту за замовчуванням, лишається неперевіреною. Наш власний конвеєр
використовує саме зафіксовані вище опції, тож для проєкту відповідь є; для стороннього
користувача – ще ні.

Прогін було обірвано на ліміті провайдера, тому агент не встиг ні розділити сценарії, ні написати
цей звіт – його зведено з машинних доказів у `tag-refresh-evidence.json`.
