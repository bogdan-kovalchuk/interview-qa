# Відстеження прогресу

Скелет існує завжди (`CONTENT_SPEC.md` §3a), тому головне питання щодня – **де саме дірки**.
Цей документ описує таблицю, яка на нього відповідає.

Таблиця **генерується**, ніколи не ведеться руками. Джерело – самі файли питань: те, що в них
фактично написано, і нічого більше. Заявити «тут готово» неможливо.

---

## 1. Артефакти

| Артефакт | Формат | Для чого |
|---|---|---|
| `dist/export/progress.csv` | CSV, один рядок = одне питання | відкрити в Excel, відсортувати, спланувати |
| `dist/export/progress.json` | JSON з тими самими даними + агрегати | вхід для сайту й ботів |
| `/{lang}/status/` | сторінка сайту з фільтрованою таблицею | подивитись очима, поділитись посиланням |
| `python -m iqa report --todo` | текст у консоль | агент або автор бере наступну задачу |

## 2. Колонки таблиці питань

Найнижчий рівень деталізації – одне питання. Кожна колонка вмісту має три значення:
`done` / `todo` / `n/a` (секція не потрібна для цього `type`).

### Ідентичність і розташування

| Колонка | Приклад |
|---|---|
| `id` | `py-asyncio-0007` |
| `track` | `python` |
| `section` | `asyncio` |
| `slug` | `blocking-call-freezes-event-loop` |
| `status` | `draft` / `review` / `published` |
| `level` | `middle` |
| `type` | `mechanism` |

### Вміст по кожній мові

Блок повторюється для `en` і `uk` (і для будь-якої мови, що з'явиться пізніше):

| Колонка | Що означає |
|---|---|
| `{lang}_file` | файл узагалі існує |
| `{lang}_title` | заголовок написано (не `TODO`, не копія з іншої мови) |
| `{lang}_short` | `## Short answer` написано |
| `{lang}_detailed` | `## Detailed explanation` написано |
| `{lang}_example` | `## Example` написано або `n/a` для цього `type` |
| `{lang}_pitfalls` | `## Pitfalls` написано |
| `{lang}_completeness` | `stub` / `partial` / `complete` |
| `{lang}_unreconciled` | інша мова змінилась після останнього узгодження (`I18N.md` §7) |

### Метадані й похідне

| Колонка | Що означає |
|---|---|
| `sources_count` | скільки джерел; окремо – чи є хоч одне не-`community` |
| `tags_count`, `frameworks` | заповненість фасетів |
| `objectives` | які цілі співбесіди питання закриває (§3a) |
| `xrefs_ok` | усі токени `qid:` у тексті резолвляться |
| `card_en`, `card_uk` | `ships` / `blocked:short-answer` / `blocked:no-translation`, за `LIFECYCLE.md` |
| `programs` | у які програми питання входить |
| `guid` | GUID нотатки (для звірки з release manifest) |
| `updated` | дата останньої зміни |

### Приклад рядка

```csv
id,track,section,status,level,type,en_short,en_detailed,en_example,uk_short,uk_detailed,card_en,card_uk,programs
py-asyncio-0007,python,asyncio,published,middle,mechanism,done,done,done,done,todo,ships,ships,"python-backend;python-data-engineer"
```

Читається так: питання опубліковане, англійська готова повністю, українська має коротку відповідь
(тож картка в українську колоду йде), але розгорнутого пояснення українською ще немає.

## 3. Агрегати

Та сама таблиця згортається на трьох рівнях: секція → трек → проєкт, і окремо по програмах.

| Розріз | Показує |
|---|---|
| по секціях | де найбільше `todo`, з чого вигідніше почати |
| по треках | перекоси наповнення між напрямками |
| по мовах | покриття перекладом і що потребує узгодження |
| по програмах | наскільки готова конкретна програма підготовки |
| по цілях | які цілі співбесіди ще не закриті жодним `complete` питанням |
| по типах секцій | чого системно бракує (наприклад скрізь немає `Example`) |

Останній розріз найкорисніший: він показує не окремі дірки, а **системні** – коли цілий клас
роботи не зроблено ніде.

---

## 3a. Покриття цілей, а не лише секцій

Таблиця вище відповідає на питання «які секції заповнені». Вона **не** відповідає на питання
«чи достатньо людина підготовлена до конкретної співбесіди» – і рев'ю плану справедливо назвало це
пропуском (M-06).

Небезпека конкретна: ціль виду «100 питань по C++» стимулює дійти до числа, а не закрити прогалини.

### Друга проєкція

```
роль → компетенція → ціль співбесіди → рівень → question IDs → стан доказовості
```

`meta/objectives/{track}.yml` описує цілі на рівні **секції**, а не всієї професії:

```yaml
- id: cpp-mem-lifetime
  title: {en: Object lifetime and ownership, uk: Час життя об'єкта і володіння}
  section: cpp/memory-model-and-lifetime
  levels: [junior, middle, senior]
  signals:
    - розрізняє automatic, static, dynamic і thread storage duration
    - пояснює, коли дає UB звернення до знищеного об'єкта
    - обирає між value, reference і smart pointer з обґрунтуванням
```

Звіт покриття показує для кожної цілі: скільки питань її закривають, на яких рівнях, і чи є серед
них хоча б одне `complete`. Ціль без жодного `complete` питання вважається незакритою, скільки б
`stub` на неї не посилалося.

**Кількість карток стає наслідком, а не критерієм приймання.**

### Обсяг на старті

Повна competency-матриця по всіх ролях зараз була б вигадуванням наперед. Тому на M1 робляться цілі
рівня секції для треків, які реально наповнюються; матриця ролей – після M5, коли буде на чому її
калібрувати.

---

## 4. Сторінка `/status/`

Публічна, обома мовами, з фільтрами за треком, секцією, мовою, рівнем повноти й програмою.
Кожен рядок – посилання на питання і на його файл у GitHub.

Це і є те, що робить «work in progress» чесним: незавершеність показана як дані, а не як дисклеймер
у футері.

---

## 5. Чому це не `tracking/coverage.csv` з наявного репозиторію

У `python_interview_questions` покриття ведеться вручну як окремий файл, який треба не забути
оновити. Такий файл завжди відстає від реальності – він каже, що автор думав про стан, а не який
стан насправді.

Тут навпаки: таблиця є **проєкцією фактичного вмісту файлів**. Розсинхрон неможливий, бо немає
чого синхронізувати. Ручний `tracking/` при міграції не переноситься.

## 6. Використання агентом

`python -m iqa report --todo` віддає наступні задачі у стабільному порядку – за замовчуванням
за пріоритетом: спершу питання без `Short answer` мовою колоди (бо вони блокують картку), потім
без розгорнутого пояснення, потім без прикладів.

```
$ python -m iqa report --todo --track cpp --limit 5
cpp-mem-0012   uk_short       блокує картку в українській колоді
cpp-tmpl-0004  en_detailed    сторінка існує, пояснення немає
cpp-tmpl-0004  uk_detailed
cpp-stl-0031   en_example     type: coding вимагає приклад
cpp-conc-0008  uk_file        мовної версії немає взагалі
```

Це і є робочий інтерфейс для «агент робить усе»: не «напиши щось про C++», а конкретна наступна
дірка з причиною, чому вона важлива.
