# Quality gates

Проєкт такого розміру не тримається на дисципліні автора. Усе, що не перевіряє CI, з часом
розсинхронізується. Нижче – мінімальний набір воріт.

Політика: **блокуючі** ворота не пропускають PR; **звітні** пишуть коментар і не блокують.

---

## 0. Скелет обов'язковий, вміст – ні

Проєкт наповнюється поступово, але **структура завжди повна** (`CONTENT_SPEC.md` §3a): обидві мовні
версії, усі обов'язкові секції, сторінка, картка. Ненаписане позначається маркером `TODO`.

Звідси проста межа для воріт:

| Перевіряється завжди | Не перевіряється, поки `TODO` |
|---|---|
| обидва мовні файли існують | чи написано `Detailed explanation` |
| усі обов'язкові секції присутні | чи написано `Example` для `coding`/`practical` |
| `id` унікальний, незмінний, у реєстрі | |
| frontmatter валідний, фасети зі словника | |
| ≥1 джерело | |
| крос-посилання `/q/{id}/` резолвляться | |
| паритет мовних версій (§1a) | |
| ліміти `Short answer` – якщо він не `TODO` | |

Тобто плейсхолдер звільняється **лише** від наявності тексту. Він не звільняється від структури,
ID, джерел і мовного паритету – саме там борг потім дорого виправляти.

`completeness` (`stub`/`partial`/`complete`) не є воротами взагалі: вона обчислюється зі сканування
секцій і використовується лише для плашок, звітів і тегів `todo::`.

## 1a. Ворота паритету мовних версій (блокуючі)

Обидві версії пише агент (`I18N.md` §4a), тому розходження між мовами ловиться машиною, а не оком.

| Ворота | Що перевіряє |
|---|---|
| `lang-files-exist` | для кожного питання існують **обидва** мовні файли (вміст може бути `TODO`) |
| `lang-structure-parity` | однаковий набір і порядок секцій в усіх мовах |
| `lang-code-identical` | блоки коду побайтово збігаються – переклад не має права правити код |
| `lang-links-parity` | однаковий набір `sources` і токенів `qid:` |
| `lang-glossary` | терміни вжиті у формі зі словника `content/i18n/glossary.csv` |
| `lang-reconciliation` | `content_revision` однієї мови не випереджає `reconciled_with` іншої (звітне, не блокує) |

Воріт якості перекладу тут немає і не буде: AI-переклад – це звичайний переклад (ADR-0012).
Parity ловить механічні поломки, а семантику не доводить ніщо – і це прийнята ціна, а не дірка.

## 5. Життєвий цикл `status`

Нормативна таблиця – `meta/LIFECYCLE.md`. Тут лише ворота, що з неї випливають.

```
draft ──► review ──► published ──► withdrawn
  │             │
  └── rejected ◄┘
```

- `draft` – не потрапляє ні на сайт, ні в колоду; валідується послаблено (можна без джерел).
- `review` – валідується повністю; на сайті видно тільки в preview-збірці.
- `published` – на сайті і в колоді; повний набір воріт.
- Відхилені питання не видаляються мовчки: запис у `meta/rejected.csv` з причиною
  (`duplicate`, `trivia`, `ambiguous`, `outdated`, `incorrect`, `out_of_scope`) – політика
  успадкована з наявного репозиторію.

## 7. Правила, які не автоматизуються

Їх перевіряє рев'ю (людське або агентське) за чеклістом:

- питання справді ставлять на інтерв'ю (а не «цікавий факт»);
- одне питання перевіряє одну ідею;
- відповідь не переказує джерело дослівно;
- приклад мінімальний і відтворюваний;
- канонічна домівка обрана за правилом `ANALYSIS.md` §5.2, а не за зручністю;
- версійні твердження мають кваліфікатор (Python 3.14, C++20, GCC 13).

## 8. Ворота production-збірки і ланцюга постачання

Додано за результатами рев'ю плану (M-16). Проєкт публікує артефакти, які люди імпортують у свої
колекції, тож походження збірки має бути перевірним.

| Ворота | Що перевіряє |
|---|---|
| `lockfiles` | Python lock і Node lock присутні й актуальні |
| `pinned-actions` | усі GitHub Actions запінені за immutable commit SHA, не за тегом |
| `dependency-audit` | аудит вразливостей і ліцензій залежностей; `THIRD_PARTY_NOTICES` актуальний |
| `production-base` | сайт збирається з `base=/interview-qa`; усі `href` у зібраному HTML коректні |
| `canonical-hreflang` | кожна сторінка має `canonical`, обидві мови мають `hreflang` |
| `sitemap-robots` | `sitemap.xml` і `robots.txt` згенеровані й валідні |
| `a11y-smoke` | базова перевірка доступності на репрезентативних сторінках |
| `release-checksums` | контрольні суми артефактів релізу і dependency manifest |
| `no-em-dash` | у жодному `.md` немає U+2014 (типографічна вимога, `AGENTS.md`), **крім** `meta/migration/legacy/**` |

Виняток для `meta/migration/legacy/**` не косметичний: це заморожений вхід для M4 – скопійовані
документи попереднього репозиторію, які не редагуються, а споживаються конвертером і зникають
після міграції. Без винятку ворота блокували б кожен PR до кінця M4 через файли, правити які
заборонено. Живі документи винятку не мають.

SBOM свідомо відкладено до відкриття зовнішніх внесків: для сольного проєкту dependency manifest
плюс контрольні суми дають те саме за меншу ціну.

## 9. Ворота достовірності тверджень

Додано за результатами рев'ю плану (M-10). Наявність одного джерела в питанні не доводить, що
кожне твердження у відповіді відповідає дійсності.

| Ворота | Що перевіряє | Тип |
|---|---|---|
| `source-present` | ≥1 джерело, не лише `community` | автоматичне |
| `claim-linked` | нетривіальні твердження мають посилання на `source_id` з точним розділом чи якорем, **за таблицею типів** `CONTENT_SPEC.md` §3b | автоматичне (наявність), людське (доречність) |
| `source-applicability` | у джерела зафіксовані версія, дата доступу і межі застосовності | автоматичне |
| `example-executed` | кожен приклад компілюється або виконується в оголошеному `execution`: `toolchain.name`+`version` як runner, `flags` як обов'язкові прапорці | автоматичне |
| `review-invalidated` | змістовна правка тіла скидає позначку пройденого рев'ю | автоматичне |

Три різні твердження – «джерело є», «джерело підтверджує це твердження» і «приклад виконано» –
розділені навмисно: перше нічого не каже про друге.

`claim-linked` читає таблицю типів, а не застосовує одне правило до всіх дев'яти. Причина
виміряна на пілотах: для `coding` розв'язання доводить `execution` і секція `Tests`, а не цитата,
а для `behavioral` джерела документують компетенцію, а не правильність відповіді. Єдине правило
для всіх типів давало ворота, які проходять, і прив'язку, яка нічого не доводить.
