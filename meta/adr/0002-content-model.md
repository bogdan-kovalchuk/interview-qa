# ADR-0002. Модель контенту

**Статус:** прийнято (2026-09-03)
**Дата:** 2026-09-03

## Контекст

Один і той самий контент має живити три різні виходи: сайт, колоду Anki і (в перспективі) датасет
або бота. Референс тримає багато питань на одній сторінці з якорями – це зручно для читання, але
робить питання не-адресованим і не-експортованим.

## Рішення

1. **Одне питання = один Markdown-файл** з YAML frontmatter і фіксованим набором секцій.
2. **Контент відв'язаний від генератора**: чистий Markdown, без MDX, без імпортів компонентів.
   `content/` можна віддати будь-якому генератору. Посилання всередині – токени `qid:`, а не URL.
3. **Секція `## Short answer` – контракт**: саме її текст іде на зворот картки Anki.
4. **Фасети у frontmatter** (`level`, `type`, `tags`, `frameworks`) – єдине джерело для всіх
   згенерованих зрізів. `roles` до цього переліку більше не входить: членство в програмах
   виводиться з `programs/*.yml`, а не дублюється у frontmatter (ADR-0010 §5).
5. **Єдиний контракт експорту.** `content/` читає рівно один компонент – `tools/`. Сайт споживає
   згенероване дзеркало `site/src/content/docs/`, решта споживачів – `dist/export/`
   (уточнено ADR-0010 §3; раніше тут було сформульовано так, що суперечило схемі сайту).

## Наслідки

- Реорганізація дерева не потребує змін у споживачах.
- PR з одним питанням читається як один файл – рев'ю дешеве.
- Тисячі файлів замість сотень сторінок: навігація мусить генеруватись, ручний `nav` неможливий.
- Схема дублюється в Python (валідатор) і TypeScript (Zod). Канонічною є **pydantic-модель**
  у `tools/iqa/model.py`; з неї експортується `meta/schema/question.schema.json`, з нього
  генерується Zod (ADR-0010 §4). CI має parity-тест: регенерація не дає діфу.

## Альтернативи

| Варіант | Чому відхилено |
|---|---|
| Багато питань на сторінці + якорі (як у референсі) | немає стабільної адреси питання, немає атомарного експорту в Anki, конфлікти в PR |
| Питання в базі даних / JSON, Markdown генерується | втрачається читабельний diff і рев'ю в PR |
| MDX з компонентами всередині питань | прив'язує контент до Astro назавжди |
