# ADR-0005. Стабільні permalink та схема ID

**Статус:** прийнято (2026-09-03)
**Дата:** 2026-09-03

## Контекст

Посилання на розгорнуту відповідь вставляється в поле картки Anki. Картки живуть у профілях учнів
роками і **не перебудовуються** при реструктуризації сайту. Водночас таксономія на 2000+ питань
неминуче буде реорганізовуватись.

## Рішення

1. Кожне питання має незмінний `id` виду `{track}-{section}-{NNNN}` (`py-asyncio-0007`).
2. У картку Anki йде **виключно** `https://{host}/{base}/{lang}/q/{id}/` – ніколи не гарний URL.
   У самому контенті URL не пишеться взагалі: там токен `qid:<id>`, який матеріалізує споживач
   (ADR-0010 §2). Base path `/interview-qa/` враховується лише на етапі матеріалізації.
3. **Ревізія 2026-09-03:** канонічна адреса сторінки питання сама живе під `/q/`, а таксономія в
   ній не бере участі: `/{lang}/q/{id}/{slug}/`. `slug` потрібен лише для читабельності й пошукових
   систем і при резолві ігнорується; коротка форма `/{lang}/q/{id}/` веде на поточну канонічну.
   Сторінки `/{lang}/{track}/{section}/` лишаються, але як **індекси** зі списком питань, а не як
   адреси самих питань.
   Причина зміни: таксономія на 2000+ питань точно буде реорганізовуватись, а поки вона є частиною
   адреси сторінки, кожна реорганізація породжує редіректи. Прибравши її з адреси, ми прибираємо
   цілий клас поломок замість того, щоб їх обслуговувати.
4. ID не змінюється при переїзді питання в інший трек і **ніколи не перевикористовується**.
5. Видалене питання віддає сторінку «питання вилучене» з посиланням на заміну, а не 404.
6. `meta/id-registry.csv` – арбітр виданих ID; CI звіряє з ним кожен PR.
7. Перейменування файлу супроводжується записом у `meta/redirects.csv` (для зовнішніх посилань).

## Уточнення 2026-09-03: короткий permalink – це resolver page, а не HTTP-редірект

Статичний хостинг не вміє віддавати 301/308. В Astro зі static-адаптером «редірект» матеріалізується
як HTML-сторінка з meta refresh, і це впливає на SEO, canonical, кешування та на те, як писати тести
(рев'ю плану, M-02).

Тому `/{lang}/q/{id}/` визначається як **resolver page**, яка:

- містить `<link rel="canonical">` на повну адресу `/{lang}/q/{id}/{slug}/`;
- виконує негайну навігацію;
- показує видиме посилання як fallback, якщо навігація не спрацювала;
- у стані `withdrawn` не редіректить нікуди, а є надгробком.

Тестується як resolver page з правильним canonical, **не** як HTTP-редірект.

## Наслідки

- Реорганізація дерева контенту стає безкоштовною – жодна картка не ламається.
- Ціна: один зайвий перехід через resolver page.
- ID перестає бути надійним індикатором розташування – розташування знає тільки датасет.
- Ім'я репозиторію (частина `{base}` у GitHub Pages URL) стає майже незмінним. **Зафіксовано
  2026-09-03: `interview-qa`**, отже канонічна форма посилання в картці –
  `https://bogdan-kovalchuk.github.io/interview-qa/uk/q/{id}/`. Перейменування репозиторію після
  першої публікації колоди заборонене.

## Хост: стандартна адреса GitHub Pages, без власного домену

**Зафіксовано 2026-09-03.** Сайт живе на `https://bogdan-kovalchuk.github.io/interview-qa/`, як і
референсний проєкт. Власний домен не заводиться.

Рішення виглядає косметичним, але для цього проєкту воно належить саме до permalink-контракту.
Посилання розходяться по картках, які роками лежать у чужих профілях Anki і ніколи не
перебудовуються. Отже хост має бути найдовговічнішим з доступних:

| | `*.github.io` | власний домен |
|---|---|---|
| Вартість | безкоштовно | щорічна оплата |
| Термін дії | немає | закінчується; несплата = миттєва смерть **усіх** посилань одночасно |
| HTTPS | автоматично, сертифікат оновлює GitHub | автоматично після налаштування DNS |
| Що дає | нічого зайвого | коротшу адресу для бренду |

Тобто власний домен додає постійне зобов'язання без технічної вигоди, а ціна його втрати –
непоправна. Коротка адреса вже забезпечена іменем репозиторію (`interview-qa`, а не
`interview-questions-and-answers`).

Якщо колись рішення переглянуть, домен треба підключати **до** першого релізу колоди: GitHub Pages
редіректить стару адресу на нову, але покладатись на редірект для вічних посилань гірше, ніж одразу
випустити картки з кінцевою адресою.

## Альтернативи

| Варіант | Чому відхилено |
|---|---|
| Пряме посилання на канонічний URL + CI-заборона змінювати URL | заморожує таксономію назавжди |
| Пряме посилання + `redirects.csv` для кожного переїзду | працює, але список редіректів росте нескінченно і одна забута зміна тихо ламає картки |
| Числовий глобальний ID (`q/10472`) | нечитабельний у diff і в тегах Anki |
| UUID | те саме плюс шум у кожному посиланні |
